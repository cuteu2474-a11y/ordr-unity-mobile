## 2. 공통 영웅 능력치 완성 — MS-02~19

### 2.1 값의 의미부터 분리

영웅의 힘은 공격력, 유닛 등급, UnitPointValue와 다른 값입니다. 원본의 `GetHeroStatBJ(...,false)`는 보너스 제외, `true`는 보너스 포함 값이므로 하나의 조회 함수 결과를 무조건 공유하면 안 됩니다.

기존 `Original323HeroAttributeWorld`를 다음 원리로 확장합니다.

- 순수 능력치 = 현재 폼 초기값 + 원본 레벨 성장 + 원본 SET 승계 보정 + 해당 원본에서 순수 값에 반영하는 영구 변경.
- 전체 능력치 = 순수 능력치에 **원본에서 그 능력치를 변경하는 것으로 확인된** 유효 보너스를 적용한 결과. 덧셈·곱셈·정수화 순서는 효과별 원본 규칙을 따른다.
- 공격력 +n%, 방어 +n, 공속 +n%는 그 자체로 힘/민첩/지능 보너스가 아니다.
- 원본 값 0, 엔진의 생략 셀 기본값 0, 자료 미확정(null)을 구별한다. 마지막 것을 0으로 치환해 완료 처리하지 않는다.
- 현재 66개 생략 셀의 0은 저장소가 채택한 OpenRealm 디코딩 모델이다. 원본 Warcraft 실측값과 같은 것으로 표시하지 않는다.

현재 파일: `Original323HeroAttributeWorld.cs`, `Original323NativeHeroAttributeEvidence.cs`, `Original323HeroLevelRules.cs`, `OrdrCharacterCombatController.cs`. 기존 컨트롤러의 `ConfigureSourceModelOriginalHeroAttributes` 연결을 재사용합니다.

### 2.3 갱신과 타격의 순서

1. 최초 생성 시 원본 폼과 XP 상태를 등록한다.
2. 비용/버프/성장 거래가 확정될 때 해당 출처 상태와 능력치 리비전을 함께 갱신한다.
3. 스킬 성공 분기가 결정된 뒤 원본이 읽는 시점에 필요한 능력치를 조회한다.
4. 원본이 시전 시 한 번 읽는 기술은 불변 스냅샷을 예약에 넣는다. 매 타격 다시 읽는 기술만 타격 시 조회한다.
5. 각 타격에서 대상의 생존/전장/면역·체력 기준을 검사한 뒤 같은 공통 피해 정산기로 보낸다.
6. 시전자 제거·교체·전장 이동 시 기존 효과 정책에 따라 취소/승계한다. 새 정책을 임의로 만들지 않는다.

나미는 현재 시전 시 지능을 읽는 코드가 있으므로 8타마다 지능이나 난수를 재조회하는 구현을 추가하지 않습니다. 능력치 보너스가 시전 중 만료되는 경우도 이 원본 시점 규칙으로 판정합니다.

### 2.4 실제 폼 교체 거래에 SET 승계 붙이기

원본 Bjq/Bxc의 순서는 **구형 순수 3능력치 읽기 → 새 영웅 경험치 설정 → 순수 3능력치 SET**입니다. 기존 티켓 API는 이 수식을 보존하지만 비용/로스터 거래를 대신하지 않습니다.

1. 기존 거래의 사전 검사에서 현재 개체·XP·폼 리비전·다음 rawcode를 검증한다.
2. `CaptureJassSetHeroStats`로 교체 전 값을 동결한다. 티켓이 없으면 불완전 승계로 진행하지 않는다.
3. 원본이 정한 비용/재료·폼/개체 교체를 기존 원자 거래 안에서 준비한다.
4. 새 폼의 XP를 확정한 상태에서 `CommitJassSetHeroStats` 적용 가능 여부를 검사한다.
5. 승계 적용과 거래 공개를 함께 성공시키도록 기존 롤백/스테이징 경로에 편입한다. 현재 API가 거래 뒤에만 호출되므로, 적용 실패 후 유닛/비용만 확정되는 틈을 먼저 해소한다.
6. 후속 레벨업은 새 폼의 **새로 얻은 성장분만** 더한다. 복사한 XP에 대응하는 성장분을 다시 누적하지 않는다.

저장할 것은 단순 표시 능력치만이 아니라 현재 폼·XP·승계 보정·영구 변경·유효 보너스·리비전입니다. 복원 시 변신 명령을 재실행하지 않습니다.

## 3. 카이도 비례 피해의 정확성 — MS-20~23 및 4콜백

현재는 `CharacterCombatRuntime.SourceModelNativeCharacters.cs`가 공격 선언에서 후속 정보를 보관하고 기본 명중 결과의 `ResolvedDamage`를 받아 비례 피해를 정산합니다. **비례식 자체는 이미 있습니다.** `ActualDamage`는 실제 줄어든 HP라 막타/초과 피해에서 다르고, `ResolvedDamage`도 원본 `GetEventDamage`와 같다고 실측된 것은 아닙니다.

### 3.1 동일한 공격 사건을 따라가기

후속 예약에는 시전자 ID·대상 ID·공격 순번·현재 폼·분기·원본 배율·치명 결과·전장 리비전이 필요합니다. 현재 개체별 단일 pending 저장으로 충분한지 확인하고, 투사체 겹침/추가 공격으로 다음 선언이 앞선 미도착 공격을 덮을 수 있으면 기존 공격 사건 ID에 매달도록 확장합니다.

처리 순서는 선언→원본 분기 추첨→기본 타격→해당 사건의 명중 결과→후속 피해입니다. 다른 적을 때린 다음 평타 결과를 가져오거나, 후속 스킬이 다시 같은 평타 콜백을 촉발해서 무한 증폭되지 않아야 합니다.

| 분기 | 비교할 비율 | 추가 확인 |
|---|---|---|
| 인간형 8% | 평타 성분50% | 치명1.5의 적용 대상, 단일 고정량·기절 |
| 용형 8% | 평타 성분30% | 기본량 난수와 비율 성분의 순서 |
| 인간형10회 | 평타 성분400%, 단일 고정 보너스150% | 보너스의 기준 피해, 원본 공격 횟수 증가 시점 |
| 용형10회 | 평타 성분300%, 단일 고정 보너스75% | 폼 변경 시 카운터와 상태 승계 |
| B_5/B_1 | 각 EventDamage×0.3 | 별도15% 분기와 원본 치명 난수 순서 |
| CBE | EventDamage×0.25 | 범위/단일 피해를 별도 패킷으로 유지 |
| CBI | EventDamage×0.1 | 두 타격의 원본 지연·위치·생존 재검사 |

### 3.2 피해타입·타이밍

원본 공격 타입과 피해 타입을 별도 기록하고, 물리/마법이라는 화면 이름만 보고 기존 타입을 바꾸지 않습니다. 고정 피해가 원본에서 방어/면역을 어떻게 통과하는지도 따로 확인합니다. ‘저항 무시’ 플래그를 모든 보스 기절 허용으로 해석하지 않습니다.

지연 타격은 원본 간격을 확인한 뒤 공통 논리 시계로 예약합니다. 최초 공격 위치 고정인지 매번 현재 위치인지, 주 대상이 죽어도 범위 타격이 남는지 각각 원본 분기대로 처리합니다. CBI의 즉시2패킷을 근거 없이 임의 시간으로 벌리지 않습니다.

**완료 기준:** 두 폼·각 분기·치명·막타 초과 피해·빗나감/불발·동시 투사체·폼/전장 변경에서 사건 1개당 정산이 정확히 한 번. 원작 의미 대조와 실행 검증은 별도 기록합니다.

## 4. 료마·시저·요크의 실제 효과

### 4.1 MS-01 료마 흑도 슈스이

현재 기본/확률 피해는 유지합니다. 저장소의 최신 원본 조사 메모는 대상 `A902/A911/A903/A904` 배제 조건 및 `현재HP×0.10×(0.79+A11S레벨×0.01)`을 요구합니다. 앞선 단순 ‘현재HP10%’ 설명만으로 추가하지 않습니다.

구현 절차:
1. 원본 Bos에서 표식 검사·체력 읽기·기본/추가 피해 순서를 확인한다.
2. 적 생성 시 실제 원본 객체 능력 목록과 A11S 레벨을 기존 적 상태에 연결한다. 일반/보스라는 분류만으로 능력 부재를 추측하지 않는다.
3. 성공한 기존 추첨 분기에서 적별 자격을 검사한다.
4. 원본 시점의 체력·레벨로 추가량을 계산하고 기존 공통 피해 경로에 한 번 전달한다.
5. 표식이 바뀌는 적은 현재 상태를 읽고, 생성 시 고정 레벨이라면 원본대로 생성 스냅샷을 쓴다. 조사 없이 전역 최신값으로 소급하지 않는다.

필수 경계: 표식 하나라도 존재, 레벨 미공급, 현재HP 낮음, 기본 타격으로 사망, 동일 확률 분기 재호출. 완료 전 부족한 원본 입력을 보류 사유로 유지합니다.

### 4.2 MS-24 시저 가스가스열매

현재 주기 함수가 0.4초마다 대상을 찾지만 피해계열 미확정 로그만 남깁니다. 남은 것은 별도 타이머 신설이 아니라 해당 경로의 피해 적용입니다.

원본에서 능력/버프/더미와 실제 피해 호출을 찾아 33,333의 타입·중심점·반경1000·첫 타격 시점·면역·중첩 방식을 확정합니다. 기존 스케줄러의 다음 예정 시각을 기준으로 0.4초 간격을 이어가고 프레임 시간으로 다음 시각을 계속 밀지 않습니다. 각 틱에 원본 기준 범위를 판정하고 공통 정산기를 호출합니다. 시전자 여러 명의 중첩 여부도 원본 규칙이 필요합니다.

저장에는 다음 틱 시각·출처 ID·전장 리비전을 보존합니다. 일시정지 중 피해 없음, 배속은 공통 시계 한 곳만 적용, 복원 직후 이미 끝난 틱 재적용 없음이 완료 조건입니다.

### 4.3 MC-01/02 요크

구매/평타 객체 H0AM은 있으므로 새 보유 소환 유닛을 만들지 않습니다. TR-30 enhancedChanges의 기술을 활성화하기 전에 이세계/버전·강화 권리·위성 해금·원본 지능과 마나·6타 간격을 확정합니다.

확정 후 기존 위성 실행기의 H0AB/H0AE 분기와 같은 구조에 H0AM을 추가합니다. 마나 고유기와 평타10% 고유기를 각각 독립 트리거로 등록하고, 혼합 피해는 물리/마법/고정 성분별로 기존 정산기를 사용합니다. 지능은 요크 ID의 값만 조회합니다. 기본 평타 성공과 스킬 성공을 혼동해 중복 추첨하지 않습니다.

저장 대상: 위성 ID/소유자·해금 권리·HP/MP·XP·보너스·다음 공격/타격·남은 타수. 본체 제거/전장 이동 시 기존 가상 효과 수명 정책을 적용합니다. 자료가 부족한 동안 요크를 구매했다는 이유만으로 강화 고유기를 켜지 않습니다.

## 5. 이미 추가된 스킬의 UI·수명·저장 후속

### 5.1 히바리 도시락

제작자 없는 독립 사용/판매와 실제 point-value 조건은 이미 추가됐습니다. 기존 지갑의 h0CN 잔량·생성 영수증이 단일 원장이어야 합니다. UI는 사용/판매 의도를 전달하고 실제 명령은 대상 ID·rawcode·점수≥101·배제 대상·잔량을 확정 시 다시 검사합니다.

동일 도시락을 사용/판매가 동시에 소비할 수 없도록 비용 소비와 버프/판매 결과를 같은 거래로 확정합니다. 대상 제거/조합 직전 입력은 실패 처리하고 잔량을 보존합니다. 성공 후 알림 오류로 거래를 재시도하지 않습니다. 원래 제작자가 없어도 기존 물품의 권리를 원장으로 확인해야 합니다.

### 5.2 연타·마리아를 저장 가능한 예약 데이터로 바꾸기

현재 Action/클로저 예약을 그대로 저장할 수 없습니다. 기존 큐를 효과 종류별 데이터로 확장합니다.

| 필드 역할 | 필요한 값 |
|---|---|
| 식별 | 효과 종류/버전·효과 인스턴스 ID·시전자/소유자 ID |
| 원인 | 시전/공격 사건 ID·원본 기술 ID·지불 영수증 |
| 시간 | 다음 논리 시각·간격·남은 타수·안정적 실행 순번 |
| 공간 | 전장 ID·리비전·고정 중심/방향 또는 대상 ID |
| 계산 | 시전 시 확정 능력치·이미 뽑은 분기/피해값·남은 단계 |
| 수명 | 원본 취소/승계 조건·폼 리비전·종료 상태 |

비비/핸콕은 타격마다 대상을 다시 뽑는 원본 규칙과 이미 소비한 난수 순서를 보존합니다. 미리 대상 전부를 확정해 저장하거나 복원 시 첫 타격부터 다시 추첨하지 않습니다. 마리아는 영속 주기의 다음 시각과 현재 모드를 저장하며 복원 시 새 효과를 발동해 주기를 초기화하지 않습니다.

비비 강화의 보류 성공/실패는 거래 영수증과 저장합니다. 같은 요청 재시도는 기존 결과를 쓰고 새 결제를 하지 않습니다. 시전자 이동·해독·제거에 따른 취소는 지금 구현된 정리 경로와 동일하게 복원해야 합니다.

**완료 기준:** 연타 중·도시락 사용 직후·강화 결과 보류 중·마리아 다음 틱 직전에 저장한 뒤 이어도 피해/재화/순서가 같아야 합니다. 이 조건 전에는 저장 거부를 단순 해제하지 않습니다.

## 6. 나머지 98개 후보를 확정 작업으로 바꾸는 방법

후보 전목록은 [스킬 후속 목록 E절](스킬-미구현-확정목록.md)에 보존합니다. 현재 미구현98개라고 세지 않습니다. 후보마다 다음 열을 채워야 다음 구현 대상으로 확정할 수 있습니다.

`기술 ID / 원본 객체·능력·함수 / 발동 사건 / 기존 호출부 / 효과별 처리기 / 입력 공급자 / 종료·저장 / 판정 / 막힌 근거`

- **네이티브 치명·기절:** 원본 능력 카탈로그→기본 공격 사전 보정→명중 후 상태를 따라간다. 같은 치명을 툴팁 확률 스킬로 또 등록하지 않는다.
- **조건/주기/누적:** 원인 사건 생산자, 누적 카운터, 발동 후 초기화, 상한을 확인한다. 문자열이 없어도 rawcode 콜백으로 구현됐으면 해당 근거를 남긴다.
- **수동/보상/제작:** 전용 스킬 포트뿐 아니라 거래·위습·보물·제작 서비스까지 확인한다. 게임 내 실행이 별도 서비스에 있으면 전투 스킬을 새로 만들지 않는다.
- **변신·임시 공격:** 기존 폼/가상 공격자·수명·주인 ID에 연결된 효과를 조사한다. 소환 이름이 없다는 이유로 실물 유닛을 추가하지 않는다.
- **강화/파생:** 기본 기술과 강화 기술, 동일 이름의 다른 등급을 ID·rawcode로 구분한다. 구버전 도감과 원본 충돌은 원본 근거를 추가한다.

판정은 ‘효과 실행 없음 / 일부 입력 미연결 / 코드 연결·미실행 / 원본 동등성 미확정 / 현재 모드 비대상’으로 분리합니다. 근거가 바뀌면 기존 행을 교체하며 오래된 누락 주장을 누적하지 않습니다.

## 7. 저장·이어하기 전체 연결 — S01~S03

상세 기본 계약은 [저장 명세](저장-이어하기-구현명세.md)를 유지합니다. 이번 스킬 후속은 그 계약의 상태 소유자에 추가해야 합니다.

### 7.1 캡처와 검증

컨트롤러의 동기 캡처 경계에서 코어·전투·상거래·보물·능력치·위성·파견·난수가 같은 논리 시각인지 확인합니다. 저장 중 시계가 멈췄더라도 비용 거래가 반쯤 끝났으면 안정 스냅샷이 아닙니다. 기존 재시도/거부 정책을 사용합니다.

교차 검사: 같은 실물 ID의 전장 중복 없음, 예약 시전자/대상 참조 유효, 비용 영수증과 결과 존재, 폼과 스탯 리비전 일치, 비복원 보상 풀과 지급 이력 일치, 난수 스트림을 공유하던 서비스가 같은 스트림을 참조.

### 7.2 복원 원리

1. 파일 버전·해시·필수 카탈로그 검사. 실패하면 정상 A/B 슬롯을 보존한다.
2. 공개하지 않은 코어/지갑/로스터/난수 객체를 준비한다.
3. 동일 ID의 적/아군·폼·목적지 월드를 공격 정지 상태로 만든다.
4. 파견·해독·공유 출전 소유권, 장비·위성·능력치·예약을 연결한다.
5. 상거래/보물/미션 영수증과 대기 결과를 복원하고 전역 교차 검사한다.
6. 틱 경계에서 컨트롤러·UI·입력·이벤트 수신 대상을 새 세션으로 한 번에 전환한다.
7. 성공 뒤 옛 구독/객체를 해제한다. 실패하면 임시 객체만 버린다.

복원 중 시작 위습/골드·이미 끝난 보상·변신/구매 명령을 재실행하지 않습니다. 과거 알림이 보상 지급의 원인이 되어서는 안 됩니다. 정식 이어하기 버튼은 모든 필수 소유자와 실제 연속 실행 검증이 끝나야 활성화합니다.

## 8. 보물·공유 목표·상거래의 남은 사건 연결

### 8.1 F01 보물/CRW

이미 원본 보상 분기와 지도 소비가 추가됐으므로 새 랜덤 보상표를 만들지 않습니다.

- 바운티헌터 자격→원본 해당 라인 처치→실제 상자 생성/개봉 사건을 순서대로 조사한다. 라운드 도달만으로 임의 상자를 지급하지 않는다.
- 상자 ID·개봉 사건 ID·보류 추첨 결과·거래 영수증을 결합한다. 재수신/실패 재시도는 같은 결과를 재사용한다.
- 원본 CRW 20/20/55/5 분기와 지도 잔여 LV, 지도 소진 시 대체 골드 규칙을 유지한다. 결과 전달 실패로 재추첨하지 않는다.
- A05D의 마나·쿨타임·시전거리/효과범위를 원본 능력 객체에서 각각 확보한다. 알람97/77초를 쿨타임으로 쓰지 않는다.
- 원피스 A0KV/i4 권리 기록, LL/LK+10, 실제 능력 적용을 구별한다. 권리가 있다고 네이티브 효과가 적용된 것으로 완료하지 않는다.
- 지도 진행·남은 보물·보류 사건·기회·알림을 전체 세션 복원에 연결한다.

### 8.2 F04 공유 목표/M03 해왕류

출현 조건/객체 스펙을 실제 생성 경로에 연결한 뒤 해당 개체의 사망 사건을 기존 보상 정산기로 보냅니다. 중복 출현·사망 증거에 같은 사건 ID를 사용합니다. 출현만으로 해왕류 충전을 주거나 보스 HP 표시가 0이라고 외부 의무를 임의 완료하지 않습니다. 기존 출현/사망 증거와 실제 전투 상태의 합류 조건을 보존합니다.

### 8.3 M01~06/I01~03

지갑·재고·보류 결과·실물 생성·미션·영수증을 기존 원자 거래로 묶습니다. 아직 효과가 없는 아이템은 원본 설명/사용 함수→실제 효과→소모 조건을 먼저 확정합니다. 획득 이력·현재 보유·사용 효과·조합 재료는 다른 생명주기입니다. 영구 효과가 원본 조건이라면 조합으로 실물을 소비해도 영구 이력을 지우지 않습니다.

**완료 기준:** 같은 사건 두 번 수신, 결과 생성 실패, 저장 후 재시도, UI 알림 실패에서도 비용과 보상은 각각 정확히 한 번.
