| 위습 | 수동 | 선택 → `직접 실행` 확인 | 위습 소모 없음 |

## 신규 모바일 조작 계층

- `Assets/Scripts/Mobile/MobileInteractionPolicy.cs`
  - `MobileInteractionPolicy.Mode`: 사용자 확정 자동/보조/수동 분류
  - `MobileCombatAutomation`: 실시간 자동 배치, 보스 선호대상 설정, Q/W/R 사용 판단
  - `IOriginalPlacementRules`: 자리 후보와 합법성 분리 검증
  - `IOriginalBossFocusRules`: 원작 허용 시에만 보스 우선 타격
  - `IOriginalAutoSkillRules`: 스킬 시전 조건·대상·원작 타이밍을 검증한 서비스의 승인
- `Assets/Scripts/Mobile/MobileManualInteraction.cs`
  - `IOriginalStoryDispatchPort`: 파견 가능·직접 파견·현재 파견 상태
  - `IOriginalFusionPort`: 원작 가용 레시피·재료 목록 미리보기·최종 조합 실행
  - `IOriginalEconomyPort`: 원작 가격·횟수·확률·보상을 갖춘 상점·도박·위습 서비스
  - **자동 호출 루프 없음**: 경제와 조합, 스토리 파견을 자동으로 실행하지 않는다.
- `Assets/Scripts/Unity/OrdrMobileTouchPanel.cs`
  - 화면 안전영역(safe area), 큰 터치 버튼, 접기/펼치기
  - 스토리 유닛별 선택·직접 파견·원작 허용 시 직접 복귀
  - 조합 재료 표시·별도 최종 확정
  - 상점/도박/위습 탭 분리 및 최종 실행 확인
  - 서비스가 없으면 기능 미연결 안내. 가짜 가격이나 가짜 성공 보상을 제공하지 않음.

## 기존 런타임 수정

1. `CharacterCombatRuntime.SpawnCharacter`가 유닛 생성 후 `MobileAutomation.TryPlace`를 호출한다. 외부 `IOriginalPlacementRules`가 합법적인 위치를 확인하지 않으면 이동하지 않는다. 소환 확률·비용은 수정하지 않는다.
2. `CombatAttackPipeline.TryBasicAttack(..., verifiedPreferredTargetId, ...)` 오버로드는 기존 공격력·공격 주기와 최대 사거리, 대상 생존 확인을 유지한다. 외부 `IOriginalBossFocusRules`가 허용한 **공격 가능한 보스**에게만 선호 대상을 지정한다. 다른 경우에는 기존 가까운 적을 공격한다. 사거리 무시나 새 우선순위 규칙을 만들지 않는다.
3. `CharacterCombatRuntime.Step`는 자동 Q/W/R 승인 요청 후, 원래 평타·확률형 스킬 처리로 이어진다. 자동 시전은 `IOriginalAutoSkillRules`가 원본 조건과 타깃을 승인하고, 스킬의 **양수 쿨타임이 데이터로 확인된 경우**에 한해 시도한다. 확인되지 않은 무쿨타임/이벤트형 스킬은 프레임마다 난사하지 않는다.
4. `IOriginalStoryDispatchPort.IsDeployed`가 true인 유닛은 자동 평타·자동 스킬 대상에서 제외된다. **스토리로 보냈다는 이유로 전장 공격을 중복 수행하지 않는다.** 원작 스토리 복귀/보상은 구현된 파견 서비스가 처리한다.
5. `CharacterCombatRuntime.MobileUnitSnapshot()`·`MobileEnemySnapshot()`을 통해 UI가 이름·등급·현재 배치·적 상태를 조회한다.
6. Unity `OrdrCharacterCombatController`는 `ConfigureMobileAutomation`·`ConfigureManualMobileSystems` API를 노출하고, 기본적으로 모바일 조작 패널을 같은 게임 오브젝트에 추가한다. `enableMobileTouchPanel`로 끌 수 있다.

### 자동 Q/W/R의 원작 충실도 보호

- **비용 정보가 확인되지 않은 `manual` 스킬**은 임의로 무료 처리하지 않고 시전을 보류한다.
- 확정 쿨타임이 0이거나 미확인인 스킬은 게임 프레임마다 반복해서 쓰지 않는다.
- `castTimeSeconds`가 양수인 스킬은 **시전 중 평타·이동 잠금 구현 전까지 자동 실행하지 않는다.** 이를 생략하면 게임 전투 DPS가 변하기 때문이다.
- 스토리 파견·원작 허용 시 복귀는 모두 사용자 탭에서만 실행하고, 파견 중인 유닛의 자동 평타/QWR은 멈춘다.
- 자동 시전 규칙 제공자는 원작 쿨타임 외에 대상 가능 여부·자원·스킬 간 공유 행동 제약도 검사해야 한다. 현재 코드가 자동화된 스킬의 실제 발동 타이밍을 원작과 동일하게 재현한다고 주장할 수 없다.

## 원본 규칙 연결 예시

```csharp
controller.ConfigureMobileAutomation(
    originalPlacementRules, // IOriginalPlacementRules
    originalBossFocusRules, // IOriginalBossFocusRules
    originalQwrRules);      // IOriginalAutoSkillRules

controller.ConfigureManualMobileSystems(
    originalStoryPort,      // IOriginalStoryDispatchPort
    originalFusionPort,     // IOriginalFusionPort
    originalEconomyPort);   // IOriginalEconomyPort
```

`ConfigureMobileAutomation`은 월드 설정 전·후 어느 시점이든 실행할 수 있다. 이미 소환된 유닛의 위치를 무단으로 재배치하지 않고, 이후 소환부터 검증 배치 정책을 적용한다.

`IOriginalStoryDispatchPort.Dispatch`, `IOriginalFusionPort.ConfirmFusion`, `IOriginalEconomyPort.Confirm` 구현체는 **실행 직전** 소유 유닛·레시피 재료·게임 재화·확률 및 횟수/쿨타임을 반드시 재확인해야 한다. 모바일 패널은 원작 트리거를 대신하지 않는다.

## 현재 구현하지 않은 원작 기능 및 조건

- 원본 W3X 기반 **합법 배치 지점/전장 경계**: `IOriginalPlacementRules` 구현체 필요
- 원본의 보스 타깃 우선 규칙: `IOriginalBossFocusRules` 구현체 필요
- 개별 수동 Q/W/R 발동/캐스팅 조건, 우선 대상과 쿨타임: `IOriginalAutoSkillRules` 구현체 필요
- 미수집 공격 수치/원본 rawcode 및 정확한 피해 공식: 기존 전투 엔진 미완료
- 스토리/조합/상점/도박/위습 실서비스: 인터페이스 및 모바일 UI만 연결, 실제 경제/스토리 트리거 미구현
- 원본 특수 대상 선택(아군 지정 스킬 등), 마나 부족·상태 조건, 소환/분신·광역 지속피해 완전 실행: 기존 스킬 실행기 미완료
- Unity 정식 프로젝트 설정/씬이 없으므로 실기 HUD까지 검증하지 못함. 즉 `OrdrMobileTouchPanel`은 런타임 입력 코드이며, 현재 APK로 플레이 가능한 기능을 뜻하지 않는다.
