# 모바일 위습 시스템 (원본 ORDR S2 2.323[C])

- 랜덤위습 e0IX: 독립 재화. 전용 빠른 사용 메뉴에서 원본 검증된 기능만 노출.
- 선택위습 e018: 독립 재화. 조합창 Merge에서 선택 후 사용.
- 안흔함 e017 / 특별 e016 / 희귀 e019 / 전설 e015: 획득 직후 자동 추첨.
- 원본 보상 풀과 확률을 임의로 만들지 않기 위해 IVerifiedWispRoller가 검증되지 않은 경우 자동 지급하지 않는다.
- 희귀위습의 99%/1% 분기 및 기본 풀 A0YE는 검증된 롤러/월드에서 처리해야 한다.
- 원본 맵 `ORDR_S2_2.323[C](4).w3x`에서 추출한 `war3map.j`의 SHA-256은 `96201e80edec1b2764f85818760306c6b2f0becd390ba4d63f41c86f3dfaff6d`이다. 이 파일에서 `tools/extract_original_wisp_pools.py`로 `data/original-2323C-wisp-pools.json`을 생성했다. 원본 위습 4종의 모든 rawcode와 균등 가중치, 함수/행 번호, 희귀위습의 99%/1% 및 기본 분기의 `A0YE`가 들어 있다.
- `OriginalWispRewardCatalog`는 추출 JSON 원문 해시까지 고정해 변경된 보상 풀·확률을 거부한다. 실제 난수 공급자는 `IOriginalWispRandom`을 통해 주입한다. 테스트용 난수를 게임에서 원본 난수처럼 쓰지 않는다.
- `MobileWispService`는 공유 지갑에 재화를 보관하고, 모든 지갑 보상 경로(임무·거래 포함)를 관찰해 자동 4종의 추첨을 시도한다. 검증된 월드가 없거나 보상에 실패하면 해당 위습은 남는다. 보관된 위습은 복원 뒤 `FlushAutomatic`으로 재시도할 수 있다.
- `IWispRewardTransaction` / `IChoiceWispMergeTransaction`은 유닛 생성·`A0YE` 적용·위습 차감·커밋을 하나의 롤백 구간으로 묶는다. 지급 이벤트 ID별 중복 보상도 차단할 수 있다.
- `OriginalWispCombatRewardWorld`는 원본 rawcode→검수된 카탈로그 ID, 원본 소환 좌표, 원본 `A0YE` 구현체가 모두 연결된 경우에만 기존 `CharacterCombatRuntime`와 공유 `UnitRoster`에 실제 유닛을 추가한다. 오류 시 미확정 유닛과 관련 시각 이벤트를 롤백한다.
- Unity 조작 패널은 화면 하단 랜덤위습 빠른 진입 버튼, 6종 잔액, 선택위습 Merge 대상/확정 화면을 제공한다. 원본 사용처 서비스가 연결되지 않으면 실행은 차단한다.
- 시작 자원 근거는 `CUo` 기본 골드 50·랜덤위습 5개, `CUn` 솔로 골드 10, `CJ` 중심의 `e0HP` 1기이다. `Original323SoloStartProfile`에 고정했다. 실제 시작은 별도 비전투 진화체 월드가 공유 목록·롤백에 연결된 후에만 허용한다.

## 여전히 미완료

1. 실제 게임 씬에서 원본 RNG 상태·모든 보상 rawcode 객체 매핑·원본 좌표·`A0YE` 게임 효과 제공자를 구성해야 한다. 아직 `ConfigureVerifiedWispCombatRoster`를 실제 월드로 호출하지 않는다.
2. 랜덤위습 전체 사용처와 가격/추가 조건, 선택위습 Merge의 실제 대상/추가 소모 규칙을 원본 트리거에서 추출하고 실거래 서비스에 연결해야 한다. 미확인 메뉴 버튼은 소모하지 않는다.
3. 원본 비전투 `e0HP` 진화체 월드 및 시작 버튼 연결, 실제 Unity EditMode/기기 테스트가 남아 있다. 위 신규 코드의 로컬 Unity 실행 검증은 아직 하지 않았다.

## 2026-10-23 추가 — 랜덤위습 자원 추첨

- 원본 `CSK` (`war3map.j` 56477~56494행): 랜덤위습 e0IX 1개 → BFi(1,100) 추첨, 67% 목재 1개 또는 33% 골드 75×진행 라운드 X3.
- `OriginalRandomWispResourceExchange`는 기존 `SharedEconomy.Wallet` 하나에서 소비와 보상을 `TryExchange`로 묶는다. 난수 오류·잔액 부족·오버플로에서는 재화가 일부만 바뀌지 않는다.
- 전투 월드의 `GameSession.CurrentWave`가 시작된 이후에만 추첨이 가능하며, **라운드 0에서는 X3가 실제로 몇인지 아직 승인되지 않아 차감하지 않는다.**
- 임시 모바일 RNG는 원본 67%/33% 분포를 보존하지만 Warcraft의 정확한 시드/순서까지 재현하는 것은 아니다. 검증된 난수 공급자가 있으면 `ConfigureRandomWispResourceRng`로 교체한다.
- 위습 탭은 이 기능을 실제 실행할 수 있게 등록하고, 나머지 기존 상점·도박 공급자는 유지한다.
- 메인·스토리 아래 빈 공간에는 **실제 공유 재화(골드·목재·랜덤위습)와 진행 라운드**만 표시한다.
- **미완료:** 흔함 소환·도움소 마나 회복은 검증된 실제 월드 실행기가 필요하다. 특성공학은 기록지침/항법, 비비 강화는 비비 전용 버튼에만 연결해야 하며 위습 탭으로 옮기지 않는다.
- Unity EditMode 테스트를 추가했으며, CI/실기 결과를 확인하기 전에는 통과로 기재하지 않는다.
