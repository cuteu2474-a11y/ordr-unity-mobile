# 캐릭터 기술 — 원본 근거와 전투 연결

> **읽는 순서:** 이 문서는 오래된 개별 구현 보고를 한곳에 모은 **기술 참고 자료**입니다. 현재 게임에 실제 연결된 기술과 남은 작업은 [현재 상태](START_HERE.md)·[개발 작업 C03~C05](PLAYABLE_ROADMAP.md)가 우선합니다. 콜백별 **피해 경로가 연결된 11건·추가 점검할 20행**은 [스킬 누락·중복 검토표](스킬-누락-검토표.md)를 봅니다. 원본 능력 ID 확인, 코드 등록, 개발용 전투 모델, Unity 검사, 원작 실기 일치는 각각 다릅니다.

## 1. 기술을 연결할 때 어디를 보나요?

| 확인할 사항 | 주요 자료와 코드 | 주의점 |
|---|---|---|
| 유닛·능력의 실체 | `data/original-2323C-map-base-stats.json`, [원본 기본 능력치](원본-유닛-기본능력치-매핑.md) | 유닛이 보유한 능력이라고 자동 발동하는 전투 기술은 아님 |
| 원본 JASS 공격 선언 | [20명 JASS·네이티브 능력 대조](원본-캐릭터-기술-추출표.md), `data/original-2323C-c03-callback-audit.json` | `w5` 공격 선언과 실제 적중, 보조 주문의 최종 피격을 구분 |
| 실행 가능한 기술과 연결 위치 | `CharacterCombatRuntime.SourceModel*.cs`, `CombatSkillTriggerEngine`, `CharacterActiveAbilities` | 도감·원본 JASS·네이티브 패시브의 이중 발동·이중 피해 방지 |

| 코드에 저장한 지원 범위 | `data/unit-runtime-status.json`, [생성 유닛 표](캐릭터별-구현목록.md) | **생성 시점의 모델 지원 수**일 뿐 최신 APK·원작 동등성 증거가 아님 |

캐릭터별 새 엔진을 만들지 않습니다. 원본 확률·시점·대상·피해/상태 수치와 자원 비용을 확인한 뒤 [전투 공통 엔진](전투-공통엔진.md)으로 연결합니다. 현재 유닛 수·자동 기술 수는 이 문서에 고정하지 않습니다.

## 2. 특별함·안흔함 20명 조사에서 실제 확인한 것

원본 2.323[C] W3X/JASS의 SHA는 [작업 규칙](../AGENTS.md)에 고정되어 있습니다. 조사 대상 **20명 / 원본 능력 121개** 가운데 `w5` 공격 선언 콜백 등록이 확인된 유닛은 **마르코·봉쿠레·스쿼드·에넬·에이스(2번 대대장)·조로(귀기) 6명**입니다. 능력 ID 31개는 조합(CWR) 등록식에도 쓰입니다. `w5` 등록이 없다고 액티브/네이티브 기술 자체가 없다는 뜻은 아닙니다.

원본 능력별 `DataA1`·지속·쿨타임·보조 유닛, 첫 20명 전체의 rawcode 대응과 별도 조사 10명의 람각·나미 오라·AUin 기절·센토 방깎 원본 수치는 [원본 캐릭터 기술 추출표](원본-캐릭터-기술-추출표.md)에 유지합니다. 위 표에 없는 다른 유닛을 ‘스킬 없음’으로 분류하지 않습니다. 또한, **`AUin` 피해 0을 JASS 광역 피해에 다시 더하지 않습니다.**

### 블루노·후쿠로의 람각과 에넬 갈래 번개 — 공격 선언과 실제 타격 분리

원본 `w5`의 공격 **선언 시점**에 블루노(`h00M`, `Bnm`), 후쿠로(`h00A`, `Bnp`), 에넬(`h00Q`, `Bnr`)은 각각 스크립트 `BFi(1,100) <= 10` 추첨을 수행하고, 성공 시 보조 유닛 `e0KD`에 주문을 지시합니다. **공격 선언은 람각 투사체의 충돌이나 갈래 번개의 최종 HP 피해가 아닙니다.** 원본 `A0VS/AUcs` 람각은 범위 200·사거리 1700, `A086/ANfl` 갈래 번개는 범위 125·사거리 1750·**최대 선택 대상 4명**입니다. 원시 능력 필드를 확정 최종 피해량으로 바꾸지 않습니다.

`Original323DeferredNativeDummySpellWorld`는 관측된 **시전 ID**와 나중에 확인된 **충돌 ID·시각·대상·면역·최종 HP 감소**를 분리해 처리합니다. 람각은 여러 충돌 시점이 가능하고, 갈래 번개는 `Original323NativeSelectedSpellTarget`의 **선택된 적 4명**과 실제 피해를 받은 적을 구분해야 합니다. 마법 면역으로 피해가 0인 적도 **선택 한도에는 포함**됩니다. 선정 증빙이 없으면 피해 목록에서 선택 대상을 추정하지 않습니다. 타격 순간의 마방은 [A04Q 설정·누적](원본-피해-방어-마법저항-근거.md)을 따르며, 원본 결과 관측기가 없으면 해당 주문의 실전 동등성은 보류합니다. [원본 관측형 스킬의 시전·충돌·종료 규칙](원본-관측형-스킬-시전-타격.md)도 참고하세요.

## 3. 네이티브 패시브와 오라 — 공통 처리 기준

- 툴팁 프로필이 없는 71종의 능력 ID, 원본 기절 17개·크리티컬 9개의 조사 대상과 확률, 안흔함 14종의 기술별 근거는 [기본 기술·네이티브 패시브 조사](원본-기본기술-네이티브-패시브.md)에 있습니다. 연습 모델의 치명타는 같은 공격에 한 번, 기절은 유효한 실제 적에 적용합니다. 보스 저항(Arsk)·명중·면역의 원작 결과는 따로 검증합니다.
- 당시 원본 기본 공격 모델은 **270종**, 모델 효과 보유는 **112항목·144효과**로 보고되었지만 이 수는 2026-10-28의 **과거 스냅샷**입니다. 현행 카탈로그/실행 범위의 숫자로 재사용하지 않습니다. 안흔함 로빈의 연습용 추가 2대상, 감속·기절 이동 경로, 소유자 제거 후 오라 갱신도 원본 미사일/잔류 구현과 구분합니다.
- **동일 종류·능력·레벨·버프·값**을 가진 오라 출처 여러 개는 한 번 계산하고, 시전자별 생명주기는 각각 관리합니다. 서로 다른 능력·버프·레벨·값은 무조건 합산하거나 최대치로 선택하지 않습니다. 이 원칙의 전체 조사와 예외는 [전체 원본 오라 감사·전투 연결](원본-오라-전투연결.md) 및 `data/original-2323C-all-unit-aura-audit.json`이 기준입니다.
- 원본 `AHad` 음수 방어력 오라는 당시 **54종·레벨별 61개 정의**로 조사되었고, 특별함 이감·공격력 버프를 포함한 당시 런타임 등록은 58종이었습니다. `Original323ArmorAuraCatalog`의 **복수 조회**와 실제 능력 레벨·마스크·현재 효과 객체를 확인해야 합니다. `DataB` 미기재를 0으로 바꿔 고정 방깎으로 승인하면 안 됩니다. E-02 미확인, 타시기 A0JI의 0값, 거프 A0VE 양수 방어력도 임의 방깎으로 처리하지 않습니다.

## 4. 연결 완료로 오해하지 말아야 할 항목

1. `w5` JASS 분기와 보조 유닛 주문은 별개입니다. 네이티브 투사체, 첫/마지막 틱, 대상 우선순위와 영웅/보스 저항은 함수 등록만으로 검증되지 않습니다.
2. 원본 오라의 현재 레벨·대상 마스크·면역·원본 갱신 틱/잔류와 `safeForUnconditionalLiveCombat: false` 조건을 유지합니다. 개발용 허가 공급자를 실전 허가로 대체하지 않습니다.
3. 도감 271종·상세 200종·554개 기술이라는 초기 수집 결과와 **한 명씩 구현** 계획은 현재 프로젝트 범위/개발 방식이 아닙니다. 2.320~2.323 패치 문구와 도감 불일치(예: 사토루 기술)도 원본 W3X 근거가 확보되기 전까지 자동 승인하지 않습니다. 자료: `data/original-stat-evidence.json`, [원본 캐릭터 대조](원본-유닛-기본능력치-매핑.md).
4. 실제 검증은 **명시적으로 요청받은 경우에만** 수행합니다. 당시 완료 건수나 합성 테스트 통과를 최신 main의 Unity·APK·원작 실기 결과로 옮기지 않습니다.

새 기술을 추가할 때는 [C03 기술별 누락 분류 → C04 기능 연결 → C05 소유자·예약 효과 정리](PLAYABLE_ROADMAP.md) 순서로 해당 **공통 원인을 묶어** 처리합니다. 과거 단계별 실행 보고는 Git 이력에서 확인합니다.
