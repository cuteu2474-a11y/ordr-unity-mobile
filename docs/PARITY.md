# 원작 규칙과 검증 경계

현재 실행 범위는 [START_HERE.md](START_HERE.md), 다음 구현은 [PLAYABLE_ROADMAP.md](PLAYABLE_ROADMAP.md)에서 관리합니다. 이 문서는 완료 판정의 의미를 정합니다. [이전 조사 보존본](archive/PARITY-20261028.md)은 당시 근거를 찾는 용도입니다.

## 고정 대상과 의도적인 모바일 변경

대상은 ORDR S2 2.323[C]의 악몽 + 이세계모드, 오프라인 싱글플레이입니다. 이 저장소는 Unity 독립 리메이크이며 OpenRealm 엔진 포팅과 혼동하지 않습니다.

같은 전장 내 일반 공격·스킬 시전·오라 도달 거리는 사용자 정책대로 무제한입니다. 광역 기술의 실제 피격 형태·반경·최대 대상 수, 타깃 자격·면역·팀·전장 구분은 별도 유지합니다. 자동 Q/W/R 등의 조작 정책과 확정된 특수 유닛 변경도 원작 수치와 구분해 기록합니다. 고정 확률·공격력·쿨타임·비용·조합을 임의로 바꾸지 않습니다.

## 구현·검증의 단계

| 단계 | 확인한 것 | 아직 주장할 수 없는 것 |
|---|---|---|
| 데이터 등록 | 도감 설명·객체 ID·필드·원본 함수의 근거 | 실제 스킬 실행·유닛 전체 완료 |
| 연결 코드 | 현재 세션에 호출 경로 존재 | 모든 실제 공급자가 구현됨·자동 동작함 |
| 로컬 검사 | 명시한 C#/Python 범위가 해당 입력에서 통과 | Unity 엔진·기기 정상 플레이 |
| 개발용 연습 | 명시적인 모델로 출현·피해·보상·승패 진행 | 원작 최종 피해/면역/시점과 동일 |
| Unity/기기 확인 | 확인한 커밋·기기·실행 흐름 | 다른 기기·모든 유닛·65R 전체 보증 |
| 원작 동등성 | 동일 버전의 실제 조건·결과 대조 | 검사하지 않은 숨은 분기·강화·중첩 전체 |

전체 유닛 완료는 각 유닛의 전체 스킬·패시브·변신·연구·자원·타깃·시점과 실제 피해/보상이 연결되고 검증됐을 때만 기록합니다. ‘200개 프로필’·‘144개 모델 효과’·‘116개 제작식’은 그 수가 아닙니다.

## 근거와 미확인 값

- 원본 W3X는 변경하지 않습니다. 각 추출 도구의 SHA와 입력 파일을 대조하고, 다른 버전의 패치·툴팁으로 빈 필드를 추측하지 않습니다.
- 완전한 SLK 별칭 행, 기본 게임 표, W3A 패치의 부모 상속은 서로 다른 경우입니다. 누락 필드가 항상 0이거나 항상 부모 값이라고 일반화하지 않습니다. 분해 Cost1이나 오라 모드처럼 확인한 좁은 근거만 해당 범위에 적용합니다.
- 원본 공격 타입과 피해 타입, 방어/저항·현재 능력 레벨·대상 면역·HP 정수화는 각각 확인합니다. ‘물리 200’이라는 이름이나 툴팁만으로 최종 HP 200을 적용하지 않습니다.
- `SourceModel*`, 참조 엔진 초기 HP/방어, 모델 난수와 소수 피해 이월은 명시적인 개발용 정책입니다. `retailParityVerified`, `safeForVerifiedMonsterWaveRuntime` 같은 원작 승인 플래그를 열지 않습니다.
- 테스트 전용 승인·가상 HP/난수·효과 영수증을 실제 원본 관측 공급자처럼 사용하지 않습니다. 인터페이스를 구현했다는 사실과 원본 동작 구현을 구분합니다.

## 검증 기록 형식

변경을 보고할 때 기준 커밋, 해당 유닛/시스템, 원본 입력/함수/필드, 실제 연결점, 실행한 검사·환경, 미확인 항목을 남깁니다. 원작 수치·코드 연결·모델·기기 관측을 한 문장으로 완료 처리하지 않습니다.

GitHub 결과 조회와 APK 요청 절차는 [검사·빌드 안내](unity-editmode-test.md), 운영 규칙은 [AGENTS](../AGENTS.md)를 따릅니다.
