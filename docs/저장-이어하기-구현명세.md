# 저장·이어하기 — 구현 명세

목표는 간단합니다. **게임을 중단했다가 다시 실행해도 같은 유닛·라운드·자원·도박 결과·전투 상태로 이어서 플레이**할 수 있어야 합니다. 저장으로 보상을 다시 받거나, 시간이 저절로 흘러가거나, 공격이 두 번 발동해서는 안 됩니다.

이 문서는 **앞으로 구현할 계약**입니다. 현재 APK에 이어하기가 완성됐다는 안내가 아닙니다. 최종 필수 기능은 [전체 기능 대장 SAVE01~SAVE10](전체-기능-구현대장.md), 실제 작업 순서는 [S01~S03](PLAYABLE_ROADMAP.md), 지금 작동하는 범위는 [현재 상태](START_HERE.md)에서 관리합니다.

## 1. 지금 있는 기능과 빠진 기능

| 영역 | 코드에서 확인된 준비 상태 | 이어하기까지 필요한 것 |
|---|---|---|
| 재화·위습 | `EconomyWallet.CaptureState/RestoreState`로 잔액, 완료 영수증, 보류 중인 **자동 위습 보상**을 보존할 수 있음 | 실제 세션 파일과 결합. 다른 서비스의 보류 추첨까지 한 번에 캡처 |
| 개인미션 | `OriginalPersonalMissionSession.CaptureState/Restore`에 3칸, 달성/보상 보류, 횟수, 현재 라운드와 저장 버전 검증 존재 | 현재 세션의 지갑 보상·진행 이벤트와 동일 시점에 복원 |
| 실물 유닛 | `UnitRoster`가 인스턴스 ID·개체 ID·좌표·선택 상태를 보유 | 전체 목록·`nextId`·선택·파견·변신/소환 상태의 캡처·ID 유지 복원 API |
| 라운드 | `GameSession`은 시작/진행/승패와 현재 라운드·적 집계를 보유 | 새 게임 `Start()`와 구분되는 원자적인 복원 진입점, 살아 있는 적/건물/크립 복구 |
| 게임 시간 | `OfflineSessionRunGate`가 수동 정지·앱 일시정지·포커스 해제 때 진행을 멈춤 | 통일된 **논리 게임 시간**과 각 예약 시각·남은 지속 시간을 저장 |
| 도박 | 이세계 도박 충전·시도·누적 등 일부 값은 지갑에 기록. 시도 중 `pending` 결과가 서비스 메모리에 존재 | 보류 결과·분기 난수·재고/충전 타이머·항법 선택을 함께 저장/재현 |
| 스킬·예약 전투 | `CombatTimedEffectQueue`는 실행 시각·순서·대상과 `Action` 콜백을 메모리에 관리 | 콜백 대신 **복원 가능한 효과 종류·대상 ID·남은 시각·순서·원본 수치**로 기술 |
| 화면 진입 | `OrdrMainSceneShell`에 게임 시작과 새 게임 경로 존재 | 유효한 저장이 있을 때만 **이어하기** 노출, 손상 파일 안내와 새 게임 분리 |

**현재 판정:** 일부 서비스에는 저장 가능한 상태 객체가 있지만, 이것들을 묶는 전체 저장 파일·복원 순서·실행 검증은 **미구현**입니다. `CaptureState` 메서드가 있다는 이유만으로 실제 APK 저장이 동작한다고 판단하지 않습니다.

## 2. 한 번의 저장에 들어가야 할 것

| 묶음 | 저장할 실제 상태 | 놓치면 생기는 문제 |
|---|---|---|
| 세션 | 형식 버전, 원본 버전/해시, 세션 식별자, 진행/승패, 라운드, 논리 시간 | 잘못된 규칙으로 로딩·시작 보상 중복 |
| 전장 | 살아 있는 적·보스·크립·스토리 건물 HP/위치/상태, 누수·처치 누계, 라운드 예약 | 라운드 초기화·적 중복 생성 |
| 유닛 | 실물 ID, 캐릭터/원본 객체 ID, 좌표·선택·파견·폼·소환수·진화 진행, 현재 HP/MP, XP/특성 | 조합 재료·소유자·전투 대상을 잘못 연결 |
| 경제 | **하나의 공용 지갑** 잔액, 완료 영수증, 보류 위습, 고유 아이템 소유, 조합 변화/불멸 횟수(CHCT/IFCT) | 재화/아이템 이중 지급·조합 한도 초기화 |
| 도박·상점 | 돈/유닛/이세계 도박 횟수·재고·충전·졸업·항법, 희귀/랜덤 리롤 권한, **이미 뽑은 보류 결과** | 앱 종료 후 재추첨·무료 당첨·재고 초기화 |
| 성장·시설 | 미션 슬롯/진행, 스토리 보상 이력, 연구·강화 레벨/연쇄 진행, 해금·구매 횟수 | 이미 완료한 미션/연구 보상을 재지급 |
| 전투 | 쿨타임, 상태 효과·오라 출처, 독립 공격, 지연 타격, 대상/소유자 리비전과 지속 만료 시각 | 이어하기 직후 이중 피해 또는 영구 버프 |
| 난수 | 게임에서 쓰는 **각 난수 흐름의 상태와 소비 순서**, 부분 추첨 단계 | 이어하기 전후 결과가 달라짐. 단순 최초 시드만으로는 부족할 수 있음 |

위 항목은 **구현 명세**이지 현재 `UnitRoster`나 각 서비스에 해당 API가 전부 있다는 뜻이 아닙니다. 원본에 없는 수치·추첨·재고를 저장을 위해 만들어 내지 않습니다.

## 3. 저장 시점과 파일 보호

1. **안전한 한 시점 확보:** 게임 논리 시간을 멈추고, 진행 중인 거래·유닛 생성/제거·보상 확정·지연 타격 적용이 끝난 일관된 경계에서 캡처합니다. 지갑과 로스터를 따로 저장하지 않습니다.
2. **검증 가능한 저장본 생성:** 형식 버전, 원본 근거 버전, 세션 ID 및 데이터 무결성 정보를 기록합니다. ID 중복·음수 잔액·존재하지 않는 대상/기술·부적절한 타이머는 저장/로드 단계에서 거부합니다.
3. **중단에 안전한 기록:** 임시 파일에 완전히 쓴 뒤 저장본을 교체하며, 교체 전의 **마지막 정상 저장**을 보존합니다. 저장 중 강제 종료됐다고 정상 저장을 먼저 지우지 않습니다.
4. **시간 멈춤 유지:** 앱이 백그라운드에 있던 실제 경과 시간만큼 재고/쿨타임/라운드/전투를 한꺼번에 진행시키지 않습니다. 사용자 확정 단일 플레이의 논리 시간 정책을 따릅니다.

저장 트리거의 구체적 위치(예: 명시적 저장, 라운드 경계, 앱 일시정지)는 **게임 상태를 한꺼번에 안전하게 캡처할 수 있는 시점**을 먼저 구현한 다음 결정합니다. 저장 경로·파일 이름은 플랫폼 코드에서 정의하며 문서에 임의의 실제 경로를 약속하지 않습니다.

## 4. 이어하기는 순서가 중요합니다

1. 저장 형식·원본 버전/해시·데이터 무결성·서로 참조하는 ID를 **게임에 반영하기 전에** 검증합니다.
2. 시작 보상 없이 빈 세션과 공통 지갑을 준비하고, 완료 영수증·도박 보류 결과·미션 완료 이력을 먼저 복원합니다.
3. 실물 유닛/적/건물의 **원래 인스턴스 ID**를 복구합니다. `UnitRoster.Add()`를 그대로 반복하면 ID가 새로 배정되므로 별도 복원 계약이 필요합니다.
4. 소유자·전장·대상 ID가 복구된 다음 버프/오라/지연 타격/소환수/쿨타임을 재연결합니다. `Action` 람다를 파일에 넣지 않고, 저장된 효과 기술자를 읽어 안전하게 재구성합니다.
5. 새로 시작하는 콜백과 이미 완료된 보상 콜백을 **다시 실행하지 않은 상태**에서 화면·입력·자동 전투를 열고 논리 시간을 진행합니다.

**복구 실패:** 원래 실행 중이던 세션이나 마지막 정상 저장을 변형하지 않고 오류를 보여줍니다. 지원하지 않는 이전 형식은 자동으로 삭제하거나 추측 변환하지 않습니다. 지원 가능한 마이그레이션만 버전별 변환기로 처리합니다.

## 6. 완료로 판정할 장면

- 조합·도박·아이템 획득 직후 중단 후 재접속: **보유 유닛/재화/영수증/추첨 결과 동일**, 재보상 없음.
- 보류 중인 위습·이세계 도박이 있는 상태에서 재시작: 결과를 다시 굴리지 않고 원래 보류 분기를 복원.
- 라운드 도중 지연 타격·버프·소환수와 적이 있는 상태에서 재접속: 남은 시간, 원래 대상과 소유자 연결, 피해 횟수 동일.
- 판매·변신·조합으로 제거한 유닛의 과거 예약 타격이 재개 후 튀어나오지 않음.
- 파일 기록 도중 강제 종료·손상·구형 버전: 정상 저장 보존, 설명 가능한 복구/차단.
- Android에서 새 게임과 이어하기가 명확히 구분되고, 저장-종료-재실행-65라운드 진행까지 확인.

**검사 상태:** 이 문서 작성은 코드 읽기·설계 정리만 했습니다. Python·NUnit·Unity·Android 테스트와 실제 저장/복구는 **실행하지 않았고**, 사용자 요청이 있기 전까지 완료 처리하지 않습니다.
