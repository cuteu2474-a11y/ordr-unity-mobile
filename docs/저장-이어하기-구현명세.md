# 저장·이어하기 — 구현 명세

> **2026-11-14 S03 복원 데이터 확장(코드만):** S02 전투 스냅샷에 공통 모바일 BFi 시드·호출 범위·기존 결과 재생 검증, 일반/고급 돈 도박 재고·시계·영수증 접두사, 졸업 상점·100골드 물품 지원의 보류 추첨, 하·중·고급/이세계 유닛 도박 보류 결과와 리롤 대상·선택 항법 상태를 추가했습니다. 새 서비스에서 복원할 수 있도록 DTO와 상태/범위 검증 API를 구현했으며 기본 전장 전체를 다시 만드는 복원 조정자는 아직 없습니다. 따라서 `OrdrCoreCheckpoint.Restore`의 전투 포함 저장 차단은 유지합니다. 기능별 데이터 구조가 추가된 것을 실제 게임 이어하기 완료로 해석하지 마세요.

> **2026-11-14 S03 적 월드 부분 복원:** 적 전투 상태에 네이티브 패시브 대상 마스크/출처·리비전, A04R 원본 출처, 원본 체력 변경 출처를 빠짐없이 캡처하도록 전투 드래프트 버전을 2로 올렸습니다. `OrdrCoreCheckpoint.PrepareWorldRestore`는 동일한 GameSession·실물 유닛·지갑·미션 ID로 코어만 준비하고, `CharacterCombatRuntime`의 복원 전용 생성자와 `RestoreEnemyWorldDraft`는 실제 적 ID·HP·상태효과·방어·좌표를 원본 라운드 카운트를 변경하지 않고 재생성합니다. 전투 소유 유닛과 타이머·모든 부수 시스템 복원은 아직 필요하므로 **정식 이어하기는 미활성 상태**입니다. v1 전투 드래프트는 상태 유실 방지를 위해 자동 복원하지 않습니다.

> **2026-11-14 S03 유닛 월드 부분 복원:** `RestoreActorWorldDraft`를 추가해 원래 로스터 인스턴스 ID로 캐릭터·스킬 HP/MP·쿨타임과 상태효과를 되살리고, 원본 공격 스펙을 재검증한 다음 `CombatAttackPipeline.RestoreState`와 `CharacterSkillEffectExecutor.RestoreTimedState`로 평타/스킬 타이밍 및 복원 가능 예약 타격을 재연결합니다. `SourceManagedResources`는 SLK 근거가 있는 원래 관리 자원에만 복구하며, 스토리/공유/해독 소유권 미복원 캐릭터는 예외 처리합니다. 단독 월드 그래프 구축 함수일 뿐 전체 APK 이어하기 버튼은 활성화하지 않았습니다.

목표는 간단합니다. **게임을 중단했다가 다시 실행해도 같은 유닛·라운드·자원·도박 결과·전투 상태로 이어서 플레이**할 수 있어야 합니다. 저장으로 보상을 다시 받거나, 시간이 저절로 흘러가거나, 공격이 두 번 발동해서는 안 됩니다.

이 문서는 **앞으로 구현할 계약**입니다. 현재 APK에 이어하기가 완성됐다는 안내가 아닙니다. 최종 필수 기능은 [전체 기능 대장 SAVE01~SAVE10](전체-기능-구현대장.md), 실제 작업 순서는 [S01~S03](PLAYABLE_ROADMAP.md), 지금 작동하는 범위는 [현재 상태](START_HERE.md)에서 관리합니다.

위 항목은 **구현 명세**이지 현재 `UnitRoster`나 각 서비스에 해당 API가 전부 있다는 뜻이 아닙니다. 원본에 없는 수치·추첨·재고를 저장을 위해 만들어 내지 않습니다.

## 3. 저장 시점과 파일 보호

1. **안전한 한 시점 확보:** 게임 논리 시간을 멈추고, 진행 중인 거래·유닛 생성/제거·보상 확정·지연 타격 적용이 끝난 일관된 경계에서 캡처합니다. 지갑과 로스터를 따로 저장하지 않습니다.
2. **검증 가능한 저장본 생성:** 형식 버전, 원본 근거 버전, 세션 ID 및 데이터 무결성 정보를 기록합니다. ID 중복·음수 잔액·존재하지 않는 대상/기술·부적절한 타이머는 저장/로드 단계에서 거부합니다.
3. **중단에 안전한 기록:** 임시 파일에 완전히 쓴 뒤 저장본을 교체하며, 교체 전의 **마지막 정상 저장**을 보존합니다. 저장 중 강제 종료됐다고 정상 저장을 먼저 지우지 않습니다.
4. **시간 멈춤 유지:** 앱이 백그라운드에 있던 실제 경과 시간만큼 재고/쿨타임/라운드/전투를 한꺼번에 진행시키지 않습니다. 사용자 확정 단일 플레이의 논리 시간 정책을 따릅니다.

저장 트리거의 구체적 위치(예: 명시적 저장, 라운드 경계, 앱 일시정지)는 **게임 상태를 한꺼번에 안전하게 캡처할 수 있는 시점**을 먼저 구현한 다음 결정합니다. 저장 경로·파일 이름은 플랫폼 코드에서 정의하며 문서에 임의의 실제 경로를 약속하지 않습니다.

## 4. 이어하기는 순서가 중요합니다

1. 저장 형식·원본 버전/해시·데이터 무결성·서로 참조하는 ID를 **게임에 반영하기 전에** 검증합니다.
2. 시작 보상 없이 빈 세션과 공통 지갑을 준비하고, 완료 영수증·도박 보류 결과·미션 완료 이력을 먼저 복원합니다.
3. 실물 유닛/적/건물의 **원래 인스턴스 ID**를 복구합니다. `UnitRoster.Add()`를 그대로 반복하면 ID가 새로 배정되므로 별도 복원 계약이 필요합니다.
4. 소유자·전장·대상 ID가 복구된 다음 버프/오라/지연 타격/소환수/쿨타임을 재연결합니다. `Action` 람다를 파일에 넣지 않고, 저장된 효과 기술자를 읽어 안전하게 재구성합니다.
5. 새로 시작하는 콜백과 이미 완료된 보상 콜백을 **다시 실행하지 않은 상태**에서 화면·입력·자동 전투를 열고 논리 시간을 진행합니다.

**복구 실패:** 원래 실행 중이던 세션이나 마지막 정상 저장을 변형하지 않고 오류를 보여줍니다. 지원하지 않는 이전 형식은 자동으로 삭제하거나 추측 변환하지 않습니다. 지원 가능한 마이그레이션만 버전별 변환기로 처리합니다.

## 6. 완료로 판정할 장면

- 조합·도박·아이템 획득 직후 중단 후 재접속: **보유 유닛/재화/영수증/추첨 결과 동일**, 재보상 없음.
- 보류 중인 위습·이세계 도박이 있는 상태에서 재시작: 결과를 다시 굴리지 않고 원래 보류 분기를 복원.
