# 원랜디 모바일 개발 작업목록

수정일: 2026-10-27  
대상: 원랜디 S2 2.323[C] · 악몽 · 이세계모드 · 오프라인 Unity 모바일

기능별 코드는 일부 구현되어 있으나, 게임을 시작해 한 판을 끝내는 연결은 아직 미완료다. 아래 순서로 기존 코드를 보완한다. 작업 번호는 유지하고, 게임에서 동작을 확인한 항목만 완료 표시한다.

### P0 연결 보강 묶음 (2026-10-27)

- **P0-03/P1-02 추가 연결(원본 소스 대조, Unity 검사 전):** 기본 `MainGame` 컨트롤러의 공유 재화·실제 전투 로스터에 랜덤위습 1개로 흔함 유닛을 소환하는 구현을 연결했다. `war3map.j`의 `CRy/BIU/BIR/BIS/BIQ/BIY`에 따라 **9종 원본 객체 순서·생성 좌표·일반 추첨 횟수별 1개/서로 다른 2개 후보·출현 누적 적은 쪽 선택**을 적용한다. 매 소환의 첫 `BFi(1,10000)`에서 **24 이하**가 나오면 원본은 흔함이 아닌 별도 `h060` **해적선**을 생성한다. 아직 그 객체의 실제 전투/소유·조합 처리가 없으므로 결과를 보류하고 위습을 소비하지 않으며 다시 추첨하지 않는다. 소환과 같은 랜덤위습 자원 교환이 동일 세션 난수 객체를 공유하도록 연결했다. 이 모바일 난수는 원본 **분포**만 재현하며 원본 Warcraft의 실제 초기 시드와 다른 시스템의 `BFi` 전역 호출 순서는 아직 동등하게 재현하지 못했다. 거래 롤백·교대 추첨·해적선 보류·원본 호출 순서 EditMode 테스트를 추가했다. **원본 완전 동일성/실기기 확인 및 P0-03 완료는 보류**한다.
- **후속 묶음 구현(실기기 미검증):** 메인 전장에 손가락 드래그·두 손가락 확대/축소와 PC 마우스 조작을 추가했다. 화면 조작은 원본 월드 좌표나 공격 판정을 변경하지 않으며 자동 카메라 추적도 하지 않는다.
- **사거리 확정 정책:** 모바일 평타 사거리는 **배정된 전장 내 무제한**이다. 서로 다른 전장 및 출전 자격 판정은 별도로 유지한다. 원본 개별 평타 사거리로 제한하지 않는다.
- **P1-01 추가 연결:** 실제 전투에서 확인된 몬스터 사망을 해당 출현 라운드와 함께 통지한다. 원본 난수·보상 이벤트 공급자가 이미 연결된 경우에만 처치 골드를 공유 지갑으로 지급한다. 이탈은 처치로 취급하지 않는다.
- **P4-02/P4-05 부분 연결:** 승리·패배 후 확인을 거쳐 씬을 새로 시작하는 경로, 게임 시간·라운드가 포함된 최근 64개 오류/진행 기록, 사용자 직접 클립보드 복사를 추가했다. 전체 상태의 저장·복원은 아직 구현되지 않았다.
- **P0-07 추가 표시:** 출현 예정·실제 출현·처치·이탈 수를 전장 하단에 표시한다. 원본 몬스터 최종 체력·방어·면역이 검증되지 않으면 실제 출현 자체는 승인하지 않는다.

- **P0-03 기존 거래 기반:** 랜덤위습을 수동으로 사용해 소환을 검증하고, 실패 시 전투 객체·공유 재화 변경을 복구하는 원자적 거래 경로를 먼저 마련했다. 위 신규 항목에서 흔함 9종 기본 추첨 공급자까지 연결했다.
- **P0-04 부분 연결:** 독립 관측 공급자가 전달하는 실제 몬스터 위치와 진행률을 기존 전투 객체에 반영한다. 대상별 위치·진행률·출처와 관측 시 읽기 전용 여부를 검사한다. **원본 이속/경로가 없으면 자동으로 움직이지 않는다.** 첫 라운드의 실제 출현 정보·최종 체력·면역 연결은 계속 필요하다.
- **P0-06, P4-02 부분 연결:** 일시정지 버튼과 앱 백그라운드·포커스 상실 시 전투 시간 정지를 추가했다. 복귀 시 미처 처리하지 못한 벽시계 시간을 몰아서 진행하지 않는다. 전체 저장·불러오기 및 새 게임 처리는 미완료다.
- **P0-07 부분 연결:** 시작 진화체 `e0HP`의 비전투 마커·선택, 원본 좌표에 대한 **시작 시 1회 카메라 위치 맞춤**, 화면을 가리던 메인 전장 박스 축소를 적용했다. 카메라는 적을 자동 추적하거나 계속 확대·축소하지 않는다. 기기에서의 터치·레이아웃 확인은 미완료다.
- **검사 범위:** 원본 흔함 소환의 공유 재화·유닛 변경과 롤백, 관측 몬스터의 위치, 카메라 경계값, 앱 전환 일시정지에 대한 Unity EditMode 회귀 테스트를 추가했다. 실제 원랜디 한 판과 실기기 동작은 검증되지 않았다.

### P0 시작 연결 진행 기록 (2026-10-27)

- **P0-01 일부 연결:** `MainGame`의 시작 버튼은 원본 검증된 피해 공급자·시작 프로필·첫 몬스터 계획·실전 승인 공급자가 연결된 경우에만 활성화된다. 시작을 누르면 첫 라운드 출현 계획을 **재화 지급 전에 검증**하고, 시작 세션→첫 라운드를 연결한다. 준비되지 않은 조건은 화면에 표시한다.
- **P0-02 일부 연결:** 원본 시작값 **골드 60, 랜덤위습 5개, 진화체 `e0HP` 1개**를 기존 공유 지갑·유닛 보유 상태에 동일하게 반영하는 비전투 진화체 등록 어댑터를 추가했다. 중복 생성·다른 세션 접근·시작 실패 시 유닛/재화 되돌리기를 검사한다. 진화체의 실제 사용/진화 행동은 별도 연결이 필요하다.
- **아직 미완료:** 기본 씬에 원본 확인된 실제 피해 계산기와 1라운드 최종 체력·방어·면역·좌표 자료/승인 공급자가 없어 버튼은 잠긴다. 위습 사용→첫 공격→적 처치의 실제 플레이 검증은 수행되지 않았으며, P0 항목을 완료 처리하지 않는다.
- **검사:** 로컬 Python 자료 회귀 138건 통과. 추가한 Unity 시작/롤백 테스트와 전체 Unity 결과는 `main` 자동 Actions에서 검증 예정이며, 결과는 별도 요청 시 확인한다.

- 일반 공격, 단일 스킬, 광역 스킬의 **대상 선택/시전 거리 제한은 제거**한다.
- 아군 버프 오라와 적군 디버프 오라는 **해당 전장 내 적격 대상 전체**에 적용하며 거리 감쇠·반경 제한을 두지 않는다.
- 광역 스킬의 **실제 피격 범위·최대 타격 수·피격 조건**은 원본 규칙대로 유지한다. 무제한 시전 거리와 무제한 광역 피해는 다르다.

### 몬스터 이동 관측 묶음 처리·중복 오라 갱신 제거 (2026-10-27)

- **성능 개선:** 이미 구현한 `Original323ObservedMonsterMovementWorld`를 새 구현으로 교체하지 않고 기존 위치 관측 경로를 묶음 처리로 수정했다. 몬스터마다 `RefreshEnemyAuras()`를 호출하던 방식 대신 원본 프레임의 대상 전체를 반영한 뒤 **최대 한 번** 오라를 갱신한다. 실제 위치/진행률 변화가 없으면 갱신하지 않는다.
- **무결성 개선:** 독립 관측 공급자의 모든 결과를 먼저 검증한다. 몬스터의 위치뿐 아니라 경로 진행률·상태효과 개정 번호, 세션 시간·라운드·생존/사망/누수 수·유닛 수도 변조 여부를 검사하고 문제가 있으면 위치를 일부만 반영하지 않는다. 스턴 적용 대상은 기존처럼 이동에서 제외한다.
- **자료 구조 재사용:** UI와 전투가 이미 사용하는 `MobileEnemySnapshot`에 읽기 전용 경로 진행률을 연결했다. 실제 적 이동·사거리 무제한·원본 피해 공식·광역 반경과 현재 분리된 메인/스토리 전장은 변경하지 않았다.
- **검증:** 관측 도중 진행률/상태효과 변조, 두 번째 대상에서 오류 발생 시 이전 대상 미적용, 여러 적 이동 시 오라 재계산 한 번 및 위치 불변 재관측을 대상으로 EditMode 회귀 사례를 보강했다. 실기기 및 Unity CI 통과 확인은 별도 작업이다.

### 기존 구현 중복 대조·최적화 작업 (2026-10-27)

- **원본 피해 계산은 이미 구현된 것을 재사용:** `Ordr323DamageWorldBinding` / `Ordr323OriginalDamageRules` / `CombatDamageRulesAdapter` / `CharacterCombatRuntime` 경로가 존재함을 확인했다. 객체별 네이티브 평타 연결은 `OriginalMapCommonNativeAttackBinding` 및 `ConfigureOriginalCommonNativeDamageWhenVerified`를 재사용한다. 별도 계산 엔진을 복제하지 않는다.
- **검증 중복 정리:** 전체 맵 대응 공격 데이터와 흔함 9종 전용 데이터는 별도 범위를 가진 실제 사용 중인 카탈로그이므로 유지한다. 중복 구현된 공격 필드 존재/원본 공격 타입 검증을 한 곳으로 합쳤다.
- **전투 중 조회 최적화:** `CombatWaveDirector`에 라운드별 개체 ID→원본 rawcode 색인을 추가했다. 몬스터가 죽을 때 매번 같은 출현 리스트를 1~2회 다시 탐색하는 경로를 제거하고 동일한 사망·보스 보상/출처를 유지한다.
- **불필요한 중복 실행 제거:** 이미 화면에서 세고 있는 평범한 몬스터 이탈마다 제한된 오류/진행 기록을 채우던 컨트롤러 이벤트 수신을 제거했다. 실전 이탈 이벤트·누수 카운트·처치 판정과 보상은 유지한다.
- **코드 삭제 원칙:** 실제 사용 여부가 확인되지 않은 파일이나 기능은 임의 삭제하지 않는다. 기존 기능을 유지하면서 확인된 중복 검증·중복 조회·무의미한 기록만 없앤다. 신규 원본 피해량/몬스터 스탯은 임의로 추가하지 않는다.
- **검사:** 유닛 등급별 카탈로그 범위, 몬스터 처치와 출현 라운드, 재사용 ID, 보스 rawcode 원본 보존에 관한 EditMode 회귀 검증을 추가했다. GitHub 자동 Unity CI 실행 시작 이후 결과는 별도 요청이 있을 때 확인한다.

- **실전 최종 몬스터 정보 일괄 연결:** 원본 관측 공급자가 각 개체의 최종 체력·방어·면역 정보·좌표를 제공하면 템플릿과 대조하고 전체 라운드 단위로 독립 승인한다. 하나라도 누락·불일치·미검증이면 계획 전체를 거절한다. 여러 라운드도 반환 전에 모두 검증한 다음 한 번에 등록한다.

- [ ] **P3-03 스토리·크립·부가 전투 구현** — 수동 파견, 출전 조건, 복귀, 보상과 MVP 집계를 연결한다.
- [ ] **P3-04 연구·항법·도움소 구현** — 특성공학, 유닛강화, 항법 선택, 도움소와 연금술을 연결한다. 확정한 특별함·특수함 모바일 조작 규칙을 반영한다.
- [ ] **P3-05 개인 미션·클리어 정산 연결** — 각 행동의 미션 집계, 기록지침 효과, 특성포인트 사용과 클리어 보상을 완성한다.

**완료 기준:** 시작부터 마지막 라운드와 승리·패배 후 정산까지 진행할 수 있다.

## P4. 저장과 모바일 사용성

- [ ] **P4-01 전체 게임 저장·불러오기** — 유닛, 전투, 라운드, 시간, 난수, 재화와 미션 상태를 함께 저장하고 복원한다.
- [ ] **P4-02 앱 전환·일시정지·새 게임 처리** — 앱 복귀 시 이어서 진행하고, 새 게임에서는 이전 상태를 초기화한다.
- [ ] **P4-03 화면·터치 조작 점검** — 가로 화면, 전장 배치, 좌측 탭·우측 상세, 전용 스킬 슬라이드와 스크롤을 휴대폰·태블릿에서 확인한다.
- [ ] **P4-04 성능·안정성 개선** — 후반 전투와 장시간 실행에서 프레임 저하, 메모리 증가와 시간 지연을 점검하고 수정한다.
- [ ] **P4-05 오류 기록 추가** — 버전, 시드, 라운드와 오류 원인을 기록해 문제를 재현할 수 있도록 한다.

**완료 기준:** 저장·복원과 앱 전환 후에도 진행이 유지되고, 모바일에서 핵심 조작을 사용할 수 있다.

## P5. 전체 점검과 APK 제작

- [ ] **P5-01 기능 묶음별 통합 검사** — 관련 기능을 구현하고 확인된 오류를 수정한 뒤, 전투·재화·조합·저장 흐름을 함께 검사한다.
- [ ] **P5-02 전체 게임 점검** — 65라운드, 캐릭터 스킬, 경제, 파견, 강화, 미션과 저장 기능의 남은 오류를 수정한다.
- [ ] **P5-03 Android APK 제작** — 핵심 기능 구현과 통합 검증을 마친 뒤, 패키지·리소스·버전·서명 설정을 갖춰 APK를 만든다.
- [ ] **P5-04 기기 설치·플레이 확인** — 설치, 시작, 전투, 조합, 앱 전환, 저장·복원과 게임 종료를 확인하고 테스트본을 전달한다.

## 작업 원칙

- 원본 규칙과 수치를 유지하고, 이미 확정한 모바일 조작 변경을 적용한다.
- 기존 구현을 재사용하고, 관련 기능과 오류를 묶어서 수정한 뒤 검사한다.
- `main`에서 작업한다. 푸시 후 GitHub Actions가 시작되면 응답을 마치고, 결과는 별도 요청 시 확인한다.
