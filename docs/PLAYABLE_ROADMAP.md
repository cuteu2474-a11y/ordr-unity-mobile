대상: **원랜디 S2 2.323[C] · 악몽 · 이세계모드 · 오프라인 Unity 모바일 리메이크**

**현재는 정상적으로 한 판을 플레이할 수 있는 상태가 아니다.** 기능별 코드와 조건부 전투 검사는 있지만, 기본 씬에서 게임 시작부터 전체 진행까지 연결되지 않았다.

**첫 내부 플레이와 APK 제작은 별도 단계다.** 첫 라운드가 실행돼도 핵심 기능 완성 전 APK를 만들지 않는다. P0에 필요한 근거와 실행 데이터부터 확보하며, 전체 캐릭터 자료 조사가 끝날 때까지 첫 플레이 연결을 미루지 않는다.

## P0. 최우선 — 실제 씬에서 게임 시작 → 첫 전투

- [ ] **P0-01 시작 진입점 연결** — 데이터 로드 → 실제 서비스 구성 → 초기 상태 지급 → 세션 시작 → 첫 웨이브 호출을 기본 씬에 연결한다. 성공 기준: 사용자가 시작하면 실제 게임 상태가 만들어지고, 중복 시작으로 자원이 늘지 않는다.
- [ ] **P0-02 초기 지급 완성** — 원본 싱글플레이의 지갑·초기 진화체와 유닛/위습 상태를 실제 월드에 생성한다. 성공 기준: 별도 테스트 객체 없이 첫 조작이 가능하고, 시작 실패 시 지급과 생성이 함께 복구된다.
- [ ] **P0-03 첫 유닛 획득 연결** — 원본 초기 자원과 확인된 위습 사용 경로로 실제 전투 유닛을 얻고 배치한다. 성공 기준: 화면·보유 목록·조합 재료 목록이 같은 유닛 인스턴스를 참조한다.
- [ ] **P0-04 첫 라운드 몬스터 확정** — 원본의 최종 체력·방어·출현 수/간격·좌표·이동 경로·대상 분류·면역을 실행 데이터로 제공한다. 성공 기준: 초기 계산 모델이나 이름만으로 승인하지 않고 실제 생성된 몬스터와 일치한다.
- [ ] **P0-05 기본 공격 실서비스 구현** — 첫 전투에 필요한 공격 경로·원본 주사위·주기·피해 분류·최종 HP 변환을 실제 계산기에 연결한다. 성공 기준: 미리보기 표시와 구분되는 실제 체력 감소가 발생하며 임의 피해 상수를 사용하지 않는다.
- [ ] **P0-06 독립 앱의 시간·난수·대상 상태 연결** — 확정된 원본 규칙에 따라 앱이 라운드 시간·난수 상태·몬스터 분류/면역을 직접 관리한다. 성공 기준: 플레이 중 외부 Warcraft 관측 결과를 매번 기다리는 구조 없이 실행된다. 승인 함수를 무조건 참으로 바꾸거나 모의 공급자를 연결하지 않는다.
- [ ] **P0-07 실제 전장 표시와 조작 연결** — 메인/스토리 전장 구분, 유닛·몬스터 좌표, 선택·체력·처치 표시를 실제 게임 상태와 맞춘다. 성공 기준: 자리 표시 화면을 넘어 실제 유닛이 공격하고 적이 이동·사망하는 것을 확인할 수 있다.
- [ ] **P0-08 첫 라운드 통합 확인** — 위 작업을 모두 연결한 뒤 시작 → 획득 → 배치 → 출현 → 공격 → 체력 감소 → 처치를 기본 씬에서 확인한다. 성공 기준: 재현 입력·커밋·남은 한계를 기록하고, 이때부터 '첫 전투 가능'으로 표시한다.

기존 상세 항목 연결: B-01~B-08, E-01~E-04, J-01~J-04, K-04의 첫 전투 범위.

## P1. 초반 연속 플레이 — 보상·위습·상점·도박·조합

- [ ] **P1-01 처치 보상과 공유 경제 연결** — 원본의 골드 판정·보너스·난수 순서와 중복 지급 이력을 실제 처치에 연결한다. 성공 기준: 도망간 적에는 처치 보상을 주지 않고 모든 메뉴가 같은 잔액을 표시한다.
- [ ] **P1-02 위습 전체 사용처 연결** — 랜덤·선택 위습, 자동 처리 대상 위습, 도움소 충전과 자원 교환의 확인된 규칙을 연결한다. 성공 기준: 성공한 사용만 소비·집계되고 올바른 실제 유닛/자원이 생성된다.
- [ ] **P1-03 상점 실상품 연결** — 원본 상품·가격·제한·조건·결과를 실제 구매 거래와 모바일 목록에 연결한다. 성공 기준: 잔액 부족·취소·연타·결과 생성 실패에서 비용이나 유닛이 부분 변경되지 않는다.
- [ ] **P1-04 도박 실제 결과 연결** — 종류별 원본 비용·확률·보상·시도 횟수와 공통 난수 사용 순서를 구현한다. 성공 기준: 실제 결과·소비·미션 집계가 하나의 성공 사건으로 연결되며 임의 확률표를 사용하지 않는다.
- [ ] **P1-05 첫 조합부터 실제 제작 연결** — 원본 재료·재화·조건을 확인한 조합부터 실제 재료 제거·결과 생성·배치를 완성한다. 성공 기준: 검색/미리보기와 실제 제작을 구분하고 실패 시 지갑·유닛·전투 상태가 복구된다.
- [ ] **P1-06 다음 라운드 자동 진행 연결** — 원본 라운드 시간·잔존 적·보스 조건에 따라 다음 라운드를 진행한다. 성공 기준: 초반 1~5라운드를 연속 실행하고, 정상적으로 확보한 재료의 조합과 새 유닛의 다음 전투 참여까지 확인한다. 조합 시점을 맞추려고 보상이나 확률을 바꾸지 않는다.

기존 상세 항목 연결: F-01~F-10, G-01~G-12, E-04~E-07, J-03/J-07/J-08.

## P2. 캐릭터별 실제 전투와 스킬 완성

- [ ] **P2-01 흔함 9종 개별 완료** — 각 유닛의 공격력·주기·타격 시점·피해 경로·판매·재료 사용 차이를 실제 전투로 확인한다. 성공 기준: 공통 엔진 연결을 9종 전투 완성으로 자동 간주하지 않는다.
- [ ] **P2-02 안흔함 전체 효과 연결** — 로빈의 동시 공격, 브룩의 기절, 육식 크리티컬·람각, 에이스·타시기·하찌 등의 추가 피해를 원본 효과 단위로 완성한다. 성공 기준: 스킬 이름만 표시하거나 복합 효과의 일부만 적용한 상태를 완료 처리하지 않는다.
- [ ] **P2-03 구현한 26개 패시브의 실제 대상 상태 통합** — 현재 몬스터의 영웅 여부·대상 마스크·면역과 동적 변경을 실행 상태에 연결한다. 성공 기준: 17개 기절·9개 크리티컬이 실제 웨이브의 적에게 올바르게 발동하고 면역·죽은 적·다른 전장에는 잘못 적용되지 않는다.
- [ ] **P2-04 특별함·희귀함부터 순차 확대** — 직접 피해·광역·다단히트·오라·소환·변신·스택을 낮은 등급부터 캐릭터별로 연결한다. 성공 기준: 확률·범위·타깃·피해·시전/적중 순서·처치 기여까지 해당 스킬의 전체 동작을 기록한다.
- [ ] **P2-05 복합 스킬과 자동 시전 완성** — 추가 피해가 섞인 능력, 복수 능력 중첩, 현재 능력 레벨·강화 분기·마나·쿨타임·시전 잠금·자동 Q/W/R을 연결한다. 성공 기준: 서로 다른 능력을 중복 실행하거나 고정 레벨로 대체하지 않는다.

기존 상세 항목 연결: E-05~E-12, H 전체, I 전체.

## P4. 저장·모바일 운용·안정성

- [ ] **P4-01 전체 게임 저장/복원** — 유닛·위치·체력/마나·능력 레벨·상태효과·예약 타격·라운드·시간·난수·경제·미션을 같은 시점으로 저장한다. 성공 기준: 복원 후 미래 결과와 미지급 보상이 일관되며 컴포넌트 저장만으로 전체 저장 완료를 주장하지 않는다.
- [ ] **P4-02 앱 전환·일시정지·새 게임** — 백그라운드 진입과 복귀, 세션 종료·재시작에서 시간을 일관되게 처리한다. 성공 기준: 보상·시전·웨이브가 중복되거나 이전 게임 상태가 새 게임에 남지 않는다.
- [ ] **P4-03 휴대폰·태블릿 조작 확인** — 가로 화면, 메인 상단/작은 스토리 하단, 좌측 탭/우측 상세, 전용 스킬 슬라이드, 스크롤·긴 한글·터치 영역을 확인한다. 성공 기준: 핵심 조작이 잘리거나 가려지지 않는다.
- [ ] **P4-04 후반 성능·안정성 확인** — 다수 유닛·적·스킬·장시간 실행에서 프레임·메모리·시간 밀림·예약 효과 정리를 확인한다. 성공 기준: 후반과 앱 복귀에서 진행이 끊기거나 상태가 누적 손상되지 않는다.
- [ ] **P4-05 재현 가능한 진단 제공** — 버전·시드·라운드·입력·피해/거래 보류 원인을 개발 로그로 남긴다. 성공 기준: 실기 문제를 재현할 수 있고 게임 화면에 과도한 개발 설명을 노출하지 않는다.

기존 상세 항목 연결: J-09~J-13, K-05/K-08.

## P5. 완료 판정과 APK

- [ ] **P5-01 원작 대조 통합 검사** — 정한 기능 묶음의 구현과 확인된 오류 수정을 끝낸 뒤 피해·스킬·거래·시간·저장·입력 흐름을 함께 검사한다. 성공 기준: 모의 승인·임의 수치 없이 해당 범위의 실행 근거와 잔여 차이를 기록한다.
- [ ] **P5-02 핵심 기능 완료 판정** — 실제 시작 → 65라운드 진행 → 승리/패배 → 정산, 캐릭터/경제/조합/파견/강화/저장과 필수 예외를 확인한다. 성공 기준: 미구현 필수 기능을 임의로 제외하지 않고, 완료 전까지 APK를 제작하지 않는다.
- [ ] **P5-03 Android 테스트 APK 제작** — 위 완료 판정 후 패키지·가로 방향·리소스·버전·서명/설치 설정을 구성한다. 성공 기준: 설치 가능한 실제 게임 빌드가 생성된다.
- [ ] **P5-04 실기 전체 플레이 확인** — 설치·시작·조작·전투·조합·앱 전환·저장 복원·게임 종료를 실제 기기에서 확인한다. 성공 기준: 확인한 기기·빌드·범위·문제와 수정 내역을 기록한 뒤 테스트본을 전달한다.

기존 상세 항목 연결: K-03~K-12. 기존 K-01 등 CI 결과 확인 항목은 아래 사용자 운영 규칙을 우선한다.

## 계속 지킬 운영 규칙

- **main만 사용**하며 불필요한 브랜치·워크플로를 추가하지 않는다.
- 서로 연결된 기능을 묶어 구현하고, 그 묶음에서 확인된 오류를 수정한 다음 통합 검사한다. 작은 변경마다 반복 실행하지 않는다.
- 푸시 후 **GitHub Actions 실행 시작을 확인하면 결과를 기다리지 않고 응답을 종료**한다. CI 결과는 성현 님이 별도로 요청하실 때만 확인한다. 기존 실행을 반복 취소하지 않는다.
- 원본 공격력·확률·쿨타임·비용·조합·피해 공식을 임의로 채우거나 바꾸지 않는다. 같은 전장 평타 사거리 무제한 등 이미 확정한 모바일 변경은 별도 정책으로 유지한다.
- 검증용 모의 객체·조건부 테스트 성공·카탈로그 등록을 기본 게임의 플레이 완료로 표시하지 않는다.
- 기능을 완료하면 **작업 ID·실제 연결 위치·커밋·검사 범위·결과·남은 한계**를 함께 기록한다. CI 결과는 요청 전까지 '실행 시작 확인, 결과 미조회'로 기록한다.
- 이 문서는 작업 목록이다. 이번 문서 반영으로 게임 기능·테스트 통과·플레이 가능 상태가 새로 확인된 것은 아니다.

## 이번 문서 이후 첫 실행 묶음

**P0-01~P0-08: 첫 라운드의 실제 플레이 연결**을 우선한다.

시작/공유 상태/초기 지급 연결과 첫 유닛·첫 적의 실행 데이터를 함께 준비하고, 기본 씬의 실제 전투를 완성한 뒤 통합 검사한다. 특정 원본 근거가 막히면 필요한 입력과 다음 독립 작업을 기록하며, 동일한 인터페이스·문서만 반복 추가하는 방식으로 완료 처리하지 않는다.
