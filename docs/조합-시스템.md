# 조합 시스템

> **읽는 순서:** 이 문서는 **현재 모바일 게임의 조합 방식**을 설명합니다. 실제 코드 연결 범위와 APK 차이는 [현재 상태](START_HERE.md), 남은 작업은 [개발 작업](PLAYABLE_ROADMAP.md)을 우선합니다. 기준은 최신 `main` 문서·코드이며, **코드에 등록됨 ≠ 실기에서 검증됨**입니다.

## 1. 조합이란?

보유한 유닛과 원작이 요구하는 재화·아이템·횟수 등의 조건을 충족했을 때, **재료를 소비해 상위 유닛을 얻는 기능**입니다. 원랜디 S2 2.323[C]의 **악몽·이세계모드**를 기준으로 하며, 결과 유닛·재료 수·비용·해금 조건을 편의상 바꾸지 않습니다.

모바일에서는 복잡한 재료 찾기를 도와주지만, **조합 실행은 플레이어가 직접 확정**합니다. 위습 소환, 랜덤 획득, 스토리 보상 등은 유닛 획득 경로일 수 있어도 모두 ‘조합’은 아닙니다.

## 2. 게임에서 조합하는 순서

1. **조합 메뉴**에서 만들고 싶은 유닛을 찾습니다. 목록·등급·보유 재료와 부족한 재료를 확인할 수 있습니다.
2. 게임이 현재 보유 유닛 중 사용 가능한 **실제 개체**를 재료 후보로 고릅니다. 스토리 파견 중인 유닛은 자동 재료 선택에서 제외합니다.
3. 골드·목재·아이템 및 별도 조건을 확인하고 **조합을 확정**합니다.
4. 확정 순간에 재료·잔액·조건을 다시 검사합니다. 중간에 유닛이 팔리거나 바뀌었다면 진행하지 않습니다.
5. 성공한 경우에만 지정된 재료와 비용을 소비하고 결과 유닛을 생성합니다. 실패하면 재료·지갑·보유 유닛 변경을 취소합니다.

조합 목록의 검색·필터·미리보기는 **안내 기능**입니다. 목록에 보인다는 이유만으로 제작이 허가되지는 않습니다.

## 3. 현재 어디까지 연결됐나요?

| 구분 | 현재 코드 기준 |
|---|---|
| 원본 CWR 등록 | **266건**(개발 전용 등록 포함) |
| 재료 조합 실행 허가 | **241건** |
| 나머지 등록 | 위습/랜덤 획득·안내·개발용 등 **별도 경로**로 분류. ‘미구현 조합 25개’와 같은 뜻이 아님 |
| 작동 방식 | 공통 조합 계획 → 조건 재확인 → 공유 지갑·실제 유닛을 한 거래로 소비/생성 → 실패 시 롤백 |
| 검증 수준 | **코드 연결 범위**. 최신 APK에서 241건 모두 실제 제작·전투까지 확인했다는 의미가 아님 |

일반적인 안흔함·특별함·희귀함·전설·히든부터, 초월·불멸·영원한·제한됨·변화·신비함 및 세라핌 관련 결과까지 **등급별로 따로 만든 조합 엔진이 아니라 공통 거래 엔진**을 사용합니다. 단, 등급별로 원본에 없는 재료·보상·사용 가능 조건을 추가하지 않습니다.

등록 수와 분류 기준: [CWR 경로 감사 자료](../data/original-2323C-cwr-last26-batch56.json). 실제 허가 목록은 [Original323CommonFusionPort.cs](../Assets/Scripts/Mobile/Original323CommonFusionPort.cs)와 원본 등록 데이터를 함께 확인합니다.

## 4. 조합 조건은 무엇인가요?

| 종류 | 의미 | 처리 원칙 |
|---|---|---|
| **유닛 재료** (`UNIT`) | 정해진 캐릭터를 정해진 수만큼 보유 | 실제 유닛 개체를 중복 없이 선택하고 소비 |
| **골드·목재** (`GOLD/WOOD`) | 조합마다 지정된 비용 | 공유 지갑에서 정확한 비용만 차감 |
| **아이템** (`ITEM`) | 원본에서 특정 아이템을 요구 | 실제 획득·보유 증거가 있을 때만 사용. 무료 지급 금지 |
| **특성 포인트 등** (`SKPT`) | 특정 조합의 추가 재화/상태 조건 | 실제 보유량과 원본 조건에 따라 같은 거래에서 검증·차감 |
| **변화·불멸 관련 횟수** (`CHCT/IFCT`) | 제작 횟수/조건을 따로 관리 | 공용 지갑의 성공 기록을 사용하며 임의로 횟수를 충전하지 않음 |
| **특수 재료 선택** (`PICK`) | 원본이 인정하는 후보군에서 추가 유닛 요구 | 이미 고른 일반 재료를 다시 고르지 않고, 실제 보유 후보만 사용 |
| **라운드·모드·해금 등** | 원본에 존재하는 진행 제한 | 현재 게임 상태와 대조. 다른 모드 전용 밴 조건을 이세계에 옮기지 않음 |
| **표시 전용** (`UPUN`) | 조합 안내에 등장하는 원본 표기 | 실제 차감 콜백이 없는 항목을 추가 유닛 재료로 소비하지 않음 |

같은 종류의 유닛을 여러 기 요구하는 경우에도 **서로 다른 실물 개체**를 필요 수량만큼 갖고 있어야 합니다.

**하위등급 원본 근거:** 흔함에서 안흔함으로 가는 **13종 원본 등록식**과 실제 유닛 소모·표시 전용 `UPUN` 구분은 [하위등급 원본 데이터](../data/original-2323C-lower-grade-gameplay.json)를 참조합니다. 원본에서 별도 골드·목재가 없는 식에 비용을 추가하거나, 등록식에 없는 좀비를 13종 명단에 넣지 않습니다.

### 몇 가지 예시

- **루피 기어세컨드(특별함)**: 원본 `A012`. 흔함 루피 **3기**를 소비합니다. 골드·목재를 임의로 덧붙이지 않습니다.
- **스모커·스쿼드(특별함)**: 각각 `A19Z`·`A1A1`. 원본이 요구하는 유닛 **3종씩**으로 조합합니다. 최신 코드는 결과 유닛 생성 경로를 허가하지만, 원작 `AOsf` 기술 콜백 자체의 완전한 재현은 검증되지 않았습니다. **특별 획득 조건이 필요한 유닛은 아닙니다.**
- **루피 기어써드(희귀함)**: 원본 `A00F`. 특별함 **루피 기어세컨드·봉쿠레·에넬**을 각 1기씩 소비해 희귀함 루피 기어써드(`R-06`)를 얻습니다. 원본에 없는 골드·목재는 추가하지 않습니다. [원본 희귀함 감사 자료](../data/original-2323C-rare-growth.json)의 재료 3종과 [현재 조합 연결 코드](../Assets/Scripts/Mobile/Original323CommonFusionPort.cs)의 결과 `R-06`을 대조한 예입니다.
- **압살롬(특별함)**: 원본 `A029`. 다른 재료 외에 **실제 좀비 3기**가 필요합니다. 재료가 없다고 무료 좀비를 지급하지 않습니다.
- **상위 조합**: 마르코의 `AI02`, 니카의 `AI01`, 알비다의 특성 포인트 등은 해당 원본 조합에 한해 별도로 검증합니다. 모든 조합에 공통으로 요구하는 것이 아닙니다.
- **니카 두 제작 경로:** 동일한 루피 계열이라도 E-01과 E-02는 재료·조건·완성 개체가 다릅니다. 원본 판매 사건 및 두 경로의 객체 구분은 [루피·니카 원본 근거](원본-루피-흔함-니카-계승.md)를 확인하고, 어느 한 경로를 다른 경로로 대체하지 않습니다.
- **베가펑크 초월(`TR30`)**: 실제 원본 재료 `SM-01/h0AN`을 갖고 있어야 합니다. 해당 재료의 **통상 획득 사건은 아직 미연결**이며, 다른 세라핌 유닛을 대신 재료로 사용할 수 없습니다.

예시는 규칙을 이해하기 위한 것입니다. **[전체 조합·획득 등록 266건 표](전체-조합-획득등록-목록.md)**에서 모든 원본 결과 유닛·필요 재료·골드/목재·아이템·추가 조건·특수 획득 경로를 확인할 수 있습니다. 실제 제작 허가는 현재 실행 코드에서 따로 판단합니다.

## 5. 실패·중복을 어떻게 막나요?

- 재료의 **개체 ID·종류·수량**을 확정 시점에 다시 검사합니다.
- 한 개체를 여러 재료 자리에 **중복 사용하지 않습니다**.
- 스토리 파견 중이거나 이미 판매·소비된 개체를 재료로 확정하지 않습니다.
- 골드·목재·아이템·횟수와 결과 생성은 **하나의 거래**로 처리합니다.
- 거래 도중 조건이 달라지거나 결과 생성이 실패하면 **전체를 되돌립니다**.
- 같은 거래·보상 영수증으로 재료를 이중 차감하거나 보상을 중복 지급하지 않도록 합니다.
- 조합 성공 후 전투에 연결되는 유닛도 **원본 결과 객체**를 기준으로 합니다. 조합 성공 자체가 모든 스킬의 원작 동등성을 보장하지는 않습니다.

## 6. 아직 구분해서 봐야 할 부분

**이미 연결된 것**
- 241개 원본 재료 조합의 코드상 실행 허가, 공유 지갑/로스터 거래, 보유 재료 선택·조건 재확인.
- 스모커·스쿼드·희귀 브룩처럼 원작 네이티브 시전이 복잡한 일부 유닛의 **모바일 결과 생성 경로**.
- 원본에 대응하는 일부 아이템·특성 포인트·횟수 조건의 차감 및 증빙.

**남아 있는 것**
- 원작의 제작 **후속 기술·더미/오라·타이머** 효과 중 일부는 결과 생성만 연결됐으므로, 전투 효과까지 동일한지 추가 확인이 필요합니다.
- `CJM` 이세계 유닛 도박의 **기본 결제·충전·보상 실물 생성 경로는 연결**됐지만, **해왕류 완료에 따른 충전 공급자·환전소 상품**은 남아 있습니다. 항법 선택과 A0YZ 수동 리롤은 [현재 경제·도박 시스템](경제-도박-시스템.md)에 별도로 연결된 범위를 확인합니다. `SM-01/h0AN`의 정상 획득 사건도 아직 미연결입니다. 관련 항목을 일반 조합식이나 무료 소환으로 바꾸지 않습니다. [현재 도박 기능](경제-도박-시스템.md)을 확인하세요.
- 최신 **Unity 통합 검사·APK 설치·실제 65R 플레이에서의 전체 조합 동작**은 별도 검증이 필요합니다. 과거 날짜별 테스트 통과 기록을 현재 통과로 보지 않습니다.

관련 작업은 [개발 작업](PLAYABLE_ROADMAP.md)의 **M·I·Q 영역**을 확인합니다.
