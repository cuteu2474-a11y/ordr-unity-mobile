# 화면·조작 시스템

> **모바일 사용 설명서:** 원랜디 S2 2.323[C] 악몽·이세계모드의 **현재 코드 동작과 확정된 최종 UI 정책**을 함께 설명합니다. 조합 UI는 소스에 반영됐지만 기존 APK에는 아직 미반영이며 Unity 실행 검증 전입니다. [현재 상태](START_HERE.md)는 코드와 다운로드 APK의 차이, [개발 작업](PLAYABLE_ROADMAP.md)은 미완료 기능을 다룹니다. 버튼이 보인다고 실제 휴대폰에서 검증됐다는 뜻은 아닙니다.

## 1. 화면은 어떻게 구성되나요?

- **가로 화면**에서 왼쪽은 메뉴, 가운데는 메인 전장, 아래에는 작은 스토리 전장, 오른쪽은 선택한 기능과 유닛의 내용으로 배치합니다.
- 상단에는 **골드·목재·랜덤위습·선택위습·특성포인트** 수량을 한 줄로 표시합니다.
- 버튼은 크게, 실제 보유 수량과 실행 가능 여부는 선명하게 보여줍니다. ‘Selected Unit’·‘Current Battle’ 같은 영어 장식 머리말, 시설 소개 배너·슬로건은 최종 화면에서 없앱니다. 도박 항목의 설명은 길게 누를 때만 엽니다.
- 메인 전장 유닛 초상화는 넓은 화면에서 **약 160px(기존 40px의 4배)**로 표시하며, 작은 전장에선 카드 안에 맞춰 축소하고 한 페이지의 유닛 수를 줄입니다. 정사각형 편대·페이지 이동은 표시 방식이므로 실제 유닛 좌표나 공격 판정은 변경하지 않습니다.
- **전투 시작·일시정지·처음으로** 조작은 점수판이 아닌 왼쪽 메뉴 하단에서 실행합니다. 처음으로 돌아가는 동작은 2회 확인하며, 스크롤과 버튼 터치를 구분합니다.

### 사용자 확정 시각 기준

- 오른쪽 상세 메뉴를 둘러싼 큰 은색/장식 테두리는 제거하고 어두운 평면 배경을 사용합니다. 행 버튼·닫기·내용을 구분하되 중첩 프레임을 추가하지 않습니다.
- ‘남은 수량 5개’ 같은 부분은 공용 소형 버튼 바탕으로 표시하고, 문구와 실제 수량은 별도로 그립니다. 같은 PNG의 색/밝기를 바꿔 가능·0개/비활성 상태를 구분합니다. 시각 변경만으로 새로운 결제·소환 동작을 만들지 않습니다.
- 메인·스토리 전장 바닥은 공통 이미지를 공유하고 톤/잘라 쓰는 영역만 달리할 수 있습니다. 기존 요새를 재사용하며 유닛 초상화·적·HP바가 먼저 읽히도록 바닥 대비를 낮춥니다. 경로·충돌·카메라·전장/파견 상태는 기존 실제 데이터를 유지합니다.
- [전장·수량 버튼·요새 원본](../art/battlefield-ui-v1/README.md)은 `Assets/Resources/OrdrArt`와 실제 표시 코드에 연결했습니다. 수량의 숫자는 공유 지갑 잔액, 색은 잔액/부모 행 활성 상태를 읽으며 수량 면을 눌러도 기존 행의 접기/펼치기 또는 재시도 한 번만 전달합니다. 추가 구매 명령은 없습니다. 메인과 스토리는 같은 바닥 텍스처를 공유하고, 스토리는 필드 높이의 24%를 사용해 요새·HP바·파견 줄/페이지를 분리합니다. 비정사각 바닥의 실제 sprite bounds로 배율을 계산해 원래 전장 영역을 유지합니다. **코드 연결 상태이며 Python/NUnit/Unity/APK 실행과 실제 Android 화면 검증은 미완료**입니다.

## 2. 한 번 누르면 되는 행동과 확인이 필요한 행동

| 조작 | 게임에서의 정책 |
|---|---|
| **보유 유닛 행** | 한 번 눌러 실제 유닛을 선택합니다. 같은 종류의 여러 기는 서로 다른 개체로 관리합니다. |
| **랜덤위습의 기본 기능** | 흔함 유닛 1회 소환 / 골드·목재 1회 추첨 / 도움소 마나 1회 충전. **항목 한 번 터치로 실행**하고 두 번째 확인을 요구하지 않습니다. |
| **자동 위습 4종** | 안흔함·특별·희귀·전설위습은 자동 지급합니다. 화면 행은 잔액·지급 보류 원인과 재시도 가능한 상태를 보여줍니다. |
| **선택위습** | **조합 메뉴에서만** 대상·조건을 확인하고 직접 사용합니다. 위습 탭에 중복 항목을 만들지 않습니다. |
| **일반 조합** | 재료·비용·제약을 확인한 다음 **최종 제작을 직접 확정**합니다. **확정 한 번당 원본 조합 거래 1건**만 실행하고 1회/3회 선택은 없습니다. 목록·필터·미리보기는 제작 권한이 아닙니다. |
| **도박** | 도박 항목을 **짧게 한 번 누르면 즉시 한 번 실행**합니다. **약 0.55초 길게 누르면** 해당 항목의 비용·확률·조건 설명만 열고 재화를 소모하지 않습니다. 스크롤 드래그는 실행하지 않습니다. 원본 비용·해금·재고 판정은 그대로입니다. |
| **상점** | 항목 선택 뒤 비용·재고·조건을 확인하고 **구매 확정**을 누릅니다. |
| **강화소 1·2** | 짧게 누르면 단계 구매를 **요청**하지만, 검증된 비용과 실제 전투 효과가 연결되지 않은 현재 상태에서는 차감 없이 거절됩니다. 길게 누르면 세부 정보를 확인합니다. |
| **연구소** | 원본 연구 4종의 정보를 펼쳐 봅니다. 실제 구매·효과 버튼은 아직 없습니다. |
| **판매·분해·영구 소비** | 실제 선택 개체와 소모 결과를 다시 확인합니다. 취소할 수 없는 거래에는 확인 단계가 필요합니다. |
| **스토리 파견·복귀** | 플레이어가 직접 실행합니다. 파견 중인 유닛을 메인 전투와 중복 사용하지 않습니다. |
| **항법 선택·초기화** | 되돌리기 어려운 행동이므로 확인 절차를 유지합니다. 카지노·리스크헷지 선택 행은 길게 누르면 각 특성이 나타납니다. |
| **샌즈 체력본충(Q)** | 선택 샌즈의 유닛 카드에서 브룩 안흔함(+2) 또는 희귀함(+12) 먹이기를 누릅니다. 해당 등급 실물 1기 소모가 버튼의 명시적 확정이며 추가 팝업은 없습니다. 뼈 30개 강화가 자동 반영됩니다. 원본 쿨타임·반복 사용 조건은 확인 전입니다. |
| **일반 공격·확률 스킬·허용된 Q/W/R** | 조건이 확인된 범위에서 자동 처리합니다. 원본 비용·쿨타임·대상 규칙을 생략해 난사하지 않습니다. |

화면은 **실제 서비스의 자격 판정과 거래 결과**를 보여주는 역할입니다. UI가 자체적으로 재화·유닛·전투 피해를 지급하지 않습니다. 실행할 수 없는 기능은 버튼이 보이더라도 비활성 상태와 이유를 명확히 표시합니다.

## 3. 유닛·조합 화면

- **유닛 메뉴**는 실제 유닛 목록·선택 개체·판매·관리·진화체를 다룹니다. **‘Selected Unit’·‘보유유닛’ 같은 중복된 구역 머리말을 최종 화면에 표시하지 않습니다.** 이름·등급·수량·행동에 화면 면적을 쓰며, 도감 검색·유닛 검색을 별도 메뉴로 만들지 않습니다.
- **진화체**는 유닛 쪽에 놓고, 원본 조건을 충족하면 자동 처리합니다. 별도의 위습 버튼/팝업을 추가하지 않습니다.
- **조합 메뉴**는 가로형 전장 **오른쪽 패널**에 있습니다. 이름 검색 입력 대신 **전체/가능/임박/★ 저장**, 등급·유닛 보유 필터와 페이지로 고릅니다. 결과 초상화·이름·등급 아래에 **필요 유닛·돈·나무를 같은 가로 줄**로 배치하고 길어지면 **해당 재료 줄을 좌우로 스크롤**합니다. 보유/부족 재료를 색으로 구분합니다. 현재 목록은 **8건씩**, 원본 JASS 등록식 읽기 자료는 **10건씩** 페이지를 넘깁니다. 오른쪽 패널 하단에는 선택한 결과의 **‘조합 확정’** 버튼이 고정되며 한 번에 거래 1건만 실행합니다. 소스 반영 상태이며 Unity·기존 APK 동작은 미검증입니다.
- **재료 확보만 보기**는 유닛 재료가 있는지의 필터일 뿐, 추가 골드·아이템·조건까지 충족해 실제 조합이 허가됐다는 뜻은 아닙니다.
- 자동 재료 후보에서 파견 중인 유닛과 이미 사용한 개체는 제외하고 **최종 확정 순간 다시 검사**합니다.
- 조합 확정 구역에 **1회/3회 수량 선택** 또는 **‘재료와 재화가 준비되었습니다’** 같은 불필요한 문구를 두지 않습니다. 원본 재료·비용·부족한 조건·확정 버튼은 유지합니다. 한 번의 확정이 원본에서 여러 결과 개체를 지급할 경우 **거래 1건의 원본 결과 수량**은 그대로 적용합니다.

### 보유 유닛의 수동 분해

| 유닛 | 실행 | 원본 결과 |
|---|---|---|
| **갱 뱃지** | **분해 시작** → 5초 시전 | 안흔함 후쿠로·흔함 버기·흔함 해군 총병 각 1기 |
| **버기 마기탄** | **분해 시작** → 2초 시전 | 흔함 버기 2기 또는 3기(각 50%) |

자동 시전은 하지 않습니다. **시전 중 취소**, 이동·스토리 파견 등으로 취소, 일시정지 중 시전 시간 동결을 적용합니다. 완료 시점에 본체를 소비하며 결과 생성이 실패하면 복원합니다. [특별함·특수함 확정 정책](특별함-특수함-운용정책.md)에서 분해·로우·베티·오타마·가이몬의 정확한 예외를 함께 확인하세요.
정확한 제작 조건은 [조합 시스템](조합-시스템.md), 위습별 소환·확률은 [위습 시스템](위습-시스템.md)을 확인합니다.

## 4. 스토리·점수판·부가 메뉴

- **스토리**에서는 건물과 파견 유닛을 표시합니다. 작은 전장에서는 실제 공격·피격 사건을 바탕으로 공성 연출을 보여주며 화면 위치와 게임 전투 위치를 혼동하지 않습니다.
- **점수판**은 원작의 채팅형 기록 표현을 참고한 **개인 기록·흔함 획득·유틸보드** 3개 탭입니다. 개인 기록은 라운드·남은 시간·남은 적 3개 큰 카드와 처치·전투 유닛·보물·돈 도박·항법의 짧은 행만 표시합니다. 흔함 획득은 누적 수량과 유닛별 횟수, 유틸보드는 네 가지 감소 수치만 표시합니다. 중복된 제목·소개글·집계 유닛·라운드 기록/게임 제어 섹션은 보이지 않습니다. **득점·감점 내역이나 클리어 점수 계산은 추가하지 않습니다.** 유틸보드 합산 수치의 해석은 원본 자료 기준의 잠재치이며 실제 적용 결과로 확정하지 않습니다.
- **기록지침**에는 원작 보물 탐색을 배치합니다. 가이몬 보유·꿈·사용 가능 상태 등 실제 조건을 만족할 때만 실행됩니다.
- **도움소**에서는 마나와 항법 상태를 확인하며, **랜덤위습을 통한 마나 충전 버튼은 위습 메뉴 한 곳에만** 배치합니다.
- **미션**은 연결된 실제 게임 사건에만 반응합니다. **연구소**는 정보 열람, **강화소**는 다음 단계 요청 및 차단 사유 확인까지가 현재 UI 범위입니다. 원본 수치가 문서에 있다는 이유로 구매·전투 효과를 완료로 표시하지 않습니다.

## 5. 개발할 때 지켜야 할 연결 원칙

1. **전투 화면과 실제 상태를 분리:** 화면용 배치·카메라·초상화가 원본 위치·대상·피해 계산을 바꾸지 않게 합니다.
2. **실행 자격은 기존 공통 엔진에서 판단:** 화면은 서비스의 결과만 요청하며 임의 확률·비용·보상을 만들지 않습니다.
3. **전투 자동화와 수동 경제를 구분:** 원본 공격·스킬 판정은 자동, 조합·경제·파견은 확정 정책을 유지합니다.
4. **게임 전장 도달 거리와 광역 판정을 구별:** 성현 님이 확정한 같은 전장 공격·스킬·오라 사거리 무제한 정책을 유지하되, 각 기술 고유 광역 반경·인원·면역은 임의로 없애지 않습니다.
5. **화면을 실제 기기에서 검증하기 전에는 미검증으로 표시:** 작은 가로 화면의 잘림·스크롤·터치·대량 전투 성능은 [검증 작업](PLAYABLE_ROADMAP.md)의 Q 영역에서 확인합니다.
