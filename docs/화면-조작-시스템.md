# 화면·조작 시스템 — 모바일 UI 구현 기준

**메인 전장 배치 설계 변경(2026-11-14, 문서 확정·코드 적용 보류):** 전투 유닛은 왼쪽 면 고정 배치, 일반 적은 기존 순환, 라운드 보스는 왼쪽 위아래 왕복으로 정합니다. 개별 이동/추적·진형 이동 조작을 요구하지 않고 실제 위치와 유한 사거리로 자동 공격합니다. 아래의 정사각 카드·페이지 정렬은 목록 표시 기준이며 전투 좌표를 대신하지 않습니다. 세부 슬롯·경로 간격은 추후 결정합니다. [거리·동선 확정 설계](전투-공통엔진.md#메인-전장-거리와-동선-확정-설계).

**작은 가로 화면 조작:** 왼쪽 메뉴는 위아래로, 전장 사이 스킬 줄은 좌우로 드래그합니다. 드래그를 마칠 때 메뉴 선택이나 스킬 발동을 실행하지 않습니다. 자원 칸이 좁으면 이름 아래에 실제 숫자를 표시하며 수량을 이미지나 약식 값으로 대체하지 않습니다. 오른쪽 대기 화면·상단 자원·스킬 줄 위 터치는 전장 유닛 선택으로 전달하지 않습니다.

## 1. 한눈에 보는 게임 화면

### 화면에 공통으로 적용할 디자인

1. **게임다운 버튼, 큰 글씨, 뚜렷한 대비:** 작은 흰색 안내글을 빽빽하게 쌓지 않습니다. 유닛 이름·현재 수량·비용·남은 횟수·가능/불가 이유가 먼저 보이게 합니다.
2. **한 화면에 한 가지 주요 행동:** 상세 카드의 핵심 실행 버튼 위치를 일정하게 유지합니다. 긴 목록만 스크롤하고 화면 전체가 불필요하게 이동하지 않도록 합니다.
3. **장식보다 정보:** `Selected Unit`, `Current Battle`, ‘보유유닛’ 같은 반복 머리말, 점수판 타이틀·시설 광고·‘재료가 준비되었습니다’ 같은 중복 문구는 제거합니다.
4. **실제 수량을 이미지와 분리:** ‘남은 수량’은 공용 **작은 수량 버튼 바탕**에 실시간 숫자를 얹습니다. 5개/0개는 예시일 뿐 고정 이미지가 아닙니다. 상태별 색·밝기를 바꾸되 0개도 읽혀야 합니다.
5. **터치 면적과 스크롤 분리:** 항목을 스크롤하다가 도박·위습·구매가 실행되면 안 됩니다. 접기/펼치기용 수량 면도 부모 행 **한 번의 동작**만 실행하고 추가 소환/결제를 만들지 않습니다.
6. **모바일 화면에 맞춘 반응형 배치:** 좁은 가로 화면에서는 유닛 크기·페이지당 항목 수·카드 너비를 조절하고, 긴 조합 재료줄은 **그 줄만 가로 스크롤**합니다. 버튼·닫기·페이지 조작이 잘리지 않아야 합니다.

**공통 결과 팝업:** 도박 당첨/실패의 확정 보상과 위습에서 실제 얻은 유닛을 메인 전장 **왼쪽 상단(HUD 아래)**에 같은 양식으로 약 3.2초간 표시합니다. 신규 유닛은 거래 전후 로스터의 실제 인스턴스 차이로 사진·이름·수량을 표시하고, 유닛이 없으면 확정 도박 메시지를 사용합니다. 팝업은 시간이 지나면 사라지고 터치가 뒤의 유닛을 선택하지 않도록 차단합니다. 비용·충전·원본 확률은 변경하지 않으며, 작은 기술 문구는 길게 누르는 상세에서만 확인합니다. 실제 Android 가독성은 별도 미검증입니다.

## 2. 왼쪽 메뉴에서 무엇을 보여주고 실행하나요?

### 시작 화면과 전투 제어

- 시작 지급은 **원본대로 랜덤위습 5개·골드 60·진화체 1기**입니다. UI에서 임의로 랜덤위습 1개를 표시/지급하지 않습니다. 시작 코드와 실제 APK 실행 결과는 별도로 구분합니다.
- 플레이 중 **시작·일시정지·재개·처음으로**는 왼쪽 하단에 둡니다. **처음으로**는 실수로 세션을 잃지 않도록 두 번 확인합니다.
- 스크롤/드래그는 메뉴 선택 또는 소모 행동으로 간주하지 않습니다. 백그라운드·일시정지 중 시간·쿨타임·시전/예약 효과는 게임 엔진의 상태를 그대로 반영합니다.

## 3. 유닛·조합은 이렇게 구성합니다

### 유닛 목록과 전장 초상화

- 오른쪽에는 **보유 개체 목록 → 한 개체의 상세 정보/행동** 순서로 보입니다. 등급·이름·성장·사용 가능한 행동이 우선이며 도감 검색/이름 검색/불필요한 탭을 추가하지 않습니다.
- 메인 전장 초상화는 과대 확대하지 않습니다. **최대 94×화면 배율 px, 카드 높이의 52% 이내**로 제한하고, 카드 하단을 불투명한 이름판에 전용 할당합니다. 유닛 이름은 큰 흰 글씨, 동일 유닛 수량은 우상단 **`×N` 금색 배지**로 표시합니다. 작은 등급·인스턴스 설명은 전장에서 제거하고 등급은 기존 테두리 색으로 구분합니다. 좁은 가로 화면은 카드당 정보 가독성을 우선해 페이지로 넘깁니다.
- 유닛을 **정사각형 편대**로 정리하고 페이지를 넘기는 것은 **표시 방식**입니다. 실제 유닛 좌표·공격 대상·사거리·스토리 파견 자격을 변경하지 않습니다. 유닛 대신 색 원형 점으로만 표시하지 않습니다.
- **진화체는 유닛 메뉴**에서 보여줍니다. 원본 조건 충족 시 획득/해방은 자동이며 별도 ‘진화체 사용’ 버튼이나 보상 팝업을 만들지 않습니다.
- 개체 판매·소모·분해 전에 **어느 실물 한 기를 처리하는지** 명확히 하고, 취소/실패 시 원래 개체·지갑·상태가 보존되게 합니다.

### 조합 오른쪽 패널

| 영역 | 표시/동작 |
|---|---|
| **목록 상단** | **전체 / 가능 / 임박 / ★ 저장**과 등급·보유 재료 필터. **이름 검색창 없음** |
| **결과 목록** | 결과 초상화·이름·등급·제작 상태. 한 페이지 **8개**로 이동 |
| **결과 상세** | 원본 유닛 재료·필요 수량·**골드·목재·부가 조건을 같은 가로 줄**에 표시. 긴 경우 **재료줄만 좌우 스크롤** |
| **보유/부족** | 있는 재료와 부족 재료를 구분. **‘재료 보유’ 필터는 전체 조합 허가와 다름**(돈·아이템·라운드·횟수 등 추가 조건 존재) |
| **패널 하단** | 고정 **‘조합 확정’** 버튼. **확정 한 번 = 원본 거래 1건**, 1회/3회 선택 없음 |

재료는 파견·비파견을 분리해 표시하지 않고 **모든 보유 개체를 합쳐 `보유 N`**으로 표시합니다. 제작 준비/소비 대상은 원본 거래가 허용하는 실제 개체만 포함하며, 스토리·크립 파견 중인 개체도 **별도 복귀 없이 조합·판매·분해**할 수 있습니다. 성공 거래에서 해당 개체의 파견과 예약 효과를 정리하고 실패 시 원래 상태를 유지합니다. 조합 자동 실행은 하지 않습니다. 이미 소비된 개체는 제외하고 **확정 순간** 재료/재화/자격을 다시 검사합니다. 원본의 **한 거래가 여러 결과 개체를 지급**하는 경우 그 결과 수량은 바꾸지 않습니다. 원본 JASS 등록식의 별도 열람 페이지는 **10개씩** 넘길 수 있지만, 등록식 266건을 모두 제작 버튼으로 표시하면 안 됩니다.

### 스토리 오른쪽 상황판 상세 배치 명세

**2026-11-16 문서화한 후속 설계.** 최근 청록·금빛 스토리 시안을 기준으로 한 배치 계약이며, 이번 변경은 문서만 해당합니다. 기존 건물/크립 탭·HP 막대·파견 목록의 코드 연결 기록을 이 배치의 적용/실기 검증 완료로 간주하지 않습니다.

**핵심 변경:** 단계는 `8/14`가 아니라 **현재 단계 숫자 `8`만 크게** 보여 줍니다. 전체 14단계 규칙은 그대로 보존하고 화면의 분모만 없앱니다. 시선 순서는 **단계 → 목표 이름 → 체력 → 파견 유닛**입니다.

**파견 동작·표시의 최신 확정 사항:** [모바일 파견 계약](토벌-크립-파견-시스템.md#확정된-모바일-파견표시-계약-2026-11-16). 같은 상태 묶음·가능 개체만 노출·직접 목적지 이동·복귀 없는 조합/판매·다음 크립 자동 공격·최종 수동 복귀를 따릅니다. 파견 버튼 한 번으로 필요한 이동기·변신도 함께 처리하며 원본 자격·비용·쿨타임을 유지합니다.

#### A. 적용 범위와 좌표 읽는 법

- 대상은 스토리 메뉴를 열었을 때의 오른쪽 패널입니다. 왼쪽 메뉴·상단 재화·가운데 전장의 위치와 전투 규칙은 변경하지 않습니다.
- 패널 내부 왼쪽 위를 `(0, 0)`, 오른쪽 아래를 `(100, 100)`으로 봅니다. x는 오른쪽, y는 아래로 증가합니다.
- 실제 내부 사각형이 `(L, T, W, H)`이면 `화면 x=L+W×x/100`, `화면 y=T+H×y/100`으로 변환합니다. 아래 비율은 내부 안전 영역 기준이며 기기 전체 화면 비율이 아닙니다.
- 표의 구간은 요소를 담는 영역입니다. 글자 기준선이나 터치 사각형을 비율만으로 고정하지 않고 기존 화면 배율·폰트 실측·최소 터치 크기를 함께 적용합니다.
- 양옆 기본 여백은 3%, 구역 사이 여백은 1~2%입니다. 작은 화면에서 글자를 무조건 축소하지 않고 아래의 반응형 우선순위를 적용합니다.
- 청록색 바탕·옅은 금빛 내용 영역·금색 강조를 유지합니다. 시안의 외곽 색감은 살리되 **기존 큰 장식 테두리 금지 원칙**에 따라 콘텐츠를 잠식하는 두꺼운 프레임과 행마다 겹치는 장식은 추가하지 않습니다.

**제목(y=0~8)**

#### D. 현재 목표 카드: 단계 숫자와 이름

| 요소 | x 범위 | y 범위 | 표시/정렬 |

| 격파 보상 | 6~94 | 37~40 | 아이콘·보상명·실제 수량 한 줄 |

- 단계 숫자는 패널 안에서 가장 크게 표시합니다. 예: 어두운 청록 배지 위 밝은 금색 `8`. `/14`와 별도 `진행 8/14`는 표시하지 않습니다.
- 숫자 `8`, 목표명 `에니에스 로비`, 체력 `650,000 / 1,000,000`은 **배치 설명용 시안 예시**입니다. 이 값들의 조합을 실제 단계/원본 수치 매핑으로 사용하지 않습니다.
- 목표 이름은 실제 단계 데이터에서 읽습니다. 긴 이름은 2줄을 허용하고 이름/상태 영역 내부를 재배분합니다. 상태·시간이나 체력과 겹치게 하지 않습니다.
- 상태는 실제 모델의 해금 대기·공략 중·격파 완료·전체 완료 등을 표현합니다. 준비 중에도 실제 공격이 가능하다는 기존 규칙을 UI가 막지 않습니다.
- 제한 시간이 있는 대상만 상태 줄 오른쪽에 시계 아이콘과 남은 시간을 표시합니다. 실제 게임 시계를 읽고 UI 전용 제한 시간을 만들지 않습니다.
- 마지막 격파 뒤 존재하지 않는 다음 단계 숫자/건물을 만들지 않습니다. 전체 완료 상태를 표시하고 파견 버튼 자격은 기존 서비스 결과를 따릅니다.

#### E. 체력과 보상

**체력**

1. 막대 위 왼쪽에 `건물 체력`, 오른쪽에 `현재 / 최대`를 표시합니다.
2. 수치는 천 단위 구분을 포함한 실제 값을 사용합니다. 시안의 `65%`는 제거하여 수치·막대가 같은 의미를 중복 설명하지 않게 합니다.
3. 막대 바탕은 어두운 회갈색, 잔여 체력은 청록색입니다. 체력 숫자는 무늬 없는 밝은 바탕 위 짙은 글자로 표시합니다.
4. 표시 비율만 0~1로 제한하며 실제 HP를 UI에서 보정하거나 변경하지 않습니다. 최대 HP가 없거나 유효하지 않으면 가짜 100%를 채우지 않고 상태를 표시합니다.
5. 실제 격파 사건이 있으면 완료 상태를 표시합니다. 보기용 애니메이션을 위해 다음 단계 진행이나 보상을 지연/재실행하지 않습니다.

**격파 보상**

- 목표 카드 맨 아래 한 줄: 작은 상자 아이콘 → `격파 보상` → 실제 재화/보상 아이콘과 수량.
- `골드 · 목재`처럼 종류만 표시하지 않습니다. 실제 해당 대상의 보상만 표시하며 예시 수량을 넣지 않습니다.
- 자동 지급 보상에 별도 수령 버튼을 만들지 않습니다. 원래 수동 사용권이 있는 보상과 자동 지급을 구분합니다.
- 종류가 많으면 작은 글자로 압축하지 않고 대표 표시와 하단 기록 상세로 연결합니다. 획득 예정과 획득 완료를 구분하고 베리는 표시/지급하지 않습니다.

#### F. 파견 중과 파견 가능 목록

**파견 중**

- y=42~46 부근에 `파견 중`과 실제 해당 목적지 파견 수를 나란히 왼쪽 정렬합니다.
- 그 아래 기본 2행을 배치하고 넘치는 항목은 이 영역 안에서만 스크롤합니다. **2행은 표시 높이이지 파견 정원 2기라는 규칙이 아닙니다.**
- 0기이면 `파견 중인 유닛 없음`을 한 줄로 보여 줍니다. 빈 장식 카드를 반복하지 않으며 남는 공간은 파견 가능 목록에 돌릴 수 있습니다.
- 기존 일괄 복귀 기능을 유지한다면 목록 아래에 공간을 확보하고 기존 확인 절차를 유지합니다. 본 명세가 해당 기능 삭제를 뜻하지 않습니다.

**파견 가능**

- 기본 y=67~71에 `파견 가능` 제목, y=71~92에 목록을 배치합니다.
- 목표/체력/탭/기록은 고정하고 이 목록만 움직입니다.
- 현재 목적지의 실제 자격 판정을 사용합니다. 0기이면 가능한 유닛이 없다는 상태를 표시합니다.
- 파견 가능한 유닛만 표시합니다. 불가·미확정 개체는 숨기며 불가 포함 필터와 불가 이유 설명은 만들지 않습니다.
- 다른 크립/건물에 배치된 개체를 메인 대기 개체로 잘못 표시하지 않습니다. 목적지 이동 가능 여부는 공통 서비스가 결정합니다.

**두 목록에 공통인 행 구조**

| 열 | 패널 기준 x 범위 | 표시 규칙 |
|---|---:|---|
| 초상화 | 6~17 | 정사각형, 행 세로 중앙. 이미지 없으면 안전한 대체 표시 |
| 이름/등급 | 20~72 | 이름 위·등급 아래, 왼쪽 정렬. 긴 이름은 버튼 영역을 침범하지 않음 |
| 행동 | 76~94 | 행 세로 중앙. 파견은 청록, 복귀는 금색 |
| 스크롤바 | 95~97 안쪽 | 해당 목록 높이에 한정. 버튼 터치 영역과 분리 |

- 초상화의 실제 크기는 행 높이에 맞추므로 x 구간 전체를 강제로 채우지 않습니다.
- 기본은 **같은 종류·같은 상태끼리 묶은 행(예: 루피 ×3)**입니다. 버튼 한 번으로 한 기를 처리하며 상태가 다른 개체는 분리합니다. 동명·동등급 중복 개체는 선택 시 실제 인스턴스를 식별할 수 있어야 하며 내부 ID를 작은 개발용 글씨로 상시 노출하지 않습니다.
- 묶음 행을 적용하더라도 상태가 같은 개체에만 한정합니다. 수량은 실제 보유/파견 수이며, 한 번의 파견이 어느 한 기에 적용되는지 결정적이어야 합니다. 개체별 상태가 다르면 개별 행을 유지합니다.
- 이름·등급·버튼의 열 위치를 두 목록에서 동일하게 유지합니다. 파견 뒤 행이 옮겨져도 읽는 위치가 바뀌지 않게 합니다.
- 버튼 한 번은 기존 명령 한 번입니다. 요청 중 동일 버튼 중복 입력을 차단하고 실패하면 실제 상태를 유지한 채 사유를 표시합니다.
- 조합·판매·분해·변신·유닛 소멸·파견/복귀 사건 뒤 목록·개수·선택 대상을 같은 실제 상태에서 갱신합니다. 삭제된 개체가 남거나 메인/건물/크립에 중복 출전하면 안 됩니다.
- 정렬은 안정적으로 유지하며 HP 갱신마다 행 순서나 스크롤 위치를 초기화하지 않습니다.

#### G. 하단 기록과 위습 사용 위치

- 고정 y=94~100의 한 줄에 기록 아이콘(왼쪽), `보상 · 진행 기록`, 펼치기 화살표(오른쪽)를 둡니다. 행 전체가 하나의 터치 대상입니다.
- 기록을 열면 **파견 영역 y=42~92만 기록 목록으로 전환**합니다. 제목·탭·현재 목표·체력은 계속 보입니다. 다시 누르면 원래 파견 화면과 스크롤 위치로 돌아옵니다.
- 기록은 실제 획득/진행 장부를 조회합니다. 펼치기·접기·화면 재진입으로 지급을 재실행하지 않습니다.
- 시안의 상시 `초월위습 1 / 사용` 행은 이 패널의 고정 영역에서 제거하여 목록 공간을 확보합니다.
- **초월위습은 위습 메뉴**, **그린블러드는 스토리 메뉴의 보상 상세**에서 조회·사용합니다. 권리·지급 대기 상태는 보존하며 초월위습 사용 버튼은 스토리에 중복 배치하지 않습니다.
- 기존 접힌 보상 헤더의 미사용 권리/지급 대기 표시는 짧은 배지로 유지하여 기록을 열지 않아도 누락을 알 수 있게 합니다.

#### H. 크립 탭의 차이

외곽 제목·탭·고정 목표 영역·파견 행 구조는 재사용하지만 건물 단계 숫자를 크립에 그대로 복제하지 않습니다.

| 항목 | 건물 공략 | 크립 사냥 |
|---|---|---|
| 주요 목표 | 현재 건물 단계 숫자+건물명 | 선택한 실제 크립 대상과 상태 |
| 체력 | 실제 건물 HP | 해당 크립 월드의 실제 HP |
| 조건/시간 | 건물 해금·실제 제한 시간 | 대상별 실제 접근/출현/사냥 조건 |
| 보상 | 해당 건물 보상 | 해당 크립의 실제 보상 |
| 파견 | 건물 목적지의 개체 | 선택한 크립 목적지의 개체 |

듀공·파파구·슈슈 등 대상 선택은 기존 규칙을 따릅니다. 크립 파견의 실제 목적지/자격 서비스가 연결되기 전에는 상태 조회와 미지원 이유만 보여 주며 활성 파견 버튼을 꾸미지 않습니다. 별도 토벌 퀘스트를 이 목록에 합치지 않습니다.

#### I. 반응형·입력·공통 구조

- 위 비율은 기본 배치입니다. 작은 가로 화면에서는 **최소 터치 크기/글자 가독성 → 고정 목표 정보 → 목록 접근성 → 장식 여백** 순서로 보존합니다.
- 공간이 부족하면 제목/장식 여백을 먼저 줄이고 목록의 보이는 행 수를 줄입니다. 파견 중 2행을 강제해 파견 가능 영역이나 기록 버튼을 없애지 않습니다.
- 긴 목표 이름·큰 HP 수치·긴 유닛 이름은 각 할당 영역 안에서 줄바꿈합니다. 버튼 밖으로 밀거나 의미 없는 작은 흰 글씨로 줄이지 않습니다.
- 파견 중과 파견 가능은 형제 스크롤 영역입니다. 터치 시작 영역이 드래그를 소유하고 경계를 넘더라도 다른 목록/전장으로 입력을 넘기지 않습니다.
- 스와이프로 판정된 손가락을 떼도 파견/복귀를 실행하지 않습니다. 스크롤바나 기록 영역 터치가 뒤의 전장 유닛 선택으로 통과하지 않습니다.
- 탭별 선택 대상·목록 스크롤은 필요 범위에서 보존하되 대상 소멸/목록 축소 시 유효 범위로 보정합니다.
- `OrdrMobileTouchPanel`과 `OrdrMobileUiTheme`의 기존 레이아웃·폰트·버튼·입력 처리를 재사용합니다. 고정 목표 카드, 개체 행, 상태/보상 표시를 공유하고 탭별 실제 데이터만 바꿉니다.
- UI가 별도 HP·재화·전투 시계·보상 장부·파견 자격을 소유하지 않습니다. 일시정지 중 파견은 기존 허용 정책을 따르고 공격 논리 시간은 멈춥니다.

#### J. 후속 적용 순서와 수용 기준

아래는 **미적용 설계의 작업 항목**이며 이번 문서 작성으로 완료 체크하지 않습니다. 기존 구현을 먼저 대조하고 필요한 차이만 묶어 적용합니다.

1. 고정 영역/목록 영역 레이아웃과 공통 행을 함께 정리합니다.
2. 현재 단계 숫자 단독 강조, 목표/상태/시간, 실제 체력/보상 표시를 연결합니다.
3. 파견·복귀·목적지/개체 자격과 로스터 변경 시 목록 갱신을 기존 서비스에 연결합니다.
4. 기록 전환과 미사용 보상 접근 경로, 크립 미지원 상태, 좁은 화면/입력 경계를 함께 정리합니다.
5. 별도 실행 요청 시 기능 묶음 단위로 검증하고 현재 상태·개발 작업표에 결과를 기록합니다.

| 확인 장면 | 수용 기준 |
|---|---|
| 현재 건물 단계 8 | 큰 `8`만 표시. `/14` 없음. 실제 이름/HP/보상이 같은 목표를 참조 |

관련 원본/운영 규칙은 [스토리](스토리-시스템.md), [토벌·크립 파견](토벌-크립-파견-시스템.md)을 따릅니다. 이번 문서화는 원본 보상·체력·해금·파견 자격 변경이나 APK 제작 요청이 아닙니다.


### 크립 파견·토벌의 확정 화면 흐름

**크립 사냥은 스토리 안에 배치**합니다. ‘건물 공략 / 크립 사냥’은 같은 메뉴의 내용 전환이며 크립 전용 왼쪽 메뉴·시설 탭을 만들지 않습니다. 대상 → 실제 보유 개체 → 파견 → 실제 전투 → 복귀 흐름과 가능한 개체만 표시하는 규칙, 크립 목적지별 전장 분리, 기존 카드·버튼 재사용은 [토벌·크립 파견 명세](토벌-크립-파견-시스템.md)를 따릅니다. 개인미션 3칸은 미션, 별도 처치형 퀘스트는 토벌에서 관리합니다. 이 UI 정책의 구현/실기 상태는 [현재 상태](START_HERE.md)에서 구분합니다.

### 스토리·시설의 상태와 결과

- **스토리 건물**은 실제 HP·현재 단계·해금/파견 상태를 표시합니다. **실제 공격·피격 사건이 없는데** 요새가 피해를 입거나 건물이 격파된 것처럼 연출하면 안 됩니다.
- **강화소 18종**은 **독립 전투 모델에 다음 단계 구매·공유 지갑·공격력/공속 효과를 연결한 코드 경로가 있습니다.** 따라서 ‘18종 모두 구매 불가’라고 단정하지 않습니다. **구매 성공은 항목별 해금·현재 단계·비용·실제 모델 결과**를 읽어 표시합니다. 원본 네이티브 완료/취소 및 Unity·APK 동등성은 **아직 검증 대상**입니다. 세부 근거는 [연구소·강화소 명세](연구소-강화소-구현명세.md)입니다.
- **연구소 4종**의 원본 이름·가격·효과는 수집되어 있지만 실제 연구 **결제·시작/완료·취소·오라 적용은 아직 미연결**입니다. 화면은 열람 가능 상태와 실행 불가 이유를 명시합니다. 연구소를 ‘강화소처럼 즉시 한 단계 구매’로 만들지 않습니다.
- **미션·보상·탐색**은 실제 게임 사건의 결과만 반영합니다. 표시용 버튼·애니메이션을 결과 지급으로 간주하지 않습니다.

## 7. UI가 완성됐다고 말하려면

다음은 **디자인 수용 기준**입니다. 체크 여부와 실기 결과를 이 문서에 누적하지 않고 [현재 상태](START_HERE.md)와 [개발 작업표 Q01·Q03·Q05](PLAYABLE_ROADMAP.md)에서 관리합니다.

1. 가로 화면에서 **왼쪽 메뉴·상단 장부·메인/스토리 전장·오른쪽 패널**을 동시에 읽을 수 있고 중요한 버튼·카드가 잘리지 않습니다.
2. 일반/보스·유닛 사진·HP·요새가 배경보다 잘 보이며, 사진 미제공/리소스 로드 실패에도 텍스트·선택·전투가 유지됩니다.
3. 화면의 보유량·현재 단계·부족분·결과는 **실제 서비스 상태와 일치**합니다. 금액 부족·최대 단계·해금 전·0개·대기 중에도 잘못된 활성 상태가 나타나지 않습니다.
4. **탭 1회는 행동 최대 1회**, 긴 누름은 설명만, 스크롤/드래그는 결제/소환/도박 0회입니다. 연타·중복 요청·화면 전환에도 원본 거래 1회 규칙을 유지합니다.
5. 조합의 필터·페이지·재료 가로줄·확정 버튼이 작은 가로 화면에서도 보이며 원본 재료/돈/나무/특수 조건을 빠짐없이 확인할 수 있습니다.
6. 전장 편대·초상화·바닥·이펙트 변경 후에도 **실제 좌표·경로·대상 자격·타격·HP·파견**이 변하지 않습니다.
7. **코드 연결 ≠ Unity 실행 ≠ APK 설치/플레이 ≠ 원작 일치**를 분리해 보고합니다. 모바일에서 검증하기 전에는 ‘완료’라고 표시하지 않습니다.
