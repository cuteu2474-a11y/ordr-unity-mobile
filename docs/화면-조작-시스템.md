# 화면·조작 시스템 — 모바일 UI 구현 기준

**작은 가로 화면 조작:** 왼쪽 메뉴는 위아래로, 전장 사이 스킬 줄은 좌우로 드래그합니다. 드래그를 마칠 때 메뉴 선택이나 스킬 발동을 실행하지 않습니다. 자원 칸이 좁으면 이름 아래에 실제 숫자를 표시하며 수량을 이미지나 약식 값으로 대체하지 않습니다. 오른쪽 대기 화면·상단 자원·스킬 줄 위 터치는 전장 유닛 선택으로 전달하지 않습니다.

> **원랜디 S2 2.323[C] · 악몽 + 이세계 · Unity Android 가로 화면.** 이 문서는 **게임 화면을 어떻게 배치하고, 무엇을 누르면 어떤 행동을 해야 하는지**에 대한 최종 설계 기준입니다. 화면에 기능이 보이는 것과 실제 게임에서 완성·검증된 것은 다릅니다.

## 1. 한눈에 보는 게임 화면

| 위치 | 항상 보여줄 것 | 조작과 표시 원칙 |
|---|---|---|
| **상단 상태줄** | 골드·목재·랜덤위습·선택위습·특성포인트, 현재 진행에 필요한 수치 | 보유량을 실제 공유 장부에서 갱신. 필요하면 다른 종류 위습의 보유/자동 지급 상태도 조회 가능하게 제공. 숫자나 가격을 이미지에 고정하지 않음 |
| **왼쪽 메뉴** | 점수판·위습·유닛·조합·스토리·토벌·시설/운영 기능의 직접 버튼 | **시설 탭 없이** 메뉴를 한 번 눌러 오른쪽 내용을 전환. 전투 시작·일시정지·처음으로는 왼쪽 하단 |
| **가운데 위** | 메인 전장, 아군 초상화·적·HP·실제 이동 경로 | 메인 화면에서 가장 큰 영역. 유닛 선택·페이지·스크롤을 제공하되 화면용 배치가 전투 계산을 바꾸지 않음 |
| **가운데 아래** | **작은 스토리 전장**: 대상 요새·HP·파견 유닛·페이지 | 전체 전장 표시 높이의 **약 24%**. 메인과 바닥 그림은 공유하되 전투·파견·클리핑·피격 상태는 분리 |
| **오른쪽 패널** | 선택한 메뉴의 카드·항목·실제 비용·결과·행동 버튼 | **어두운 평면 배경**에 큰 버튼. 커다란 은색 장식 테두리·겹친 패널·소개 배너는 사용하지 않음 |

처음 플레이하는 사람에게는 **왼쪽에서 기능 선택 → 오른쪽에서 정보 확인/행동 → 가운데에서 게임 결과 확인**이라는 흐름이 바로 보여야 합니다.

### 화면에 공통으로 적용할 디자인

1. **게임다운 버튼, 큰 글씨, 뚜렷한 대비:** 작은 흰색 안내글을 빽빽하게 쌓지 않습니다. 유닛 이름·현재 수량·비용·남은 횟수·가능/불가 이유가 먼저 보이게 합니다.
2. **한 화면에 한 가지 주요 행동:** 상세 카드의 핵심 실행 버튼 위치를 일정하게 유지합니다. 긴 목록만 스크롤하고 화면 전체가 불필요하게 이동하지 않도록 합니다.
3. **장식보다 정보:** `Selected Unit`, `Current Battle`, ‘보유유닛’ 같은 반복 머리말, 점수판 타이틀·시설 광고·‘재료가 준비되었습니다’ 같은 중복 문구는 제거합니다.
4. **실제 수량을 이미지와 분리:** ‘남은 수량’은 공용 **작은 수량 버튼 바탕**에 실시간 숫자를 얹습니다. 5개/0개는 예시일 뿐 고정 이미지가 아닙니다. 상태별 색·밝기를 바꾸되 0개도 읽혀야 합니다.
5. **터치 면적과 스크롤 분리:** 항목을 스크롤하다가 도박·위습·구매가 실행되면 안 됩니다. 접기/펼치기용 수량 면도 부모 행 **한 번의 동작**만 실행하고 추가 소환/결제를 만들지 않습니다.
6. **모바일 화면에 맞춘 반응형 배치:** 좁은 가로 화면에서는 유닛 크기·페이지당 항목 수·카드 너비를 조절하고, 긴 조합 재료줄은 **그 줄만 가로 스크롤**합니다. 버튼·닫기·페이지 조작이 잘리지 않아야 합니다.

**메뉴 구성의 예외:** 별도의 ‘시설’ 탭이나 상시 ‘도박소 2’ 버튼은 만들지 않습니다. 조건에 따라 나타나거나 교체되는 시설은 원본 이벤트·자격을 따릅니다.

### 시작 화면과 전투 제어

- 시작 지급은 **원본대로 랜덤위습 5개·골드 60·진화체 1기**입니다. UI에서 임의로 랜덤위습 1개를 표시/지급하지 않습니다. 시작 코드와 실제 APK 실행 결과는 별도로 구분합니다.
- 플레이 중 **시작·일시정지·재개·처음으로**는 왼쪽 하단에 둡니다. **처음으로**는 실수로 세션을 잃지 않도록 두 번 확인합니다.
- 스크롤/드래그는 메뉴 선택 또는 소모 행동으로 간주하지 않습니다. 백그라운드·일시정지 중 시간·쿨타임·시전/예약 효과는 게임 엔진의 상태를 그대로 반영합니다.

## 3. 유닛·조합은 이렇게 구성합니다

### 유닛 목록과 전장 초상화

- 오른쪽에는 **보유 개체 목록 → 한 개체의 상세 정보/행동** 순서로 보입니다. 등급·이름·성장·사용 가능한 행동이 우선이며 도감 검색/이름 검색/불필요한 탭을 추가하지 않습니다.
- 메인 전장 초상화는 넓은 화면에서 **약 160px**을 목표로 합니다(기존 약 40px 표시 확대 방향). 작은 화면은 크기를 무리하게 고정하지 않고 페이지당 개체 수를 줄입니다.
- 유닛을 **정사각형 편대**로 정리하고 페이지를 넘기는 것은 **표시 방식**입니다. 실제 유닛 좌표·공격 대상·사거리·스토리 파견 자격을 변경하지 않습니다. 유닛 대신 색 원형 점으로만 표시하지 않습니다.
- **진화체는 유닛 메뉴**에서 보여줍니다. 원본 조건 충족 시 획득/해방은 자동이며 별도 ‘진화체 사용’ 버튼이나 보상 팝업을 만들지 않습니다.
- 개체 판매·소모·분해 전에 **어느 실물 한 기를 처리하는지** 명확히 하고, 취소/실패 시 원래 개체·지갑·상태가 보존되게 합니다.

### 조합 오른쪽 패널

| 영역 | 표시/동작 |
|---|---|
| **목록 상단** | **전체 / 가능 / 임박 / ★ 저장**과 등급·보유 재료 필터. **이름 검색창 없음** |
| **결과 목록** | 결과 초상화·이름·등급·제작 상태. 한 페이지 **8개**로 이동 |
| **결과 상세** | 원본 유닛 재료·필요 수량·**골드·목재·부가 조건을 같은 가로 줄**에 표시. 긴 경우 **재료줄만 좌우 스크롤** |
| **보유/부족** | 있는 재료와 부족 재료를 구분. **‘재료 보유’ 필터는 전체 조합 허가와 다름**(돈·아이템·라운드·횟수 등 추가 조건 존재) |
| **패널 하단** | 고정 **‘조합 확정’** 버튼. **확정 한 번 = 원본 거래 1건**, 1회/3회 선택 없음 |

재료는 파견·비파견을 분리해 표시하지 않고 **모든 보유 개체를 합쳐 `보유 N`**으로 표시합니다. 제작 준비/소비 대상은 원본 거래가 허용하는 실제 개체만 포함하며, 복귀가 필요하면 **`유닛 복귀` 버튼을 명시적으로 눌러 한 기씩** 복귀시킬 수 있습니다. 조합 자동 실행은 하지 않습니다. 이미 소비된 개체는 제외하고 **확정 순간** 재료/재화/자격을 다시 검사합니다. 원본의 **한 거래가 여러 결과 개체를 지급**하는 경우 그 결과 수량은 바꾸지 않습니다. 원본 JASS 등록식의 별도 열람 페이지는 **10개씩** 넘길 수 있지만, 등록식 266건을 모두 제작 버튼으로 표시하면 안 됩니다.

### 수동 분해의 화면 동작

| 유닛 | 누르는 버튼 | 완료 조건과 결과 |
|---|---|---|
| **갱 뱃지** | 분해 시작 | **5초 시전**, 안흔함 후쿠로·흔함 버기·흔함 해군 총병 각 1기 |
| **버기 마기탄** | 분해 시작 | **2초 시전**, 흔함 버기 2기 또는 3기(각 50%) |

시작 즉시 결과를 주거나 자동 분해하지 않습니다. **시전 중 취소·이동·파견·일시정지 시간 동결**과 완료 시점의 본체 소비·결과 생성 실패 복원을 유지합니다. 예외는 [특별함·특수함 운용](특별함-특수함-운용정책.md)을 따릅니다.

## 4. 한 번 누르기·길게 누르기·확인 기준

| 상황 | 정확한 규칙 |
|---|---|
| **랜덤위습 3가지** | 흔함 유닛 소환 / 골드·목재 추첨 / 도움소 마나 충전. 각 항목 **한 번 탭으로 한 번 실행**, 추가 확인 팝업 없음 |
| **안흔함·특별·희귀·전설위습** | 원본 지급 시 **자동 추첨/생성**. 실패나 보류 상태·결과를 화면에 보여주고 중복 재추첨 금지 |
| **선택위습** | **조합 메뉴**에서만 대상·조건을 선택하고 사용. 위습 탭에 중복 기능 없음 |
| **도박** | **짧은 탭은 1회 바로 실행**, **약 0.55초 길게 누르면 조건·비용·확률 설명만** 표시. 길게 누르거나 스크롤해도 비용 차감 없음 |
| **강화소** | 짧은 탭은 **다음 단계 1건 구매 요청**. 성공 여부는 원본 모델·공유 지갑·해금/최대/효과 처리 결과를 반영. 길게 누르면 효과/비용 설명 |
| **조합·상점** | 미리보기/재료 선택은 결제 아님. 각각 **사용자 최종 확정** 후 실제 한 거래만 요청 |
| **판매·분해·영구 소비** | 대상 실물과 결과를 확인. 단, 이미 **명시적 소모 버튼 자체가 합의된 확정**인 유닛 기술은 불필요한 2차 팝업 추가 금지 |
| **스토리 건물·크립** | **파견·복귀 수동**, 목적지·실제 개체·불가 사유 표시. 화면 전환은 파견/복귀·전투 초기화를 실행하지 않음 |
| **토벌** | 원본 조건 확인 뒤 수동 도전/소환은 한 탭에 한 요청. 중복 시작/소환·재결제·격파 보상 중복 방지 |
| **항법 선택·초기화** | 되돌리기 어렵다면 확인 절차 유지. 카지노/리스크헷지 등은 길게 눌러 특성 설명 가능 |
| **샌즈 체력본충(Q)** | 유닛 카드에서 **브룩 안흔함(+2) / 희귀(+12) 1기 소비**를 직접 누르는 것이 확정. 추가 팝업 없음. 뼈 30개 강화 자동 반영, 원본 미확인 쿨타임/반복 조건은 임의 창작 금지 |
| **전투** | 일반 공격·확률 스킬·허용 Q/W/R 자동. UI 버튼/초상화가 별도 난수·공격·피해 사건을 발생시키면 안 됨 |

**모든 경제·소환·조합·강화 행동은 기존 서비스에 단 한 번 요청**합니다. 두 번 빠르게 누르거나 화면을 전환·재시도해도 거래 중복, 재화 임의 차감, 무료 지급이 생겨서는 안 됩니다. 실행 불가 상태에는 **부족 수량·해금 조건·남은 시간·보류 사유** 중 실제 원인을 표시합니다.

## 5. 점수판·스토리·시설 정보 표시

### 점수판: 기록만, 임의 점수 계산 없음

| 탭 | 보여줄 정보 | 표시하지 않을 것 |
|---|---|---|
| **개인 기록** | **라운드·남은 시간·남은 적** 큰 카드 3개 + 처치·전투 유닛·보물·돈 도박·항법 간결한 행 | 중복 점수판 제목·설명·게임 제어 섹션 |
| **흔함 획득** | 누적 흔함 수량과 각 종류 획득 횟수 | 별도 도감/유닛 검색 |
| **유틸보드** | 원본 기준의 **감소 수치 4개** | 임의 득점·감점 로그나 완성되지 않은 합산 해석 |

원작 채팅형 기록의 **빠른 가독성**을 살리고, 별도 클리어 점수 공식·스토리 MVP/기여도 순위판을 만들지 않습니다.

### 크립 파견·토벌의 확정 화면 흐름

**크립 사냥은 스토리 안에 배치**합니다. ‘건물 공략 / 크립 사냥’은 같은 메뉴의 내용 전환이며 크립 전용 왼쪽 메뉴·시설 탭을 만들지 않습니다. 대상 → 실제 보유 개체 → 파견 → 실제 전투 → 복귀 흐름과 불가 사유, 크립 목적지별 전장 분리, 기존 카드·버튼 재사용은 [토벌·크립 파견 명세](토벌-크립-파견-시스템.md)를 따릅니다. 개인미션 3칸은 미션, 별도 처치형 퀘스트는 토벌에서 관리합니다. 이 UI 정책의 구현/실기 상태는 [현재 상태](START_HERE.md)에서 구분합니다.

### 스토리·시설의 상태와 결과

- **스토리 건물**은 실제 HP·현재 단계·해금/파견 상태를 표시합니다. **실제 공격·피격 사건이 없는데** 요새가 피해를 입거나 건물이 격파된 것처럼 연출하면 안 됩니다.
- **강화소 18종**은 **독립 전투 모델에 다음 단계 구매·공유 지갑·공격력/공속 효과를 연결한 코드 경로가 있습니다.** 따라서 ‘18종 모두 구매 불가’라고 단정하지 않습니다. **구매 성공은 항목별 해금·현재 단계·비용·실제 모델 결과**를 읽어 표시합니다. 원본 네이티브 완료/취소 및 Unity·APK 동등성은 **아직 검증 대상**입니다. 세부 근거는 [연구소·강화소 명세](연구소-강화소-구현명세.md)입니다.
- **연구소 4종**의 원본 이름·가격·효과는 수집되어 있지만 실제 연구 **결제·시작/완료·취소·오라 적용은 아직 미연결**입니다. 화면은 열람 가능 상태와 실행 불가 이유를 명시합니다. 연구소를 ‘강화소처럼 즉시 한 단계 구매’로 만들지 않습니다.
- **미션·보상·탐색**은 실제 게임 사건의 결과만 반영합니다. 표시용 버튼·애니메이션을 결과 지급으로 간주하지 않습니다.

## 7. UI가 완성됐다고 말하려면

다음은 **디자인 수용 기준**입니다. 체크 여부와 실기 결과를 이 문서에 누적하지 않고 [현재 상태](START_HERE.md)와 [개발 작업표 Q01·Q03·Q05](PLAYABLE_ROADMAP.md)에서 관리합니다.

1. 가로 화면에서 **왼쪽 메뉴·상단 장부·메인/스토리 전장·오른쪽 패널**을 동시에 읽을 수 있고 중요한 버튼·카드가 잘리지 않습니다.
2. 일반/보스·유닛 사진·HP·요새가 배경보다 잘 보이며, 사진 미제공/리소스 로드 실패에도 텍스트·선택·전투가 유지됩니다.
3. 화면의 보유량·현재 단계·부족분·결과는 **실제 서비스 상태와 일치**합니다. 금액 부족·최대 단계·해금 전·0개·대기 중에도 잘못된 활성 상태가 나타나지 않습니다.
4. **탭 1회는 행동 최대 1회**, 긴 누름은 설명만, 스크롤/드래그는 결제/소환/도박 0회입니다. 연타·중복 요청·화면 전환에도 원본 거래 1회 규칙을 유지합니다.
5. 조합의 필터·페이지·재료 가로줄·확정 버튼이 작은 가로 화면에서도 보이며 원본 재료/돈/나무/특수 조건을 빠짐없이 확인할 수 있습니다.
6. 전장 편대·초상화·바닥·이펙트 변경 후에도 **실제 좌표·경로·대상 자격·타격·HP·파견**이 변하지 않습니다.
7. **코드 연결 ≠ Unity 실행 ≠ APK 설치/플레이 ≠ 원작 일치**를 분리해 보고합니다. 모바일에서 검증하기 전에는 ‘완료’라고 표시하지 않습니다.
