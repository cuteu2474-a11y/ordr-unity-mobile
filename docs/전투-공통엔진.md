# 전투·스킬 공통 엔진

> **2026-11-14 스토리 제프 공격 누락 근본 원인/수정(정적 검사, Unity/실기 미검증):** `BeginUnitPreparation`가 스토리 건물은 생성하지만 `sourceModelDamage.Enable()` 및 `BindExistingVerifiedAttacks()`를 65R 시작까지 미뤘고, `OrdrCharacterCombatController.Update`는 `IsUnitPreparation`이면 `Combat.Step` 전에 종료했습니다. 원본 R-32 제프(h02G)는 사거리 525의 정상 공격 유닛이며 스토리 좌표에서 건물 공격이 가능해야 합니다. 이제 스토리 준비 단계에서 **기존 동일 원본 모델/공격자원 엔진을 한 번만** 활성화하고 스토리 전투 시간을 진행합니다. 이후 65R 시작은 같은 엔진을 재설정하지 않으며, 몬스터 웨이브 자동 시작·보상은 준비 중 금지합니다. 기존 레인별 유한 메인 사거리와 보스 왕복은 유지하며, 별도 `R-32`→1단계 스토리 건물 공격 회귀 검사를 추가했습니다.

> **실제 모바일 65R과 모델 검사 격리:** Unity 플레이 `OrdrCharacterCombatController.BeginStandaloneBattle`은 `SourceModelPracticeBattle(..., mobileMainLane: true)`로 시작합니다. 기존 10/20/65R 독립 모델 검사 생성자는 기본 `false`이며 기존 좌표·동선을 보존합니다. APK 설정에서만 `SourceModelMainLaneGeometry`가 배치/보스 동선을 켜고 `CombatAttackPipeline`은 메인 레인 유한 사거리를 적용합니다. 공격력·주기·원본 범위 수치를 변경하지 않습니다. 첫 시도의 Unity EditMode 실패 86건은 이 모드 경계 누락 및 전장 리소스 검사 기대값 변경에서 발견됐으며 수정 후 결과는 아직 검증되지 않았습니다.

> **역할:** 원본 전투 데이터를 **기술 등록 → 발동 판단 → 유효 대상 → 피해 계산 → 상태·처치·사건**으로 연결하는 코드 지도입니다. 개별 캐릭터 완성률과 실제 APK 실행 상태는 [현재 상태](START_HERE.md), 남은 C 작업은 [개발 작업](PLAYABLE_ROADMAP.md)을 우선합니다.

**블루노·후쿠로 람각의 공통 파동:** 원본 `Bnm/Bnp`는 공격자 위치에 공격자 방향의 `e0KD`를 만들고 동일 좌표를 `carrionswarm` 점시전 대상으로 지정합니다. 원본 SLK `A0VS`의 `Rng=1700`은 시전 거리이고 `DataC=800`이 파동 이동 거리입니다. `Area=200`에서 `DataD=250`으로 반폭이 확대되고 `DataA=150` 마법 피해를 가집니다. 모바일 코드에서는 공격 선언 순간 시전자 방향을 고정한 후 캐스터 기점 이동 거리 800·반폭 선형 확대를 적용했습니다. 원본 동일점 시전의 엔진 방향 처리·실제 이동 타이밍·피격 충돌 크기·면역 판정은 별도 확인 대상이며 가상 임시 주문을 보유 유닛으로 생성하지 않습니다.

## 1. 실제 전투는 어떻게 흘러가나요?

| 단계 | 코드 책임 | 확인할 핵심 |
|---|---|---|
| 유닛·스킬 명세 | `CombatDataSchema.cs`, 원본 유닛·스킬 카탈로그 | 유닛 `rawcode`, 능력/출처, 피해 계열, 확률, 쿨타임, 범위, 효과를 분리 저장 |
| 공격·발동 | `CombatAttackPipeline.cs`, `CombatScheduler`, `CombatSkillTriggerEngine.cs` | 선언/실제 적중 구분, 유닛 개체별 쿨타임·주기, 같은 사건의 중복 추첨 방지, 원본 RNG 계약 |

| 상태·지속효과 | `CombatStatusEngine.cs`, 원본 오라·네이티브 효과 실행 경로 | 원본 출처/지속/중첩/대상 판정, 변신·판매·사망·세션 변경에 따른 상태 정리 |

이 표는 **존재하는 코드와 책임**의 요약이지 모든 유닛의 원본 피해가 실제로 승인·검증되었다는 표가 아닙니다. 도감 기반 모델, JASS 콜백, 워크래프트 네이티브 패시브가 **같은 타격을 중복 실행하지 않도록** 기존 경로를 재사용합니다.

`CombatTargetRules`와 `CombatEnemyPathDriver`는 전장별 적격 대상 및 이동 경로를 나눕니다. 전투 시간축은 긴 프레임의 여러 평타·주기형 타격을 순서대로 처리하고, 지연 타격은 대상 퇴장·사망 시 정리하며 실행 시 원본 조건을 다시 봐야 합니다. 데이터·인터페이스만으로 크립/해왕류/도전 전투의 출전 자격이나 특수 소환 효과까지 자동 완성되지는 않습니다.

## 2. 스킬 데이터를 구분하는 규칙

- `DamageSchool`은 **Physical / Magical / ScriptDefined**, `DamageTraits.Explosive`는 별도 속성입니다. **폭발형=마법**으로 합치지 않습니다.
- `SkillTriggerKind`는 **OnAttack / OnHit / Periodic / VerifiedCondition / PassiveAura**입니다. 공격 선언 때와 실제 양수 피해가 확정된 뒤의 사건을 구분해야 합니다.
- `SkillTargetArea`는 **Single / CircleAroundTarget / EntireEligibleZone**이고, 효과에는 피해·방깎·마방깎·암브·이감·기절·공속/공격력 버프·마법/폭발/전체 증폭·체력 재생 등이 있습니다.
- `CombatSkillSpec`은 **백만분율 확률(0~1,000,000)**, 쿨타임, 주기, 반경, 효과 목록과 근거를 보관합니다. `SkillEffectSpec.Magnitude`는 **원본 명시 단위 그대로** 저장합니다. 임의의 퍼센트/중첩 공식으로 바꾸지 않습니다.
- 같은 원본 유닛을 여러 기 보유해도 **개체별 발동·쿨타임**이 별개입니다. 같은 타격 사건의 중복 RNG 호출을 피하며, 주기형의 다음 시각을 관리합니다. 다만 현재 난수 공급자가 **워크래프트 III와 동일한 호출 순서**임은 별도 검증 대상입니다.

## 3. 원본 피해 계산의 경계

원본 JASS에는 공통 스크립트 피해 함수 `Bcb → UnitDamageTarget`와 **`ATTACK_TYPE_CHAOS` / `DAMAGE_TYPE_UNIVERSAL`**, **`ATTACK_TYPE_NORMAL` / `DAMAGE_TYPE_UNIVERSAL`** 같은 조합이 존재합니다. 이 타입들을 단순히 물리·마법·고정 피해 한 종류와 동일시하지 않습니다.

`Ordr323OriginalDamageRules`는 실제 근거가 있는 타격 정보, 공격별 방어 관여 규칙, 상태 수정자와 최종 정수화 공급자를 분리합니다. 원본 규칙이 확인되지 않은 타격에 **임의의 안전한 계산식**을 끼워 넣어 '실전 원본 동등'으로 표시하면 안 됩니다. 더 구체적인 계산 자료는 [원본 피해·방어·마법 저항](원본-피해-방어-마법저항-근거.md)에서 확인합니다.

### 메인 전장 거리와 동선 확정 설계

**2026-11-14 후속 구현 요청 반영: 독립 65R 전투 모델의 핵심 코드 연결, Unity/Android 실행 검증 대기.** 메인 전장의 거리·동선은 아래 설계를 따릅니다. 이 절은 구현 완료나 원작 동등성 검증 결과가 아닙니다.

| 항목 | 확정 방향 |
|---|---|
| 아군 배치·조작 | 사각 전장의 왼쪽 면에 고정 배치. 개별 이동·추적 또는 진형 전체 이동을 필수 조작으로 만들지 않음. |
| 일반 적 | 기존 전장 순환 경로를 유지. 왼쪽 공격 구간을 지나 멀어지면 각 유닛의 사거리에서 벗어날 수 있음. |
| 기본 공격 | 실제 유닛 좌표와 적 좌표 사이의 거리 및 원작 유닛 사거리로 공격 가능 여부 판정. 대상 탐색과 실제 공격 가능 판정을 분리. |
| 이감·범위 공격 | 이감은 실제 이동속도에 적용하고 면역·저항·중첩 규칙 유지. 공격 범위 내 체류 시간과 적 밀집이 실제 공격 기회·범위 피격에 반영되어야 함. |
| 메인 라운드 보스 | 유닛 배치면인 왼쪽 면을 위아래로 왕복. 원작에서 보스를 따라 조작한다는 사용자 가정을 모바일 동선으로 대체하는 명시적 예외. 모든 유닛의 상시 공격을 보장하지 않음. |
| 왕복 경계 | 끝점에서 추가 정지 시간 없이 방향 전환. 기존 개체·HP·상태·제한시간 유지. 끝점 도달로 탈출/처치/보상/재소환을 발생시키지 않음. |
| 보스 진행 | 원작 등장 시점·수량·제한시간·시간초과·격파 보상·점수 규칙 유지. 왕복 횟수를 제한시간이나 승패 기준으로 사용하지 않음. |
| 스킬·오라 | 기본 공격 사거리, 스킬 시전 거리, 효과 반경/형태/대상 수, 오라 범위를 각각 구분. 원본 근거와 기존 사용자 확정 예외를 유지하고 각 기술의 원본 판정 유지. |

**결정 이유:** 유한 사거리는 이감으로 공격 구간 체류 시간을 늘리는 가치와 근거리/원거리의 차이를 보존합니다. 고정 배치와 보스 왕복은 휴대폰에서 유닛마다 이동시키는 부담을 줄입니다. 보스가 주력 딜러와 먼 곳에서 느려지면 접근이 늦어질 수도 있으므로 이감에 임의의 피해 보너스를 추가하지 않습니다.

**범위와 수치 경계:** 이 합의는 메인 전장 일반 적·라운드 보스에 한정합니다. 스토리 건물·크립 파견·토벌·공유 목표를 자동으로 같은 동선/사거리 정책에 편입하지 않습니다. 공격력·공격 주기·확률·쿨타임·HP·보상·이감 수치 자체는 변경하지 않습니다. 화면 픽셀과 전투 좌표를 분리하고 사거리·경로·이동속도에 일관된 거리 단위를 사용합니다.

**추후 결정·검증:** 왼쪽 배치의 세부 슬롯/유닛 간격, 일반 경로와 배치면 사이 간격, 보스 왕복 시작점·끝점·길이는 아직 수치 확정 전입니다. 근거리 유닛도 공격 기회가 있고 모든 유닛이 전장을 상시 덮지 않는지 확인해야 합니다. 보스 경로와 일반 적이 겹칠 때의 범위기 동시 피격, 이감 유무와 위치별 공격 가능 시간·공격 횟수·처치 시간·시간초과를 함께 검증합니다. 원작에서 컨트롤한다는 가정만으로 난이도 동등성을 보장하지 않습니다. 차이가 나면 경로·배치·거리 단위부터 검토하며 원작 전투 수치를 임의로 보정하지 않습니다.

**실제 코드 연결:** `SourceModelMainLaneGeometry`가 기존 4개 경로 중심에서 왼쪽 배치 3열×12행과 보스 상·하 왕복을 도출합니다. `SourceModelPracticeBattle`은 일반 순환·보스 왕복을 구분하며 기존 이감·기절·HP·타이머를 유지합니다. `CombatAttackPipeline`은 **독립 모델 메인 전장에만** 원본 `OriginalMapBasicAttack.OriginalRange`를 적용하고 다른 전장의 거리 처리는 별도 코드 대조가 필요합니다. 크립 후속 설계는 원작 공격 자격 확인 후 공격 가능한 위치에 자동 배치하는 방식입니다. `CombatAuraSystem`의 등록된 **양수 반경** 적 오라는 메인 전장에서 거리 판정합니다. 수치 누락은 미확정으로 남깁니다. 스킬 별도의 시전 거리·독립 자동 스킬·다른 오라 처리 경로, 진형 화면 표시 일치와 실물 APK 검증은 남아 있습니다.

**기존 코드와의 구분:** 메인 전장 평타의 원본 거리 공급자와 별도로 다른 전장·스킬·오라의 거리 판정 경로를 조사해야 합니다. 첫 대상 선택·직선 연장·거리 0/누락 처리도 검토 대상입니다. 현재 연결 코드가 후속 확정 설계와 모두 일치한다고 간주하지 않으며, 원본 수치가 없으면 근거를 확인하고 임의 사거리를 창작하지 않습니다.

## 4. 실제 수정 작업에서 지킬 원칙

1. **출처 확인:** 원본 W3X/JASS·SLK의 `rawcode`와 대상/확률/시간/비용/피해 단위를 먼저 식별합니다. 원본 스크립트의 맵 전용 난수, 네이티브 공격·발동의 선후도 구분합니다.
2. **공통 경로 우선:** 개별 기술마다 새 HP 계산·오라 중첩·영수증을 만들지 않습니다. 원본 효과를 현재 공통 발동/피해/상태/거래 경로에 연결합니다.
3. **실제 사건 기준:** 공격 선언만으로 명중 횟수를 올리지 않고, 조합·판매·변신·사망 뒤 남은 예약 스킬·버프·소환수 소유자를 확인합니다.
4. **검증 분리:** 원본 자료 추출, 코드 등록, 전투 실행, Unity 검사, 휴대폰 실기는 각기 다른 상태입니다. 현재 미완성 경로는 [C01~C04 및 Q 작업](PLAYABLE_ROADMAP.md)에서 확인하고 사용자 요청 전에는 검사를 실행하지 않습니다.
