# 전투·스킬 공통 엔진

> **역할:** 원본 전투 데이터를 **기술 등록 → 발동 판단 → 유효 대상 → 피해 계산 → 상태·처치·사건**으로 연결하는 코드 지도입니다. 개별 캐릭터 완성률과 실제 APK 실행 상태는 [현재 상태](START_HERE.md), 남은 C 작업은 [개발 작업](PLAYABLE_ROADMAP.md)을 우선합니다.

## 1. 실제 전투는 어떻게 흘러가나요?

| 단계 | 코드 책임 | 확인할 핵심 |
|---|---|---|
| 유닛·스킬 명세 | `CombatDataSchema.cs`, 원본 유닛·스킬 카탈로그 | 유닛 `rawcode`, 능력/출처, 피해 계열, 확률, 쿨타임, 범위, 효과를 분리 저장 |
| 공격·발동 | `CombatAttackPipeline.cs`, `CombatScheduler`, `CombatSkillTriggerEngine.cs` | 선언/실제 적중 구분, 유닛 개체별 쿨타임·주기, 같은 사건의 중복 추첨 방지, 원본 RNG 계약 |
| 최종 피해 | `IOriginalDamageResolver`, `Ordr323OriginalDamageRules.cs`, `Ordr323DamageWorldBinding`, `Ordr323MapDamageMath` | 적 방어·마방·면역·방깎·증폭·원본 주사위·최종 HP 정수화. 표시 공격력 ≠ 실제 최종 피해 |
| 상태·지속효과 | `CombatStatusEngine.cs`, 원본 오라·네이티브 효과 실행 경로 | 원본 출처/지속/중첩/대상 판정, 변신·판매·사망·세션 변경에 따른 상태 정리 |
| 지연 타격·오라·사용형 기술 | `CombatTimedEffectQueue.cs`, `CombatAuraSystem.cs`, `CharacterActiveAbilities.cs` | 다단 타격의 예약/취소·실행 시 재계산, 아군 상태 갱신, 원본 마나·체력·쿨타임을 갖춘 사용형 스킬 |
| 웨이브·결과 | `CharacterCombatRuntime.cs`, `SourceModelPracticeBattle.cs`, `CombatWaveDirector.cs` | 실물 적·영웅 대상의 HP 반영, 사망·보상·웨이브 사건, 중복 호출 방지 |

이 표는 **존재하는 코드와 책임**의 요약이지 모든 유닛의 원본 피해가 실제로 승인·검증되었다는 표가 아닙니다. 도감 기반 모델, JASS 콜백, 워크래프트 네이티브 패시브가 **같은 타격을 중복 실행하지 않도록** 기존 경로를 재사용합니다.

`CombatTargetRules`와 `CombatEnemyPathDriver`는 전장별 적격 대상 및 이동 경로를 나눕니다. 전투 시간축은 긴 프레임의 여러 평타·주기형 타격을 순서대로 처리하고, 지연 타격은 대상 퇴장·사망 시 정리하며 실행 시 원본 조건을 다시 봐야 합니다. 데이터·인터페이스만으로 크립/해왕류/도전 전투의 출전 자격이나 특수 소환 효과까지 자동 완성되지는 않습니다.

## 2. 스킬 데이터를 구분하는 규칙

- `DamageSchool`은 **Physical / Magical / ScriptDefined**, `DamageTraits.Explosive`는 별도 속성입니다. **폭발형=마법**으로 합치지 않습니다.
- `SkillTriggerKind`는 **OnAttack / OnHit / Periodic / VerifiedCondition / PassiveAura**입니다. 공격 선언 때와 실제 양수 피해가 확정된 뒤의 사건을 구분해야 합니다.
- `SkillTargetArea`는 **Single / CircleAroundTarget / EntireEligibleZone**이고, 효과에는 피해·방깎·마방깎·암브·이감·기절·공속/공격력 버프·마법/폭발/전체 증폭·체력 재생 등이 있습니다.
- `CombatSkillSpec`은 **백만분율 확률(0~1,000,000)**, 쿨타임, 주기, 반경, 효과 목록과 근거를 보관합니다. `SkillEffectSpec.Magnitude`는 **원본 명시 단위 그대로** 저장합니다. 임의의 퍼센트/중첩 공식으로 바꾸지 않습니다.
- 같은 원본 유닛을 여러 기 보유해도 **개체별 발동·쿨타임**이 별개입니다. 같은 타격 사건의 중복 RNG 호출을 피하며, 주기형의 다음 시각을 관리합니다. 다만 현재 난수 공급자가 **워크래프트 III와 동일한 호출 순서**임은 별도 검증 대상입니다.

## 3. 원본 피해 계산의 경계

원본 JASS에는 공통 스크립트 피해 함수 `Bcb → UnitDamageTarget`와 **`ATTACK_TYPE_CHAOS` / `DAMAGE_TYPE_UNIVERSAL`**, **`ATTACK_TYPE_NORMAL` / `DAMAGE_TYPE_UNIVERSAL`** 같은 조합이 존재합니다. 이 타입들을 단순히 물리·마법·고정 피해 한 종류와 동일시하지 않습니다.

`Ordr323OriginalDamageRules`는 실제 근거가 있는 타격 정보, 공격별 방어 관여 규칙, 상태 수정자와 최종 정수화 공급자를 분리합니다. 원본 규칙이 확인되지 않은 타격에 **임의의 안전한 계산식**을 끼워 넣어 '실전 원본 동등'으로 표시하면 안 됩니다. 더 구체적인 계산 자료는 [원본 피해·방어·마법 저항](원본-피해-방어-마법저항-근거.md)에서 확인합니다.

**모바일 전투 거리 정책:** 같은 전장에 속한 유효한 적에게는 **일반 공격·스킬·오라의 도달 거리를 무제한**으로 적용합니다. 다만 **전장 구분·대상 자격·면역·광역 타격의 형태/반경/대상 수**는 유지합니다. 메인 전장과 스토리/도전 전장, 특수 크립·해왕류의 출전 자격을 한 목록으로 섞지 않습니다. 예를 들어 단일 대상을 선택하는 거리는 무제한이어도 해당 스킬이 원본에서 원형 범위 750에만 피해를 주면 타격 반경을 무제한으로 바꾸지 않습니다.

**구현 경계:** 기본 공격의 모바일 경로는 `CharacterCombatRuntime`의 `CombatAttackReachMode.UnlimitedWithinAssignedBattlefield`로 구분하며, 범용 엔진의 `OriginalUnitRange` 기본값과 혼동하지 않습니다. `BasicAttackSpec.range`가 0 또는 누락됐다는 이유로 모바일 유닛의 평타를 막지 않되, 먼저 `CanAttackInThisLane` 등 전장·대상 적격성을 확인해야 합니다. 이 정책 때문에 원본의 피해·발동 확률·쿨타임·광역 지형을 변경하지 않습니다.

## 4. 실제 수정 작업에서 지킬 원칙

1. **출처 확인:** 원본 W3X/JASS·SLK의 `rawcode`와 대상/확률/시간/비용/피해 단위를 먼저 식별합니다. 원본 스크립트의 맵 전용 난수, 네이티브 공격·발동의 선후도 구분합니다.
2. **공통 경로 우선:** 개별 기술마다 새 HP 계산·오라 중첩·영수증을 만들지 않습니다. 원본 효과를 현재 공통 발동/피해/상태/거래 경로에 연결합니다.
3. **실제 사건 기준:** 공격 선언만으로 명중 횟수를 올리지 않고, 조합·판매·변신·사망 뒤 남은 예약 스킬·버프·소환수 소유자를 확인합니다.
4. **검증 분리:** 원본 자료 추출, 코드 등록, 전투 실행, Unity 검사, 휴대폰 실기는 각기 다른 상태입니다. 현재 미완성 경로는 [C01~C04 및 Q 작업](PLAYABLE_ROADMAP.md)에서 확인하고 사용자 요청 전에는 검사를 실행하지 않습니다.

개별 유닛의 원본 능력과 개발용 타격·오라 연결 사례는 [캐릭터 기술·전투 연결](캐릭터-기술-원본과-전투연결.md)에 정리했습니다. 원본 SLK/JASS 표와 현재 코드의 완성 판정은 분리해 읽습니다.
