# APK에서 10라운드 연습 전투 진행

기준 소스: `4af3cfe` 이후 `main`. 정식 원랜디 65라운드 완성본과 별도의 개발용 연습이다.

## APK의 플레이 흐름

1. 첫 화면에서 **유닛 준비하고 시작**을 누르고 위습을 소환한다. 보유 유닛이 생기면 **10R 연습 전투 시작**을 누른다. 준비 중에는 전투 시간이 진행되지 않는다.
2. 위습 메뉴에서 1회·5회·보유분 소환을 직접 확정한다. 시작 재화·진화체는 기존 원본 시작 경로로 한 번 지급한다. 자동 무료 유닛은 만들지 않는다.
3. 흔함·안흔함·특별함의 원본 객체 공격력 주사위·공격 주기로 자동 공격한다. 사거리는 기존 모바일 정책대로 같은 전장 안에서 무제한이다. 안흔함 13종/특별함 31종 조합과 판매는 전투 중에도 사용할 수 있다.
4. 몬스터는 원본 출현 객체·수량·0.5초 간격으로 생성된다. 원본 라인 사각형 중심을 순환하며, 한 바퀴를 돌아도 이탈·사망으로 처리하지 않는다.
5. 실제 처치 때만 원본 CVM 골드 규칙으로 추첨하고 같은 지갑에 지급한다. 2라운드부터는 CVv의 랜덤위습 2개를 한 번씩 지급한다.
6. 일반 라운드는 35초, 10라운드 보스는 60초다. 적 70마리 누적 또는 미처치 보스 제한시간으로 패배한다. 10라운드의 보스와 남은 적을 처치하면 **연습 완료**다. 정식 65라운드 클리어 보상·베리를 지급하지 않는다.
7. 남은 시간·라운드·적 수를 표시하고, 일시정지·앱 전환 중에는 논리 시간을 진행하지 않는다. 끝나면 새 게임으로 다시 시작할 수 있다.

시작 시 한 번 전장 범위를 맞추고, 전투 중에는 수동 드래그·확대/축소·선택 유닛 보기·전장 전체 보기를 사용한다. 유닛 월드 좌표나 공격 판정은 카메라에 의해 바뀌지 않는다.

## 원본 검증과 연습 모델의 구분

- 몬스터 HP·방어는 저장소에 있던 **참조 엔진 기반 악몽 초기 모델**에서 가져온다. 예: 1라운드 알비다 338 HP. 새로운 편의 난이도나 임의의 약한 몬스터 HP를 만들지 않는다.
- 공격력 주사위·기본 공격 주기·첫 공격 지연은 원본 객체 자료를 사용하고, 공격/방어 타입 배율과 방어 계수 0.02는 기존 맵 계산기를 재사용한다.
- 체력이 정수인 공통 엔진에서 소수 피해는 적별 잔여분으로 보존한다. **Warcraft의 실제 부동소수점 처리와 최종 HP 동일성은 미검증**이다.
- 기술·오라·공격속도 연구·동적 전투 보정과 이세계 후속 변형은 완성되지 않았다. 연습에서는 기본 공격만 연결하며, 미완성 스킬을 확정 발동하거나 임의 피해로 대체하지 않는다.
- 이동은 원본 사각형 중심과 객체 기본 이속을 사용하는 모델이다. 네이티브 회전·영역 진입 시점·충돌·이속 보정까지 동일하다는 의미가 아니다.
- 원본 최종 전투 승인 공급자·난수 관측기·HP 정수화 승인 구현체를 만들어 넣지 않는다. `HasSourceVerifiedDamageRuntime`은 false로 유지하고 기존 정식 첫 라운드 시작 검사를 통과시키지 않는다.
- [별도 연습 모델](../data/mobile-practice-battle-model.json)은 정식 검증 웨이브 형식이 아니며 두 검증 플래그를 false로 보존한다. [생성기](../tools/build_mobile_practice_battle_data.py)가 고정 원본 JASS·기존 HP 모델·객체 방어 타입·기본 이속을 대조한다.

## 검사

- 구현 후 로컬 Python 자료 회귀 **140건 통과**.
- 실제 공통 런타임에서 자동 공격→처치→같은 지갑 지급, 순환 이동, 35초 경계의 위습 중복 방지, 70마리 패배, 10라운드 완료, 보스 시간초과, 준비 로스터 유지, 일시정지 및 정식 검증 차단을 검사하는 Unity EditMode 통합 사례 8개를 추가했다.
- Unity 컴파일·통합 테스트 및 새 Android APK는 기존 워크플로에서 수행한다. 실행 시작 확인 후 결과는 별도 요청 전 조회하지 않는다.
- 이 작업에서 모바일 실기 설치·터치·성능 검증은 하지 않았다. 전체 게임 저장·65라운드·모든 스킬·상점·도박·스토리는 남아 있다.
