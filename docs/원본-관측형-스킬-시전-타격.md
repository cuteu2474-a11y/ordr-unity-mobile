# 원본 관측형 스킬 — 시전·충돌·타격·종료

> **개발자용 공통 근거:** 특별함·희귀함 캐릭터의 원본 JASS/네이티브 주문을 **실제 원본 시전 확인 → 시점별 충돌 확인 → 피해·기절 적용 → 종료 처리**로 연결한 경로를 정리했습니다. 코드에 경로가 존재하는 것과 원본 효과가 실제 APK에서 자동 발동하는 것은 다릅니다. 최신 구현 범위는 [현재 상태](START_HERE.md)와 [C 작업](PLAYABLE_ROADMAP.md)에서 판단합니다.

## 1. 왜 스킬을 네 단계로 나눠야 하나요?

| 단계 | 원본에서 확인할 사실 | 모바일 공통 처리 | 완료로 간주하면 안 되는 것 |
|---|---|---|---|
| **발동·시전** | 실제 원본 JASS 분기, 시전자, 능력 ID, 명령 시각 | 고유 시전 ID·실물 소유자·원본 W3X 지문을 검증해 예약 | 능력 보유만 확인하고 자동 피해 적용 |
| **대상 선정·충돌** | 네이티브가 고른 대상과 충돌별 시각·순서·면역 | 충돌별 `SourceEventId`·전장·현재 대상 상태 재확인 | 주변 적을 임의로 추가하거나 선정 수=피해 수로 계산 |
| **HP·기절 적용** | 실제 최종 정수 HP 감소, 기절 근거·지속시간 | `CombatResolution.TryApplySkillDamage` 및 `CombatStatusEngine` 사용 | 원본 능력 설명의 `DataA`를 최종 HP 피해로 직접 적용 |
| **시전 종료** | 원본 더미 소멸·명령 거절·실제 무피해 완료 | 관측된 종료 사유로 예약 정리·중복 사건 차단 | 일정 시간 경과·첫 대상 사망만으로 임의 완료 |

같은 스킬을 기존 **더미 주문 경로**와 **관측형 특별·희귀 스킬 경로**에서 두 번 처리하지 않습니다. 전장·면역·HP·마법저항·원본 버프 적용 단계와 사건 ID가 다르면 겉으로 비슷한 공격이어도 하나로 합치지 않습니다.

## 2. 특별함·희귀함의 공통 관측 타격

[CharacterCombatRuntime.SpecialRareObservedSkills.cs](../Assets/Scripts/Combat/CharacterCombatRuntime.SpecialRareObservedSkills.cs)는 특별함 **33종**, 희귀함 **42종**을 위한 **동일한 관측 사건 처리 통로**입니다. 캐릭터별 자동 기술 75개가 원작 그대로 완성되었다는 뜻이 아닙니다.

1. `OriginalMapBaseStatCatalog`의 **캐릭터 ID ↔ 원본 유닛 rawcode ↔ 실제 능력 ID** 소유 관계를 확인합니다.
2. `IOriginal323SpecialRareImpactWitness`가 **현재 전투 시각에 실제 발생한 타격**과 동일 실물 시전자를 확인해야 합니다. 툴팁이나 능력 객체 보유 사실만으로 10% 같은 확률을 만들지 않습니다.
3. 배치 적용 전에 대상의 생존·진영·전장·면역/저항·타깃 중복·최종 HP 정수값·합계 오버플로 등을 확인합니다. 기절은 원본 근거가 있는 적에게만 적용합니다.
4. 실제 감소/기절은 기존 `CombatResolution`과 `CombatStatusEngine`에 맡깁니다. `SourceEventId`로 **같은 원본 타격의 두 번째 적용을 차단**합니다. 실패한 사건과 무관한 정상 사건은 계속 처리할 수 있습니다.
5. 일부 전투 후크가 사전검사와 실제 적용 사이에 예외를 일으키는 극단 상황은 **전투 전역 스냅샷 롤백이 보장되었다고 말할 수 없습니다.** 이 원자성 경계는 후속 검증 항목입니다.

설정 진입점은 `OrdrCharacterCombatController.ConfigureVerifiedOriginalSpecialRareNativeImpacts(witness)`, 사건 진입점은 `TryApplyObservedOriginal323SpecialRareImpact(sourceEventId)`입니다. 원본 실전 관측 공급자가 연결되지 않은 기본 씬에서는 이 인터페이스를 근거로 자동 피해가 발생하지 않습니다.

## 3. 여러 시각에 타격하는 주문 — 시전과 충돌을 별도 관리

[Original323SpecialRareNativeSequenceWorld.cs](../Assets/Scripts/Combat/Original323SpecialRareNativeSequenceWorld.cs)는 **시전 한 번에 시간차 충돌이 여러 번 발생하는** 능력을 위해 위 공통 타격 경로를 재사용합니다.

- `Original323ObservedSpecialRareNativeCast`는 원본이 관측한 시전 ID·유닛/능력·시각·**원본 충돌 횟수**를 제공합니다. 충돌 횟수를 모바일 임의 기술 주기나 피해 횟수로 정하지 않습니다.
- `TryRegisterCast(sourceCastId)`로 실제 시전을 확인하고, `TryResolveNextImpact(sourceCastId)`를 호출할 때마다 원본이 관측한 순번 **1…N**과 충돌 시각·대상을 별도로 확인합니다. 같은 적이 나중에 다시 맞을 수도 있습니다.
- 사전 타격 확인과 실제 HP 적용에는 **같은 원본 영수증 객체**를 사용해야 합니다. 검증 사이에 타격 대상을 바꿔치기하는 오류와 사건 중복을 차단합니다.
- 충돌 검증이 실패하면 **원본 타격 순번을 소비하지 않습니다.** 실제 시전자와 원본 소유 관계가 사라졌다면 임의 진행하지 않습니다. 시전자 사망 뒤 남은 투사체의 귀속 규칙은 아직 별도 근거가 필요합니다.

| 원본 유닛 예시 | 원본 객체에 등록된 능력 | 당시 시험 목적 |
|---|---|---|
| 에넬(특별함) `h00Q` | `A084` | 동일 대상의 시간차 재타격·서로 다른 적의 개별 HP 감소·중복 사건 거부 |
| 도플라밍고(희귀함) `h01L` | `A057` | 실제 근거가 있는 기절·후속 피해·상태 만료 구분 |

여기서 `A084/A057`은 **객체의 소유 능력 관계**입니다. 이 ID만으로 원본의 모든 피해·기절·발동 확률을 승인하지 않습니다. 과거 테스트에서 사용한 피해 13/17/23, 41/53/37 및 기절 0.4초 같은 숫자는 **TEST_ONLY 가상 영수증**이지 원본 수치가 아닙니다.

### 블루노·후쿠로 람각: 공격 선언과 실제 충돌은 별개

블루노(`U-04/h00M/Bnm`)와 후쿠로(`U-13/h00A/Bnp`)는 원본 `w5` **공격 선언 시점**에 각각 `BFi(1,100) <= 10`을 추첨하고 성공 시 보조 유닛 `e0KD`에 `A0VS/AUcs` 람각 주문을 지시합니다. 원본 능력 필드의 **범위 200·시전 거리 1700**은 최종 HP 감소값이 아닙니다. 람각은 서로 다른 충돌 시점이 있을 수 있으므로 원본 시전 ID·충돌 ID·대상·면역·실제 HP 감소를 구별하고, 시전자 방향(facing)이나 충돌 증거가 없으면 피해를 추정하지 않습니다. 원본 시전 거리와 효과 범위를 구분해 적용합니다.

## 4. 에넬 갈래 번개 — 선정된 대상과 실제 피해 대상은 다릅니다

에넬 **S-18 / `h00Q`**의 별도 JASS 공격 선언 경로는 원본 `Bnr`입니다. 공격 **선언 시점**에 `BFi(1,100) <= 10` 분기가 성공하면 더미 `e0KD`에 `A086/ANfl` 갈래 번개를 원래 공격 대상에게 지시합니다. 위 3절의 소유 능력 `A084`와 **이 더미 주문 `A086`을 혼동해서는 안 됩니다.**

| 원본 능력 항목 | 근거 있는 값 | 실제 전투에서의 의미 |
|---|---|---|
| 공격 선언 분기 | **10%** | 스크립트 분기이며 실제 최종 피해 확률과 동일하다고 단정 불가 |
| 네이티브 `A086/ANfl` | **최대 선정 대상 4명** | 마법 면역으로 HP 피해 0인 적도 **선정된 4명 한도에 포함** |
| 원본 영역·시전 거리 | **125 / 1750** | 원본 객체 필드. 모바일 거리 정책과 별도로 보존 |
| 원시 피해 필드 | `DataA=1500` | 원본 주문 데이터이고 방어·마법저항 이후 최종 HP 감소량은 아님 |

[Original323DeferredNativeDummySpellWorld.cs](../Assets/Scripts/Combat/Original323DeferredNativeDummySpellWorld.cs)는 공격 선언·더미 시전·실제 충돌 관측을 분리합니다. [네이티브 마법피해 확인](../Assets/Scripts/Combat/Original323NativeMagicDamageReconciliation.cs)은 선정된 4명과 피해를 받은 적을 구분하고, 원본 마법저항/면역 및 최종 HP 변환 근거를 요구합니다.

**원본 주문의 종료:** `IOriginal323DummySpellTerminationWitness`가 실제 원본 더미의 소멸, 명령 거절 또는 피해 없는 시전 완료를 `Original323ObservedDummyCastEnd`로 확인해야 보류 시전을 종료할 수 있습니다. 첫 대상의 사망·모바일에서 1초 경과·임의 타이머로 끝내면 안 됩니다.

- **선정됐지만 피해가 0:** 해당 적도 4인 제한에 포함하고, 원본 종료 사유가 확인된 경우에만 무피해 완료를 허용합니다.
- **이미 피해가 발생:** ‘한 번도 피해를 주지 않았다’는 종료 사유는 거절합니다. 이후 원본 더미 소멸이 실제로 확인되면 앞선 피해를 유지한 채 종료할 수 있습니다.
- **종료 뒤:** 같은 시전 ID로 늦게 들어온 타격을 다시 적용하지 않습니다. 종료 확인이 추가 공격·기절·원본 RNG를 발생시키지 않습니다.

Unity 구성은 `ConfigureOriginal323DeferredDummySpellWorld` 또는 `ConfigureOriginal323VerifiedNativeMagicDummyWorld`의 종료 증인 지원 오버로드를 사용합니다. 실제 종료 관측 때 `TryConfirmObservedOriginalDummyCastEnd(sourceCastId)`, 실제 충돌 때 `TryApplyObservedOriginalDummySpellImpact(sourceCastId, out damage)`를 호출합니다. **원본 더미의 실시간 종료 증인·선택 순서·최종 피해 산식은 별도 미완성**입니다.

## 5. 무엇이 실제로 검증됐고, 무엇이 남았나요?

**코드에 있는 연결**
- 특별함·희귀함의 원본 관측 사건 수신·사전 검사·중복 방지·HP/기절 경로.
- 원본 시전별 시간차 충돌 순서와 영수증 동일성 확인 경로.
- 에넬 `e0KD/A086`의 검증된 원본 종료 사건을 받아 정리하는 경로.

**아직 동등성/실기까지 증명되지 않은 것**
- 특별함·희귀함 원본 전체 기술의 실제 JASS 발동·원본 W3A/SLK 효과, 원본 충돌/종료 관측 **공급자의 실전 연결**.
- 네이티브의 다중 대상 선정 순서·면역/저항·최종 피해 정수화·충돌 시각, 시전자 사망 뒤 남은 투사체.
- Unity 최신 EditMode·APK 설치·실제 65R 플레이. 관련 시험 코드 `Original323SpecialRareObservedSkillTests`, `Original323SpecialRareNativeSequenceTests`, `Original323DeferredDummySpellTests`가 존재해도 **최신 통과 결과는 별도로 확인**해야 합니다.

다른 유닛의 공격 선언 원본과 보조 주문 값은 [20명 JASS·네이티브 분석](원본-캐릭터-기술-추출표.md), 실제 피해 계산 경계는 [원본 피해·방어·마법 저항](원본-피해-방어-마법저항-근거.md)을 따릅니다. **원본 공격력·쿨타임·발동 확률·맵 파일은 변경하지 않습니다.**
