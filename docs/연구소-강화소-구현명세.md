# 연구소·강화소 — 실제 플레이 연결 명세

> ORDR S2 2.323[C] · 악몽/이세계 · Unity Android. 강화소 1/2의 18종 구매와 전투 효과를 **독립 전투 모델에 코드 연결**했습니다. 원작 네이티브 완료/취소와 실행 동등성은 미검증입니다. 연구소의 원본 연구 시작 3종 결제/전투 효과를 독립 모델로 연결했고, 기후 변화는 네이티브 이동 공급자가 있을 때만 시작 가능합니다. 수치 원본은 [실측표](원본-연구-강화-실측.md)와 [증거 JSON](../data/original-2323C-player-research-upgrades.json)에 보존합니다.

**2026-11-07 코드 보정(실행 미검증):** 연구소 `Rhgb/Rhra/Rhpt/Rhfc`의 원본 목재 2/1/3/2개 차감을 공통 지갑의 실제 키 `wood`에 맞췄습니다. 이전 `lumber` 키 때문에 연구 시작이 불가능하거나 잘못된 부족 메시지가 나올 수 있던 경로를 수정했고 화면 비용 표시에서도 두 표기를 목재로 묶습니다. 원본 연구 시작 후 완성·취소, 시간/환급/실기 동등성은 여전히 미연결입니다.

## 게임에서 어떻게 보여야 하나요?

- 왼쪽 메뉴에서 **연구소 / 강화소 1 / 강화소 2**를 각각 바로 엽니다. 별도의 시설 탭은 만들지 않습니다.
- 화면에는 **연구·강화 이름, 현재/최대 단계, 다음 비용, 구매 가능 상태**를 큰 카드로 보여줍니다. 쓸데없는 머리말과 설명 문장은 제거합니다.
- 일반 강화는 **짧게 한 번 누르면 다음 단계 하나만 구매**합니다. 상세 효과·선행 조건은 길게 누를 때 보이게 합니다.
- 돈이나 목재가 부족하면 **얼마가 부족한지**, 원본 효과 처리기가 연결되지 않았다면 **왜 구매할 수 없는지** 알려줍니다. 표시용 카드가 재화를 소비하거나 유닛을 강화하는 것처럼 꾸미지 않습니다.
- 연구소는 **연구 시작과 완료가 다를 수 있는 기능**입니다. 4개 연구를 강화소의 즉시 구매 버튼으로 단순 대체하면 안 됩니다.

## 연구소 4개 — 확인된 원본

| 연구 | 실제 골드·목재 | 원본 연구 시작 시 처리 | 모바일 구현 주의점 |
|---|---|---|---|
| 해상 디너 | **25,000골드·목재 2** | `A0PA` 부여, 아군 HP 초당 +0.45 | 현재/이후 소환 유닛 재생·영역 대상 |
| 카리스마 | **15,000골드·목재 1** | `A0P8` 부여, 아군 공격력 +12% | 기본 공격/스킬·중첩 및 적용 대상 |
| 식량 보급 | **25,000골드·목재 3** | `A0PB` 부여, 아군 MP 초당 +0.8 | 각 개체 MP 풀과 재생 계산 |
| 기후 변화 | **15,000골드·목재 2** | `A0P9` 부여, 적 이동속도 −10% | 원본 범위 1,850과 실제 적용 대상·전장 판정을 확인 |

- 연구별 최대 1단계, 원본 `timebase=100`. 단위와 실제 완료 시점·취소 환급은 **미검증**입니다.
- 원본 JASS **`CV9`가 `EVENT_PLAYER_UNIT_RESEARCH_START`를 등록하고 `CV8`이 오라를 부여**합니다. 따라서 `연구 완료 후에만 오라 활성화`라는 단순 구현은 원본과 다릅니다.
- 연구를 시작한 뒤 취소·게임 종료·이어하기를 했을 때 기술 레벨과 오라·재화가 어떻게 되는지는 **별도 원본 사건 분석 전까지 미확정**으로 둡니다.
- 위 4개 연구와 스토리 진행 연구 **`R01N/R01O/R01P/R01Q/R01S`**는 서로 다른 항목입니다.

### 연구 시작 모바일 연결(코드만)

- `Original323PlayerResearchSession`은 원본 h06S의 **각 1단계 가격**을 공유 지갑과 1회 영수증에 결합합니다. 연구 시작 시 영수증·비용·시작 레벨이 한 거래로 확정되고 실패·예외에는 전부 복구합니다. **원본 완료/취소/환불과 100초 타이머는 연결하지 않았습니다.**
- `Rhgb/A0PA`: 스토리 파견이 아닌 같은 라인의 원본 HP 풀 보유 아군에게 초당 +0.45 HP. `Rhpt/A0PB`: 같은 조건에서 초당 +0.8 MP. 새 유닛은 원본 객체 자원 풀이 확인된 경우에만 효과를 받습니다.
- `Rhra/A0P8`: 기존 소유 유닛·이후 생성/변신 유닛의 **기본 공격력**에 12%를 방어 계산 전 1회 적용합니다. 고정 마법피해에는 추가하지 않습니다. 타 연구와 중복 구매 불가입니다.
- `Rhfc/A0P9`: 원본 네이티브 이동 공급자를 별도로 연결한 환경에만 구매를 열고, 해당 메인 라인 적에게 -10% 이동 상태를 부여합니다. 기본 APK에 이동 공급자가 없다면 **구매 차단·재화 미차감**입니다. 원본 1,850 반경/중첩·기기 동작은 검증 전입니다.
- UI는 **짧게 탭하면 연구 시작 1회**, 길게 누르면 효과·원본 미검증 경계를 설명합니다. 화면에 0/1 또는 시작됨을 표시하되 **연구 완료로 표기하지 않습니다**. 상태 복사는 거래 롤백/향후 저장 계약용이며 앱 종료 후 이어하기는 아직 아닙니다.


## 강화소 18종 — 비용과 효과를 읽는 법

강화소 1 **8종**, 강화소 2 **10종**의 레벨 상한 합계는 **353**입니다. 그러나 모두 `0단계`에서 시작하지는 않습니다. 원본 시작 함수 **`CUo`**가 아래 8개 기술을 1레벨로 지정합니다.

| 초기 1레벨이 있는 곳 | 기술 |
|---|---|
| 강화소 1 | 희귀, 불멸, 특별, 초월, 제한, 전설, 랜덤전용 **7종** |
| 강화소 2 | 영원 **테조로** 1종 |

흔함류와 나머지 영원 9종에는 같은 초기 지정이 없습니다. 독립 모델은 이 기술을 0에서 시작하고, 나머지 판매 기술 8종과 연계 기술 20종은 CUo의 1레벨을 반영합니다. 네이티브 전체 초기화와의 동등성은 별도 검증 대상입니다.

원본 증거 JSON의 각 기술 `steps`는 다음 여섯 값 순서입니다.

| 위치 | 뜻 |
|---|---|
| 1 | 레벨 번호 |
| 2 | 골드 SLK 계산값: `goldbase + (레벨-1) × goldmod` |
| 3 | 목재 SLK 계산값. 원본 필드가 없으면 `null` |
| 4 | 연구시간 SLK 계산값. 원본 필드가 없으면 `null` |
| 5 | `effect1`이 명시된 경우의 첫 번째 효과 계산값(주로 공격속도) |
| 6 | `effect2`가 명시된 경우의 두 번째 효과 계산값(주로 공격력) |

이 값은 **객체 필드에서 계산한 자료**입니다. 실제 구매 가격·적용 레벨·할인·연구 시작 처리·기술 효과의 누적 방식까지 실행 확인한 영수증은 아닙니다. 예를 들어 원본 불멸 강화 `R002`는 공격력 `base2=30,000`, `mod2=2,500`입니다. 툴팁의 ‘2,500 증가’만 보고 **1레벨 효과를 +2,500으로 덮어쓰면 안 됩니다.** 흔함류 `R00F`는 `effect1` 코드가 없어 숫자 `0.03`만으로 공속 효과를 생성하지 않습니다.

**15종의 원본 문자열**의 `Requires12=R00H`, `Requirescount=21`과 R00H 이름 ‘20라운드 보스 처치후 가능’, JASS CIN의 o01W 크로커다일 격파 → R00H=1을 대조했습니다. 독립 모델은 해당 기술의 다음 레벨 12 이상에서 실제 o01W 격파를 요구합니다. 단순 20R 진입이나 다른 적 처치로 해금하지 않습니다. 이 문자열의 네이티브 단계 인덱스 의미는 실행 대조 전입니다.

### 모델 정책과 아직 확인할 부분

- 원본 증거의 미기재 목재/시간은 계속 `null`입니다. **독립 모델**은 별도 목재 차감·대기시간을 추가하지 않고 CV8 시작 승급을 한 번 적용합니다. 이를 원작 무료/즉시 완료의 실측 결과로 인증하지 않습니다.
- 원작 네이티브 연구 완료가 레벨을 다시 증가시키는지, 취소/환불·재진입이 어떤 결과를 만드는지 실행 대조가 필요합니다. 모델에 추측으로 두 번째 승급이나 취소 버튼을 만들지 않았습니다.
- `CaptureState/RestoreState`는 기술 38개·보스 해금의 복사/검사·거래 롤백용입니다. **앱 종료 후 이어하기는 아직 연결하지 않았습니다.** S01~S03에서 공유 지갑 영수증·전투 상태와 같은 시점에 저장해야 합니다.
- 연구소 3종의 시작 결제·모바일 오라 연결만 P04 부분 구현입니다. 기후 변화 네이티브 이동 공급자, 완료·취소/환불·전체 저장/복원은 여전히 P04/S01~S03입니다.
- [8개 회귀 검사](../Assets/Tests/EditMode/SourceModelPlayerUpgradesTests.cs)는 초기 단계/가격·최대·실패·해금·연쇄 순서·상속·복원·실제 평타/공속 경로를 다룹니다. **작성만 했으며 NUnit·Unity·Android 실행과 새 APK 제작은 하지 않았습니다.**

### 자료를 다시 만들 때

`node tools/build_player_upgrade_runtime.mjs UnitBalance.slk UpgradeData.slk war3map.j`

원본 세 입력의 고정 SHA를 확인한 뒤 런타임 자료를 생성합니다. 게임이나 테스트를 실행하는 명령은 아닙니다. 원본 파일을 저장소에 올리지 않습니다.

남은 작업은 [P04/P05·S01~S03·Q01/Q05](PLAYABLE_ROADMAP.md), 최종 요구는 [전체 기능 대장](전체-기능-구현대장.md)을 따릅니다.
