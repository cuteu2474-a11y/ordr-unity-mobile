# 연구소·강화소 — 실제 플레이 연결 명세

> ORDR S2 2.323[C] · 악몽/이세계 · Unity Android. 이 문서는 **다음 구현자가 무엇을 연결해야 하는지** 설명합니다. 정확한 원본 수치는 [원본 실측표](원본-연구-강화-실측.md), 전체 353레벨 증거는 [원본 JSON](../data/original-2323C-player-research-upgrades.json)에 보관합니다. **현재 실제 게임 완료 판정이 아닙니다.**

## 게임에서 어떻게 보여야 하나요?

- 왼쪽 메뉴에서 **연구소 / 강화소 1 / 강화소 2**를 각각 바로 엽니다. 별도의 시설 탭은 만들지 않습니다.
- 화면에는 **연구·강화 이름, 현재/최대 단계, 다음 비용, 구매 가능 상태**를 큰 카드로 보여줍니다. 쓸데없는 머리말과 설명 문장은 제거합니다.
- 일반 강화는 **짧게 한 번 누르면 다음 단계 하나만 구매**합니다. 상세 효과·선행 조건은 길게 누를 때 보이게 합니다.
- 돈이나 목재가 부족하면 **얼마가 부족한지**, 원본 효과 처리기가 연결되지 않았다면 **왜 구매할 수 없는지** 알려줍니다. 표시용 카드가 재화를 소비하거나 유닛을 강화하는 것처럼 꾸미지 않습니다.
- 연구소는 **연구 시작과 완료가 다를 수 있는 기능**입니다. 4개 연구를 강화소의 즉시 구매 버튼으로 단순 대체하면 안 됩니다.

## 연구소 4개 — 확인된 원본

| 연구 | 실제 골드·목재 | 원본 연구 시작 시 처리 | 모바일 구현 주의점 |
|---|---|---|---|
| 해상 디너 | **25,000골드·목재 2** | `A0PA` 부여, 아군 HP 초당 +0.45 | 현재/이후 소환 유닛 재생·영역 대상 |
| 카리스마 | **15,000골드·목재 1** | `A0P8` 부여, 아군 공격력 +12% | 기본 공격/스킬·중첩 및 적용 대상 |
| 식량 보급 | **25,000골드·목재 3** | `A0PB` 부여, 아군 MP 초당 +0.8 | 각 개체 MP 풀과 재생 계산 |
| 기후 변화 | **15,000골드·목재 2** | `A0P9` 부여, 적 이동속도 −10% | 원본 범위 1,850과 모바일 동일 전장 무제한 정책을 분리 |

- 연구별 최대 1단계, 원본 `timebase=100`. 단위와 실제 완료 시점·취소 환급은 **미검증**입니다.
- 원본 JASS **`CV9`가 `EVENT_PLAYER_UNIT_RESEARCH_START`를 등록하고 `CV8`이 오라를 부여**합니다. 따라서 `연구 완료 후에만 오라 활성화`라는 단순 구현은 원본과 다릅니다.
- 연구를 시작한 뒤 취소·게임 종료·이어하기를 했을 때 기술 레벨과 오라·재화가 어떻게 되는지는 **별도 원본 사건 분석 전까지 미확정**으로 둡니다.
- 위 4개 연구와 스토리 진행 연구 **`R01N/R01O/R01P/R01Q/R01S`**는 서로 다른 항목입니다.

## 강화소 18종 — 비용과 효과를 읽는 법

강화소 1 **8종**, 강화소 2 **10종**의 레벨 상한 합계는 **353**입니다. 그러나 모두 `0단계`에서 시작하지는 않습니다. 원본 시작 함수 **`CUo`**가 아래 8개 기술을 1레벨로 지정합니다.

| 초기 1레벨이 있는 곳 | 기술 |
|---|---|
| 강화소 1 | 희귀, 불멸, 특별, 초월, 제한, 전설, 랜덤전용 **7종** |
| 강화소 2 | 영원 **테조로** 1종 |

흔함류와 나머지 영원 9종에는 `CUo`의 같은 초기 1레벨 지정이 **확인되지 않았습니다**. 이는 곧 게임 시작 시 0레벨이라고 확정하는 뜻이 아닙니다. 다른 원본 초기화 경로도 확인해야 합니다.

원본 증거 JSON의 각 기술 `steps`는 다음 여섯 값 순서입니다.

| 위치 | 뜻 |
|---|---|
| 1 | 레벨 번호 |
| 2 | 골드 SLK 계산값: `goldbase + (레벨-1) × goldmod` |
| 3 | 목재 SLK 계산값. 원본 필드가 없으면 `null` |
| 4 | 연구시간 SLK 계산값. 원본 필드가 없으면 `null` |
| 5 | `effect1`이 명시된 경우의 첫 번째 효과 계산값(주로 공격속도) |
| 6 | `effect2`가 명시된 경우의 두 번째 효과 계산값(주로 공격력) |

이 값은 **객체 필드에서 계산한 자료**입니다. 실제 구매 가격·적용 레벨·할인·연구 시작 처리·기술 효과의 누적 방식까지 실행 확인한 영수증은 아닙니다. 예를 들어 원본 불멸 강화 `R002`는 공격력 `base2=30,000`, `mod2=2,500`입니다. 툴팁의 ‘2,500 증가’만 보고 **1레벨 효과를 +2,500으로 덮어쓰면 안 됩니다.** 흔함류 `R00F`는 `effect1` 코드가 없어 숫자 `0.03`만으로 공속 효과를 생성하지 않습니다.

또한 **15종의 원본 문자열**에 `Requires12=R00H`, `Requirescount=21`이 있습니다. 어떤 단계에서 실제 제한으로 작동하는지 확인 전에는 강제로 해금하거나 임의 선행 조건을 붙이지 않습니다.

## 기존 코드에서 연결할 곳

| 기능 | 기존 코드와 현재 사실 | 다음 작업 |
|---|---|---|
| 강화 목록·최대 단계 | `Original323PlayerBuildingResearchCatalog.cs`에 18개 원본 ID와 상한 등록 | 원본 JSON을 정확한 이름·ID로 연결. 표시용 모델이 실제 구매를 실행하지 않도록 분리 |
| 원자 결제 | `Original323PlayerUpgradeSession.cs`는 공유 지갑·영수증·롤백 및 `Quote/Purchase` 제공 | **원본 시작 레벨** 반영. 실제 비용·시간·연계 연구 확인 뒤 `Original323VerifiedUpgradeStep` 주입 |
| 실제 전투 효과 | `IOriginal323VerifiedUpgradeWorld`는 `CanApply/TryApply/Undo` 계약만 있음 | 일반 공격/스킬·현재 소유 유닛과 **나중에 생성된 유닛**까지 공격력·공속을 동일하게 적용하는 월드 구현 |
| 전투 초기화 | `OrdrCharacterCombatController.ConfigureOriginal323VerifiedPlayerUpgrades(...)`는 전투 시작 전에 단계와 효과 월드 수신 | JSON 데이터와 런타임 능력 계산기를 연결한 뒤 전투 초기화 전에 구성 |
| 현재 UI | `OrdrMobileTouchPanel.DrawPlayerBuildingResearch(...)`의 강화소 탭은 `Quote/Purchase` 호출. 연구소는 **정보 표시 전용** | 연구소 별도 구매/시간 상태 연결, 강화 카드에 다음 가격과 선행 조건·실패 사유 명확히 표시 |
| 보존 | 강화 세션의 단계·다음 구매 시각은 현재 내부 장부 | 영구 저장·이어하기 시 복구·중복 영수증 방지·게임 재시작 초기화 연결 |

**특히 중요한 빈틈:** 강화 세션의 `LevelOf(...)`는 초기값이 없으면 **0**을 반환합니다. 원본 `CUo`의 첫 1레벨 지정이 아직 이 장부에 반영되지 않았습니다. 따라서 원본 실측 JSON을 단순히 주입하더라도 **첫 결제 단계가 어긋날 수 있습니다.** 기존의 1레벨 자동 지급과 원본 연구 시작 승급 처리를 먼저 설계해야 합니다.

## 구현 순서와 완료 판정

1. **초기 레벨·연쇄 연구:** 원본 `CUo`의 8종 초기 1레벨, `CV8`의 특정 강화 연구 시 연계 기술 승급, 기술 완료/취소 사건을 한 번에 분석합니다. 기술 레벨 증가가 중복 적용되지 않도록 원본 결과 기준으로 결정합니다.
2. **공통 연구 거래:** 연구소 4개와 강화소 18개의 원본 비용·연구 시간·상태 변화를 공통 공유 지갑/영수증에 연결합니다. 미기재 비용·시간을 추정하여 무료·즉시 구매로 열지 않습니다.
3. **공통 전투 효과:** 대상의 등급/유닛 ID, 같은 전장 정책, 기존/미래 유닛·변신체, 공격력·공격속도·HP/MP 재생·이속 감소를 한 계산 경로에서 처리합니다. 네이티브 기술 효과를 두 번 적용하지 않습니다.
4. **취소·실패·저장:** 연구 시작-완료-취소와 결제 실패, 중단·앱 복귀·이어하기, 유닛 생성 후 기술 상속을 확인합니다.
5. **묶음 검증:** 연관 기능을 충분히 구현한 뒤 사용자 요청에 따라 Unity/Android를 통합 검증합니다. **현재는 구현 및 실기 검증 전입니다.**

진행 작업 번호는 [P04·P05](PLAYABLE_ROADMAP.md), 전체 최종 목표는 [전체 기능 구현 대장](전체-기능-구현대장.md), 실제 코드·APK 현황은 [현재 상태](START_HERE.md)를 따릅니다.
