## 1. 근거 수준과 현재 결론

- **직접 읽은 원본:** 제공된 `war3map.j`(63,651줄)의 `CTo/CTn/CTp/CTq/CTr/CTs/CTt`, `KR` 배정·구역 정의, `B0L/B_i/CBM/B_m/B_l`. 원본 전체 파일은 공개 저장소에 복사하지 않습니다.
- **저장소 추출 데이터:** [크립 객체](../data/original-2323C-monster-object-stats.json), [초기 능력](../data/original-2323C-monster-object-abilities.json). 이 자료가 기록한 원본 W3X SHA는 `0794996c9bc73eaa3020f20ebc45fb37cfa64a6e98ffe8aa0dfa3b356e77bc5c`입니다.
- **이전 객체 조사 재사용:** [288항목 접근 목록](크립-접근조건-전체목록.md), [이동기 21항목 거리·쿨타임](크립-접근조건-분류.md). 이번에 원본 W3X의 SLK/W3A/지형을 새로 추출한 것은 아닙니다. 제공 JASS 사본의 전체 바이트 해시도 이번에 재계산하지 않았으므로 줄 번호와 함수 본문으로 출처를 식별합니다.
- **새로 확정한 핵심:** 세 단계는 같은 플레이어 구역 중심에서 생성됩니다. 2·3단계에는 피해자 귀속과 공격자 소유자를 대조하는 별도 피해 콜백이 있습니다. 아오키지 초월의 변환은 실제 특성포인트 4개 소비·객체 교체이며, 카이도의 특성 구매와 공중 폼 전환은 같은 행동으로 취급할 수 없습니다.
- **아직 미확정:** 유닛별 원본 경로/착지·공격 대상 허용·최종 면역·피해 가능성. 현재 자료만으로 76개 접근 후보를 76개 허용 유닛으로 승격하지 않습니다. 아래 전수표의 '미확정'은 '원작 사냥 불가'가 아닙니다.

## 2. 크립별 실제 데이터와 생성 위치

방어 유형은 세 객체 모두 `normal`. 위 HP/방어는 악몽 최종값이 아닙니다. 세 객체의 초기 능력 목록은 동일합니다:
`Amim,A911,A11S,A04M,A04O,A04N,A04P,A04Q,A04R,A10R`.
`Amim` 존재는 확인했지만 모든 스킬 피해가 막힌다는 뜻으로 쓰지 않습니다. 실제 공격 타입·피해 타입·동적 능력 변경을 별도로 판정해야 합니다.

**좌표 근거:** JASS 3619~3622 `KR[0..3]=K/L/M/N`, 14656~14659의 Rect, 56989의 CTo. 좌표는 사각형 양 끝의 산술 평균입니다.

각 Rect는 512×512입니다. **이 Rect가 통행 가능한 전체 바닥이나 착지 허용 영역이라는 근거는 없습니다.** 생성 중심만 확인했습니다. 모바일 자동 배치에 구역 중심을 무조건 아군 위치로 쓰지 않습니다.

CTo는 `Player(5)` 소유로 적을 생성하고 `A90A` 레벨과 마나에 `JG+1`을 기록합니다. 크립 귀속은 적 소유자 Player(5)가 아니라 이 별도 표식입니다. 다음 단계는 처치자의 구역이 아니라 **죽은 크립 표식 sy-1의 구역**에 생성됩니다.

## 3. 단계별 공격 귀속과 보상

### CTn: 2·3단계의 타인 크립 보호

JASS 56959 부근 CTn~57053 CTt를 대조했습니다.

1. 공격원 소유 플레이어 ID를 JG, 피해 크립 A90A 레벨을 sy로 읽습니다.
2. `sy == JG+1`이면 반환합니다.
3. 다르면 피해 크립에 `Avul/A0KK`를 붙이고, 이벤트 피해량을 HP에 되돌려 더합니다.
4. 공격원을 stop·일시정지하고 0.1초 후 부여 능력 제거·정지를 해제합니다.
5. 이 콜백 등록은 CTo의 Yd=true일 때만 합니다. CTs의 듀공은 false, 후속 파파구/슈슈는 true입니다.

**구현 해석:** 1단계에도 같은 보호가 있다고 일반화하지 않습니다. 싱글플레이에서는 정상 플레이어와 구역 귀속이 일치해야 합니다. 소환 효과/더미의 소유자 귀속을 잃으면 잘못 차단될 수 있으므로 가상 공격도 원래 소유자를 유지합니다. 모바일에서는 유효하지 않은 피해를 정산 전에 막는 구조를 검토하되, 다른 반응형 효과와의 사건 순서를 확인해야 합니다. 원본의 피해 복구 코드만 보고 최종 사망·다른 피격 트리거까지 완전히 되돌아간다고 단정하지 않습니다.

## 4. 조건부 이동·변신: 구현자가 혼동하면 안 되는 부분

### 아오키지 초월 TR-16

- 기존 객체 조사: H097 지상 → H0B1 공중.
- 직접 읽은 B0L(26142~26170): 특성포인트에 해당하는 FOOD_USED가 4 미만이면 stop 후 반환. 기존 객체 제거 후 같은 위치에 H0B1 생성.
- XP와 보너스 제외 STR/AGI/INT를 새 객체에 복사하고 A0ZG/A0FR 레벨 증가, Bhm 호출, 특성포인트 4개 차감.
- B0U 등록부(26346): A0SU에 B0L 연결.
- **단순 위치 이동이 아니라 영구 상태 승계가 필요한 변환**입니다. 파견 한 번으로 필요한 변신을 수행한다는 승인에 따라 연결할 수 있지만, 먼저 이 변환이 해당 크립 접근에 필요한지 확인해야 합니다.
- 변신 완료 개체를 다시 파견할 때 비용 재차감 금지. 파견 실패와 이미 확정된 영구 변신을 구분해 단계별 확정 상태를 보관합니다. 취소했다고 원본에 없는 역변신/무료 환급을 만들지 않습니다.

### 카이도 불멸 I-11

- 기존 객체 조사: h07M 지상, h0AD 공중.
- CBP(40019): **h0AD 공격 콜백이 CBM**입니다. CBM은 자유 이동/파견 명령이 아닙니다.
- CBM(39956): HP=100이면 B_m(false), 그 외 HP+1; B05F가 없을 때 14% 분기에서 B_e·stop·metamorphosis 명령·Jj 실행. 추가 공격 분기가 이어집니다.
- B_m(39368)은 HP를 1로 만들고 Jc/Jh 효과를 실행합니다. 이것만으로 이동 폼 획득을 증명하지 못합니다.
- CBO는 A0PS를 부여·영구화합니다. 별도 A0P0→B_i(39255) 특성 구매는 4포인트를 소비하지만 **A0PS 제거**, A0PX/A0Q1 레벨2, A0OG 추가입니다.
- 따라서 **카이도도 아오키지처럼 4포인트를 쓰면 공중형 파견 가능**이라고 구현하면 안 됩니다. A0PS/A0OG의 W3A 폼·발동·유지 조건과 Jj/B_e까지 대조해야 합니다.

## 6. 후속 구현용 데이터 계약 (제안 이름, 아직 코드 없음)

| 데이터 | 필수 내용 |
|---|---|
| TargetDefinition | stage/rawcode/ownerSlot/spawnEvidence/기본값과 최종 스펙 출처 구분 |
| AccessEvidence | unitId/currentRawcode/form/targetRawcode/접근 경로/공격 대상 허용/유효 피해 경로/출처 |
| AccessVerdict | Allowed / Conditional / Denied / Unverified. 증거 부재는 Unverified이며 Denied로 저장하지 않음 |
| PreparationPlan | 필요한 abilityRawcode, 비용 자원·수량, 시전/쿨타임/폼 요구, 이미 충족 여부, 확정된 단계 |
| DispatchState | 실제 instanceId, 출발/현재 목적지, ownerSlot, 대상 encounterId, laneRevision, 준비 명령 ID |
| Settlement | encounterId별 사망 원인·처치 소유자·구역 소유자·난수 결과·보상/다음 단계 생성 완료 키 |

후보 화면은 Allowed와 **지금 필요한 준비를 실행할 수 있는 Conditional**만 표시합니다. 내부 Unverified/Denied 사유는 개발 자료에만 남기며 사용자 화면에는 불가 목록/설명을 추가하지 않습니다.

### 명령 처리 순서

1. 현재 실물·목적지·폼·자원·쿨타임·크립 생존 상태를 같은 시점에서 읽습니다.
2. 원본 공격 자격을 확인하고 필요한 준비 계획을 만듭니다. 조회에서는 차감/시전/난수/이동을 하지 않습니다.
3. 파견 클릭 시 재검사 후 준비 요청 ID를 고정합니다. 연타는 같은 준비를 중복 실행하지 않습니다.
4. 승인된 이동기/변신을 기존 캐스팅·자원 엔진으로 수행합니다. 이미 충족한 폼은 비용을 다시 쓰지 않습니다.

## 9. 구현 후 확인할 장면 (이번에는 실행하지 않음)

- 후보 조회 반복으로 이동기·변신 비용/난수가 소비되지 않음.
- 같은 폼 재파견, 쿨타임 도중 재요청, 연타, 준비 도중 조합/판매·목적지 변경이 중복 시전/유령 개체를 만들지 않음.
- 듀공 사망 뒤 같은 ownerSlot의 파파구 1기, 이후 슈슈 1기만 생성. 처치자와 구역 소유자를 혼동하지 않음.
- 2·3단계 타인 귀속 피해·보상 차단, 정상 본인 피해 유지. 가상 공격의 소유자 보존.
- 한 스킬의 마법 성분이 막혀도 유효한 평타/다른 성분을 잘못 차단하지 않음.
- 파견 중 소비 성공 시 기존 효과 정리, 실패 시 상태 보존, 최종 완료 후 자동 복귀 없음.
