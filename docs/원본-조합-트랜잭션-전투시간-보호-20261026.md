# 원본 조합 거래 중 전투 시뮬레이션 보호

> **자료의 위치:** 본문은 해당 기능의 원본 근거와 작성 당시 구현 기록입니다. 현재 실행 범위는 [START_HERE](START_HERE.md), 다음 작업은 [PLAYABLE_ROADMAP](PLAYABLE_ROADMAP.md), 운영 정책은 [AGENTS](../AGENTS.md)를 우선합니다. 본문의 과거 APK/테스트 보류·사거리·다음 작업을 현재 지시로 복사하지 않습니다.

기준: 2026-10-26 · 원랜디 S2 2.323[C] Unity 독립 리메이크

## 실제 개선 사항

이번 변경은 원본 조합 실행의 중간 상태가 전투 계산이나 화면에 노출되지 않도록
`CharacterCombatRuntime`의 실제 결과 캐릭터 생성 경로를 나눴습니다.

1. 원본 `IOriginalJassVerifiedFusionSwapRules`가 확인한 정확한 생성 위치를 **그대로 사용**합니다.
   일반 유닛 자동 배치 정책은 검증 중인 조합 결과에 개입하지 않습니다.
2. 최종 승인 전에는 결과 캐릭터의 `UnitSpawned`/`UnitPlaced` 화면 이벤트를 내보내지 않습니다.
   실패하면 결과만 취소하며, 원본 재료 인스턴스는 그대로 살아 있습니다.
3. 재료 유닛 6종을 제거할 때 각 유닛마다 적 오라를 다시 계산하지 않습니다.
   중간에 일부만 사라진 상태를 외부 오라/스킬 콜백에서 관측하거나, 원본 마법 피해의
   상태 변경 이력(Revision)을 불필요하게 바꾸는 것을 막습니다.
4. 최종 생성 승인 시 정확히 한 번의 소환·위치 확정 이벤트를 예약합니다.
   적 오라 계산은 모든 재료 제거가 끝난 다음, 다음 실제 전투 `Step` 시작에서 재개합니다.
5. 조합 검증 중에 `Step` 호출이 들어오면 이벤트 버퍼·잔여 전투 시간·공격 시각을
   **변경하기 전에** 거절합니다. 추가 유닛 생성/제거/이동, 적 생성/이동,
   유닛 상태효과·오라 추가/제거, 라운드 시작도 정상 진입점에서 차단합니다.
6. 검증 도중 원본 재료의 좌표나 상태효과가 다른 저수준 경로로 바뀌면 기존의
   최종 사전 검증이 이를 탐지합니다.

## 회귀 시험 (Unity EditMode 소스)

`OriginalJassLiveSharedWalletFusionTests`에 다음 시나리오를 추가했습니다.

- 진행 중인 조합과 경쟁하는 `Step(0.25)`가 전투 시간을 소비하거나
  이벤트를 배출하지 못하는지
- 검증 중 상태효과 추가·적 생성 차단, 실패한 결과 캐릭터의 소환 이벤트 미출력
- 실제 비비 영원(ET01) 시험용 원본 증거를 통한 성공 시 결과 소환/위치 이벤트 각 1회
- 외부에서 등록한 적 오라가 실패한 조합의 임시 생성·삭제로 다시 적용되거나
  불필요하게 재설정되지 않는지

## 아직 보장하지 않는 부분

**원본 CHu/CHx 효과 전부를 검증한 실전 원본 증거 공급자는 아직 연결되지 않았습니다.**
또한 저수준 전투 엔진 자체가 예외를 던져 **재료 해제 연산이 이미 일부 수행된 뒤**
실패할 경우 스킬 타이머·원본 RNG까지 완벽하게 되돌리는 전역 스냅샷은 아직 없습니다.
따라서 이번 변경을 모든 실패 상황의 완전한 원자성 입증으로 해석해서는 안 됩니다.

원본 규칙·공격력·스킬 확률·비용은 변경하지 않았고,
원본 W3X 수정·APK 빌드도 하지 않았습니다. CI 및 실기 테스트 통과는 미확인입니다.
