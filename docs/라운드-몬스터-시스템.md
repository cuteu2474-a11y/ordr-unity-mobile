# 라운드·몬스터 시스템

> **적용 대상:** ORDR S2 2.323[C] 악몽·이세계 고정 모바일 연습. 이 문서는 **현재 Unity에서 연결한 플레이 방식**, **원본 JASS에서 확인한 규칙**, **아직 원작 결과와 일치한다고 증명하지 못한 부분**을 나눠 설명합니다. 최신 APK/코드 차이는 [현재 상태](START_HERE.md), 다음 구현 작업은 [개발 작업](PLAYABLE_ROADMAP.md)을 먼저 보세요.

## 1. 지금 무엇을 플레이할 수 있나요?

현재 코드에는 **독립 65라운드 연습 전투**가 연결되어 있습니다. `65R 전투 시작` 버튼은 `BeginStandaloneBattle()`로 이어지고, 워크래프트 클라이언트나 별도 원본 관측기 없이도 몬스터를 생성·이동·공격·처치·탈출시키는 모델을 실행합니다. **실제 Android에서 65R을 완주했다는 뜻은 아닙니다.**

| 경로 | 목적과 현황 | 수치·검증 한계 |
|---|---|---|
| **독립 65R 연습** | 원본의 라운드별 몬스터 `rawcode`·기본 생성 규칙과 재구성된 HP/방어·이동 모델로 현재 게임을 진행 | `mobile-standalone-enemy-model.json`은 **원본 근거 기반 모델**입니다. 최종 원작 실측·이세계 후처리·면역·충돌·난수/타이머의 완전 동등성은 미검증 |
| **원본 실측 검증 전용** | `BeginVerifiedMonsterWave()`가 외부에서 입증된 실제 악몽 몬스터 수치와 출현·피해 사건만 받도록 보호 | 승인된 65R 실측 자료 **0라운드**. `retailParityVerified:false`, `safeForVerifiedMonsterWaveRuntime:false` 유지 |

두 경로는 서로 다른 목적입니다. **검증 전용 경로의 승인 부족이 독립 연습 전투를 막는 것은 아닙니다.** 반대로 독립 연습에서 적 체력이 감소했다고 해서 원작 완전 재현을 인증한 것도 아닙니다.

## 2. 65라운드는 어떻게 진행되나요?

원본 `war3map.j`의 `CUl`, `CVo/CVp/CVs/CVw`, `CVX/CVY/CVZ/CVa/CVb/CVc/CVd/CVf`, `CVG/CVT/CVi/CVz` 및 [65라운드 생성 근거](../data/original-2323C-monster-wave-script-evidence.json)를 대조한 결과입니다. 아래 시간은 **각 출현 타이머가 시작된 뒤의 상대 시간**입니다.

| 구간 | 몬스터 구성(활성 플레이어 1명 기준) | 출현 시점 | 원본 라운드 제한시간 |
|---|---|---|---|
| 1~50 일반 라운드 | 일반 몬스터 **35마리** | 첫 출현 **0.5초**, 이후 0.5초 간격, 마지막 **17.5초** | **35초** |
| 10·20·30·40·50 | 일반 몬스터 대신 **보스 1마리** | 첫 타이머 **0.5초** | **60초** |
| 51~65 전 라운드 | 일반 몬스터 **35마리** | 0.5~17.5초 | **32초** |
| **55·60·65** | 일반 몬스터 **35마리 + 보스 1마리** | **보스와 첫 일반 몬스터 모두 0.5초**, 일반 몬스터는 17.5초까지 | **32초** |

- **첫 라운드 출현 전 준비 시간은 21초**, **50→51라운드 전환 대기는 70초**입니다. 연습 모델에서 논리 시간으로 계산하며 `PreparationSecondsRemaining`은 대기만, `SecondsRemaining`은 대기를 포함한 라운드 시간을 뜻합니다.
- **51~64라운드의 일부 비보스 라운드**에는 15번째 일반 몬스터 출현(약 7.5초) 시 추가 **광폭화 몬스터**를 만들 수 있는 원본 조건이 있습니다. 플레이어 슬롯·사건 조건에 따라 실제 수량은 달라집니다. 싱글플레이에서 가능한 추가 수는 최대 1마리이며, 조건을 확인하지 않고 무조건 한 마리 더 만들면 안 됩니다.
- **55·60·65 보스가 18초에 등장한다는 과거 설명은 오류였습니다.** 원본 `CVc`의 `CVb` 호출을 재검증한 **첫 0.5초 등장**이 정정된 기준입니다.
- 라운드는 **시간 경과 중심**으로 전환합니다. 이전 라운드에서 살아남은 적이 있더라도 다음 라운드가 열릴 수 있습니다. `CombatWaveDirector`는 출현 예정·실제 출현·처치·탈출·생존 개수를 라운드별로 따로 계산하므로, 단순 UI 개수 변화로 처치를 추정하지 않습니다.
- 독립 연습은 **누적 탈출 70마리**를 패배 조건으로 처리합니다. 원본 `CU8/CU7`의 보스 시간초과 패배와 별개의 사건이며, UI 시간만 보고 실제 보스 사망/실패를 추정하지 않습니다.

### 보스를 잡으면 받는 점수

원본 `Bdf`·`BdK`: **55·60·65라운드 보스가 사망**했을 때 해당 라운드 타이머 **16초 미만이면 1,000점**, 16초 이상이면 **500점**입니다. 이 값은 **골드·목재가 아닌 점수**이며, 10~50라운드 보스·일반 몬스터·중복 처치에는 해당 특별 점수를 지급하지 않습니다. 현재 코드는 모델의 라운드 시계를 사용하므로 원본 클라이언트의 절대 시각과 일치하는지는 별도 검증이 필요합니다.

## 3. 몬스터의 체력·방어력은 어떻게 정했나요?

원본 `Units/UnitBalance.slk`, `Units/CampaignUnitStrings.txt`에서 **몬스터 후보 100종**의 *객체 기본값*을 추출했습니다(일반 60·보스 8·퀘스트 11·스토리 14·크립 3·기타/불확실 4). 실제 65R 배열에 연결된 것은 **일반 60종 + 보스 8종**입니다. 후보 100종 모두가 한 게임에서 등장한다는 뜻은 아닙니다.

악몽 선택 `CUM`은 몬스터 플레이어 `Player(6)`에게 연구를 적용하지만, **모든 연구가 모든 몬스터에게 동시에 적용되지는 않습니다.** 각 유닛의 `upgrades` 허용 목록과 연구를 교차해야 합니다.

| 연구 | 원본 악몽 설정 레벨 | 계산할 때 필요한 구분 |
|---|---:|---|
| `R024` | 3 | 이동 속도 계열. 유닛별 연구 자격 확인 |
| `R00J` | 11 | 방어 연구. 유닛의 `defUp × 연구 레벨` 영향 |
| `R02M` | 1 | 보스 계열 연구. 해당 레벨의 모델 입력 **8.5** |
| `R00A` | 15 | HP 연구. 해당 레벨의 `rhpo` 수치 **1.5** |
| `R00T` / `R00V` | 4 / 6 | HP 연구 입력 **1.08 / 5.76** |
| `R00U` / `R00W` | 8 / 9 | HP 연구 입력 **8.0 / 7.48** |

원본 [연구·유닛 자격 근거](../data/original-2323C-nightmare-monster-tech-evidence.json), [강화 후 초기치 재구성 결과](../data/original-2323C-nightmare-monster-initial-model.json)에서 대상별 교집합과 계산 근거를 찾을 수 있습니다. 재구성 방식은 Warsmash 엔진의 `rhpo` float32·Java식 반올림과 `rarm`/`defUp`을 참고한 **계산 모델**이며 원본 워크래프트 실측을 대체하지 않습니다.

| 라운드·적 사례 | 원본 객체 기본 HP | 악몽 초기 HP **모델** | 악몽 방어 **모델** |
|---|---:|---:|---:|
| 1R 일반 | 135 | 338 | 0 |
| 10R 아론 보스 | 14,500 | 137,750 | 13 |
| 15R 일반 | 2,670 | 9,559 | 12 |
| 39R 스팬담 | 1 | 1 | 39 |
| 50R 센고쿠 보스 | 20,800,000 | 197,600,000 | 350 |
| 65R 일반 | 16,210,000 | 161,775,800 | 191 |

`data/original-2323C-map-base-stats.json`의 캐릭터 수치를 몬스터 최종 HP로 대신 사용하지 않습니다. 출현 뒤 버프·스킬·체력 변경·실제 기기 계산은 별개입니다. 실제 변경을 외부에서 검증하는 경로는 `CombatEnemy.TryApplyObservedMaximumHealthChange`와 `TryApplyObservedPhysicalArmorChange`, `IOriginal323LiveMonsterStatWitness`를 사용합니다. 사망/처치는 반드시 `CombatResolution`의 기존 경로를 거칩니다.

## 4. 몬스터 특수 능력·크립·스토리 적

원본 [몬스터 능력 목록](../data/original-2323C-monster-object-abilities.json)에 기록된 능력은 **객체가 소유한 기술 후보**입니다. 실제 적에게 면역이나 저항이 적용됐다는 독립 증명은 아닙니다.

| 분류 | 확인된 원본 객체 능력 | 현재 해석 |
|---|---|---|
| 일반 웨이브 몬스터 60종 | `Aeth` | 유령 표시 속성으로 분류. **피해 면역으로 자동 판정하지 않음** |
| 스토리 적 14종 | `A08Q` (`Arsk`) | 저항성 피부 후보. 기절 지속시간·마법 면역은 별도 확인 |
| 크립 3종 | `Amim` | 마법 면역 후보. 원본 실전 효과 자동 승인 전 |
| 기타 3종 | `Avul` | 무적 후보. 전장/종류별 실제 적용 미확인 |
| 웨이브 일반·보스 68종 | `A04Q`, `A04M`, `A04R` | 마방·방깎 관련 원본 객체. **현재 능력 레벨·중첩이 실제 피해를 좌우** |

독립 연습용 크립은 `Original323CreepObjectCatalog`에서 읽어 필요할 때 `SpawnPracticeCreepStage(stage,x,y)`로 **명시적으로** 소환합니다.

| 크립 단계 | 이름 | 객체 기본 HP | 기본 방어 |
|---|---|---:|---:|
| 1 | 듀공 | 360,000 | 27 |
| 2 | 파파구 | 1,000,000 | 125 |
| 3 | 슈슈 | 1,200,000 | 150 |

크립은 **일반 라운드 수·70마리 탈출 계산에서 분리**됩니다. 원본 `CTs`가 최초 1단계를 생성하고 `CTp/CTq`의 이전 단계 **사망 콜백**이 다음 단계를 생성하며, 처치 보상은 아래와 [토벌·크립](토벌-크립-파견-시스템.md)에 확인됐습니다. **실제 `Amim` 면역·저격/파견 유닛과 이동·모바일 실행**은 별도 검증 대상입니다. 크립의 최초 격파에 연결된 이세계 도박 충전은 [경제·도박 시스템](경제-도박-시스템.md)을 보세요. 원본 14개 **스토리 건물 전투**는 [스토리 시스템](스토리-시스템.md)에서 별도로 관리합니다.

접근 수단은 [크립 접근 조건 분류](크립-접근조건-분류.md)에 정리했습니다. 도감 288항목의 이동형·순간이동·변신을 구분했으며, 실제 크립 진입·공격 대상·면역·피해 승인은 별도입니다. 유닛별 원본 객체와 활성 공격거리는 [전체 목록](크립-접근조건-전체목록.md)에서 확인합니다.

### 부가 전투·공유 도전과제: 2.323[C] 원본 JASS 우선

공개 공략은 초기 조사 단서였으며, 아래 **원본 JASS의 사망·보상 함수**가 확인된 대상은 더 이상 ‘후보’로 표시하지 않습니다. 원본 객체 기본 HP·네이티브 공격/면역·Android 실행은 별도입니다.

| 대상 | 현재 확정된 원본 규칙 | 남은 검증 |
|---|---|---|
| **크립 3단계** | `CTp/CTq/CTr`: 1단계 **모든 참가자 골드 1,000+목재 1**, 2단계 **처치자 50% 지정 유닛 `h060`+목재 2 / 50% 목재 7**, 3단계 **처치자 골드 5,000+목재 1+아이템 발굴 1회**. 이전 단계 사망으로 다음 단계 소환 | 크립 실제 `Amim` 면역·파견·기기 처치/정산 |
| **정의의 문·해군대장·해왕류** | `CNI/CNH`, `CM2/CM1`, `CNV/CNU`의 별도 공유 목표·보상 확인. 문을 파괴하면 3대장 중 1기가 등장 | 실제 HP/면역·보상·저장 실행 |
| **샨도라 황금종** | `CM7/CM6/CM5`: **7시 황금종 파괴**, 골드 3,000+랜덤위습 1+아이템 발굴 1회, **5% `AI01` 추가 추첨**(미획득 시) | 공격 가능 조건·실기 전투 |
| **개인 토벌 7종(피카 포함)** | `CK0~CK6`: **원본 수동 소환/60초 제한/개인 격파 보상**, 네이티브 **15R·20R 크로커다일·31R·41R·홀케이크섬 해금**, **재고 1·3,600초 재충전** 확인. 일반 라운드 피카와 분리. [상세 근거](토벌-크립-파견-시스템.md) | **단발 안내와 재충전 후 재도전 가능성의 충돌**, 실제 가격 UI·악몽 최종 HP/면역·모바일 전투/정산 |
| **공유 미션 8종 → 포네그리프** | `ni` 8회 완료 → `CMy` 해금, `CMx/CMw` 해독 **150초/해석자 50초**, 성공 `BeL`의 **현존 보물 위치 공개** | 대상별 능력 자격·모바일 해독/보물 표식·저장/실기 |
| **등불·비석·파편·추가 해적단/스모커** | 이름은 공개 가이드의 조사 후보 | 2.323[C]에서 실제 객체 생성·해금·사망/보상 사건 확인 전 기능으로 단정하지 않음 |

**8개 공유 미션의 이름·시간·실제 보상·해독 과정**은 [공유미션·포네그리프 원본 규칙](공유미션-포네그리프-시스템.md), **개인 토벌과 크립**은 [토벌·크립 파견](토벌-크립-파견-시스템.md)에 자세히 정리했습니다. 원본 보상 메시지에 표시되지 않은 `Bhd` 아이템 발굴처럼 **실제 지급 함수 본문**도 확인했습니다. 베리 지급은 모바일에서 제외합니다.

**사용자 확정 UI:** 크립은 **스토리 → 크립 사냥**에서 보유 개체를 파견하고, 별도 처치형 퀘스트는 왼쪽 **토벌**에서 실행 조건과 진행을 봅니다. 원본 수동 시작 대상에 도전/소환을 연결하며 자동 출현 대상은 실제 등장 상태를 표시합니다. [토벌·크립 파견 명세](토벌-크립-파견-시스템.md)는 모바일 조작 기준이고, 출현·해금·비용·보상·면역의 원본 확인을 대체하지 않습니다. 크립 이동/접근 조건은 [크립 접근 조건](크립-접근조건-분류.md), 원본 객체 스탯과 보상 근거는 위 표·원본 데이터에서 관리합니다.
## 5. 처치 골드와 원본 난수

원본 `CVM`에서는 몬스터가 실제로 죽고 소유 표식 `A901`이 적용된 경우(일반·보스·광폭화 포함) `BFi(1,4)==3`인 **25%**에 골드를 지급합니다. 탈출에는 지급하지 않습니다. **금액 계산 시 사용하는 `YJ`는 사망 몬스터의 출현 라운드가 아니라, 사망 순간의 전체 현재 라운드**입니다.

```text
기본 금액 = R2I(1 + 2×(YJ/5) + 3×(YJ/6) − YJ/10)
실제 지급 = R2I(기본 금액 × 2 × (1 + 플레이어 골드 보너스))
```

`R2I`는 사사오입이 아닌 **0방향 정수 절삭**입니다. 원본의 단정밀도(float32) 계산과 `BFi` 호출 순서를 고려해야 합니다. 검증 전용 `Original323MonsterGoldService`는 실제 사망·난수 증빙 및 공유 지갑의 영수증/중복 방지를 요구합니다. 독립 연습이 지급하는 모델 골드는 **원본 사망 관측 승인과 구분**합니다.

원본의 `BFh/BFi`는 몬스터 골드·위습·도박·일부 공격 발동이 공유하는 **스크립트 난수열**입니다. 최초 `GetRandomInt(1,1000000)`로 시드를 얻고 이후 `H6 = ModuloInteger(69069×H6+1,2147483647)`로 갱신합니다. 한 시스템의 추첨을 더 하거나 빼면 다른 시스템의 결과도 달라집니다. 반면 위습 `PlaceRandomUnit`의 **워크래프트 네이티브 유닛 풀 추첨은 별도 난수**입니다. 전투와 거래의 난수를 임의로 하나의 Unity 난수로 합치지 않습니다. 돈 도박의 2회 `BFi` 소비·정산은 [경제·도박 시스템](경제-도박-시스템.md), 위습 분기는 [위습 시스템](위습-시스템.md)에 있습니다.

## 6. 한 판 완주에 필요한 사건 연결

라운드·스토리·크립·토벌은 **같은 세션에서 동시에 진행되지만 서로 다른 대상과 집계**입니다. 다음 항목을 통과해야 시작부터 승패까지 하나의 게임으로 이어집니다. 원본 수치 상세는 이 문서의 앞 절과 각 시스템 문서가 담당합니다.

| 실제 사건 | 이어져야 할 결과 | 섞으면 안 되는 것 |
|---|---|---|
| 새 게임 시작 | 원본 시작 지급과 라운드 준비 시계·전장 초기화가 한 번만 진행 | 이어하기에서 시작 위습/골드 재지급 |
| 일반 몬스터 생성·전진·사망/탈출 | 출현 라운드·실제 HP·공통 피해·킬/탈출·처치 골드와 다음 라운드 | **탈출을 처치로**, 화면에서 사라진 적을 사망으로 계산 |
| 정규 보스와 51~65R 특수 출현 | 보스 타이머/시간초과·55/60/65 점수·조건부 광폭화 | 일반 몬스터 35마리와 보스를 임의로 상호 대체 |
| 스토리 건물 파괴 | 14단계 다음 건물·제한 시간·연구/XP/위습/아이템 보상 | 스토리 건물을 일반 몬스터 킬/탈출 수에 합산 |
| 크립 파견·별도 토벌 | 실제 파견/출현→피격·처치→원본 보상/도박 충전 영수증 | 기본 HP·객체 ID만으로 임의 소환, 같은 유닛 중복 출전 |
| 최종 승패 확정 | 원본 패배·승리 조건과 세션 종료, **성공이 확정된 한 판에 누적 클리어 횟수 한 번** | 65R 화면 도달만으로 승리 확정, 베리 보상/잔액 생성 |
| 중간 종료·이어하기 | 전장·라운드/건물/크립·보물·추첨/보상 이력과 논리 시계 복원 | 복귀 직후 과거 스폰/격파/드롭 재실행 |

**경계:** 위 표는 필요한 게임 흐름을 설명한 것으로, 실제 Android 65라운드 완주나 각 보스/토벌의 원본 동등성을 검증했다는 뜻이 아닙니다. [토벌·크립 파견](토벌-크립-파견-시스템.md) · [스토리](스토리-시스템.md) · [저장·이어하기](저장-이어하기-구현명세.md) · [최종 기능 범위](전체-기능-구현대장.md).
