| 원본 호출 | 능력 | 의미 | 처리상 주의 |
|---|---|---|---|

## 1. 일반 캐릭터의 A04M·A04Q 적용

### 원본과 도감 대응 확인

원본 JASS에 이 6개 `w5(rawcode,callback)` 등록과 해당 콜백 내 `Bdq/Bd5` 호출이 실제로 있고, 현재 도감의 **unitId/skill index/name/trigger/effect 값**이 6/6 일치함을 코드 및 원본 문자열로 정적 비교했다.

### 구현 파일·연결 방법

- `Assets/Scripts/Combat/Ordr323VerifiedDefenseSkillLinks.cs`: 6개 고정 매핑과 원본 방어 능력 적용 라우터. 다른 이름·발동형·수치의 스킬은 보류.
- `data/original-2323C-character-defense-skill-links.json`: 원본 함수/호출/등록 위치 근거.
- `CharacterSkillEffectExecutor`: 원본 월드에서 아머브레이크·마방깎 컴포넌트는 검증 라우터를 통과해야 실제 적용. 미등록 것은 `EffectDeferred`.
- `CharacterCombatRuntime`: 입증된 A04M 스택을 별도 보관하고 적 퇴장 시 제거. **광역 피해·상태 효과도 같은 전장의 적만** 적용하도록 대상 필터 수정.
- `EnemyDefenseProfile` + `Ordr323VerifiedDefenseAbilities`: A04Q의 실제 원본 레벨을 가진 적만 동적으로 레벨을 상승시킬 수 있음. 레벨 16 기본값에 에넬 스킬 +10이면 26이 되어 마법 저항 10%→0% (W3A `Def5`).
- `Ordr323DamageWorldBinding.Create(...)`: `ConfigureOriginal323DefenseSkillLinks` 자동 적용 및 아머브레이크 원본 출처 검증.
- NUnit 사양: `Assets/Tests/EditMode/Ordr323VerifiedDefenseSkillLinkTests.cs` 10개 테스트 작성. 원본 스킬 연결 거부, 1~3스택 수치 보류, 베르고 중복/캐번디시/레일리/시키, 에넬 동적 A04Q, 인공 입력에서 피해 900→1000 변동 검증을 위한 코드.

### 피해 전후 방어 감소의 JASS 적용 순서

원본 JASS 함수 내부 호출 순서를 추가 확인하고 엔진의 사전·사후 효과 처리 구간을 분리했다.

- **베르고 `BrP → BrN`**: `Bdq(RN,1)` (주 대상 사전 1) → `Bcb(...300000...)` (주 대상 직접 피해) → 범위 `BrN`: `Bcb(...240000...)` → `Bdq(대상,1)`. 원본 300,000 직접 피해는 기존 도감의 `H-10:skill:1`에 별도 컴포넌트가 없어 아직 재현되지 않는다. 추가 피해를 0으로 간주하거나 240,000으로 치환하면 안 된다.
- **에넬 `Br6:17603~17607`**: `Bd5(대상,10)` → `BeC(대상,10)` → `Bcb(...2150000...)`. 스킬 피해 계산보다 **A04Q 마방깎 레벨 증가가 선행**하도록 분리. `BeC`의 다른 능력 영향은 아직 미구현이다.
- **캐번디시 `B5Z:33469~33475`**: `Bcb(...2565000...)` 및 `Bcc(...855000...)` 이후 `Bdq(RN,5)`. 단, 강화 능력 `A123` 보유 시 `B5Z:33448~33449`에서 **별도 무조건 Bdq(RN,1)** 발생. 강화 분기의 오브젝트 유무는 아직 유닛 데이터 공급자에서 확인해야 하므로 이 추가 1스택은 자동 적용하지 않는다.
- **레일리 `B8q:37210~37214`**: `Bcb(...1250000...)`, `Bcb(...2750000 *1~1.5...)` 다음 `Bdq(대상,5)`.
- **시키 `B92:38553~38555`**: `Bcb(...400000...)` 다음 `Bdq(대상,1)`.
- **베르고 맥시멈 스윙 `BrO:17093~17095`**: `Bcb(...1250000...)` 다음 `Bdq(대상,4)`.

**코드 적용:** `Ordr323VerifiedDefenseEffectRouter.TryApplyAtPhase`와 `CharacterSkillEffectExecutor` 선행 효과 실행을 추가했다. 베르고의 직접 1스택, 에넬의 마방깎 10레벨은 일반 피해 컴포넌트 앞에, 다른 범위 스택은 피해 뒤에 처리한다. 에넬은 후행 처리 시 두 번 적용되지 않도록 한다.

**아직 불완전한 점:** 기존 공통 스킬은 도감 컴포넌트 순서로 피해를 재생하므로, JASS의 *누락된 직접 피해·강화 분기·조건부 시전·모든 증폭/반올림*까지 재현한 것은 아니다. 타격 전 디버프가 적용되는 상황은 전용 검증 정책이 준비되지 않았다면 스킬 실행 자체를 보류할 수 있다. 실제 스킬 타격 선후 관계의 게임 실행 검증은 별도입니다.

### 추가 전설 4명·5개 기술

원본 `war3map.j`에 **몬스터 방어 능력을 변경하는 공격 이벤트**가 다음 캐릭터에도 존재하는 것을 확인했다. 원본 rawcode는 `w5` 등록에서 확정, 도감 unitId는 `war3map.j`의 `Bi8` 분류 코드·아이콘 이미지 경로 및 일치하는 피해/발동 확률로 대조했다. **원본 W3U 유닛 파일 완전 검증과 도감 ID 매핑은 별개 단계**이므로 rawcode↔도감 ID는 외관·숫자 교차 근거를 명시한다.

| 도감 캐릭터·원본 rawcode | 도감 스킬·JASS 함수 | 원본 호출 순서 | 대응 효과 |
|---|---|---|---|
| `L-20` 스모커 전설 / `h02V` | 화이트 아웃 / `Btx → Btv` (`main:62740`) | `Bcb(450000×1~1.5)` → `Bdq(3)` | **후행 A04M +3** |
| `L-23` 시키 전설 / `h039` | 바위낙하 / `Bt8 → Bt7` (`main:62742`) | 5% 분기에서 소환체 출현 후 `Bdq(2)`; 생성 소환체 실제 타격은 독립 | **범위 A04M +2** (실제 소환 타격순서 미완료) |
| `L-23` 시키 전설 / `h039` | 바닷물 가두기 / `Bt8 → Bt6` | `Bcb(145000)` → `Bdq(1)` | **후행 A04M +1** |
| `L-07` 레일리 전설 / `h03A` | 패기발산 / `BuD → BuC` (`main:62743`) | `Bdq(3)` → `Bcb(1200000×1~1.5)` → `Bcb(1000000)` | **피해 전 A04M +3** |
| `L-37` 후지토라 전설 / `h031` | 중력검 / `Bus → Bur` (`main:62752`) | `Bcb(192500)` → `Bd5(1)` | **후행 A04Q +1 레벨** |

- 원본 아이콘 식별자: `BTN0114_smoker`, `BTN0526_Shiki`, `BTN0527_laily`, `BTN0537_Issho`. 같은 이름의 다른 등급과 혼동하지 않도록 실제 등록 rawcode와 스킬 수치를 함께 대조.
- 원본 데미지 스크립트와 도감 스킬 컴포넌트의 숫자/발동 방식이 **추가 5/5 매칭**됨. 단 특수한 소환/디버프가 같은 기술에 혼합된 곳은 **해당 컴포넌트만 매핑**한 것이며 전체 기술 완성 아님.
- `Ordr323VerifiedDefenseSkillLinks.cs`에 누적 11개 등록. 레일리와 시키의 선행 효과는 `HasPreDamagePart` 판정에 포함; 나머지는 피해 후 디버프 적용. 당시 회귀 사양은 별도 코드에서 확인합니다.
- **보류/미검증:** 스모커의 퍼지·버프 제거, 시키의 소환 유닛 실제 타격, 레일리 기타 스킬·마나, 중력검 나머지 CC, JASS 원본 주사위·원작 DPS·마법 저항 타입, Unity 컴파일/테스트는 아직 완료되지 않음.

## 2. 보니(TR-21)의 별도 A04P 방어 감소

### 원본 A04P 경로와 공격 선언 이벤트

**원본 `ORDR_S2_2.323[C](2).w3x`의 `war3map.j`와 `war3map.w3a`를 직접 추출해 비교.** 보니(초월 `TR-21`) 기본형 `H0BX`와 변신형 `H0BY`의 콜백 `B4C`/`B4D`가 사용하는 방어 감소는 **`Bd2` → `A04P`**이며, 기존 아머브레이크 **`Bdq` → `A04M`**과 다른 능력임을 확인했다.

#### 공격 이벤트 시점·A04P 레벨 근거

- `war3map.j:3123~3139`: `w5`는 `EVENT_PLAYER_UNIT_ATTACKED` 조건을 등록한다. **공격 적중(on-hit)이 아니라 공격 선언(attack declared) 시점.**
- `B4H:31899~31904`: `w5(H0BX,B4C)`, `w5(H0BY,B4D)` 등록. `B4C`는 기본형, `B4D`는 변신형.
- `B4C:31720` / `B4D:31787`: 공격당 적 대상 `Bd2(RN,10)` — **A04P 레벨 +10** (추가 능력이 처음 생기면 레벨1부터 계산).
- `B4C:31749~31752`: 독립 30% 분기에서 `Bd2(RN,20)` (기본형); `B4D:31803~31816`: 독립 50% 분기에서 +20 (변신형).
- `B4C:31757~31763` / `B4D:31830~31843`: 독립 15% / 30% 범위 분기에서 `BiZ`로 **주 대상 중심 반경 320**, `B39`/`B4B`의 `Bd2(GetEnumUnit(),2)`.
- `Bd2:8548~8553`: 능력이 없을 때 `UnitAddAbility(A04P)`, 이어서 `SetUnitAbilityLevel`로 정수 레벨 추가.
- `war3map.w3a`: `A04P`의 `Idef` 덮어쓰기는 **5~41레벨**에서 `1-level`: -4부터 -40까지 확인. 즉 +10 부여 시 레벨 11, 알려진 방어력 감소는 -10.
- 원본이 `GetUnitAbilityLevel(RN,I2)-1==40`을 최상위 스택 조건으로 검사함을 확인. **41레벨 초과시 엔진 내부 동작(실패/캡/유지)은 검증 전**이므로 넘치는 이벤트는 보류.
- `B4C`에 공격자 현재 체력 10 이하 시 조기 종료, 마나150 조건, 전환 상태 등 **추가 발동 제약**이 존재한다. +10 이후 확률 프로크를 무조건 재생하면 안 된다.

### 구현 내용

1. `CombatEffectType.OriginalA04PLevelIncrease` — **기존 A04M ArmorBreakStack과 별도 상태**, 영속형 A04P 레벨 변경의 이벤트 출처와 누적량 추적. 기존 열거형 ID를 변경하지 않도록 새 타입을 끝에 추가.
2. `Ordr323BonneyDefenseController` — 공격 선언 +10, 검증된 개별 프로크 +20, 320 반경 프로크 +2; 기본형/변신형의 확률(30/15%, 50/30%) 상수; 중복 이벤트·미확인 레벨·최대 확인 범위 밖을 보수적으로 처리.
3. `Ordr323VerifiedPartialModifierRules.TryResolveArmor` — **A04P만 독립적으로 존재하고 원본 출처 장부와 일치할 때** 레벨별 Idef를 기본 방어력에 반영. 원본 방어력 50 + A04P 증가량10이면 방어력40. A04P가 시작 레벨 1+2=3인 경우 실제 W3A 덮어쓰기가 없어 피해 계산 보류, 1+4=5가 되면 -4 사용.
4. `Ordr323OriginalDamageRules.Calculate` — 원본 A04P 상태가 존재할 때 적 방어력 재계산으로 연결.
5. `CombatAttackPipeline` — `TryBasicAttack`에서 실제 피해를 계산하기 **직전**, 공격 선언 콜백 호출. 메인·스토리 유닛/적 분리는 기존 Runtime에서 유지.
