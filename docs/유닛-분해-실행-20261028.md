# 갱 뱃지·버기 마기탄 분해 실행

`a6ad074`의 네이티브 전투 효과 연결에서 이어, 보유한 특별함 두 유닛의 수동 분해를 기본 APK에 연결했다. 전체 유닛 스킬 완료는 아니다.

| 보유 유닛 | 원본 시전 시간 | 소비·결과 |
|---|---:|---|
| 갱 뱃지 | 5초 | 본체 1기 소비 → 안흔함 후쿠로·흔함 버기·흔함 우솝 각 1기 |
| 버기 마기탄 | 2초 | 본체 1기 소비 → 흔함 버기 2기 또는 3기, 각 50% |

## 조작과 세션 연결

보유 유닛 목록에서 **분해 → 분해 시작**을 누른다. 시전 중에는 남은 시간과 취소 버튼을 표시한다. 시작 탭만으로 유닛을 없애거나 결과를 추첨하지 않는다. 완료 시점에 실제 보유 인스턴스를 교환한다.

시전 중 해당 유닛의 자동 공격·공격 미리보기를 멈춘다. 다른 유닛과 몬스터는 계속 진행한다. 이동, 제거, 조합 재료로 소비, 스토리 파견 또는 게임 종료 시 시전을 중단한다. 이동했다 원래 자리로 돌아와도 이전 시전을 이어가지 않는다. 일반 판매 능력이 없는 두 유닛에 판매를 새로 허용하지 않는다.

유닛 준비 단계에서도 분해 시간을 진행하지만 몬스터·라운드는 시작하지 않는다. 전투 중에는 실제 진행한 전투 시간으로 처리한다. 일시정지·앱 백그라운드·포커스 해제 중에는 시전 시간이 흐르지 않으며 복귀 후 벽시계 시간을 따라잡지 않는다. 모바일 프레임 경계에서 완료를 처리하므로 Warcraft의 시전 애니메이션·세부 틱 동등성을 승인한 것은 아니다.

## 원본 근거와 거래 보호

[추출 자료](../data/original-2323C-unit-decomposition.json)는 원본 JASS `Bn2/BoK`, SPELL_EFFECT 등록, 객체 소유 능력, AbilityData.slk의 2초/5초 시전 필드, BIY 배치 좌표를 대조한다. 버기는 `BFi(2,3)`을 완료 때 한 번 사용한다. 갱 뱃지는 난수를 사용하지 않는다. 생성 위치는 기존 모바일 고정 배치에 해당하는 플레이어 0·Vw=false 경로다.

골드·목재 비용과 판매 포인트는 없다. 마나 필드는 별도로 확인했다. 두 능력은 완전한 SLK 별칭 행에 존재하며 W3A 수정 기록이 없다. 누락된 정수 Cost1을 0으로 읽고 정수 0을 생략해 쓰는 [w3x2lni 읽기](https://github.com/sumneko/w3x2lni/blob/82916514a12b7edb15252d42225cd8cc8ce61cfd/script/core/slk/frontend_slk.lua)·[쓰기](https://github.com/sumneko/w3x2lni/blob/82916514a12b7edb15252d42225cd8cc8ce61cfd/script/core/slk/backend_slk.lua)를 교차 대조했다. 이는 W3A 패치의 부모 데이터 상속과 구분하며, 모든 미확인 필드를 일괄 0으로 바꾸는 규칙이 아니다.

기존 유닛 교체 거래를 여러 결과에 확장했다. 결과 전부를 준비한 뒤 원래 유닛을 소비하고 생성·배치 이벤트를 공개한다. 두 결과까지 준비한 후 세 번째 생성에 실패해도 준비한 결과 전부를 제거하며 원본 인스턴스·위치·선택·공격 상태를 보존한다. 실패한 결과가 화면에 생성된 것처럼 남지 않는다.

버기 추첨도 같은 세션의 공유 난수를 사용한다. 모바일 난수는 거래 실패 시 되돌리고, 되돌릴 권한이 없는 원본 난수 공급자는 같은 유닛의 이미 뽑은 결과를 보존한다. 원본 Warcraft 초기 시드와 다른 시스템의 전체 전역 호출 순서를 동일하게 재현했다는 뜻은 아니다.

원본 W3X는 수정하지 않았다. 재추출 명령은 다음과 같다.

```sh
python3 tools/extract_original_unit_decomposition.py \
  --jass /path/to/war3map.j \
  --ability-slk /path/to/AbilityData.slk \
  --w3a /path/to/war3map.w3a
```

[전체 유닛 현황](../data/unit-runtime-status.json)에 두 수동 기능을 따로 기록했다. 기존 112개 항목·144개 전투 모델 효과 수에 분해를 섞어 세지 않는다. 원작 전체 검증 유닛 0, `allUnitsComplete=false`를 유지한다. 남은 액티브·변신·소환물·연구·복합 패시브는 후속 구현 대상이다.
