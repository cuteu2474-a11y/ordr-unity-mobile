# 위습 시스템

> **현재 게임 설명서:** 원랜디 S2 2.323[C] **악몽·이세계모드**의 위습 획득·사용·보상을 한곳에 정리했습니다. 기준은 현재 `main` 코드입니다. **코드에 연결된 기능과 최신 APK·실기에서 확인된 기능은 다릅니다.** [현재 상태](START_HERE.md)와 [남은 작업](PLAYABLE_ROADMAP.md)을 함께 보세요.

## 1. 위습은 무엇인가요?

위습은 **유닛을 소환하거나 특정 보상·자원을 얻을 때 사용하는 재화**입니다. 모바일에서는 위습 개수를 공유 지갑에서 관리하고, 실제 보상 유닛은 보유 유닛 목록에 생성합니다. 위습마다 사용 방식이 다릅니다.

| 종류 | 원본 코드 | 사용 방식 | 무엇을 얻나요? |
|---|---|---|---|
| **랜덤위습** | `e0IX` | **위습 메뉴에서 직접 사용** | 흔함 유닛 / 골드·목재 추첨 / 도움소 마나 충전 중 선택 |
| **선택위습** | `e018` | **조합 메뉴에서 직접 사용** | 원본 자격을 충족하는 선택 대상 유닛 |
| **안흔함위습** | `e017` | **획득 시 자동 처리** | 안흔함 보상 풀 13종 중 1기 |
| **특별위습** | `e016` | **획득 시 자동 처리** | 특별함 보상 풀 33종 중 1기 |
| **희귀위습** | `e019` | **획득 시 자동 처리** | 희귀함 또는 특별함 보상 풀에서 1기 |
| **전설위습** | `e015` | **획득 시 자동 처리** | 전설 보상 풀 60종 중 1기 |
| **스토리 초월위습** | `e01A` | **스토리 보상 획득 뒤 직접 선택** | 꾸러미 보상 / 쿠마 / 레일리+해적선 중 하나 |

마지막 **스토리 초월위습**은 위의 여섯 종류와 별도로 관리하는 *스토리 보상 선택권*입니다. 일반적인 전설위습과 같은 자원이 아닙니다.

## 2. 게임에서는 어디서 사용하나요?

- **위습 메뉴 → 랜덤위습:** 세 가지 기본 기능을 펼쳐서 사용합니다. 버튼 한 번이 실행 한 번이며, 추가 확인 화면은 없습니다.
- **조합 메뉴 → 선택위습 사용:** 선택 가능한 유닛과 원본 요구 조건을 살펴보고 **바로 사용**합니다. 선택위습을 위습 메뉴에 중복 배치하지 않습니다. 위쪽 재화 표시줄에서는 개수를 확인합니다.
- **위습 메뉴 → 안흔함·특별·희귀·전설위습:** 보유 수와 자동 지급 상태를 확인합니다. 정상 조건에서는 별도의 수동 소환 버튼 없이 보상이 처리됩니다. 문제가 나면 원인과 재시도 가능한 상태를 표시합니다.
- **위습 메뉴 → 스토리 초월위습:** 지급받은 수량이 있을 때만 보상 선택지가 나타납니다. **메뉴를 여는 행위만으로 지급하거나 소비하지 않습니다.**
- **위습 메뉴 하단:** 최근 위습 사용 기록과 관련 재화 기능을 확인할 수 있습니다.

### 미사용 위습 전장 알림(모바일 화면)

플레이 중 공유 지갑에 **랜덤위습이 1개 이상** 남아 있으면 메인 전장 위쪽에 위습 빛 모양의 마커가 둥둥 떠 있습니다. 스토리의 미사용 **초월 보상 선택권**도 별도 마커로 표시됩니다. **선택위습은 전장에 떠 있지 않고 조합 메뉴에서만 사용**합니다. 마커에는 남은 개수를 표시하고, 실제로 전부 사용하면 즉시 사라집니다. 게임 일시정지·배속과 무관한 화면 장식 애니메이션이며 피해/배치/원본 난수에는 개입하지 않습니다.

- **랜덤위습 마커:** 탭하면 위습 메뉴에서 흔함 소환·자원 추첨·도움소 충전을 직접 선택합니다.
- **초월선택 마커:** 탭하면 위습 메뉴의 보상 선택으로 이동합니다. 자동 지급형 안흔함·특별·희귀·전설위습은 별도 수동 마커를 만들지 않습니다.

원본의 실제 위습 유닛 움직임을 그대로 시뮬레이션하는 것은 아니며, 미사용 위습이 전장에 계속 보이도록 하는 **모바일 시각적 대체 표현**입니다. 전장 마커 위의 터치는 전투 유닛 선택/스킬 시전으로 전달하지 않습니다. Android 실기 가독성 및 터치 검증은 별도입니다.

## 3. 랜덤위습으로 할 수 있는 세 가지

각 행동은 **랜덤위습 1개를 소비**합니다.

| 행동 | 보상·조건 |
|---|---|
| **① 흔함 유닛 소환** | 흔함 유닛 1기를 실제 보유 유닛으로 생성합니다. 원본 소환 풀에는 흔함 9종과 아주 낮은 확률의 해적선(`h060`, 24/10,000)이 포함됩니다. **한 번 누르면 즉시 소환**합니다. |
| **② 골드·목재 추첨** | 진행 중인 **1라운드 이상**에서 사용. **67% 목재 1개**, **33% 현재 라운드 × 75골드**를 받습니다. |
| **③ 도움소 마나 충전** | 살아 있는 실제 도움소(`h08A`)가 연결되어 있어야 합니다. 마나를 `min(100, 20 + ⌊라운드 × 1.5⌋)`만큼 충전하되 최대 마나를 넘지 않습니다. **이미 마나가 가득해도 사용하면 위습은 소비**됩니다. |

랜덤위습은 **자동으로 흔함 유닛을 뽑지 않습니다.** 플레이어가 세 행동 중 하나를 직접 선택합니다.

### 흔함 소환의 원본 추첨 구조 (개발 근거)

화면에서는 **1회 터치로 1회 소환**하지만, 내부에서는 원본 `YR → CRy → BIU`의 결과를 보존해야 합니다. 아래는 2026-10-27에 원본 JASS에서 추출한 분기이며, 네이티브 워크래프트 전체 난수 시드의 동등성을 뜻하지 않습니다.

| 원본 분기 | 처리 규칙 |
|---|---|
| `BIU` → 해적선 | `BFi(1,10000) <= 24`이면 **`h060` 해적선**. 흔함 9종 추첨·횟수 누적은 건너뜁니다. 결과 실물 생성이 불가능하면 **재추첨 없이 보류**합니다. |
| `BIR` (일반 추첨 횟수 홀수) | 흔함 **9종 중 1종**을 균등 추첨합니다. |
| `BIS` (일반 추첨 횟수 짝수) | 흔함 후보 두 개를 뽑고 같으면 두 번째를 다시 뽑습니다. 누적 소환 횟수가 **적은 후보**를 선택하며 동률이면 첫 후보를 사용합니다. |
| `BBv` | 정상적인 흔함 결과를 **실제 지급 완료**한 때만 해당 종류의 횟수 및 일반 소환 횟수를 늘립니다. |
| `BIY` | 첫 플레이어 `Vw=false` 소환 좌표는 `(-4768 + 256 × 원본 인덱스, 3232)`. 일반 자동배치로 덮어쓰지 않습니다. |

흔함 원본 `rawcode` 순서는 **루피 `h003` · 조로 `h002` · 나미 `h001` · 우솝 `h007` · 상디 `h004` · 쵸파 `h008` · 버기 `h005` · 해군 총병 `h009` · 해군 칼병 `h006`**입니다. 소환된 유닛의 원본 `A07Y` 능력 효과는 **소환 객체 확인과 별개**이며 검증 없이 승격시키지 않습니다.

랜덤위습 차감·소환·원본 누적 횟수는 공유 거래로 확정합니다. 실패 시 위습과 원본 추첨 결과를 보존하고, 동시에 두 소환 거래가 확정되지 않도록 잠급니다. 모바일에서 사용한 복구 가능한 난수 세션은 **원본 전체 `H6/BFi` 호출 순서의 재현이 아닙니다.**
## 4. 자동 위습 보상과 확률

| 위습 | 보상 분기 | 분기 안에서 선택하는 방식 |
|---|---|---|
| 안흔함위습 | 안흔함 13종 | 각 1가중치(동일 비중) |
| 특별위습 | 특별함 33종 | 각 1가중치 |
| 희귀위습 | **99% 희귀함 42종 / 1% 특별함 8종** | 먼저 99:1 분기를 추첨하고, 선택된 풀에서 각 1가중치 |
| 전설위습 | 전설 60종 | 각 1가중치 |

이 숫자는 **원본 JASS에서 추출한 보상 풀**을 현재 코드가 따르는 방식입니다. 유닛별 조합 재료가 아니라 위습으로 **직접 지급되는 결과**입니다.

**특별위습 보상 생성 위치:** 원본 `CSC`에 맞춰 플레이어 0번의 시작 좌표 **`(-3776, 4480)`**를 사용합니다. 다른 자동 배치 기능이 이 좌표를 덮어쓰지 않도록 별도 경로에서 처리합니다. 안흔함위습은 `(-3760, 3904)`를 사용합니다.

**희귀위습의 `A0YE`:** 99% 희귀함 보상에 기록한 개체별 권한을 유닛 메뉴의 **수동 희귀 리롤**에 연결했습니다. 공용 횟수·목재 비용·실물 교체는 [경제·도박 시스템](경제-도박-시스템.md)을 따릅니다. 네이티브 시전 준비·상속 비용과 Unity/APK 실행은 미검증입니다.

또한 풀의 가중치·분기는 반영했지만, 워크래프트 3의 **실제 난수 시드와 호출 순서까지 동일하게 재현한 것은 아닙니다.**

## 5. 스토리 초월위습 보상

원본 스토리 10단계 격파에 따른 초월위습 지급 경로와 확인된 원본 보상 사건을 모바일에 연결했습니다. 보상 선택권 **1개당 아래에서 하나**만 선택합니다.

| 선택지 | 현재 모바일 처리 |
|---|---|
| **꾸러미 상자 - 초월** | 중간 상자 유닛을 따로 만들지 않고, **골드 15,000~30,000 + 목재 14~20**을 각각 추첨해 즉시 받거나 **고유 아이템 10종 중 미획득 1종 + 목재 4개**를 선택합니다. |
| **바솔로뮤 쿠마** | 쿠마 유닛 1기를 지급합니다. |
| **실버즈 레일리 + 해적선** | 레일리 1기와 해적선 1기를 함께 지급합니다. |

고유 아이템은 **한 종류를 중복 획득할 수 없으며**, 해당 아이템이 이후 조합 재료로 사용되더라도 이미 한 번 받은 이력은 유지합니다. 보상 지급과 선택권 소비는 하나의 거래로 처리합니다. **꾸러미는 10종 모두의 원본 획득 경로지만 유일한 경로는 아닙니다.** 스토리 **5단계 AI03·6단계 AI00·8단계 AI02**의 **각 5% 격파 보상**도 같은 영구 획득 이력을 공유합니다. **이 스토리 드롭 자체에는 꾸러미의 목재 4개를 덧붙이지 않습니다.** [아이템 전체 획득 경로](전체-아이템-시설-목록.md).

**원본 꾸러미 고유 아이템 선택표:** `A14A→AI02`, `A14B→AI00`, `A14C→AI01`, `A14D→AI03`, `A14E→AI18`, `A14F→AI21`, `A14G→AI17`, `A14H→AI19`, `A14I→AI16`, `A14J→AI20`. 이는 **원본 수령 경로**의 확인이지, 고유 아이템 10종의 장착·사용 효과 완료가 아닙니다. [전체 아이템·시설 목록](전체-아이템-시설-목록.md)에 사용 효과를 추후 모두 연결합니다.

## 6. 행운의 토큰과 위습 획득

엘리자베스 관련 원본 기능으로 얻는 **행운의 토큰 실물 3개**를 교환하면 **80% 특별위습 / 20% 희귀위습** 가운데 하나를 얻습니다. 토큰은 별도의 숫자 재화로 바꾸지 않고, 보유한 **실제 토큰 유닛 세 개**를 소비합니다. 보상 위습은 위 4절의 자동 보상 규칙으로 이어집니다.

### 유닛 판매로 얻는 랜덤위습

현재 판매 서비스는 보유한 **실제 유닛을 판매한 뒤** 아래 보상을 지급합니다. 위습과 목재는 같은 공유 지갑에 반영되며, 판매 실패 시 거래를 되돌립니다.

| 판매 유닛 등급 | 랜덤위습 지급 | 목재 보너스 |
|---|---|---|
| 흔함 | **3기 판매할 때마다 1개** | 해당 3번째 판매 때 **35%로 1개** |
| 안흔함 | **50%로 1개** | 별도 추첨 **20%로 1개** |
| 특별함 | **1개 확정** | **35%로 1개** |
| 희귀함 | **2개 확정** | **1개 확정** |

이는 [현재 판매 코드](../Assets/Scripts/Mobile/Original323LowerGradeSaleService.cs)의 결과이며, 옛 문서에 기록된 **희귀함 판매 → 랜덤위습 2개·목재 1개**도 이 규칙에 포함됩니다.

위습을 얻는 다른 사건들은 해당 **스토리·상점·미션·유닛 효과**에서 각각 원본 지급 조건을 충족해야 합니다. 단순히 위습 버튼이나 메뉴를 열었다는 이유로 획득하지 않습니다.

## 7. 실패하면 어떻게 되나요?

1. 위습 종류·잔액·사용 가능 조건을 확인합니다.
2. 자동 지급은 보상 추첨 결과를 **보류 기록**한 뒤 실제 유닛 생성을 시도합니다.
3. 거래가 성공하면 위습 소비와 유닛 지급을 함께 확정합니다.
4. 생성·검증에 실패하면 지갑과 유닛 생성을 되돌립니다. **재시도 시 기존 추첨 결과를 유지**해 보상 재추첨을 막습니다.
5. 수동 행동은 한 번의 터치가 한 번의 실행입니다. 실행 도중 결과가 불명확한 예외가 발생하면 **임의로 자동 재실행하지 않습니다.**

보유 수·보류된 이유·최근 사용 기록은 모바일 화면에서 확인할 수 있습니다. 다만 **게임 전체를 종료하고 재실행했을 때의 전투·유닛·난수 상태까지 완전 복원하는 저장 기능은 미완성**입니다.

## 8. 현재 남아 있는 확인 사항

- **`A0YE` 검증 경계:** 수동 희귀 리롤은 코드 연결했으며 네이티브 시전 준비·상속 비용·실기 검증은 남아 있습니다.
- **원본 RNG·타이밍 동등성**: 확률과 보상 풀은 연결됐지만, 원본 네이티브 난수열까지 일치하는지는 확인되지 않았습니다.
- **초기 랜덤위습 수량:** 원본 JASS `CUo`가 **5개**를 지급하며, 모바일 `Original323SoloStartProfile`도 5개입니다. 단독 플레이 `CUn` 보너스를 포함해 골드는 60, 진화체는 1기입니다. 현재 코드 및 기존 테스트 기대값 일치를 확인했으며 최신 Unity·APK에서의 실동작은 미검증입니다.
- **실제 APK 검증**: 최신 `main`에 연결된 버튼·자동 지급·스토리 보상이 **지금 다운로드되는 이전 APK에서도 동일하게 작동한다는 뜻은 아닙니다.** 전 기능의 최신 통합 검사와 휴대폰 플레이 검증은 별도입니다.
