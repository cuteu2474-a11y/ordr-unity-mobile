## 1. 확인 완료: 실제 몬스터 마법 저항 체계

- JASS 전역 `JV=$41303451` = ASCII `A04Q` (490행).
- `Bd4`(8554행~)는 대상 몬스터에게 `A04Q` 능력을 추가하고 지정 레벨로 설정한다.
- `Bvi`(20698행), `CKz`(50860행) 등 몬스터 생성 시 `Bd4(Cm,LK[JG])`를 호출한다.
- `CUM` 악몽 분기(58030~58039행)는 `NJ=16`, `LK[0..3]=16`; 신 난이도는 21.
- `war3map.w3a`의 `A04Q` `Def5` (마법 피해 수령 배율)은 레벨 5~41에서 `0.79,0.80,...,1.15`.
- `Def5`는 Warcraft III Defend 능력의 **magic damage reduction / 마법 피해 수령 배율** 필드다. 엔진 구현 근거: Warcraft III ABILITY_RLF_MAGIC_DAMAGE_REDUCTION_DEF5 (필드 ID `Def5`).
- 따라서 **악몽 16레벨: 0.90배(저항 10%)**, 신 21레벨: 0.95배(저항 5%), 26레벨: 1배(저항 0%)이다.
- 원본 기록지침 아이템 `BhL`(10551행)에서 `LK[JG]+=5`: 몬스터 마방 5% 감소 효과와 일치한다. 브룩 특성 `BzL`(24958행)에서 `LK[JG]+=3`: 3% 감소.
- 워큐리 능력은 악몽에서 `LK[JG]`와 `NJ`를 15 낮춥니다. 이 값은 **이후에 생성되는 적**의 `A04Q` 레벨에 사용됩니다. 이미 생성된 적의 `Bd5` 등 개별 능력 수정 및 실제 엔진 반영 타이밍은 별도 검증 대상입니다.
- **추가 확인(2026-10-26):** `w3a`에 빠져 있던 `A04Q` 레벨 1~4는 원본 `Units\\AbilityData.slk`의 `DataE1..4`에 **0.75, 0.76, 0.77, 0.78**로 명시되어 있습니다. 따라서 1~41레벨의 개별 자료가 연결되었습니다. 레벨 42 이상과 개별 버프 중첩은 여전히 임의 계산 금지입니다.

## 1-1. 악몽 A04Q 레벨의 JASS 사건별 변화 추적 (2026-10-26)

동일 SHA-256 맵을 다시 확인하고 [이벤트 원본 근거 JSON](../data/original-2323C-nightmare-a04q-event-evidence.json)에 함수·원본 JASS 행번호·객체 데이터 SHA를 등록했습니다.

| 사건/시점 | 일반 몬스터 다음 생성 `LK[JG]` | 보스 다음 생성 `NJ` | 원본 |
|---|---:|---:|---|
| 악몽 시작 | 16 | 16 | `CUM` 58035~58039 |
| 워큐리 발동(악몽) | 전체 플레이어 −15 | −15 | `BeR` 8862~8881 |
| 니카가 워큐리 해제 | 전체 플레이어 +15 | +15 | `BeQ` 8750~8764 |
| 기록지침 아이템 `AI19` 사용 | 사용 플레이어만 +5 | 변화 없음 | `BhL` 10551 |
| 브룩 특성 `TR12` | 발동 플레이어만 +3 | 변화 없음 | `BzL` 24958 |
| 원피스 보물 완성 | 완료 플레이어만 +10 | 변화 없음 | `CRW` 55679~55680 |

악몽 기본 `A04Q=16`에서는 마법 피해 90% 수령(마법 저항 10%)이며, **워큐리 효과로 레벨 1이 된 이후에 생성되는 몬스터**는 레벨 1 원본 값에 따라 피해 75% 수령(마법 저항 25%)이 됩니다. 플레이어별 아이템·특성은 보스의 전역 `NJ` 값에 영향을 주지 않습니다.

`Original323NightmareA04QSpawnState`는 이 **다음 생성 시점에 쓰는 레벨**만 추적합니다. 이벤트는 독립 관측 근거(`IOriginal323NightmareA04QEventWitness`)가 있을 때만 반영하며, 지원 범위 1~41을 벗어나면 마법 저항률을 임의로 제한·계산하지 않습니다.

**중요한 한계**

- 이 객체는 원본 이벤트별 상태 모델이지 게임을 직접 플레이한 결과가 아닙니다. 원본 `Bd5` 등은 이미 생성된 **개별 유닛**의 마법방어 레벨을 바꾸므로 현재 살아 있는 몬스터의 레벨을 이 모델로 단정하지 않습니다.
- `ElderCurseCatalog.Warcury`의 설명용 마방 +15%를, 이미 `A04Q` 16→1 감소로 반영한 같은 몬스터에게 **다시 합산하면 중복 적용**입니다.
- 최종 체력·방어·스턴 면역·공격별 피해 계산, 이벤트의 실제 발동 여부 및 출현 위치는 독립 검증이 필요합니다. 이 상태 모델만으로 원본 65라운드를 실전 활성화하지 않습니다.

## 2. 확인 완료: 아머브레이크 방어력 보정

- JASS 전역 `Hl=$4130344D` = `A04M` (484행).
- `Bdq`(8524~8529행)는 대상에게 `A04M` 능력을 추가하고 레벨을 누적.
- 여러 스킬에서 `GetUnitAbilityLevel(target,Hl)-1`을 아머브레이크 스택으로 참조(21486행 등).
- 추출 `war3map.w3a`의 `A04M` 수정 필드 `Idef`는 레벨 **5~76**에서 **−4~−75 방어력**이다.
- 따라서 아머브레이크 스택 `N=level−1` 대응으로 **N=4~75인 구간의 방어력 감소는 −N**이라는 사실을 직접 검증했다.
- 스택 1~3에 해당하는 레벨 2~4는 실제 원본 `w3a` 덮어쓰기에서 찾지 못했다. 원본 워크래프트 기본 능력값 대조 전에는 구현에서 계산 보류.
- 별도 방어력 감소 능력 `A04N`(`Idef`,레벨5~11: −12~−30), `A04O`(5~11: −85~−115), `A04P`(5~41: −4~−40)도 확인. 실제 적용 유닛/스킬별 인스턴스 수집은 남음.
- 공통 전투 엔진 `armorBreakStacks`와 합치는 계산기가 추가되어 **A04M만 있는 확정 범위**의 몬스터 피해 계산에 활용됨. 다만 수집된 단순 `armorBreak` 태그만으로는 실제 JASS `Bdq(A04M)` 호출인지 알 수 없다. 실행에 사용하려면 `Ordr323VerifiedPartialModifierRules` 생성자의 **원본 A04M 스택 출처 검증 함수**에서 해당 적/스택을 승인해야 한다. 기본 생성자는 스택 >0 시 계산을 보류한다. 서로 다른 방깎 오라·발동형 상태가 있으면 임의 합산하지 않고 보류함.

## 3. 정확히 추적한 BdV 증폭 역산 우선순위

- `BdV`(8434~8457행)에서 `GetEventDamage()` 등의 관측 피해를 **역산**:
  1. 수비자에게 `B06J` 버프가 있으면 `/1.1`
  2. 그렇지 않고 `B04W` 있으면 `/1.25`
  3. 그렇지 않고 `B07S` 있으면 `/1.2`
  4. 다음으로 방어력 계수 `V2`가 양수면 `/V2`
- **if/elseif**이므로 세 버프가 동시에 붙어도 `1.1*1.25*1.2`로 전부 나누는 규칙이 아니다.
- `Ordr323JassDamageInversion`에 이 순서를 정확하게 옮겼다.
- 주의: 이 함수는 `GetEventDamage`를 역산하는 유틸리티이지 **모든 실제 공격의 증폭 누적 공식이 아니다.** 최종 전투 피해에 이 배율을 그대로 곱하지 않는다.

## 4. '방깎 총합' UI와 실제 몬스터 디버프는 다름

- `BH9`(4310행)는 캐릭터 능력/버프 테이블 등록이고 `BIH`(4374~4457행)는 **플레이어 유틸리티 정보창 집계**다.
- 구분 `Mo=1`: 오라형 방깎(`jP`), `Mo=2`: 오라형 이감(`jR`), `Mo=3`: 발동형 이감(`jS`), `Mo=4`: 발동형 방깎(`jQ`). 텍스트 확인 `BjK` 11924~11927행.
- `BIH`는 소유 유닛/중복 계열을 조사하여 **표시할 숫자만 선택**한다. 이 결과를 적 개체의 실제 방어력 차감 공식으로 사용하는 호출은 발견되지 않았다.
- 특히 `BIE`의 동일 그룹 비교는 한 특수 버프에서 더 큰 절댓값을, 나머지에서는 더 작은 절댓값을 택하는 실제 코드이므로 '무조건 최대치 하나'로 단순화하면 안 된다.
- **정보창 계산 ≠ 실제 중첩 법칙**. 실제 오라/발동 디버프가 적에게 적용되는 조합은 여전히 미완료.

## 1-2. 기존 몬스터 개별 A04Q 변경 연결 (2026-10-26)

- `CombatEnemy.TryApplyObservedOriginalA04QLevel`은 몬스터의 **현재 A04Q 레벨**과 원본 이벤트 관측 증빙을 받아 해당 몬스터의 방어 프로필만 갱신합니다. 기존 HP·최대 HP·기본 방어력·방어 타입은 그대로 둡니다.
- `CharacterCombatRuntime.TryApplyObservedEnemyA04QLevel` 및 `OrdrCharacterCombatController.TryApplyObservedLiveMonsterA04Q`을 통해 실제 피해 계산기가 참조하는 동일 몬스터 객체에 연결합니다. 외부 `IOriginal323LiveMonsterA04QWitness`가 정확한 몬스터 ID, 이전 레벨, 관측된 변경 후 레벨을 승인해야만 반영합니다.
- **미관측 상태에서 자동 변경하지 않습니다.** `LK[JG]`/`NJ`의 전역·플레이어별 변화는 이후 생성될 몬스터만 대상으로 하며, 이미 생성된 몬스터에게 소급하지 않습니다.
- 이전 능력 레벨이 미확인인 경우, 지원 범위 밖의 새 레벨(1~41 외), 중복·오래된 이벤트, 증빙 누락·테스트 전용 문자열, 사망 몬스터는 갱신을 거부합니다.
- 테스트는 검증된 *능력 데이터 표*가 실제 전투 경로에 즉시 반영되는지 가상 입력으로 확인하는 것이며, **실제 게임에서 Bd5 이벤트를 자동으로 관측하거나 최종 몬스터 HP·방어력을 수집했다는 뜻은 아닙니다.** 실전 몬스터 생성 승인은 기존 조건을 유지합니다.
