# 기록지침 시스템 — 모바일 구현 명세

> **최종 조작 원칙:** 기록지침은 왼쪽 메뉴에서 바로 여는 원본 기능 화면입니다. **보물 탐색은 가이몬 없이도 가능한 일반 기능**이며, 가이몬·나미는 효과를 보정합니다. 모바일에서는 지도 좌표를 직접 찍는 조작 대신 **`탐색` 버튼 한 번**으로 원본과 동등한 탐색 기회·발견 결과를 재현합니다. 베리는 사용자 결정에 따라 완전히 제외합니다.
>
> 원본: **ORDR S2 2.323[C]**. 이 문서는 **게임에서 어떻게 동작해야 하는지**를 정합니다. 실제 구현/검증은 [현재 상태](START_HERE.md), 남은 작업은 [개발 작업](PLAYABLE_ROADMAP.md)에서 판단합니다.

## 1. 기록지침에서 무엇을 하나요?

| 화면 안의 기능 | 플레이어가 보는 것과 하는 일 | 중요한 구분 |
|---|---|---|
| **보물 탐색** | 남은 보물·탐색 가능 여부 확인 → **탐색** 한 번 → 꽝 또는 실제 위습 보상 | **기본 기능**. 가이몬 보유·꿈 발동이 탐색 자체의 조건은 아님 |
| **항법·진행 정보** | 항법 선택 가능 시점, 현재 선택, 남은 조건 확인. 원본에서 요구하는 항법 선택 흐름으로 이동 | 도움소·도박소의 전용 행동을 기록지침에 복제하거나 중복 실행하지 않음 |
| **기록 능력·미션 보상** | 와일드카드·로얄로더 등 실제 획득한 능력/레벨과 관련 진행 상태 표시 | 보상을 **지급한 원본 사건**이 확인되어야 상태 변경. 임의 구매·무료 승급 버튼 금지 |
| **특수 정보** | 보물 위치 공개 등 원본에 있는 정보 효과 표시 | 정보 공개와 실제 수집·보상 지급은 다른 사건 |

기록지침을 별도 시설 탭이나 빠른 이동 메뉴로 중복 생성하지 않습니다. 전장 한가운데 새 조작창을 띄우거나 메뉴를 여러 번 왕복하게 만들지 않습니다. 원본 기능과 관계없는 ‘기록 도구’ 버튼도 다시 추가하지 않습니다.

## 2. 일반 보물 탐색 — 원본에서 확인된 규칙

원본 `Units/UnitAbilities.slk`에 **보물찾기 능력 `A05D`**를 가진 객체가 **기록지침 `H0C4`와 시노부(제한) `h084`**로 확인됩니다. 가이몬(특수) `h0BG`는 이 능력의 필수 소유자가 아니라 **탐색 효과를 강화하는 별도 유닛**입니다.

| 상황 | 원본 행동 | 모바일에서 지킬 결과 |
|---|---|---|
| 보물 생성 | 10·20·30·40·50라운드마다 `BeM`이 보물 **4개**를 원본 영역 내 무작위 좌표에 추가 | 보물 총수·출현 라운드·수집 여부 관리. 매번 기존 보물을 초기화하지 않음 |
| 보물지도 효과 | `BeM`의 **추가 보물 3개** 생성 경로 | 보물지도를 실제 사용한 사건에서만 추가. **시작 시 무료 3개 지급으로 해석하지 않음** |
| 일반 탐색 | `CJm → BeN`이 탐색 중심 기준 **가로·세로 각각 ±850** 영역에서 미획득 보물을 찾음 | 가이몬이 없어도 허용. 보물 없으면 **꽝**, 한 번에 여러 개가 범위에 있으면 **복수 획득** |
| 가이몬의 꿈 | `CCP`가 실제 가이몬 획득/적용 상태에 따라 1회 플래그를 변경 | 적용 뒤 탐색 반폭 **978**, 가이몬+확인된 나미 상태면 **1,125**. 가이몬 부재 시 기본값 850 |
| 나미 보정 | 원본 `YL` 상태에 따라 위습 수량 추첨이 추가되며 가이몬 효과와 상호작용 | 단순 ‘나미를 보유 중’이라는 이유로 `YL`을 추측하지 않음. 원본 상태·적용 시점을 확인 |
| 가이몬의 위치 공개 | `CCQ → BeN(..., false)`가 시작 지점 기준 반폭 **2,000** 내 보물 정보를 공개 | 수집·위습 지급 **0건**. 탐색 성공률을 바꿀 정보 효과는 내부 기회 모델에 반영 |

### 보상을 정하는 방식

- **50라운드 이전, 일반 탐색:** 발견한 보물 하나당 **랜덤위습 또는 안흔함위습**을 원본 `BFi(1,2)`로 결정합니다.
- **50라운드 이전, 가이몬의 꿈 적용:** 위의 랜덤위습 분기가 **흔함선택위습**으로 바뀌며, 안흔함위습 분기는 유지됩니다. 가이몬 보상은 **보물 한 개당 위습 2기**입니다.
- **50라운드 이후:** 발견 보상의 종류는 **랜덤위습**이며 가이몬 적용 시 2기입니다.
- **나미의 `YL` 보정:** 원본은 `YL`이 참이면 위습 수량 `1~2`를 추가 추첨한 뒤 가이몬 상태가 참이면 2기로 덮어씁니다. 같은 난수 호출 순서까지 고려해야 합니다.
- **베리:** 원본에 추가 지급 분기가 있지만 **모바일에서는 획득·잔액·표시·사용 전부 제외**합니다. 다만 원본의 확률 추첨이 공유 난수열에 영향을 주므로, 베리만 버리더라도 후속 게임 결과가 달라지는지 검토해 **난수 호출 순서와 보상 제외를 분리**합니다.

위의 **보상 종류 1:1 분기**를 ‘탐색 버튼의 성공률 50%’로 착각하면 안 됩니다. 성공 여부는 **실제 남은 보물 수·내부 탐색 위치·탐색 범위·정보 공개 상태**에 달려 있습니다.

## 3. 모바일에서 실제로 누르면 어떻게 처리하나요?

1. **기록지침 열기:** 남은 보물 수와 탐색 가능/불가 사유를 보여줍니다. 가이몬 보유 여부는 버튼 활성화 조건이 아니라 **효과 상태**로 표시합니다.
2. **탐색 한 번 누르기:** 현재 라운드·원본 보물찾기 능력/기회·소모 조건을 검사합니다. 원본 `CJm`의 레벨별 분기와 `BJI` 호출의 의미는 검증 없이 ‘무료·무제한’이나 임의 쿨타임으로 바꾸지 않습니다.
3. **내부 탐색 시행:** 사용자에게 지도 좌표를 요구하지 않습니다. 원본의 `BFj` 위치 분포와 보물 누적 상태를 기준으로 **한 번의 유효 탐색 기회**를 사용합니다. 이미 공개된 보물 정보가 있으면 그 정보의 영향까지 반영합니다. 정확한 조작 대응은 원본과 동일 조건의 발견 분포로 보정합니다.
4. **결과 정산:** 못 찾았으면 꽝. 찾았으면 여러 보물도 모두 처리하고 각 보물의 원본 위습 결과를 **공유 지갑에 한 번만 지급**합니다. 정산 실패에는 원래 결과를 보관하고 재시도 때 재추첨하지 않습니다.
5. **화면 갱신:** `남은 보물`, `이번 탐색 결과`, `획득 위습`만 간결하게 표시합니다. 이미 소모한 기회·수집한 보물이 화면 전환이나 앱 재개로 되살아나면 안 됩니다.

**버튼 한 번 = 탐색 한 건**입니다. 길게 누르기는 설명만, 스크롤은 실행하지 않습니다. 추가 확인 팝업과 고정 당첨 연출은 만들지 않습니다.

## 4. 기록지침의 다른 기능과 연결하기

| 기능 | 확인된 근거·현재 구조 | 연결 기준 |
|---|---|---|
| **항법 선택 안내** | 원본 `CVC`는 21라운드부터 기록지침을 통한 선택을 안내하고 25라운드 이전 선택을 요구합니다. `Original323NavigationSelection`은 **21R 이후 한 번 선택** 상태만 공통 관리 | 선택 자격·원본 전체 선택지·선행 효과·25R 미선택 처리까지 대조. 도박소/도움소 전용 실제 기술은 해당 메뉴의 서비스를 재사용하고 **선택권을 이중 소비하지 않음** |
| **와일드카드·로얄로더** | 개인미션 보상의 `AddAbilityLevel`·`SetAbilityLevel`이 UI에서 기록지침 능력의 단계로 표시됨 | 실제 미션 보상 영수증 → 기록지침 기술 상태 변경 → 적용 효과 → 저장. 원본 활성 스킬·조건/비용을 확인 전까지 새 구매 기능 추가 금지 |
| **기록·특수 조작** | 원본 전체 항법/기록 관련 사건의 세부 효과가 일부 미확인 | 근거가 확인된 기능만 카드를 열고, 없는 기능을 ‘추정 버튼’으로 채우지 않음 |

**누적 클리어 횟수**는 기존 게임 기록 상태에서 유지하며 베리와 연동하지 않습니다. 스토리·위습·미션·도박 기능도 기록지침에 중복 버튼으로 추가하지 않습니다.

## 5. 현재 코드와 원본의 차이 — 개발 시 우선 수정

| 현재 확인된 코드 경계 | 왜 문제인가 | 구현 방향 |
|---|---|---|
| `OrdrMobileTouchPanel.DrawTreasureGacha`가 **가이몬 보유·꿈 적용**을 버튼 조건에 넣음 | 기본 보물 탐색이 차단됨 | `기록지침 + 일반 탐색 자격`과 `가이몬 강화 상태`를 분리 |
| `OrdrCharacterCombatController.RequestMobileTreasureGacha`도 같은 조건으로 거절하고 `TrySearch(..., true, ...)`를 고정 호출 | 화면만 풀어도 서비스가 거부하거나 **보상을 가이몬 방식으로 계산**함 | 실제 꿈/나미 상태를 사용해 일반·강화 탐색을 공통 실행 |
| `MobileTreasureAttempt`는 `nami && !gaimon`을 불허 | 가이몬 없이 나미 보정이 적용되는 원본 `YL` 경로와 충돌 가능 | 위습 수량 보정 플래그와 가이몬 꿈 플래그를 별도 모델링해 원본 진입 조건 대조 |
| `MobileTreasureGacha`는 외부 검증된 시도 공급자 없이는 실행 불가 | 클래스 존재·버튼 존재만으로 실제 모바일 게임이 작동하지 않음 | 원본 `BeM/BFj/BeN/BeI`에 근거한 **독립 모바일 기회/보물 생성·정산 연결**을 만들되 검증되지 않은 고정 당첨률을 주입하지 않음 |
| `Original323TreasureWalletWorld`는 외부 원본 시전 관측을 전제로 함 | 단독 APK에서 관측 공급자가 없으면 지급까지 이어지지 않음 | 원본 기반 **독립 실행 모델**과 원작 대조용 관측 포트를 명확히 구분해 통합. 공통 영수증·롤백 재사용 |
| `OrdrMobileTouchPanel` 개인미션 화면과 `MobileTreasureGachaResult.RewardText`에 **베리 문구**가 남아 있음 | 최신 사용자 제외 정책과 불일치 | 베리 표시·지급 경로 모두 제거하되 난수 순서 변화는 별도 판정 |

**재사용할 코드:** `Original323TreasureHunt`(원본 좌표/발견/보상), `MobileTreasureGacha`(탭 한 번의 기회·중복 차단), `Original323GaimonDreamState`(효과 상태), `Original323GaimonRevealPort`(정보 공개), 기존 `EconomyWallet`(지급 영수증), `NavigationProgression`/`Original323NavigationSelection`(항법 상태), `OrdrMobileTouchPanel`/컨트롤러(화면·입력). 공통 기능을 복제하는 별도 가이몬 전용 탐색 엔진은 만들지 않습니다.

## 6. 완료 판정 및 아직 확인할 원본 항목

- [ ] **가이몬 없이** 기록지침에서 일반 탐색이 실제로 실행되고, 시노부 `A05D`도 원본 자격에 따라 동작합니다.
- [ ] 원본 보물의 10/20/30/40/50R 출현·보물지도 추가 3개·잔여 수·복수 발견을 유지합니다.
- [ ] 기본/가이몬/나미 보정, 50R 전후 보상, 위치 공개와 실제 수집의 차이를 유지합니다.
- [ ] 모바일 탐색 시도·원본 `A05D` 레벨/시전/기회 조건을 검토하며 보정 전 분포를 임의 확률로 확정하지 않습니다.
- [ ] 위습 원자 지급·실패 복구·난수열·중복 탭·저장/복원까지 일관되게 처리합니다. **베리 지급·표시는 없습니다.**
- [ ] 항법·와일드카드·로얄로더는 실제 원본 사건/능력으로 연결하고, 원본 미확정 항목은 상태만 표시합니다.
- [ ] **실행 요청을 받았을 때** Unity·Android에서 일반 탐색→가이몬 획득→나미 보정→50R 전환→저장 복구까지 묶어서 확인합니다.

**원본 근거:** [원본 2.323[C] 보물 조사 JSON](../data/original-2323C-treasure-research.json)의 `searchAbilityOrigin` 및 `BeH/BeI/BeM/BeN/CCP/CCQ/CJm/CVC`와 고정 원본 JASS 해시([개발 규칙](../AGENTS.md)). 항법 상세는 [악몽·이세계·항법](악몽-이세계-항법-시스템.md), 현재 상태는 [START_HERE](START_HERE.md), 다음 작업은 [개발 작업 F01](PLAYABLE_ROADMAP.md)입니다.
