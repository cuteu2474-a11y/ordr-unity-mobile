## 강화소 1 — 8종

표의 `시작값 + 증가값`은 `UpgradeData.slk`에 기록된 **레벨 1 기준치와 다음 레벨당 변화량**입니다. *이미 획득한 버프를 매번 누적 합산*한 수치가 아닙니다. 골드 역시 `goldbase + (레벨-1)×goldmod`로 계산한 **원본 필드 투영값**이며, 실제 결제 영수증·게임 내 최초 구매 레벨은 별도 확인 대상입니다.

| 기술 | 최대 | 골드: 시작 + 단계 증가 | 공속 필드: 시작 + 단계 증가 | 공격력 필드: 시작 + 단계 증가 | 시작시 1레벨 지정 |
|---|---:|---|---|---|---|
| 흔함류 `R00F` | 7 | **3 + 2** | 효과 코드 미기재 | **3 + 3** | 없음 |
| 희귀 `R008` | 16 | **10 + 20** | **70% + 4%p** | **200 + 200** | 있음 |
| 불멸 `R002` | 21 | **100 + 50** | **210% + 6%p** | **30,000 + 2,500** | 있음 |
| 특별 `R00E` | 15 | **5 + 5** | **25% + 2%p** | **20 + 30** | 있음 |
| 초월 `R003` | 21 | **100 + 50** | **215% + 6%p** | **22,500 + 2,150** | 있음 |
| 제한 `R004` | 21 | **90 + 50** | **185% + 5%p** | **20,000 + 2,000** | 있음 |
| 전설 `R000` | 21 | **70 + 50** | **195% + 5%p** | **7,250 + 725** | 있음 |
| 랜덤전용 `R019` | 21 | **90 + 40** | **25% + 14%p** | **1,000 + 1,000** | 있음 |

주의: `R00F`는 수치 필드 `base1=0.03/mod1=0.03`이 있어도 `effect1` 코드가 없습니다. 이를 **공속 +3%**라고 활성화하면 안 됩니다. `R002`의 툴팁은 ‘공격력 2,500 증가’를 안내하지만 SLK에는 `base2=30,000/mod2=2,500`이 저장돼 있습니다. **기본값과 레벨 증가값이 다른 구조**입니다.

## 아직 ‘실제 게임 검증’으로 취급하지 않는 것

1. **원본 레벨 기준:** `CUo`의 초기 1레벨 지급, `CV8`의 연구 시작 즉시 기술 레벨 갱신, 원작 자체 연구 완료 증가가 합쳐지는 실제 최종 레벨·구매 횟수. 단순한 353칸 합계를 실제 구매 353번으로 해석하지 않습니다.
2. **가격 최종 차감:** SLK 공식상 단계별 골드는 추출됐지만 실제 지갑 차감은 연구 시작·완료·취소·할인 등의 경로까지 확인해야 합니다. SLK에 미기재된 `lumberbase/timebase`는 소스 JSON에서 `null`을 유지합니다.
3. **효과 적용 대상:** 기술 `rats`(공속)·`ratx`(공격력) 데이터가 어떤 현재/미래 유닛에 상속되고, 보조 강화 기술에 다시 전달되는지 전수 확인해야 합니다. JASS의 연계 업그레이드 처리(`CV8`)도 존재합니다.
4. **APK 상태:** 이번 작업은 *원본 W3X 정적 추출 및 문서화*입니다. `Original323PlayerUpgradeSession`의 실제 효과 적용자·연구소 구매 처리·저장·복원·취소·Unity/Android 검사는 미완료입니다. 이 근거만으로 강화 구매 버튼을 활성화하지 않습니다.
