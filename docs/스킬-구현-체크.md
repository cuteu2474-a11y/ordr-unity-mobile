## 3. 자동 감사표가 최신 구현과 어긋나는 이유

현재 저장된 감사 JSON은 554개 기술을 코드 근거16/일부4/등록 검토409/미확정125로 분류하고 `validatedWitnesses=20`으로 기록합니다. 반면 현재 수동 증거 원장에는 **27개 등록**이 있습니다.

27개는 모두 지정 처리기와 호출 문자열을 현재 파일에서 찾을 수 있었지만, 이를 자동 도구 재실행 결과나 27개 완성 스킬로 표시하지 않습니다. 과거 일부 분류에는 쿠마 후속 스턴처럼 지금 코드와 어긋나는 설명도 있습니다.

**27개 원장 등록 중 기존 감사표에서 여전히 등록 검토/미확정인 7개:** I-10:skill:1·2(제트), D-06:skill:0·1(바제스), I-07:skill:0(센고쿠), D-04:skill:0(페로나), L-33:skill:1(크래커). 최신 수동 스킬 4종과 전용 다단타는 별도로 증거 보강이 필요합니다.

따라서 16/554를 실제 구현률로 쓰거나 125개를 미구현 개수로 쓰지 않습니다. 프로필200과 기술 보유 프로필182의 차이는 기술 없는 프로필을 포함한 집계 기준 차이이며 그 자체로 누락이 아닙니다.

**다음 정리 방식:** 실제 효과별 호출 근거를 원장에 보강 → 현재 한계에 맞게 증거 설명 수정 → 허가된 실행 작업에서 기존 생성 도구로 JSON/CSV/문서를 함께 재생성. 이번에는 Python 실행 없이 별도 수동 체크 문서만 작성했으며 자동 생성 파일은 손으로 고치지 않았습니다.

- 비비/핸콕 다단타: 중간에 적 사망·신규 진입·파견·일시정지 발생 시 원본 타깃 선정과 남은 타수 확인.
- 히바리: 아이템 없음/사용 성공/실패/같은 요청 재전달/수신자 교체에서 아이템·버프·영수증 일치.
- 비비 강화: 추첨 후 지갑 알림 예외 발생 시 재시도 결과·비용·난수 위치 확인.
- 쿠마: 확률 공격과 전이 후 강제 시전 구분, 기절 1회·추첨 1회 또는 추가 추첨 없음 확인.
- 마리아/센고쿠/슈가: 진행 중 저장, 정상 만료, 소유자 제거, 전장 이동의 타격·효과·보상 차이 확인.

기존 검사 소스의 존재는 확인했으나 실행하지 않았습니다. 이번 결과의 한계는 원본 JASS/실기 전수 대조 없음, 554개 전체 호출 완결성 미검증, 실패 주입 재현 없음입니다. 코드에 명시된 수치/현재 모델과 원작 동등성은 구분합니다.
