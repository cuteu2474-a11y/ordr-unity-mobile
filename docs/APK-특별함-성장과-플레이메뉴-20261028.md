# 특별함 성장과 플레이 메뉴

`4e3a750`의 10라운드 개발용 연습 전투에 이어, 전투 준비와 등급 성장을 보완했다.

## 플레이 순서

1. 첫 화면의 **유닛 준비하고 시작**을 누르면 위습 메뉴가 열린다. 준비 중에는 적 출현과 전투 시계가 진행되지 않는다.
2. 시작 랜덤위습을 직접 소환하고 필요하면 조합한다. 전투 유닛이 0개이면 화면의 전투 시작 버튼을 비활성화해 빈 전장으로 실수로 시작하지 않도록 한다.
3. **10R 연습 전투 시작** 또는 플레이 메뉴의 **준비 완료**를 누른다. 이미 받은 시작 자원·보유 유닛을 유지한다.
4. **플레이** 메뉴에서 위습 소환, 보유 유닛·판매, 현재 만들 수 있는 조합으로 바로 이동한다. 조합은 선택·확정 후에만 재료를 소비한다.
5. 보유 유닛이 바뀌면 열려 있는 플레이/조합 메뉴가 0.5초 주기로 변경을 감지해 재료 상태를 다시 계산한다. 화면 갱신은 소환·조합·난수·전투 시간을 실행하지 않는다.
6. 전투 메뉴에서 보스 체력, 누적 적 경고, 전투 시간·처치 수·처치 골드·라운드 위습을 확인한다. 완료한 라운드마다 소요 시간·실제 처치·골드·남은 적을 기록하며, 게임 종료 뒤에도 메뉴에서 볼 수 있다. 기록은 이번 실행에만 유지된다.

## 특별함 성장

기존 안흔함 13종에 **특별함 31종 재료 조합**을 더해 실행 가능한 조합이 총 44종이다. 예를 들어 원본 `A012`는 흔함 루피 3개를 소비해 `h00U / S-07` 루피 기어세컨드를 만든다. 추가 골드·목재를 임의로 요구하지 않는다.

`Original323CommonFusionPort`에 명시한 능력·결과 rawcode·프로젝트 ID를 원본 JASS와 객체 자료로 대조했다. `CHu/CHx/CHy` 재료 처리와 `CT1` 시전자가 가진 능력을 검사하며 결과는 실제 시전자 위치에 생성한다. 원본 `UPUN`은 `CH5/CHi` 검사·차감 콜백이 없는 표시 항목이며 추가 유닛 재료로 소비하지 않는다. 전투 중 조합도 기존 원자적 교체를 사용하고, 사라진 재료 ID·중복 ID·다른 유닛으로 바뀐 오래된 확인은 거부한다.

- `A19Z` 스모커와 `A1A1` 스쿼드는 `AOsf` 계열 네이티브 시전 경로 추가 대조 전까지 제작을 열지 않는다.
- `A029` 압살롬은 실제 좀비 3개를 요구한다. 좀비를 공짜로 지급하거나 현재 미연결인 좀비 획득 경로를 만들지 않았다.
- 원본 고정 파일은 읽기만 했다. 원본 맵은 수정하지 않았다.
- [감사 결과](../data/original-2323C-special-material-swaps.json), [감사 도구](../tools/audit_original_special_fusions.py).

특별함도 같은 연습 전투의 기본 공격 파이프라인에 연결한다. 객체 공격력 주사위·공격 주기·첫 공격 지연과 기존 모델 방어 계산을 사용하며, 조합 후 자동 공격자가 재등록된다. 기술·오라·연구·네이티브 광역 평타는 이 연습에서 완성된 기능으로 간주하지 않는다. 평타 연습에서는 모리아의 좀비 재료 보상과 네이티브 추가 발동도 차단한다. 정식 원작 피해 검증 플래그는 계속 false다. 65라운드 완성이나 원작 최종 전투 동등성을 의미하지 않는다.

## 검사

- 고정 원본 JASS·AbilityData.slk를 읽어 특별함 31종의 재료·결과·원본 능력 소유자·타깃 없는 시전 종류와 타이밍을 대조했다.
- 로컬 Python 자료 회귀 144건 통과, `git diff --check` 통과.
- Unity EditMode에 31종의 실제 재료 소비/결과 생성 사례와 특별함의 오래된 재료 거부, 기본 공격·스킬 차단, 전투 중 루피 조합 뒤 공격 지속 사례를 추가했다. 기존 10라운드 완료 검사는 기록 합계·중복 방지도 확인하도록 확장했다.
- 로컬 Unity 실행 환경이 없어 Unity 컴파일·EditMode 실행·APK 생성은 기존 GitHub Actions에 맡긴다. 실행 시작만 확인하고 결과는 요청 전 조회하지 않는다. 모바일 실기 터치·가독성·성능은 미검증이다.
