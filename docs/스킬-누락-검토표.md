## 어떤 순서로 실제 누락을 판정하나요?

1. **유닛 확인:** 등록 ID·원본 rawcode가 현재 보유 유닛과 같은지 확인합니다. 변신·소환·보조 유닛은 본체와 별개입니다.
2. **원본 사건 분해:** 공격 선언, 확률 추첨, 주문 시전, 대상 선정, 타격, 상태·지속 피해, 종료를 구분합니다. [관측형 스킬 기준](원본-관측형-스킬-시전-타격.md)을 사용합니다.
3. **기존 처리기 대조:** `CharacterCombatRuntime.SourceModel*.cs`, `SourceModel*SkillCatalog`, `CombatSkillTriggerEngine`, 네이티브 패시브 및 예약 효과 큐에서 이미 구현한 부분을 찾습니다. `SourceModelUnconnectedSkillCatalog`라는 **클래스 이름만 보고 미연결이라고 판정하지 않습니다.**
4. **한 효과 단위로 상태 판정:** `이미 연결 / 일부만 연결 / 원본 자료 부족 / 구현 누락 확정` 네 가지 중 하나로 구분합니다. **확률·쿨타임·대상·피해량** 중 근거가 빠지면 완료로 표시하지 않습니다.
5. **묶어서 구현:** 실제 누락으로 확정한 효과만 공통 전투 엔진에 연결하고, 원래 분기 난수·면역·공격/마법 유형·소유자 생명주기를 유지합니다. 중복되는 도감 기술 자동 발동은 추가하지 않습니다.

개별 행의 최종 판정은 새로운 감사 데이터를 근거로 갱신합니다. 이 문서에 과거 코드 변경 이력이나 빌드 통과 숫자를 누적하지 않습니다.

## 이 표로 '완료'라고 말할 수 있는 조건

- **코드 조사 완료:** **추가 검토 17행** 각각에 ‘기존 담당 처리기’ 또는 ‘누락된 세부 효과’를 판정해야 합니다. 이미 피해 일부가 연결된 **14행**은 네이티브 주문·부가 효과의 남은 부분까지 구분합니다. 단순 유닛 카탈로그 등록은 제외합니다.
- **구현 완료:** 실제 누락이 확인된 각 효과는 발동 → 비용/쿨타임 → 타격/상태 → 종료 경로가 이어져야 합니다. 본체 사망·판매·파견 변경 후 예약 타격이 남지 않아야 합니다.
- **검증 완료:** 검사 명시 요청이 있을 때 Unity와 실기에서 실행해야 합니다. 현재의 문서·코드 대조만으로 원작 동등성이나 APK 완성을 선언하지 않습니다.
