# 스토리 시스템

> **읽는 순서:** 이 문서는 게임에서 스토리를 어떻게 진행하고 어떤 보상을 받는지 설명합니다. 기준은 ORDR S2 2.323[C] 악몽·이세계모드의 현재 `main` 코드입니다. **코드에 경로가 있다는 사실과 최신 APK·실기에서 완성됐다는 사실은 다릅니다.** 전체 현황은 [현재 상태](START_HERE.md), 실제 미완성은 [개발 작업](PLAYABLE_ROADMAP.md)으로 확인합니다.

## 1. 스토리는 어떻게 진행하나요?

- 스토리는 **유닛을 조합하는 메뉴가 아니라, 적 건물을 파괴하는 별도 전장**입니다. 메인 전장 위·작은 스토리 전장 아래 배치입니다.
- 시작 때 **로그타운**을 생성합니다. 각 건물을 격파하면 원본 순서에 따라 다음 단계가 진행됩니다. **총 14개 건물**이며 임의로 단계 해금 버튼을 만들지 않습니다.
- 공격할 유닛을 직접 선택해 **스토리 파견**하고, 필요하면 수동 복귀합니다. 원본 CWL/CWM 이동 자격이 유효할 때 실제 유닛의 전장만 변경합니다.
- **원본 스토리 진입 잠금:** 유닛이 스토리 진입 구역으로 이동할 때 `CWL`은 플레이어의 **일반 보스 생존 수(`un`) 또는 개인 토벌 적 생존 수(`lN`)가 0이 아니면 진입을 거부**하고 ‘보스 혹은 미션유닛이 살아있어 스토리로 이동할 수 없다’고 안내합니다(`CWK`). 반면 `CWM`의 메인 전장 복귀 경로에는 이 두 카운터 검사가 없습니다. 모바일의 수동 파견에도 **진입 차단과 복귀 허용을 구분**해야 하며, 파견 UI만 구현됐다는 이유로 원본 조건을 충족했다고 보지 않습니다. 원본 `war3map.j` `CWL/CWK/CWM`, 토벌 카운터 `CKz/CKx/CKy`, 일반 보스 카운터 `CVb/CVr/Bdf` 참조.
- 전장에 건물 HP·파괴 진행도·파견 유닛 수·일부 제한 시간이 표시됩니다. 화면상의 카드 위치는 유닛의 실제 전투 좌표를 변경하지 않습니다.
- **악몽 35라운드 시작 때 13단계 와노쿠니가 남아 있으면 패배**합니다. 13단계 격파 뒤 120초 후 14단계 에그헤드가 등장하며, 등장 뒤 240초 이내에 파괴해야 합니다.
- 스토리 건물 처치는 일반 65라운드 몬스터의 처치·누수·남은 수 집계와 별개입니다. 싱글플레이에 별도의 MVP/기여도 화면을 만들지 않습니다.

## 3. 특히 중요한 스토리 보상

| 시점 | 원본 규칙과 현재 연결 | 아직 구분할 것 |
|---|---|---|
| **5·6·8단계** | 각 건물 **실제 격파 시 5% 확률의 고유 아이템** 분기: **5단계 스릴러바크 → AI03, 6단계 샤봉디제도 → AI00, 8단계 마린포드 → AI02**. 이미 한 번 수령한 종류는 제외하고, 같은 격파 영수증으로 기초 보상과 함께 확정하는 코드 경로가 있습니다. | 5% 추첨 결과와 **영구 수령 이력**은 별도이며, 아이템을 사용/소비해도 재획득하지 않습니다. 전체 저장·실기·원본 난수열 검증은 별도입니다. [아이템 전체 목록](전체-아이템-시설-목록.md). |
| **9단계** | 고대의 배 `h05Y` 생성 경로를 실물 로스터에 연결했습니다. 원본 `R01N/O/P/Q/S` 연구 진행도 중 해당 단계도 추적합니다. | 다른 종류의 도박 배와 혼동 금지. |
| **10단계** | 원본 `e01A` 초월위습 지급 사건과 **연습 선택권**을 구분합니다. 위습/스토리 메뉴에서 꾸러미·쿠마·레일리+해적선 중 직접 선택하는 경로가 있습니다. | 모델 격파만으로 원본 `CQB` 지급 증거를 중복 처리하지 않습니다. [위습 설명](위습-시스템.md). |
| **13·14단계** | 원본 영웅 그룹 대상 **경험치 300** 사건을 모바일의 현재 원본 객체/폼 매핑·영웅 성장 경로에 연결했습니다. | 비영웅에게 임의 지급하거나 실제 워크래프트 영웅 그룹 `Hp[VT]`와 완전 동일하다고 주장하지 않습니다. |
| **14단계** | 그린블러드 `A13A` **1회 사용권**과 네 세라핌 변신(`SPH1~4`)을 원자 거래로 처리하는 경로가 있습니다. | 일반 대상에 `A134/A13C` 추가, 후속 `CEN` 및 실제 적용 결과는 미완성 부분을 구분합니다. |

원본 스토리 연구 다섯 종류는 **5·8·9·10·12단계**에서 `R01N/R01O/R01P/R01Q/R01S`로 기록합니다. **8~13단계의 `BdL`은 이세계 유닛 도박 충전을 각 1회 지급하며 특성포인트를 주지 않습니다.** 이전 특성포인트 해석을 교정했습니다. 충전은 같은 지갑에서 실제 도박 결제로 소모합니다. [경제·도박 규칙](경제-도박-시스템.md).

원본 9~14단계 건물의 기초 재생량은 초당 1,000 HP이며, 14개 건물의 원본 기초 HP·방어·연구 보정은 별도 자료로 보존합니다. 원본의 네이티브 연구 적용 순서, 동적 `NJ`, 전체 면역·방어·피해 최종값은 **실전 동등성 확인 전**입니다.

## 4. 모바일 화면·전투의 경계

**사용자 확정 UI:** 스토리 메뉴 안에서 **건물 공략 / 크립 사냥**을 전환합니다. 듀공·파파구·슈슈는 대상 선택 뒤 실제 보유 개체를 수동 파견·복귀하는 흐름으로 둡니다. 화면을 바꿔도 건물 단계·제한시간·파견을 유지하고, 건물과 크립은 별도 전투 목적지로 판정합니다. 상세 행동·중복 출전 방지는 [토벌·크립 파견 명세](토벌-크립-파견-시스템.md)를 따릅니다. 이 확정 설계를 현재 APK에 구현됐다는 뜻으로 읽지 않습니다.

- 파견·복귀는 플레이어가 실행합니다. **스킬·일반 공격은 전투 공통 엔진**에서 처리하며, 스토리 카드가 별도의 피해 계산을 하지 않습니다.
- 스토리 보상·위습·유닛 생성은 메인 전장과 **같은 지갑과 유닛 인스턴스**를 씁니다. 실패 시 한 기능이 이미 처리한 보상을 재지급하지 않도록 원본 사건/영수증을 확인합니다.
- 원본에서 실제 건물 출현을 확인하는 공급자 없이 **임의 생성·클리어·보상 지급**을 승인하지 않습니다.
- 성현 님이 요청하기 전까지 Unity·APK 테스트를 실행하지 않으며, 기존 APK의 결과를 최신 소스의 실기 완료로 쓰지 않습니다.
