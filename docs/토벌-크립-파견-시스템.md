# 토벌·크립 파견 시스템

> **사용자 확정 조작 명세:** 크립 사냥은 **스토리 메뉴 안에서 유닛을 파견하는 방식**으로 진행합니다. 별도 토벌은 대상별 도전 UI를 제공합니다. 이 문서는 최종 화면·동작 요구이며, 코드·APK 반영 상태는 [현재 상태](START_HERE.md), 구현 순서는 [개발 작업](PLAYABLE_ROADMAP.md)에 둡니다.

## 1. 어디에서 실행하나요?

| 기능 | 진입 위치 | 플레이 방식 |
|---|---|---|
| 개인미션 18종 | 왼쪽 **미션** | 시작 시 받은 3개 목표의 진행도·보상 확인. 실제 행동으로 자동 달성 |
| 스토리 건물 14단계 | 왼쪽 **스토리 → 건물 공략** | 유닛 선택 → 수동 파견 → 건물 공격 → 필요 시 복귀 |
| 크립 3단계 | 왼쪽 **스토리 → 크립 사냥** | 대상 선택 → 파견 가능한 보유 개체 선택 → **파견** → 사냥 → 수동 복귀 |
| 별도 처치형 퀘스트 | 왼쪽 **토벌** | 대상별 조건·상태 확인. 원본이 수동 시작인 대상에 **도전/소환** 제공 |

스토리 안의 ‘건물 공략 / 크립 사냥’은 같은 메뉴의 내용 전환입니다. 크립 전용 왼쪽 메뉴나 별도 시설 탭은 추가하지 않습니다. 개인미션의 3칸 목표와 토벌 대상 목록을 섞지 않습니다. 전체 개인미션은 [개인미션 시스템](개인미션-시스템.md)을 따릅니다.

## 2. 스토리 안의 크립 사냥

### 대상과 조작

| 단계 | 대상 |
|---|---|
| 1 | 듀공 |
| 2 | 파파구 |
| 3 | 슈슈 |

단계 순서는 원본 분류입니다. 실제 출현·선행 격파·재출현 조건은 원본으로 확인하고, 위 순서만으로 임의 해금을 만들지 않습니다.

1. **크립 사냥**에서 대상의 상태·실제 HP·접근 조건·확인된 보상을 봅니다.
2. 실제 보유 유닛 중 파견할 개체를 선택합니다. 접근/이동 자격, 공격 대상 자격, 면역에 따른 피해 가능 여부를 각각 판정합니다. 불가 사유는 ‘접근 불가 / 공격 대상 부적합 / 해당 피해 면역’처럼 구분합니다.
3. **파견**을 누르면 선택한 실제 개체의 목적지를 변경합니다. 목록을 열거나 대상을 미리 보는 행동은 파견이 아닙니다. 원본 출현 규칙이 충족된 적과 공통 전투 엔진으로 싸웁니다.
4. 파견 목록에서 목적지와 전투 상태를 확인하고 **복귀**를 직접 요청합니다. 격파 뒤 자동 복귀·자동 다음 대상 이동은 별도 확정 전 추가하지 않습니다.

### 파견 중 지킬 규칙

- 유닛 한 기는 **메인 / 스토리 건물 / 특정 크립 목적지 중 한 곳**에만 소속됩니다. 같은 인스턴스를 복제하거나 메인과 파견 전투에 중복 참여시키지 않습니다.
- 스토리 건물 파견 자격을 크립에 자동 복사하지 않습니다. 공중·수륙·순간이동 분류도 사냥 허가 자체가 아닙니다. [크립 접근 조건](크립-접근조건-분류.md)을 따릅니다.
- 메인·스토리·다른 크립 목적지 사이의 평타·스킬·오라·소환수 효과를 분리합니다. **같은 전장 도달 거리 무제한**은 목적지 자격·면역·고유 광역 판정과 함께 유지합니다.
- 건물/크립 화면 전환은 표시만 바꿉니다. 진행 중인 건물 제한시간, 적 HP, 파견, 예약 타격, 보상 이력을 초기화하지 않습니다.
- 파견 중 실물을 판매·조합·분해 재료로 중복 소비하지 않도록 기존 거래 제한을 함께 검사합니다. 파견 실패에는 기존 소속·재화·예약 상태를 유지합니다.
- 복귀·목적지 변경·유닛 소멸 뒤에는 이전 목적지의 지연타·오라·소환수가 잘못 남지 않게 합니다. 파견 목적지와 적/보상 이력도 전체 세션 저장에 포함합니다.

**숫자의 출처와 한계:** [원본 몬스터 객체 자료](../data/original-2323C-monster-object-stats.json)의 **객체 기본값**입니다. 악몽·이세계 적용 후 최종 HP·방어, 스폰 여부, 퀘스트/히든 보스 역할, 면역과 보상은 **11종 모두 확인되지 않았습니다**(`runtimeEnemyRoleVerified: false`). 이 숫자를 그대로 모바일 최종 보스 체력으로 사용하지 않습니다.

해왕류·폐문·해군대장 등 부가 목표의 원본 조건은 [라운드·몬스터 시스템](라운드-몬스터-시스템.md)에서 확인합니다. 일반 라운드 피카와 퀘스트 피카처럼 이름이 같은 별도 객체를 섞지 않습니다. 아군 스킬로 생성되는 소환수와 적 토벌 목표도 구분합니다.

- **수동 시작 대상:** 원본의 해금·비용·횟수·전투 중 여부를 검사한 뒤 ‘도전’ 또는 ‘소환’을 한 번 요청합니다.
- **자동 출현 대상:** 등장 조건·현재 상태·실제 전투 진행을 표시합니다.
- **처치와 정산:** 공통 전투의 실제 격파 사건으로 판정합니다. 버튼을 누르거나 화면에서 HP 표시를 없앤 것으로 완료하지 않습니다. 격파 영수증 한 번으로 원본 보상·도박 충전 등 후속 효과를 정산합니다.

## 4. 공통 카드와 버튼

대상 카드에는 **이름·가능한 초상화·조건·비용·보상·상태·실제 HP**를 배치합니다. 크립에는 파견 인원과 개체 목록도 표시합니다.

| 상태 | 표시와 행동 |
|---|---|
| 미해금 / 조건 부족 | 부족한 조건과 실행 불가 이유 |
| 파견 또는 도전 가능 | 대상에 맞는 **파견 / 도전 / 소환** 중 해당 행동 |
| 파견 중 / 전투 중 | 실제 유닛·목적지·HP·원본에 있는 제한시간. 중복 시작 차단 |
| 격파 / 정산 대기 / 완료 | 실제 격파와 보상 지급 상태를 구분 |
| 재출현 대기 | 원본에 반복 출현이 있는 경우에만 실제 남은 시간 표시 |

짧은 탭 한 번은 행동 요청 한 건입니다. 스크롤·길게 누르기는 거래/파견을 실행하지 않습니다. 비용·보상·재출현이 미확인인 값은 **‘확인 필요’**로 두고 무료·0초·확정 보상으로 표시하지 않습니다.

**기존 카드·버튼·유닛 초상화·공용 바닥을 재사용**합니다. 추가 이미지 생성은 필수 조건이 아닙니다. 오른쪽 큰 장식 테두리 없이, 실제 적·HP·파견 상태가 먼저 읽히게 합니다. [화면·조작 정책](화면-조작-시스템.md)을 유지합니다.

## 5. 원본 확인과 완료 기준

UI 배치·수동 파견 방식은 확정했습니다. 대상별 출현/소환 사건, 해금·비용·횟수, 이동/공격 자격, 면역, 제한시간, 보상·재출현은 각각 원본 근거를 연결해야 합니다. 객체 기본 HP를 악몽 최종 HP로 대신하지 않습니다.

완료 기준은 **메뉴 → 실제 대상/개체 선택 → 조건 검사 → 파견/도전 → 실제 전투 → 격파·보상 → 복귀/정리**가 이어지는 것입니다. 중복 탭·부족 조건·실패·정지/앱 복귀·화면 전환·저장 복원에서도 적/유닛·재화·보상이 복제되지 않아야 합니다. UI를 문서화한 것과 게임 구현·실기 검증은 구분합니다.

## 6. 히든 보스·부가 목표의 문서 누락 점검

원본의 **정규 라운드 보스 8종**, **크립 3종**, 위 11개의 **[퀘스트] 표식 객체**는 서로 다른 집계입니다. [원본 객체 추출표](../data/original-2323C-monster-object-stats.json)는 이름과 기본 능력치를 알려 주지만 **소환 사건·해금·실제 소속·보상까지 입증하지 않습니다.** 따라서 공개 공략에서 말하는 ‘히든 보스’를 새로운 적 등급이나 자동 출현 대상으로 일괄 확정하지 않습니다.

| 빠뜨리기 쉬운 목표 | 지금 확인한 범위 | 원본에서 추가로 찾을 사건 · 최종 화면 |
|---|---|---|
| **퀘스트 표식 11종** | 위 원본 객체 ID 확보. **피카**는 일반 54R 객체 `o01R`과 퀘스트 객체 `o02F`를 분리 | 누가/언제 생성하는지, 수동 도전 가능 여부, HP·면역, 사망 후 정산. 확인된 처치형만 **토벌**에 노출 |
| **오로성 후보와 분류 미정 객체** | 워큐리 `o02E`, 새턴 `o031`, 나스쥬로 `o032`, 고런트 `o002`는 원본 객체 추출표의 **기타/분류 미확정** 후보 | 실제 적인지·신/악몽 환경 효과인지·부가 보스인지 JASS 사건 조사. **히든 보스 4종이라고 확정하지 않음** |
| **해왕류·폐문·해군대장** | 기존 [몬스터 부가 전투 조사](라운드-몬스터-시스템.md#부가-전투크립-보상-공개-공략은-원본-코드와-별도)에 외부 공략 단서 | 이동·파괴·출현 순서, 라운드/횟수, 도전과 실제 사망 보상. 별도 처치형이면 **토벌** |
| **추가 해적단·스모커** | 공개 공략의 별도 활동 후보로만 기록 | 원본 생성·전투/이벤트·재화 사건을 확인해 전투/파견/보상 중 정확한 경로에 배치 |
| **황금종·황금조각·등불·비석·파편** | [2.320 패치 기록](https://ordr.kr/patch-notes/2-320)에 **황금종 HP 조회 명령**이 등장. 나머지는 공개 가이드에서 발견한 후보 | 2.323[C]에 존재하는 객체·기능을 각각 확인. 같은 물건으로 합치거나 임의 보상 생성 금지 |
| **포네그리프 미션** | [2.322 패치 기록](https://ordr.kr/patch-notes/2-322)에 베리 보상 사례가 있음 | 2.323[C] 원본에서 **베리 이외의 게임 진행·해금·보상**이 있는지만 조사. 베리만 지급하면 구현 제외. 개인미션과 섞지 않음 |
| **보물 탐색의 별도 보상** | 원본에서 베리도 가능하다는 과거 기록이 있음 | 모바일에서는 **베리 획득·잔액·상점 모두 제외**. 가이몬 탐색과 위습 등 게임 내 유효한 보상은 유지 |

**확정 제외 결정:** 베리는 원본의 클리어·미션·탐색 보상으로 등장하더라도 **모바일에서는 지급·정산·누적·소비·표시하지 않습니다.** 2.322 패치 기록은 원본 자료로만 남기며, 베리 보상 경로를 구현/검증 과제로 만들지 않습니다. **누적 클리어 횟수**, 베리 외 미션 보상·토벌·보물 탐색은 그대로 구현 대상입니다.

**한 대상을 조사 완료로 표시할 조건:** 다음 여덟 칸이 원본 `war3map.j`·객체·보상 함수에 연결돼야 합니다. 빈칸은 `미확인`이라고 그대로 남깁니다.

| 항목 | 원본 확인할 내용 |
|---|---|
| ① 대상·역할 | 객체 ID, 실제 적/건물/장식/항법 표식 구분 |
| ② 시작 | 생성 함수·호출 주체·라운드/스토리·수동 소환 여부 |
| ③ 해금·제약 | 선행 처치/연구/아이템·비용·횟수·재출현 |
| ④ 실제 전투 | 난이도 적용 최종 HP/방어·면역·대상 제한·타이머 |
| ⑤ 종료 | 실제 사망·목표 성공/실패 조건과 중복 방지 키 |
| ⑥ 보상 | 원본 함수·실물 지급·도박 충전·연구/진행 해금, 베리 전용 여부 |
| ⑦ 화면 | 확인된 수동 도전만 토벌 버튼. 크립은 스토리 내 파견 |
| ⑧ 복구 | 격파/도전 중 저장·앱 복귀 후 동일 상태·보상 한 번 |

**수집해야 할 근거:** 각 대상의 원본 객체 ID → 생성/해금 사건 → 실제 행동/피격 → 사망 또는 미션 완료 → 보상 영수증 → 재도전/저장입니다. 확인된 경로부터 기존 **스토리(크립 파견) / 토벌(별도 처치) / 미션·기록 / 보물 탐색** 화면에 연결합니다. 분류가 불명확하면 화면 버튼부터 만들지 않습니다. [전체 기능 대장 R10·X08](전체-기능-구현대장.md)과 [개발 작업 F04](PLAYABLE_ROADMAP.md)가 남은 범위를 추적합니다.
