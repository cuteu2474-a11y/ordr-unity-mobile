# 토벌·크립 파견 시스템

> **사용자 확정 조작 명세:** 크립 사냥은 **스토리 메뉴 안에서 유닛을 파견하는 방식**으로 진행합니다. 별도 토벌은 대상별 도전 UI를 제공합니다. 이 문서는 최종 화면·동작 요구이며, 코드·APK 반영 상태는 [현재 상태](START_HERE.md), 구현 순서는 [개발 작업](PLAYABLE_ROADMAP.md)에 둡니다.

## 1. 어디에서 실행하나요?

| 기능 | 진입 위치 | 플레이 방식 |
|---|---|---|
| 개인미션 18종 | 왼쪽 **미션** | 시작 시 받은 3개 목표의 진행도·보상 확인. 실제 행동으로 자동 달성 |
| 스토리 건물 14단계 | 왼쪽 **스토리 → 건물 공략** | 유닛 선택 → 수동 파견 → 건물 공격 → 필요 시 복귀 |
| 크립 3단계 | 왼쪽 **스토리 → 크립 사냥** | 대상 선택 → 파견 가능한 보유 개체 선택 → **파견** → 사냥 → 수동 복귀 |
| 별도 처치형 퀘스트 | 왼쪽 **토벌** | 대상별 조건·상태 확인. 원본이 수동 시작인 대상에 **도전/소환** 제공 |

스토리 안의 ‘건물 공략 / 크립 사냥’은 같은 메뉴의 내용 전환입니다. 크립 전용 왼쪽 메뉴나 별도 시설 탭은 추가하지 않습니다. 개인미션의 3칸 목표와 토벌 대상 목록을 섞지 않습니다. 전체 개인미션은 [개인미션 시스템](개인미션-시스템.md)을 따릅니다.

## 2. 스토리 안의 크립 사냥

### 대상과 조작

| 단계 | 대상 |
|---|---|
| 1 | 듀공 |
| 2 | 파파구 |
| 3 | 슈슈 |

단계 순서는 원본 분류입니다. 원본 `CTs`는 1단계 크립을 생성하고, `CTp`가 1단계 사망 시 2단계를, `CTq`가 2단계 사망 시 3단계를 생성합니다. `CTr`에는 다음 단계 생성이 없습니다. 반복 재소환 조건은 별도로 확인하며 위 순서만으로 임의 해금·자동 재도전을 만들지 않습니다.

1. **크립 사냥**에서 대상의 상태·실제 HP·접근 조건·확인된 보상을 봅니다.
2. 실제 보유 유닛 중 파견할 개체를 선택합니다. 접근/이동 자격, 공격 대상 자격, 면역에 따른 피해 가능 여부를 각각 판정합니다. 불가 사유는 ‘접근 불가 / 공격 대상 부적합 / 해당 피해 면역’처럼 구분합니다.
3. **파견**을 누르면 선택한 실제 개체의 목적지를 변경합니다. 목록을 열거나 대상을 미리 보는 행동은 파견이 아닙니다. 원본 출현 규칙이 충족된 적과 공통 전투 엔진으로 싸웁니다.
4. 파견 목록에서 목적지와 전투 상태를 확인하고 **복귀**를 직접 요청합니다. 격파 뒤 자동 복귀·자동 다음 대상 이동은 별도 확정 전 추가하지 않습니다.

### 원본 크립 3단계 처치 보상 — 사망 콜백 확정

| 단계 | 원본 사망 처리 | 실제 보상·대상 | 후속 생성 |
|---|---|---|---|
| **1단계** | `CTp` | **모든 플레이어에게** 골드 **1,000** + 목재 **1** | 2단계 생성(`CTo`) |
| **2단계** | `CTq` | **처치 플레이어만** 50%: 지정 유닛 `h060` 1기 + 목재 **2**, 50%: 목재 **7** | 3단계 생성(`CTo`) |
| **3단계** | `CTr` | **처치 플레이어만** 골드 **5,000** + 목재 **1** + **아이템 발굴 1스택** | 후속 단계 없음 |

원본 1단계는 `TriggerAddCondition(LB, CTs)`에서 전체 참가자 라인에 생성되고, 2·3단계는 **이전 단계 실제 사망**이 원인입니다. 사망 영수증을 연결해 선행 적이 죽지 않았는데 다음 크립이 생성되거나 모든 단계의 보상이 전체 플레이어에게 지급되는 오류를 방지합니다. 모바일 실행·실기 검증은 아직 수행하지 않았습니다.

### 파견 중 지킬 규칙

- 유닛 한 기는 **메인 / 스토리 건물 / 특정 크립 목적지 중 한 곳**에만 소속됩니다. 같은 인스턴스를 복제하거나 메인과 파견 전투에 중복 참여시키지 않습니다.
- 스토리 건물 파견 자격을 크립에 자동 복사하지 않습니다. 공중·수륙·순간이동 분류도 사냥 허가 자체가 아닙니다. [크립 접근 조건](크립-접근조건-분류.md)을 따릅니다.
- 메인·스토리·다른 크립 목적지 사이의 평타·스킬·오라·소환수 효과를 분리합니다. **같은 전장 도달 거리 무제한**은 목적지 자격·면역·고유 광역 판정과 함께 유지합니다.
- 건물/크립 화면 전환은 표시만 바꿉니다. 진행 중인 건물 제한시간, 적 HP, 파견, 예약 타격, 보상 이력을 초기화하지 않습니다.
- 파견 중 실물을 판매·조합·분해 재료로 중복 소비하지 않도록 기존 거래 제한을 함께 검사합니다. 파견 실패에는 기존 소속·재화·예약 상태를 유지합니다.
- 복귀·목적지 변경·유닛 소멸 뒤에는 이전 목적지의 지연타·오라·소환수가 잘못 남지 않게 합니다. 파견 목적지와 적/보상 이력도 전체 세션 저장에 포함합니다.

해왕류·폐문·해군대장 등 부가 목표의 원본 조건은 [라운드·몬스터 시스템](라운드-몬스터-시스템.md)에서 확인합니다. 일반 라운드 피카와 퀘스트 피카처럼 이름이 같은 별도 객체를 섞지 않습니다. 아군 스킬로 생성되는 소환수와 적 토벌 목표도 구분합니다.

- **수동 시작 대상:** 원본의 해금·비용·횟수·전투 중 여부를 검사한 뒤 ‘도전’ 또는 ‘소환’을 한 번 요청합니다.
- **자동 출현 대상:** 등장 조건·현재 상태·실제 전투 진행을 표시합니다.
- **처치와 정산:** 공통 전투의 실제 격파 사건으로 판정합니다. 버튼을 누르거나 화면에서 HP 표시를 없앤 것으로 완료하지 않습니다. 격파 영수증 한 번으로 원본 보상·도박 충전 등 후속 효과를 정산합니다.

### 개인 토벌 7종 — 해금·재고·도전·보상

**해금 시점의 실제 근거**
- 깅: 15R 시작의 `CVC`가 연구 `R00G`를 부여합니다.
- 클리크·와포루·거프: 20R **크로커다일** 사망 콜백 `CIN`이 해당 플레이어에게 `R00H`를 부여합니다. 와포루는 안내문대로 **21~30R**에 한정됩니다.
- 바제스: 30R **종료 단계**의 `CVD`가 `R00I`를 부여하고 와포루 상품을 비활성화합니다. 따라서 실제 안내 범위는 **31~40R**입니다.
- 피카: 40R **종료 단계**의 `CVD`가 `R018`을 부여하고 바제스 상품을 비활성화합니다. **41R부터** 가능합니다.
- 모리아: 스토리 **[12] 홀케이크섬** 완료 보상 `CQf`가 모든 참가자에게 `R01S`를 부여합니다.
- 50R 이후 신세계 출항 처리 `CVi`는 **7개 판매 상품을 모두 비활성화**합니다.

**비용·재고·재도전 — 원본 객체와 안내문을 구분**
- **구매 비용:** 원본 `Units/UnitBalance.slk`에서 7개 상품 모두 `goldcost`·`lumbercost`가 **미기재**이고, `CK0~CK6`에도 별도 재화 차감이 없습니다. **원본 자료상 별도 골드·목재 구매 비용은 확인되지 않습니다.** 다만 실제 게임 UI의 최종 비용 표시는 미검증이므로 임의의 유료 금액을 만들지 않습니다. `goldRep=135`는 **수리 비용 필드**이지 구매 비용이 아닙니다.
- **상점 재고:** 7개 상품의 객체값이 모두 `stockMax=1`, `stockRegen=3600`초(**60분**)이며 `stockStart`는 미기재입니다. 재고 **1개와 명목 재충전 시간**이 확인된 것이지, 60분 후 실제 재도전이 가능하다고 입증된 것은 아닙니다.
- **횟수:** 7개 `Ubertip` 모두 **‘단발미션·한 번만 수행’**이라고 설명합니다. 그러나 판매 콜백·`CKz`에 별도 **완료/재시도 횟수 검사**가 없고, 깅·클리크는 재소환 횟수 장부(`lO/lP`)를 능력 단계에 전달합니다. 따라서 **안내 기준 1회**, 엔진상 **60분 후 재구매·실패 후 재도전 가능 여부는 실행 검증 필요**로 함께 기록합니다. 모바일에서 무제한 재도전을 확정하지 않습니다.
- **바제스 특례:** 원본 설명은 체력 회복이 매우 높으며 **205만 이상의 누적 피해**가 필요하다고 안내합니다. 이는 객체 기본 HP가 곧 악몽 최종 HP라는 뜻이 아닙니다.

### 공유 목표 — 정의의 문·해군대장·해왕류

## 4. 공통 카드와 버튼

대상 카드에는 **이름·가능한 초상화·조건·비용·보상·상태·실제 HP**를 배치합니다. 크립에는 파견 인원과 개체 목록도 표시합니다.

| 상태 | 표시와 행동 |
|---|---|
| 미해금 / 조건 부족 | 부족한 조건과 실행 불가 이유 |
| 파견 또는 도전 가능 | 대상에 맞는 **파견 / 도전 / 소환** 중 해당 행동 |
| 파견 중 / 전투 중 | 실제 유닛·목적지·HP·원본에 있는 제한시간. 중복 시작 차단 |
| 격파 / 정산 대기 / 완료 | 실제 격파와 보상 지급 상태를 구분 |
| 재출현 대기 | 원본에 반복 출현이 있는 경우에만 실제 남은 시간 표시 |

짧은 탭 한 번은 행동 요청 한 건입니다. 스크롤·길게 누르기는 거래/파견을 실행하지 않습니다. 비용·보상·재출현이 미확인인 값은 **‘확인 필요’**로 두고 무료·0초·확정 보상으로 표시하지 않습니다.

**기존 카드·버튼·유닛 초상화·공용 바닥을 재사용**합니다. 추가 이미지 생성은 필수 조건이 아닙니다. 오른쪽 큰 장식 테두리 없이, 실제 적·HP·파견 상태가 먼저 읽히게 합니다. [화면·조작 정책](화면-조작-시스템.md)을 유지합니다.

## 5. 원본 확인과 완료 기준

UI 배치·수동 파견 방식은 확정했습니다. **개인 7종 소환·60초·보상과 크립 3단계 보상, 대장·해왕류 공유 보상은 원본 함수를 확보**했습니다. 개인 토벌 7종의 네이티브 **해금·라운드 범위·판매 재고·가격 필드·단발 안내**까지 확인했습니다. 남은 것은 실제 **재도전 가능 여부·악몽 최종 HP/면역**, 전투·파견·처치·중복 정산의 모바일 연결입니다. 객체 기본 HP를 악몽 최종 HP로 대신하지 않습니다.

완료 기준은 **메뉴 → 실제 대상/개체 선택 → 조건 검사 → 파견/도전 → 실제 전투 → 격파·보상 → 복귀/정리**가 이어지는 것입니다. 중복 탭·부족 조건·실패·정지/앱 복귀·화면 전환·저장 복원에서도 적/유닛·재화·보상이 복제되지 않아야 합니다. UI를 문서화한 것과 게임 구현·실기 검증은 구분합니다.
