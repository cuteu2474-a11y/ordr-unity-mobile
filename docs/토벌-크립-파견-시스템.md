# 토벌·크립 파견 시스템

> **사용자 확정 조작 명세:** 크립 사냥은 **스토리 메뉴 안에서 유닛을 파견하는 방식**으로 진행합니다. 별도 토벌은 대상별 도전 UI를 제공합니다. 이 문서는 최종 화면·동작 요구이며, 코드·APK 반영 상태는 [현재 상태](START_HERE.md), 구현 순서는 [개발 작업](PLAYABLE_ROADMAP.md)에 둡니다.

후보 목록에서 불가 개체를 숨기는 것과 이미 파견된 개체의 현황을 보여 주는 것은 구분합니다. 다음 크립을 공격하지 못하는 기존 파견 개체도 파견 중 목록에는 남아 복귀/이동할 수 있지만, 불가 이유 설명은 추가하지 않습니다. 기존 사용자 확정·거래 비용·재료 조건과 중복 소비 방지는 유지합니다.

### 대상과 조작

| 단계 | 대상 |
|---|---|
| 1 | 듀공 |
| 2 | 파파구 |
| 3 | 슈슈 |

단계 순서는 원본 분류입니다. 원본 `CTs`는 1단계 크립을 생성하고, `CTp`가 1단계 사망 시 2단계를, `CTq`가 2단계 사망 시 3단계를 생성합니다. `CTr`에는 다음 단계 생성이 없습니다. 반복 재소환 조건은 별도로 확인하며 위 순서만으로 임의 해금·자동 재도전을 만들지 않습니다.

1. **크립 사냥**에서 대상의 상태·실제 HP·접근 조건·확인된 보상을 봅니다.
2. 실제 보유 유닛 중 파견할 개체를 선택합니다. 접근/이동 자격, 공격 대상 자격, 면역에 따른 피해 가능 여부를 각각 판정합니다. 내부 자격 판정은 구분하되 화면에는 현재 파견 가능한 개체만 표시합니다. 불가 목록·불가 이유 설명·불가 포함 필터는 제공하지 않습니다.
3. **파견**을 누르면 선택한 실제 개체의 목적지를 변경합니다. 목록을 열거나 대상을 미리 보는 행동은 파견이 아닙니다. 원본 출현 규칙이 충족된 적과 공통 전투 엔진으로 싸웁니다.
4. 파견 목록에서 목적지와 전투 상태를 확인하고 **복귀**를 직접 요청합니다. 다음 크립 출현 시 기존 파견을 유지하고 다음 대상 자격을 충족하는 유닛은 자동 공격을 계속합니다. 자격이 없는 기존 파견 유닛은 대기하며 자동 복귀하지 않습니다. 마지막 슈슈 격파 뒤에는 사냥 완료를 표시하고 수동 복귀합니다.

### 원본 크립 3단계 처치 보상 — 사망 콜백 확정

| 단계 | 원본 사망 처리 | 실제 보상·대상 | 후속 생성 |
|---|---|---|---|
| **1단계** | `CTp` | **모든 플레이어에게** 골드 **1,000** + 목재 **1** | 2단계 생성(`CTo`) |
| **2단계** | `CTq` | **처치 플레이어만** 50%: 지정 유닛 `h060` 1기 + 목재 **2**, 50%: 목재 **7** | 3단계 생성(`CTo`) |
| **3단계** | `CTr` | **처치 플레이어만** 골드 **5,000** + 목재 **1** + **아이템 발굴 1스택** | 후속 단계 없음 |

원본 1단계는 `TriggerAddCondition(LB, CTs)`에서 전체 참가자 라인에 생성되고, 2·3단계는 **이전 단계 실제 사망**이 원인입니다. 사망 영수증을 연결해 선행 적이 죽지 않았는데 다음 크립이 생성되거나 모든 단계의 보상이 전체 플레이어에게 지급되는 오류를 방지합니다. 모바일 실행·실기 검증은 아직 수행하지 않았습니다.

### 파견 중 지킬 규칙

- 유닛 한 기는 **메인 / 스토리 건물 / 특정 크립 목적지 중 한 곳**에만 소속됩니다. 같은 인스턴스를 복제하거나 메인과 파견 전투에 중복 참여시키지 않습니다.
- 스토리 건물 파견 자격을 크립에 자동 복사하지 않습니다. 공중·수륙·순간이동 분류도 사냥 허가 자체가 아닙니다. [크립 접근 조건](크립-접근조건-분류.md)을 따릅니다.
- 메인·스토리·다른 크립 목적지 사이의 평타·스킬·오라·소환수 효과를 분리합니다. 원작에서 해당 크립 공격이 가능한 유닛만 승인하고 공격 가능한 위치에 자동 배치합니다. 목적지 자격·면역·고유 광역 판정은 유지합니다.
- 건물/크립 화면 전환은 표시만 바꿉니다. 진행 중인 건물 제한시간, 적 HP, 파견, 예약 타격, 보상 이력을 초기화하지 않습니다.
- 스토리·크립 파견 중에도 별도 복귀 없이 판매·조합·분해합니다. 성공 거래에서 실제 개체 소비와 파견/예약 공격/오라 정리를 함께 확정하고 중복 소비를 차단합니다. 실패에는 기존 소속·재화·예약 상태를 유지합니다.
- 복귀·목적지 변경·유닛 소멸 뒤에는 이전 목적지의 지연타·오라·소환수가 잘못 남지 않게 합니다. 파견 목적지와 적/보상 이력도 전체 세션 저장에 포함합니다.

해왕류·폐문·해군대장 등 부가 목표의 원본 조건은 [라운드·몬스터 시스템](라운드-몬스터-시스템.md)에서 확인합니다. 일반 라운드 피카와 퀘스트 피카처럼 이름이 같은 별도 객체를 섞지 않습니다. 아군 스킬로 생성되는 소환수와 적 토벌 목표도 구분합니다.

- **수동 시작 대상:** 원본의 해금·비용·횟수·전투 중 여부를 검사한 뒤 ‘도전’ 또는 ‘소환’을 한 번 요청합니다.
- **자동 출현 대상:** 등장 조건·현재 상태·실제 전투 진행을 표시합니다.
- **처치와 정산:** 공통 전투의 실제 격파 사건으로 판정합니다. 버튼을 누르거나 화면에서 HP 표시를 없앤 것으로 완료하지 않습니다. 격파 영수증 한 번으로 원본 보상·도박 충전 등 후속 효과를 정산합니다.

### 개인 토벌 7종 — 해금·재고·도전·보상

원본의 **‘미션’ 건물**(`h07A`)은 아래 7개 토벌 상품을 판매합니다. 상점의 판매 사건(`BDE`)이 `CK0~CK6`을 거쳐 `CKz`를 호출하면 **해당 플레이어의 라인에 적(Player(6) 소유)**이 소환됩니다. 제한시간은 **60초**이며, 성공하면 `CKx → BDW`로 개인 보상을 지급합니다. 실패하면 `CKy`가 적을 제거하고 **보상을 지급하지 않습니다**.

**60초 판정의 실제 흐름:** `CKz`는 토벌 대상마다 **60초 단발 타이머(`CKy`)**와 **0.5초 간격 생존 확인 타이머(`CKx`)**를 따로 시작합니다. `CKx`는 적이 죽었고 실패 표시 `lX`가 아직 꺼져 있을 때만 **활성 토벌 수 `lN`을 감소 → 해당 적의 개인 보상 함수 `BDW` 호출 → 타이머·표시창 정리**를 수행합니다. 60초가 끝났을 때 적이 살아 있으면 `CKy`가 적을 숨겨 처치하고 `lN`을 줄이며 `lX=true`로 표시하므로 **시간초과 처치를 성공으로 오인해 보상을 중복 지급하지 않습니다**. 이미 죽었다면 `CKy`는 즉시 종료됩니다. 원본 사망 감지는 즉시 전용 보상 콜백이 아닌 **0.5초 주기 확인**이므로, 모바일에서는 사망 사건과 마감 사건의 선후관계를 보존해야 합니다. 근거: `war3map.j` `Bcu/BdD/BDW/CKx/CKy/CKz`.

**기존 카드·버튼·유닛 초상화·공용 바닥을 재사용**합니다. 추가 이미지 생성은 필수 조건이 아닙니다. 오른쪽 큰 장식 테두리 없이, 실제 적·HP·파견 상태가 먼저 읽히게 합니다. [화면·조작 정책](화면-조작-시스템.md)을 유지합니다.

## 5. 원본 확인과 완료 기준

UI 배치·수동 파견 방식은 확정했습니다. **개인 7종 소환·60초·보상과 크립 3단계 보상, 대장·해왕류 공유 보상은 원본 함수를 확보**했습니다. 개인 토벌 7종의 네이티브 **해금·라운드 범위·판매 재고·가격 필드·단발 안내**까지 확인했습니다. 남은 것은 실제 **재도전 가능 여부·악몽 최종 HP/면역**, 전투·파견·처치·중복 정산의 모바일 연결입니다. 객체 기본 HP를 악몽 최종 HP로 대신하지 않습니다.

완료 기준은 **메뉴 → 실제 대상/개체 선택 → 조건 검사 → 파견/도전 → 실제 전투 → 격파·보상 → 복귀/정리**가 이어지는 것입니다. 중복 탭·부족 조건·실패·정지/앱 복귀·화면 전환·저장 복원에서도 적/유닛·재화·보상이 복제되지 않아야 합니다. UI를 문서화한 것과 게임 구현·실기 검증은 구분합니다.
