## 강화 연구의 HP/방어 계산을 실제 엔진 코드로 대조한 모델 (2026-10-22)

추가로 Warcraft III 호환 엔진 [WarsmashModEngine](https://github.com/Retera/WarsmashModEngine/tree/f9e0aeed4be372d6016519d0e97b384aa873f374)의 구현에서 다음 계산 경로를 확인했습니다.

1. `CPlayer.setTechToLevel`: 연구가 바뀌면 플레이어 소유 유닛 중 `Upgrades Used`에 해당 연구를 등록한 유닛에만 효과를 적용.
2. `CUpgradeEffectHitPointsPcnt`: `rhpo`의 레벨별 값 `base + mod × (level−1)`을 **원본 유닛 타입 기본 HP에 곱한 후**, Java `StrictMath.round(float)`로 정수화한 HP 증가분을 적용. 여러 종류의 연구는 각각 계산되어 더해짐.
3. `CUpgradeEffectDefenseUpgradeBonus`: `rarm`은 `UpgradeData.base1=0.1` 자체를 방어력에 더하는 것이 아니라 **그 유닛의 `UnitBalance.defUp × 연구 레벨`**을 영구 방어력 증가분으로 적용.
4. `CUpgradeEffectHitPoints`: `rhpx`는 레벨당 `base + mod × (level−1)`만큼 최대 HP를 추가. 원본의 오로성 이벤트와 연결되는 `R00S`, `R01W`가 여기에 해당.

이 알고리즘을 원본 68종의 `HP`, `def`, `defUp`, `upgrades`와 결합한 재현 가능한 계산 파일이 [`data/original-2323C-nightmare-monster-initial-model.json`](../data/original-2323C-nightmare-monster-initial-model.json)입니다. `tools/model_original_nightmare_monster_initial_stats.py`에서 Java의 `float32` 계산과 양수 `.5` 올림까지 모델링합니다.

| 원본 웨이브·몹 | 기본 HP → 계산 모델 HP | 기본 방어 → 계산 모델 방어 |
|---|---:|---:|
| 1라운드 일반 | 135 → 338 | 0 → 0 |
| 10라운드 보스 아론 | 14,500 → 137,750 | 13 → 13 |
| 15라운드 일반 | 2,670 → 9,559 | 12 → 12 |
| 39라운드 스팬담 | 1 → 1 | 39 → 39 |
| 50라운드 보스 센고쿠 | 20,800,000 → 197,600,000 | 350 → 350 |
| 65라운드 일반 | 16,210,000 → 161,775,800 | 81 → 191 |

오로성 발생 시 조건부 *연구만* 따로 산출했습니다. 예를 들어 원본에 `R00S`를 등록한 일반 몬스터는 워큐리·새턴 이벤트에서 모델 HP 증가분 +1,000만, 나스쥬로에서 +2,500만입니다. `R01W`가 등록된 보스는 워큐리 +2,500만, 새턴·나스쥬로 +1,000만입니다. **39라운드 스팬담은 두 연구 모두 `Upgrades Used`에 없어 해당 연구의 효과가 모델상 0**이며, 이것이 실제 게임의 전체 이벤트 효과 부재를 뜻하지는 않습니다.

**검증 한계:** 이 표는 **Warsmash 엔진의 공개 소스 코드에 따른 계산 결과**입니다. Blizzard 원본/리포지드 실행기에서의 최종 수치가 확인된 것은 아닙니다. `A04Q` 마방, 보스 오라, 스킬·이세계 이벤트, 맵 내 유닛 상태 변경, 체력 재생, 강화 연구 반영 타이밍과 실제 엔진 반올림 차이가 남아 있습니다. 특히 원본의 *각 순간 실제 체력*과 *초기 기본 HP+연구 모델*을 혼동하지 않습니다. JSON의 `actualWarcraftClientParityVerified: false`, `safeForVerifiedMonsterWaveRuntime: false`를 유지하며 게임 전투에는 사용하지 않습니다.
- 이번 변경으로 검증된 데이터를 받는 `Original323VerifiedMonsterWaveCatalog` → `CombatWaveDirector` → `CharacterCombatRuntime.SpawnEnemyWithDefenses` 경로를 연결했습니다. 허위 기본값을 만들어 주입하지 않으며 **데이터가 없는 웨이브는 시작하지 않습니다.**

원본 W3X 파일을 로컬에 두고 `mpyq`를 설치한 뒤 다음 명령을 실행합니다. 133MB 원본 맵 자체는 저장소에 추가하지 않습니다.

```bash
python tools/extract_original_monster_object_stats.py --w3x '/path/to/ORDR_S2_2.323[C].w3x'
python tools/extract_original_monster_wave_script.py --w3x '/path/to/ORDR_S2_2.323[C].w3x'
```

추출기는 지정된 원본 SHA-256과 일치하는 파일만 받으며, 두 결과 모두 `safeForVerifiedMonsterWaveRuntime: false`를 명시합니다. 배열에 연결된 객체 기본 HP만으로 **최종 악몽 웨이브를 추측하여** 아래 *검증된 웨이브* 형식으로 자동 변환해서는 안 됩니다.

## 실제 원본 근거가 확보되면 입력할 형식

`OrdrCharacterCombatController`의 `verifiedMonsterWavesJson`에 별도 검증 파일을 연결하거나 `Assets/Resources/OrdrData/original-2323C-verified-monster-waves.json`에 배치합니다. 지금은 해당 파일을 임의 데이터로 만들지 않습니다.

```json
{
  "format": "ordr-verified-monster-waves-v1",
  "gameVersion": "S2 2.323[C]",
  "mode": "nightmare-otherworld",
  "sourceW3xSha256": "0794996c9bc73eaa3020f20ebc45fb37cfa64a6e98ffe8aa0dfa3b356e77bc5c",
  "waves": []
}
```

위 파일은 **출현을 허가하는 웨이브가 0개인 빈 형식 예시**일 뿐입니다. 실제 각 `waves[]` 원소에는 반드시 다음이 필요합니다.

- `waveNumber`, `waveEvidence`, `spawns` (비어 있으면 거부)
