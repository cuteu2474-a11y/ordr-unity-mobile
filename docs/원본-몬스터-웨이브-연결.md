# 원랜디 S2 2.323[C] 몬스터 체력·방어력과 웨이브 연결

## 현재 상태

- 원본 맵 SHA-256: `0794996c9bc73eaa3020f20ebc45fb37cfa64a6e98ffe8aa0dfa3b356e77bc5c`.
- 기존 `original-2323C-map-base-stats.json`의 체력/방어력은 **캐릭터 측 UnitBalance.slk** 값입니다. 원본 **웨이브 몬스터의 최종 체력/방어력 값은 아님**을 확인했습니다.
- 원본 맵 `Units\\UnitBalance.slk`와 `Units\\CampaignUnitStrings.txt`를 추출해 [`data/original-2323C-monster-object-stats.json`](../data/original-2323C-monster-object-stats.json)에 **이름 기반 몬스터 후보 100개**의 *객체 기본* 체력·방어력·방어 타입을 확보했습니다. 내역: 레벨 60, 보스 8, 퀘스트 11, 스토리 14, 크립 3, 분류 불확실 4. 전체가 실제로 생성되는 몬스터라는 뜻은 아닙니다.
- 예시: `o01V` 아론 보스 HP `14500`·방어력 `13`·`large`, `n000` 로그타운 HP `70200`·방어력 `10`·`fort`. 이는 모드 보정 전 **SLK 원본값**이지 악몽 최종값이 아닙니다.
- 이 저장소에는 아직 몬스터 출현 일정, 원본 객체 ID별 **모드 적용 후 최종** 체력·방어력, 악몽 이세계모드의 스크립트 보정치를 검증한 파일이 없습니다. 실제 라운드 HP 피해의 완전한 원작 재현은 **미완료**입니다.
- 이번 변경으로 검증된 데이터를 받는 `Original323VerifiedMonsterWaveCatalog` → `CombatWaveDirector` → `CharacterCombatRuntime.SpawnEnemyWithDefenses` 경로를 연결했습니다. 허위 기본값을 만들어 주입하지 않으며 **데이터가 없는 웨이브는 시작하지 않습니다.**

### 추출을 다시 실행하는 방법

원본 W3X 파일을 로컬에 두고 `mpyq`를 설치한 뒤 다음 명령을 실행합니다. 133MB 원본 맵 자체는 저장소에 추가하지 않습니다.

```bash
python tools/extract_original_monster_object_stats.py --w3x '/path/to/ORDR_S2_2.323[C].w3x'
```

추출기는 지정된 원본 SHA-256과 일치하는 파일만 받으며, 후보 몬스터 데이터에 `safeForVerifiedMonsterWaveRuntime: false`를 명시합니다. 이 자료를 아래 *검증된 웨이브* 형식으로 자동 변환해서는 안 됩니다.

## 실제 원본 근거가 확보되면 입력할 형식

`OrdrCharacterCombatController`의 `verifiedMonsterWavesJson`에 별도 검증 파일을 연결하거나 `Assets/Resources/OrdrData/original-2323C-verified-monster-waves.json`에 배치합니다. 지금은 해당 파일을 임의 데이터로 만들지 않습니다.

```json
{
  "format": "ordr-verified-monster-waves-v1",
  "gameVersion": "S2 2.323[C]",
  "mode": "nightmare-otherworld",
  "sourceW3xSha256": "0794996c9bc73eaa3020f20ebc45fb37cfa64a6e98ffe8aa0dfa3b356e77bc5c",
  "waves": []
}
```

위 파일은 **출현을 허가하는 웨이브가 0개인 빈 형식 예시**일 뿐입니다. 실제 각 `waves[]` 원소에는 반드시 다음이 필요합니다.

- `waveNumber`, `waveEvidence`, `spawns` (비어 있으면 거부)
- 각 출현 객체별 `instanceId`(출현 개체 고유), `originalRawcode`(4글자, 동일 유형 간 중복 가능), `kind`(Line/Boss 등), `atSeconds`, `x`, `y`, `pathProgress`
- **최종** `health`(정확한 양의 정수), `baseArmor`, `warcraftArmorType`, 선택적 `magicResistancePercent` 및 `a04qLevel`
- 각 독립 근거 `healthEvidence`, `armorEvidence`, `spawnEvidence`, `kindEvidence`, `positionEvidence`, 선택적 `magicResistanceEvidence`

먼저 실제 W3X에서 몬스터 객체 데이터와 JASS 난이도별 HP/방어 보정 및 생성 코드를 대조한 후 값과 구체적인 함수/행 근거를 기록해야 합니다. `sourceW3xSha256` 값만 일치하거나 근거 문자열이 단순히 존재한다고 원작 검증이 완료되는 것은 아닙니다. 데이터의 수동 확인과 실제 플레이 검증도 별도로 필요합니다.

## 동작 조건

1. Unity 컨트롤러가 이 검증 파일을 로드하여 `VerifiedMonsterWaves`를 구성합니다.
2. 원본 피해/게임 런타임을 구성하고 `BeginSession()`으로 시작합니다.
3. `BeginVerifiedMonsterWave(1)`을 호출하면, **등록된 해당 라운드에 한해** 실제 경과 시각에 적이 생성됩니다.
4. 플레이어 평타가 적 체력을 깎으려면 몬스터 방어 정보 이외에도 캐릭터의 독립적인 네이티브 공격경로 확인, 스킬/난수/데미지 정수화 근거가 필요합니다. 이 조건은 기존처럼 해제하지 않습니다.

현재 테스트에서 사용하는 몬스터 rawcode `n001`, HP 1000, 방어력 10 및 시각 0/2초는 **오직 합성 테스트 가짜 값**이며 실제 게임 원본 데이터가 아닙니다. APK/실기에서 원작 재현 성공을 주장하지 않습니다.
