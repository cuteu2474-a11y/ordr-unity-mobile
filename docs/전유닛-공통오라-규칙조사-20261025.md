# 전 유닛 공통 방깎·이감·공격력 오라 규칙

시작 main `52fc5fe`. 목적은 특별함 6종의 별도 예외를 늘리는 대신, 모든 등급에서 재사용할 원본 규칙과 데이터 경계를 확인하는 것이다. **공통 규칙 적용과 모든 대상에게 무조건 효과 부여는 다르다.** 원본의 적/아군·자신 포함/제외·유기체·공중/지상·면역·범위 제한을 유지한다.

조사 대상은 현재 논의한 방어·이동/공격속도·공격력 **오라 계열**이다. 발동형 방깎, 마방 능력 레벨 변경, 일반 감속 주문, 디버프, 모든 JASS 스킬까지 하나의 오라 공식으로 합치지 않는다.

## 확인한 공통 규칙과 코드 반영

Blizzard의 [Spell Basics — Auras](https://classic.battle.net/war3/basics/spellbasics.shtml)는 동일 오라의 중복 비중첩, 자기 오라의 자기 적용, 아군 오라와 마법 면역의 관계, Hidden/Invisible 상태 제한을 명시한다. [영웅 아이템 설명](https://classic.battle.net/war3/basics/heroitemspermanent.shtml)에는 공격력 오라 사이의 중첩 예외도 있어, 효과 이름만으로 모든 오라를 한 묶음으로 보면 안 된다.

- **동일 효과 종류 + 동일 능력 + 동일 레벨 + 동일 버프 + 동일 값**인 출처 여러 개는 계산에 한 번만 반영한다. 각 출처의 수명주기는 별도로 유지한다. 한 오라가 가진 이동속도·공격속도 등 서로 다른 성분을 합쳐 없애지 않는다.
- 이 규칙은 `Original323AuraCommonRules.TryResolveIdenticalAura`에 구현했으며 유닛 이름·등급·특별함 6종의 ID나 값3에 의존하지 않는다. 앞으로 원본 출처가 연결된 모든 유닛에서 같은 함수를 사용한다.
- 기존 방어 계산기는 실제 월드가 부여한 효과 객체인지 검증한 뒤 이 공통 함수를 호출한다. 호킨스 2기 또는 두뇌강화 2기의 동일 -3 오라는 이제 -3 한 번으로 계산되고, 중복 때문에 공격 자체가 보류되지 않는다. 서로 다른 출처 객체를 SourceId 문자열만 복사해 위조하면 계속 거부한다.
- 출처 ID에 원본 능력 레벨을 추가했다. 레벨이 빠진 출처를 암묵적으로 1레벨로 해석하지 않는다.
- 서로 다른 능력, 서로 다른 버프/레벨/수치의 조합은 위의 단순 중복 제거로 해결하지 않는다. 높은 값/낮은 값/합산 중 무엇인지 추가 근거 없이 선택하지 않는다.
- `PassesCommonEligibility`는 사망·Hidden/Invisible 및 적대 오라의 마법 면역 제한을 확인하는 공통 제외 단계다. 이 함수 통과만으로 대상 마스크·반경·현재 능력 레벨·갱신 틱·잔류가 승인되는 것은 아니다. 아직 실제 월드의 전체 속성 공급자가 없는 상황에서 이를 항상 true인 대상으로 대체하지 않는다.

## 전체 자료에서 발견한 예외

### 공유 버프는 능력 이름이나 등급과 다르다

예를 들어 가드포인트 `A0EM`과 혼포인트 `A0EN`은 **B00V를 공유**한다. 두 객체의 원시 공격력 필드는 각각 약 0.07과 0.25다. 키드 `A08H`는 다른 두 능력과 B004를, 크로커다일 `A08E`는 다른 두 능력과 B001을 공유한다. 이것을 전부 더하거나 캐릭터별 독립 버프로 취급하면 안 된다. 이번에 찾은 26개 그룹을 JSON에 기록했지만 **공유 버프의 서로 다른 값에 대한 최종 네이티브 선택 규칙을 자동 승인하지 않았다.**

### 공격력 오라는 퍼센트형만 있는 것이 아니다

W3A 공격력 오라의 `Ear4=0`과 `Ear4=1`을 구분해야 한다. 가드포인트 A0EM의 값 약0.07은 퍼센트형이고, A0O6의 값5000은 `Ear4=1`인 고정값형이다. 후자를 500000% 버프로 계산하면 안 된다. 음수 공격력 오라와 자기만 대상인 오라, 자기 제외, 적/플레이어 대상 마스크도 실제 존재한다. 공통 시스템은 부호·고정/비율 모드·근접/원거리 적용 플래그를 보존해야 한다.

또한 `A0EM → ACac → AOac`의 실제 상속 체인을 확인했다. 이름이나 첫 부모만 보고 별개 효과 유형으로 분리하지 않는다. 원본에 명시되지 않은 상속 필드는 0으로 채우지 않는다. 외부 실험 문서는 [ScrewTheTrees 원자료](https://github.com/Cokemonkey11/wc3-ability-doc/blob/main/sources/screwthetrees-wc3-editor-ability-insight-document/2023-11-14.md)도 비교했지만, 패치별 시험 조건이 달라 그 설명을 ORDR 최종 피해 공식으로 승격하지 않았다.

### 이속 설정은 기본 Warcraft 숫자가 아니다

원본 `war3mapMisc.txt`에는 **MinUnitSpeed=89, MaxUnitSpeed=490**이 명시되어 있다. 이를 공통 상수로 보존했다. 기본/연구/가감속·속도 설정·정지·하한 적용 순서는 별도 확인 대상이다. 현재 값만 알아냈다는 이유로 모든 몬스터 이동 결과를 무조건 89~490으로 잘라내지 않는다.

### 점수판 유틸 합계를 실제 전투 공식으로 사용하면 안 된다

원본 `BH9/BIB/BIC` 등록을 246개 레벨 항목으로 추출했다. 변수 기반 도우미 호출 2개는 추측해서 확장하지 않았다. `BIH`는 능력/버프와 분류를 이용해 대표 등록을 고르고 `jP/jR/jS/jQ`를 만들지만, 이 결과는 `BjL → BjK → LeaderboardAddItem`의 **유틸 점수판**에 사용된다. 실제 대상별 방어·이속을 적용하는 함수가 아니다.

`BIE`는 일반 그룹에서 절댓값이 작은 등록을 고르는 분기와, 분류4/B00E에서 반대 방향의 예외를 갖는다. 이것을 실제 전투의 ‘가장 강한 효과’ 규칙으로 복사하면 안 된다. 원본 자격 조건식도 그대로 기록했다. HUD 숫자와 현재 적이 실제로 받은 버프/레벨·반경·면역은 별도로 대조한다.

## 검증과 현재 한계

로컬 비 Unity 회귀 **113건 통과**, W3X 재추출 일치. Unity 추가 검사는 동일 오라 중복의 단일 반영, 다른 ID/버프/레벨/수치 혼합 보류, 출처 레벨 누락 거부, 공통 상태 제외, 임의 등급/값의 공통 방어 계산, 실제 중복 호킨스/두뇌강화의 HP 변화를 확인한다. Unity 전체 결과는 이번 main 커밋의 기존 EditMode Actions로 확인한다.

**반영 완료:** 전체 카탈로그 감사 자료, 원본 오라 상속/마스크/레벨/버프 대조, 유닛에 종속되지 않는 동일 중복 비중첩 계산, 방어 계산기 연결, 공통 상태 제외 함수 및 맵 이속 상수.

**미완료:** 26개 공유 버프 그룹의 서로 다른 능력/레벨 우선순위, 서로 다른 오라·발동형 디버프 혼합, 최종 공격력의 기본/주사위/강화·버프·크리티컬 적용 순서, 최종 이속과 클램프 순서, 실제 몬스터/아군 상태·면역·갱신 틱/잔류 공급자. 전 유닛 전체 스킬 완료나 모든 오라의 무조건 활성화를 뜻하지 않는다. `safeForUnconditionalLiveCombat: false`를 유지한다.
