# 크립 외 부가 목표 구현 명세

이 문서는 **공유 전투 목표 5종을 실제 등장 → 출전 → 전투 → 보상 → 후속 효과 → 저장으로 연결하는 구현 계약**과 개인 토벌 7종의 연결 범위를 정리합니다. 문서 작성 요청에 따른 설계이며 코드 구현 완료를 뜻하지 않습니다. 원작 추가 조사·실행 검증은 이번 작업에서 하지 않습니다.

규칙의 근거는 [공유미션·포네그리프](공유미션-포네그리프-시스템.md), [토벌·크립](토벌-크립-파견-시스템.md)입니다. 코드 진입점은 [CODE_MAP](CODE_MAP.md), 현재 상태는 [START_HERE](START_HERE.md), 구현 순서는 [PLAYABLE_ROADMAP](PLAYABLE_ROADMAP.md)의 F04·M03·S01~S03을 따릅니다. 아래 새 자료형 이름은 **구현 제안**이며 기존 API로 오인하지 않습니다.

## 1. 범위와 메뉴

| 구분 | 대상 | 시작 방식 / 화면 | 완료 집계 |
|---|---|---|---|
| 공유 전투 목표 | 룸바 해적단의 영혼, 정의의 문, 샨도라 황금종, 해왕류, 해군대장 | 실제 조건에 따라 등장. **미션 → 공유 미션**에서 출전/복귀 | 공유 8종 중 각각 1종 |
| 공유 비전투 목표 | 빠른 알라바스타, 파괴왕, 보물 사냥꾼 | 스토리 완료·보물 획득 사건으로 자동 판정 | 나머지 공유 3종 |
| 개인 토벌 | 깅, 클리크, 와포루, 거프, 바제스, 모리아, 피카 | **토벌**에서 도전. 개인 라인에 적 등장, 60초 제한 | 공유 8종에 더하지 않음 |
| 별도 기능 | 개인미션 배정·교체, 포네그리프 해독, 보물 탐색 | 기존 메뉴/명세 유지 | 토벌이나 공유 전투의 대체물이 아님 |

크립 3단계는 이 명세의 대상이 아닙니다. 오로성 환경 효과·미분류 객체를 신규 보스로 만들지 않습니다. 자동 출현 목표에 ‘소환’ 버튼을 추가하지 않습니다. 베리는 지급·저장·표시하지 않습니다.

## 2. 목표별 확정 자료

| 목표 / 내부 종류 | 원본 연결 키 | 실제 목표 식별 | 기본 보상 | 후속 |
|---|---|---|---|---|
| 룸바 영혼 / RumbarSouls | Ck, CNa→CNZ→CNY | 1시 파괴물. 실제 rawcode 연결 필요 | 골드 3,000·목재 1·발굴 1스택 | 공유 완료 1 |
| 정의의 문 / JusticeGate | Ci, CNJ→CNI→CNH | 3시 파괴물. 실제 rawcode 연결 필요 | 골드 20,000·흔함선택위습 2·발굴 1스택 | 해군대장 1기 생성 의무 |
| 황금종 / ShandoraBell | Cj, CM7→CM6→CM5 | 7시 파괴물. 실제 rawcode 연결 필요 | 골드 3,000·랜덤위습 1·발굴 1스택 | 미획득 시 5% AI01, 공유 완료 1 |
| 해왕류 / SeaKing | CNW, CNV→CNU/CNT | o02N | 골드 3,000·흔함선택위습 1·발굴 1스택·대상 영웅 XP 325 | 원본 도박 충전/카지노 분기, 공유 완료 1 |
| 해군대장 / MarineAdmiral | CM3, CM2→CM1/CM0 | o02M / o02Q / o02R 중 1기 | 목재 1·특성포인트 1·대상 영웅 XP 600 | 종류별 버프, 공유 완료 1 |

- Ck/Ci/Cj는 원본 참조 변수입니다. 유닛 rawcode로 사용하지 않습니다. 현재 길이 4자 검사만 통과하는 다른 객체를 정식 목표로 승인하면 안 됩니다.
- 1시/3시/7시/9시는 원본 위치 설명입니다. 모바일 화면의 픽셀 좌표·전투 좌표로 직접 변환하지 않습니다.
- 세 대장은 각각 별도 공유 미션이 아닙니다. 문 1회 완료 뒤 **한 기만** 등장하고 대장 완료는 1회입니다.
- 발굴은 기존 fZ 일반 스택, 최대 10을 사용합니다. 이미 10이면 추가 스택만 생략하며 나머지 보상은 지급합니다. 별도 교환권을 만들지 않습니다.
- 영웅 XP는 기존 원본 영웅 판정과 보유 인스턴스별 성장 장부에 적용합니다. 일반 유닛·지원 객체 전체에 일괄 XP를 더하지 않습니다.
- 미션 UI에서 특성포인트 표시를 숨기는 기존 정책과 실제 지급은 별개입니다.

### 아직 채우지 않은 입력

| 입력 | 처리 원칙 |
|---|---|
| 룸바/문/종의 정확한 객체 ID, 목표별 등장 조건·시점 | 기존 근거에서 확정된 값만 자료로 공급. 미확정을 1R 자동 생성 등으로 대체하지 않음 |
| 최종 악몽 HP·방어·방어형·마법 저항·동적 면역/능력 | 객체 기본 HP나 라운드 보스 배율로 대체하지 않음 |
| 목표별 공격 가능한 유닛·기술 조건 | 일반 스탯 존재만으로 자격 확정하지 않음 |
| 대장 선택 난수의 정확한 범위/매핑 | ‘3종 중 무작위’와 ‘각 1/3’은 구별. 미확인 균등 분포를 만들지 않음 |
| 대장별 버프 매핑·수치·대상·기간·중첩 | 신속함/강렬함/냉철함 명칭만으로 효과를 창작하지 않음 |
| 개인 토벌 재도전·최종 능력치 | 기존 단발 안내와 재고 자료를 유지. 무제한 재도전으로 확정하지 않음 |

미확정 입력은 개발 자료에서 누락으로 구분합니다. 사용자 화면에 원본 함수명·증거 문자열을 노출하지 않습니다. 정식 공급이 없는 목표를 실제 공략 가능 상태로 표시하지 않습니다.

## 3. 공통 자료와 책임 분리

기존 전투·지갑·공유 미션·난수 서비스를 함께 사용합니다. 목표마다 별도 전투 엔진이나 보상 지갑을 만들지 않습니다.

### 3.1 정의 자료 — ObjectiveDefinition (제안)

필드: missionKind, sourceKey, allowedRawcodes, spawnRuleId, sourceRevision, resolvedStatProfileId, capabilityRuleId, rewardRuleId, followUpRuleId.

정의는 변하지 않는 규칙입니다. HP 잔량·지급 여부·출전 유닛을 여기에 넣지 않습니다. 원본 출현 조건과 난이도 보정이 모두 해석된 뒤에만 기존 SpawnPlan을 생성합니다. 현재 SpawnPlan의 HP/방어/마방/좌표만으로 동적 면역을 표현할 수 없다면 기존 적 능력/상태 공급 경로를 함께 연결합니다.

### 3.2 실행 장부 — ObjectiveEncounter (기존 모델 확장)

필수 상태: runId, encounterId, missionKind, enemyId, spawnEventId, 원본 객체 ID, 정의 버전, 확정 생성 계획, 현재 전투 상태, spawnEvidence, defeatEventId/evidence, 보상 영수증, 후속 의무, 출전 인스턴스 ID.

- 동일 runId 안의 spawnEventId는 한 목표에만 귀속합니다.
- 같은 사건 ID·같은 계획 재전달은 기존 목표를 반환합니다. 같은 ID·다른 HP/객체/좌표는 거부합니다.
- 여러 목표가 같은 이름을 써도 enemyId로 구별합니다.
- 이벤트 ID는 현행 후속 함수의 제한에 맞춰 **160자 이하의 공통 생성 규칙**으로 통일하는 것을 제안합니다. 기존 SpawnPlan/격파의 256자 허용과 후속의 160자 제한을 방치하지 않습니다.
- 재시도용 새 ID를 매번 만들지 않습니다. 같은 사건에는 원래 ID를 재사용합니다.

### 3.3 사건 공급자

1. 로컬 게임의 라운드·스토리·생성·전투 상태를 읽는 공급자가 확인된 원본 조건을 평가합니다.
2. 조건 충족 사건을 장부에 기록하고 고정된 생성 계획을 만듭니다.
3. 기존 witness가 그 실제 사건과 계획의 대응을 확인합니다.
4. 기존 목표 월드가 실제 적을 생성합니다.
5. 전투 엔진의 실제 사망과 대응하는 목표 사망 확인을 모두 받은 뒤 정산합니다.

여기서 원본 사건 공급은 **Unity 로컬 실행의 사실을 원본 규칙과 연결하는 어댑터**입니다. Warcraft 실행을 앱에 의존시키지 않습니다. 동시에 고정 문자열을 반환하는 시험용 witness, UI 클릭을 사망 증거로 사용하는 우회도 금지합니다. 목표별 입력이 미확정이면 그 목표의 생산 경로는 미연결로 남깁니다.

## 4. 등장·출전·전투 흐름

### 4.1 생성

- 세션 시작 전에 출현/사망 witness와 대장 후속 공급자를 구성합니다.
- 실제 생성 조건을 충족하면 SpawnPlan을 검증하고 목표 월드에 전달합니다.
- 동일 목표가 이미 존재하거나 완료됐다면 두 번째 적을 만들지 않습니다.
- 생성 성공 후에만 UI에 실제 HP·출전 동선을 공개합니다. 계획만 존재하는 상태에서 가짜 HP를 표시하지 않습니다.
- 대장은 문 완료 장부와 생성 의무가 있어야 합니다. UI에서 직접 대장을 생성하지 않습니다.

### 4.2 유닛 출전

요청은 instanceId + enemyId를 사용합니다. 화면 목록을 만들 때와 버튼을 누를 때 모두 실제 소유·생존·목표 생존·해독/다른 전장 귀속·공격 자격을 검사합니다. 가능한 후보만 목록에 표시하고 불가능한 유닛 행과 개별 불가 사유는 만들지 않습니다. 같은 종류·상태의 개체를 묶으면 1회 탭으로 정확히 1개체를 선택합니다.

검증이 끝나면 기존 출전 API로 메인 전장 귀속을 해제하고 대상 전장에 배치합니다. 원래 인스턴스의 HP·마나·폼·쿨타임을 유지하고 복귀 위치를 기록합니다. 화면용 복제 유닛을 전투에 등록하지 않습니다. 배치와 공격 가능 거리 판정은 분리해 유지합니다.

**현재 코드와 승인 범위의 구분:** 공유 목표 코드는 다른 출전/스토리/해독 상태에서 출전을 거부하고 출전 중 조합·판매를 잠그며, 목표 퇴장 시 자동 복귀합니다. 성현 님이 확정한 ‘복귀 없는 소비·직접 목적지 변경·최종 수동 복귀’는 스토리/크립 계약입니다. 이번 문서만으로 공유 목표에까지 확대하거나 기존 동작을 최종 승인 정책이라고 단정하지 않습니다. 공유 목표의 이 세 정책을 바꾸는 작업은 별도 결정 항목입니다.

일시정지 중에도 파견 조작을 허용하는 기존 공통 정책을 따릅니다. 공격·효과·제한시간은 게임 논리 시계가 멈추면 함께 멈춥니다. Running 여부와 수동 일시정지 여부를 혼동해 출전을 막지 않도록 호출부를 대조합니다.

### 4.3 피해와 전장 격리

- 라인 평타, 자동기, 추가타, 지속피해, 예약 공격, 비보유 가상 공격의 대상 검사를 동일한 목적지 ID에 맞춥니다.
- 같은 공유 목표에 출전한 아군끼리만 해당 전장의 지원·오라를 주고받습니다. 다른 공유 목표/메인/스토리로 누출하지 않습니다.
- 출전·복귀·유닛 제거 때 이전 전장의 예약 공격과 지원 참조를 기존 전장 변경 정리 경로로 무효화합니다.
- UI HP는 실제 enemyId의 전투 상태만 읽습니다. 별도 카운터 감소로 격파를 판정하지 않습니다.
- 목표 제거·게임 종료·장면 해제는 ‘사망’과 구분합니다. 단순 제거에는 보상을 지급하지 않습니다.

## 5. 사망 상태와 정산 순서

| 현재 상태 | 사건 | 다음 상태 / 처리 |
|---|---|---|
| 생성 전 | 검증된 실제 생성 | Alive, 실제 적 1기 등록 |
| Alive | 원본 규칙에 대응하는 사망 확인이 먼저 도착 | 확인만 보관. 살아 있는 적에 보상 금지 |
| Alive | 실제 전투 사망이 먼저 도착 | DefeatedUnverified, 사망 확인 대기 |
| DefeatedUnverified | 대응 사망 확인 확보 | 보상·공유 완료 기록 재시도 |
| 정산 조건 충족 | 보상 영수증과 완료 기록 모두 확정 | Completed |
| Alive | 사망 외 제거 | Removed, 보상 없음 |
| Completed | 동일 사건 재전달 | 성공 상태 유지, 추가 지급 없음 |

현재 모델의 상태 이름을 재사용합니다. ‘정산 대기’는 UI 표현이며 사망/보상/미션 완료 장부를 합쳐 판정합니다. Completed는 기본 보상/공유 미션 완료이며 대장 생성·버프 같은 후속 의무까지 모두 끝났다는 뜻으로 쓰지 않습니다.

### 5.1 지급 순서와 실패 복구

1. 실제 사망·대응 증거·미완료 여부를 검증합니다.
2. 무작위 보상은 기존 공통 난수에서 한 번 뽑고 결과와 소비 위치를 보류 장부에 확정합니다.
3. 지급 당시 영웅 XP 수령 인스턴스와 보상 묶음을 고정합니다. 재시도로 새 영웅을 수령자로 추가하지 않습니다.
4. 기존 공유 지갑의 once 거래로 지급합니다.
5. 같은 사건으로 공유 완료를 기록합니다.
6. 미처리 후속 의무를 실행합니다.

현행 코드는 지갑 지급 다음에 미션 완료를 기록합니다. 사이에서 실패할 수 있으므로 **영수증은 있으나 완료 기록이 없는 상태**를 복구 대상으로 둡니다. 복구는 미션 기록만 마무리하며 재화를 다시 주지 않습니다. 지갑 완료 후 관찰자 예외 역시 영수증을 먼저 확인합니다.

황금종은 지급 전 5% 추첨이 있습니다. 지급이 실패한 재시도에서 다시 추첨하지 않도록 결과를 보관하는 연결이 필요합니다. UI 재열기·저장 복원이 추첨을 유발해서는 안 됩니다. 발굴 상한과 AI01 영구 획득 이력도 현재 보유량과 구분합니다.

## 6. 정의의 문 → 대장 → 버프

1. 정의의 문 실제 격파를 확인합니다.
2. 문 보상 1회와 대장 생성 의무 1회를 기록합니다.
3. 확인된 원본 난수 규칙으로 대장 종류를 한 번 결정해 장부에 저장합니다.
4. 선택된 대장을 실제 생성합니다.
5. 실제 생성 확인 후에만 생성 의무 1회를 소비합니다.
6. 대장 실제 격파 시 대장 보상·공유 완료·버프 적용 의무를 기록합니다.
7. 종류에 맞는 버프를 실제 능력/상태 시스템에 한 번 적용합니다.
8. 적용 증거를 받은 뒤에만 버프 의무를 소비합니다.

생성 후 의무 소비 전에 중단되면 같은 생성 ID로 재개하여 기존 적을 재사용합니다. 새 대장 추첨 금지. 버프 역시 실제 적용 영수증과 의무 소비를 구별하고, 적용 후 중단됐으면 소비만 재개합니다.

**예시:** 문 파괴 보상을 받고 대장이 생성된 직후 앱이 종료돼도, 이어하기에서는 같은 종류·같은 HP의 대장 한 기와 기존 문 완료 상태가 복원돼야 합니다. 문 보상 재지급, 다른 대장 재추첨, 의무 미처리를 이유로 대장 추가 생성은 모두 잘못입니다.

원본 종류별 버프의 수치·기간·대상은 미확정 항목입니다. 임의 공속/공격력 증가나 보상용 플래그만으로 ‘버프 적용 완료’ 처리하지 않습니다. 버프 적용 확인이 사망 정산보다 먼저 도착해도 보관 후 순서에 맞게 소비합니다.

## 7. 해왕류·나머지 공유 목표

### 해왕류

기본 보상과 XP, 이세계 도박 충전을 같은 격파 사건으로 연결합니다. 기존 ChargesPerBdLEvent와 카지노 상태 조회를 재사용하며 충전 횟수를 새 상수로 만들지 않습니다. 충전 권리/해금 조건을 건너뛰지 않습니다. 생성·출전·UI 방문으로 충전을 주지 않습니다. 같은 사망 재통지에 기본 보상과 충전 모두 한 번만 발생해야 합니다.

### 룸바 영혼·황금종

문과 같은 파괴물 전투 흐름을 재사용하지만 대장 생성 의무를 추가하지 않습니다. 황금종의 AI01 분기는 기존 영구 획득 이력과 보류 추첨을 사용합니다. 일반 발굴 스택 지급과 AI01 실물 획득을 같은 것으로 취급하지 않습니다.

### 공유 8종 완료

공유 비전투 목표 3종은 기존 스토리/보물 사건 경로를 유지합니다. 전투 5종을 비전투 완료 API로 우회하지 않습니다. 여덟 번째 서로 다른 공유 목표가 확정되면 기존 포네그리프 해금을 즉시 갱신합니다. 세 대장 후보·개인 토벌·크립 수를 완료 개수에 더하지 않습니다. 해독 자체의 시간/보물 공개 규칙은 기존 명세를 재사용합니다.

공유 목표 출전 엔진을 그대로 붙이지 않습니다. 개인 토벌은 해당 플레이어의 **라인에 적을 소환하는 도전**입니다. 배정형 개인미션의 교체/보상 엔진과도 별개입니다.

| 깅 | H0AU | 15R 이후, 신세계 이전 | 골드 1,500·목재 2 |
| 클리크 | H0AT | 20R 크로커다일 격파 후, 신세계 이전 | 골드 3,000·목재 4 |

**종료:** 실제 사망 사건과 마감 사건의 논리 순서를 기록합니다. 원본은 0.5초 생존 확인과 60초 마감이 별도이므로 이를 단순 UI 카운트로 대체하지 않습니다. 마감으로 적을 제거할 때는 Timeout 이유를 기록해 사망 보상이 발생하지 않게 합니다. 동일 시각의 순서는 원본 스케줄 근거가 없으면 임의로 성공/실패 우선으로 확정하지 않습니다.

**저장:** 도전 ID·재고/소모 이력·소환 횟수·적 상태·남은 논리 시간·다음 확인 시각·종료 원인·보상 영수증을 저장합니다. 로드 시 60초를 새로 시작하거나 소환 콜백을 재실행하지 않습니다.

## 9. 화면 배치와 갱신 계약

공유 목표는 기존 오른쪽 미션 상세 영역을 사용합니다. 전체 화면 크기를 바꾸거나 큰 장식 테두리를 추가하지 않습니다. 아래 순서는 위에서 아래입니다.

1. **고정 상단:** ‘공유 미션’과 실제 완료 수. 개인미션 전환 버튼은 기존 위치 유지.
2. **목표 선택 목록:** 목표 이름·상태. 세 대장 후보를 세 개의 미션으로 늘리지 않음.
3. **선택 목표 고정 요약:** 이름, 등장/전투/정산/완료 상태, 실제 HP 막대와 숫자, 출전 수. 미등장에는 가짜 HP 막대 없음.
4. **스크롤 본문 첫 부분:** 현재 출전 개체와 개별 복귀 버튼.
5. **그다음:** 출전 가능한 보유 유닛 목록. 이름·초상·동일 상태 수량·출전 버튼. 자격 없는 행 숨김.
6. **본문 끝 접힘 영역:** 보상 정보. UI 숨김 정책이 있는 특성포인트는 표시 제외하되 지급 유지.

본문만 스크롤하고 목표 이름/HP가 목록과 함께 사라지지 않게 합니다. 후보가 없으면 ‘출전 가능한 유닛이 없습니다’ 한 줄만 표시합니다. 아직 등장하지 않은 목표의 빈 출전 버튼은 만들지 않습니다. 정산 대기에는 다시 받기/다시 처치 버튼을 만들지 않고 내부 재시도 상태를 보여줍니다. 후속 버프 미처리 상태를 전체 완료로 오표시하지 않습니다.

카드 선택·탭 전환·스크롤은 조회만 수행합니다. 짧은 탭 한 번만 명령 한 건으로 처리합니다. 명령 후 최신 모델로 다시 그리며 서버처럼 별도 UI 소유 상태를 만들지 않습니다. 개인 토벌에는 실제 남은 60초만 표시하고 제한시간이 확인되지 않은 공유 목표에 같은 타이머를 붙이지 않습니다.

| 목표 | encounterId/enemyId, 현재 HP·방어/상태, Alive/DefeatedUnverified/Completed/Removed |

| 후속 | 대장 선택 결과, 생성 의무/소비 여부, 버프 실제 적용/의무 소비 여부 |

복원 순서: 자료/버전 검증 → 공유 지갑·로스터·난수 준비 → 적과 목표 장부 복원 → 출전/예약 효과 연결 → 공유 미션/후속 장부 대조 → 이벤트를 한 번씩 연결 → 전체 그래프 원자 교체. 복원 중 등장·보상·도전 명령을 다시 호출하지 않습니다.

불일치 예: 살아 있는 목표의 적이 없음, 출전 인스턴스가 없음, 같은 유닛이 두 전장에 있음, 같은 사건이 서로 다른 객체에 연결됨, 지급 영수증 없이 완료만 존재함. 이 경우 성공으로 덮지 않고 현재 플레이를 보존한 채 복원을 실패시킵니다. 단, ‘지갑 지급 완료·미션 기록 대기’처럼 명시된 중간 상태는 복구 대상으로 인식합니다.

현행 액터 복원이 공유 출전 유닛을 거부하는 보호 조건은 단순 삭제하지 않습니다. 목적지/소유권을 재결합하는 S01~S03 구현과 함께 해제해야 합니다. 전체 저장이 완성되기 전에는 정식 이어하기 UI를 활성화하지 않습니다.

## 11. 구현 묶음과 완료 확인 시나리오

구현은 다음 네 묶음으로 진행하며 목표별 중복 엔진을 만들지 않습니다.

1. **자료/실제 사건 공급:** 5종 정의, 미확정 필드 검증, 생성/사망 공급자와 컨트롤러 연결.
2. **전투/화면:** 자격 검사, 실제 출전/복귀, 모든 공격·지원 경로의 전장 격리, 모델 기반 상세 패널.
3. **정산/후속:** 공통 영수증, 문→대장, 대장 버프, 황금종 보류 추첨, 해왕류 충전, 공유 8종 해금.
4. **저장/개인 토벌 연결:** 전체 복원과 교차 검증, 개인 도전 재고·60초 종료·개별 보상 경로. 개인 토벌 미확정 규칙은 임의 확정하지 않음.
