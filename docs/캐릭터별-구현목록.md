각 U-ID는 아래 항목을 모두 확인한 뒤 체크한다.

1. **기본 수치:** 현재 버전 근거·객체/형태·피해 주사위·공격 주기·필요 자원·버프/업그레이드가 구분됨.
2. **평타:** 실제 소환→타깃→공격 선언/타격→HP 감소→처치가 작동함. 미리보기 섬광만으로 완료하지 않음.
3. **스킬/패시브:** 해당 캐릭터의 전체 항목을 개별 스킬 ID로 기록하고 발동·범위·확률·쿨타임·피해·중첩·강화 분기를 구현/검증함.
4. **프로필 미수집:** 0개 표기는 ‘수집된 항목0’일 뿐 스킬 없음이 아님. 원본 능력 코드 대조 후 없음/시스템 능력/실제 스킬을 판정함.
5. **조합·강화:** 재료/비용/특수 조건·실제 소비/생성·특성 변화가 연결됨. 소환/변신/판매 시 효과 정리도 확인함.
6. **전장 예외:** 메인·스토리·크립/특수 목표 자격, 중복 공격 금지와 필요한 스킬 예외를 확인함.

## 캐릭터별 상세 진행 기록 양식

작업을 시작한 캐릭터부터 아래 양식을 실제 값으로 채워 이 절에 추가한다. 모든 캐릭터에 빈 문서를 미리 만들지 않는다.

```markdown
### U-캐릭터ID 이름
- 상태: 조사/구현 중/구현 완료·검증 대기/완료/자료 대기
- 근거: 버전·원본 함수/객체·도감 URL·미확정 항목
- 기본 공격: 구현 위치·연결 여부·타격/처치 검증
- 스킬/패시브:
  - 원래 스킬ID 또는 패시브ID: 발동·효과·강화 분기 / 구현 커밋 / 검증 결과
  - 특수 대상·전장·중첩·폼 변화: ...
- 조합/강화/파견: 실제 연결 상태 또는 근거 있는 해당 없음
- 관련 공통 작업ID: ...
- 검증: 명령·실행 링크/로그·통과/실패/미실행
- 남은 문제/다음 작업: ...
- 최종 완료 커밋: ...
```

원문 스킬 ID를 이름 추측으로 새로 대응시키지 않는다. 수집 자료의 `unitId`, `skills[].id`와 패시브 원문을 유지한다. 스킬 설명에 없는 값은 별도 근거 확보 전까지 미확정으로 둔다.

## 갱신 규칙

- 캐릭터가 추가/대체되면 원본 근거와 함께 카탈로그·상세 프로필·이 목록을 같은 변경에서 갱신한다.
- 기존 U-ID는 재사용하지 않는다. 이름이 같은 다른 등급을 합치지 않는다.
- 데이터 집계용 JSON의 `allStatsVerified`나 `gameRawCode`를 체크박스를 맞추려고 임의 변경하지 않는다.
- 실제 진행을 반영할 때는 본 목록의 체크와 상세 기록, [공통 작업 진행 기록](개발-작업목록.md)을 함께 갱신한다.
