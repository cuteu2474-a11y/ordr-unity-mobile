# Unity 독립 몬스터 전투 — 원본 JASS 기반 실행 경로

## 현재 동작

- **65라운드 전체**를 Unity 내부에서 실행합니다. 워크래프트 실행 파일, 원작 클라이언트에서 관측한 외부 이벤트, 별도 승인 토큰이 없어도 `BeginPracticeBattle(65)`을 호출할 수 있습니다.
- `original-2323C-monster-wave-script-evidence.json`의 원본 몬스터 ID·역할·0.5초 생성 간격을 그대로 읽습니다. 55·60·65라운드는 일반 몬스터 35마리와 보스 1마리를 함께 생성합니다.
- `mobile-standalone-enemy-model.json`의 65라운드·68개 역할별 초기 HP/방어력/방어 유형/원본 객체 이동속도를 사용합니다. 초기 악몽 A04Q 레벨 **16**과 원본 W3A `Def5` 값으로 출현 적의 마법 피해 수령 계수 **0.90(마법저항 10%)**를 Unity 방어 프로필에 연결했습니다. 이후 원본 이벤트에 의한 레벨 변화는 아직 적용하지 않습니다. 기존 공통 전투 엔진이 피해, 이동, 죽음, 처치 골드, 70마리 누적 패배, 라운드 종료 및 위습 보상을 처리합니다.
- 55·60·65라운드 **보스 사망**만 모델 라운드 시계와 원본 Bdf 점수 구간(16초 미만 **1000점**, 그 밖은 **500점**)으로 합산합니다. `BossScoreAwarded`는 **골드·목재와 다른 점수**이며 라운드 이력에도 분리 기록됩니다. 보스 이외 적이나 실패·중복 사망으로는 지급하지 않습니다.
- Unity 플레이 메뉴에서 **65R**을 선택할 수 있습니다. 기존 10R·20R 경로도 유지합니다.
- 몬스터 ID·초기 전투 모델은 `tools/build_mobile_practice_battle_data.py --last-round 65`로 원본 고정 JASS와 SLK에서 일괄 재생성할 수 있습니다. 원본 맵 파일은 수정하지 않습니다.

## 원본 동일성 범위

원본 JASS에서 추출한 **정상 출현 몬스터 종류·개수·생성 간격**, 초기 난이도 연구와 오브젝트 데이터를 반영한 **모델 수치**, 몬스터가 실제로 죽었을 때의 공통 보상 이벤트는 게임 내부에서 계산됩니다. 1라운드 예시인 체력 **338**은 더 이상 외부 승인 신호가 없다는 이유로 전투 실행에서 거부되지 않습니다.

이것은 **원작 완전 재현 인증**과 다릅니다. 다음 항목은 아직 원작 클라이언트의 최종 결과와 일치한다고 증명되지 않았습니다.

- 이세계 모드의 모든 후처리 능력치, 스폰 이후의 동적 이벤트/기술/면역/재생 및 조건부 광폭화 발생. 스토리 적 A08Q 기절 저항·크립 Amim 면역·라인 Aeth는 객체 등록 정보만 확인됐으므로 실제 효과를 임의로 활성화하지 않습니다.
- 워크래프트의 실제 이동 충돌·선회, 실시간 수치 반올림, 다른 게임 시스템과 상호작용
- 원본 첫 웨이브 대기·후반 스테이지 전환 등 전체 라운드 절대 시각. 보스 점수는 Unity 논리 시계 모델이며 원본 클라이언트의 실제 타이머 일치를 증명하지 않습니다.

따라서 데이터의 `retailParityVerified`와 `safeForVerifiedMonsterWaveRuntime`은 **false**로 유지합니다. 기존 *원작 최종 실측 검증 전용* 경로에 있는 보호 로직은 변경하지 않았고, 실제 플레이 가능한 별도 Unity 독립 전투 경로를 활성화했습니다.

## 작업 분리

이 문서와 변경은 몬스터 **출현·체력·방어·이동·라운드 연결**에만 해당합니다. 플레이어 캐릭터별 스킬과 조합 정의는 다른 작업 흐름에서 관리합니다. 두 흐름은 공통 `CharacterCombatRuntime`을 사용합니다.
