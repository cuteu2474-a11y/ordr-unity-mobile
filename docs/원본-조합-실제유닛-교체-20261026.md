# ORDR S2 2.323[C] — 실제 전투 유닛 조합 교체 단계 (2026-10-26)

## 구현 범위

이번 변경은 단순 UNIT/GOLD/WOOD 원본 등록식의 실제 결과를 `CharacterCombatRuntime`에 생성하고, 재료 캐릭터의 기존 공격 예약·스킬·오라 등 게임 상태가 실패한 합성 때문에 초기화되지 않도록 단계별 소모를 지원합니다.

- `CharacterCombatRuntime.BeginOriginalFusionUnitSwap`: 정확한 실존 재료 인스턴스를 검증하고 원본 증거가 있는 위치에 결과 캐릭터를 생성. 재료는 **실제로 삭제하지 않고** 조합 검증용 목록에서만 잠시 숨김
- 성공 커밋: 결과 생성 및 원본 객체 ID, 지갑 차감과 실물 목록 검증이 모두 통과한 다음에만 기존 재료 유닛을 `RemoveCharacter`로 최종 제거
- 검증 실패/중단: `RollbackUncommittedSpawn`으로 결과만 취소하고 기존 재료의 실제 인스턴스 ID·좌표·스킬 예약·상태를 유지
- 조합 도중 추가 스폰·이동·제거 및 전투 시간 진행 차단. 직접 로스터를 변조해도 원본 재료 좌표/상태 변경을 마지막에 감지
- `OriginalJassCombatUnitFusionWorld`: 기존 실전 공유 지갑·전투 로스터 경로에서 **실제 유닛 교체**를 실행할 수 있는 구체적인 월드
- `OrdrCharacterCombatController.ConfigureOriginalJassCombatUnitCrafting`: 검증된 원본 객체 매핑, 실제 스킬 대상 규칙, 완전한 원본 조합 후속효과 증거를 연결하는 진입점
- **검증 장벽 유지**: `IOriginalJassVerifiedFusionSwapRules`가 해당 CWR 주문의 정확한 결과 소환 좌표, CHu/CHx 후속효과의 전체 구현, 생성 객체 rawcode를 승인하지 않으면 실제 유닛 교체 불가
- 일반 조합 미리보기 및 260개 비-단순 조건 조합은 계속 실행 차단. 원본 맵/피해량/조합비용/확률은 변경하지 않음

## 실행 시나리오

Unity EditMode 테스트 코드를 추가했습니다.

1. **비비 영원** 시험용 원본 네이티브 증거: 실전 유닛 6기 제거, 결과 유닛 1기 생성, 결과 원본 `h057` 확인, 공유 목재 5개 차감, 중복 제작 불가
2. 생성된 결과의 원본 rawcode 등록을 실패시키면 결과 캐릭터를 취소하고 재료 6기와 목재 잔액 모두 유지
3. 원본 조합 후속효과의 완전성 증거가 없으면 결과 생성 자체 차단
4. 준비 중에는 원본 재료 캐릭터를 삭제하지 않고, 실패하면 보존. 우회 좌표 변경도 최종 승인 차단
5. 기존 실패형 네이티브 거래의 재화 차감→롤백 회귀 유지

테스트의 원본 객체 승인 공급자는 **TEST_ONLY**입니다. 원본 실제 조합의 발동·시전·후속 효과 전수를 입증한 것이 아닙니다. `IOriginalJassVerifiedFusionSwapRules`의 프로덕션 구현과 전체 복원 가능 범위 검증이 없으므로 기본 게임은 여전히 조합 실행을 허용하지 않습니다.

## 추가 제한 및 후속 작업

결과 생성이 성공한 뒤 재료를 최종 제거하는 과정에서 예기치 못한 엔진 오류가 발생할 경우 공격 예약·스킬 상태까지 되살릴 수 있는 **전투 엔진 전체 스냅샷 기반 롤백**은 아직 없습니다. 따라서 실기 배포 전 해당 예외 구간을 보호하고 CHu/CHx의 모든 부작용(예: 독립 지속 투사체/후처리)이 원작과 일치하는지 확인해야 합니다.

GitHub에 유닛/지갑 연결 코드가 존재한다는 사실과 원본과 동일하게 플레이 가능하다는 판단은 구분합니다. Unity CI·실제 iPad/Android 플레이 테스트 결과는 별도 확인 필요. APK는 핵심 기능 완성 전 생성하지 않습니다.
