# 조합 거래 엔진 — 원본 근거와 예외 처리

> **개발자용 참고:** 초기 구현 일지에 흩어진 원본 등록식·거래 무결성·예외 위험을 통합합니다. 플레이어의 조합 방법과 **현재 제작 허가 241건**은 [조합 시스템](조합-시스템.md), 최신 APK·검사 상태는 [현재 상태](START_HERE.md), 남은 기능은 [개발 작업](PLAYABLE_ROADMAP.md)이 기준입니다. 초기 단계 수치를 현재 구현률로 사용하지 마세요.

## 1. 원본 등록식과 검색 미리보기

- 원본 `CWR` 등록 **266건** 중 **265건은 비-TEST**입니다. 초기 조사에서 `UNIT/GOLD/WOOD` 조건으로만 된 **5건**을 별도 실험 대상으로 구분했으나, 지금 제작 가능한 전체 수는 아닙니다. 현재 허가 범위는 `Original323CommonFusionPort`와 원본 경로 감사 자료로 확인합니다.
- `MobileFusionBrowser`와 `OriginalJassReadOnlyFusionPort`는 일반·신비·원본 JASS 레시피의 검색, 부족한 실물 재료·재화 표시, 재료 중복·스토리 파견 배제에 사용됩니다. **검색 결과에 보이는 것과 실제 제작 허가는 다릅니다.** 읽기 전용 포트는 확정 요청을 거절해야 합니다.
- 초기 객체 후보는 `data/original-fusion-object-reconciliation.json`의 원본 `rawcode`와 `authorizedForFusionExecution`·`approvedForMaterialConsumption`을 분리해 조사했습니다. **예전 비승인 플래그로 현재 공통 포트의 241건 허가 결과를 덮어쓰지 않습니다.** 동일 W3X 원본과 현재 실물 목록을 대조합니다.
- 신비 공개 도감 13종 미리보기·`OtherworldMysticFusionAtomicCoordinator`는 후보·실제 거래 조건을 분리한 초기 구조입니다. JASS 능력 후보를 자동으로 제작 승인하지 않습니다. [신비 원본 후보](신비조합-원본-JASS-후보대조-20261022.md)와 `data/original-jass-mystic-candidate-reconciliation.json`을 참조하세요.

초기 **단순 조건 5건**의 분류 근거입니다. 현재 실행 허가 수를 의미하지 않습니다.

## 2. 거래의 필수 보장

초기 원본 순서형 실행 경로는 `OriginalJassFusionPort → OriginalJassFusionAtomicCoordinator → OriginalJassFusionOrderedWorldAdapter`였습니다. 현재는 더 넓은 범위의 **[공통 조합 실행 포트](../Assets/Scripts/Mobile/Original323CommonFusionPort.cs)**가 있으므로 초기 경로를 별개의 새로운 범용 엔진으로 재구현하지 않습니다.

1. **확정 시점 재검사:** 미리보기에서 선택한 재료가 현재도 존재하는지, `rawcode`·개체 ID·수량·파견/판매 상태·골드/목재·아이템·특수 조건이 맞는지 확인합니다. 하나의 실물 개체를 두 번 소비할 수 없습니다.
2. **원자적 소비:** `SharedEconomySession`/`EconomyWallet.TryExchange`와 독점 원본 거래 월드 안에서 비용 차감, 재료 제거, 정확한 결과 유닛 생성, 영수증을 함께 확정해야 합니다. 초기 순서형 구현은 먼저 소모 명세를 준비하고 마지막 커밋 전에 실제 변경을 재확인하도록 설계됐습니다.
3. **전투 유닛 교체:** 초기 구현의 `BeginOriginalFusionUnitSwap`은 재료를 바로 제거하지 않고 결과를 임시 생성합니다. 검증 실패 시 `RollbackUncommittedSpawn`으로 결과만 취소하고 원본 재료·스킬 예약·좌표를 유지합니다. 성공 전까지 `UnitSpawned`/`UnitPlaced` 이벤트를 외부에 발행하지 않고, 완료 시 한 번만 공개합니다.
4. **전투 시간 보호:** 조합의 독점 단계에 `Step`·다른 소환·판매·이동·상태·라운드 변경이 끼어들어 이벤트 버퍼, 공격 예약, 적 오라 재계산을 오염시키지 못하도록 차단합니다. 최종 재료 위치·상태 재검사와 오라의 일괄 갱신을 유지합니다.
5. **롤백·중복 방지:** 결과 생성·후처리 실패 시 재화, 유닛, 결과, 영수증을 복원하고 같은 요청을 중복 실행하지 않습니다. 테스트용 월드의 성공은 실제 원본 소비 승인과 구분합니다.

**남은 위험:** 초기 코드에는 **최종 재료 삭제가 일부 이뤄진 직후 예외가 나면** 공격 예약·스킬 타이머·원본 RNG까지 완전히 복원하는 전역 스냅샷이 없다는 한계가 기록되어 있습니다. 이후 공통 거래가 확장됐더라도 현재 호출부에서 이 구간이 보호됐는지 확인해야 합니다. 또한 원본 `CHu/CHx`의 후속 기술·더미·오라·타이머는 **결과 유닛 생성만으로 구현 완료가 아닙니다.**
