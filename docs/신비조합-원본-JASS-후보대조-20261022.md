# 신비 조합 13종과 원본 JASS 조합 등록식 대조 (2026-10-22)

대상: **ORDR S2 2.323[C] / 악몽 난이도 + 이세계모드 고정**.

기존의 13종 공개 도감 조합을 원본 JASS의 `CWR` 등록식과 비교한다. 원본 맵의 유닛 객체 테이블을 통해 이름↔rawcode를 확인하지 못했으므로, 이 문서와 동반 JSON은 **후보 분석 자료**다. 조합 실행·재료 소모 권한을 부여하지 않는다.

## 현재 확인 결과

- 공개 도감의 신비 결과: **13종**, 공통 비용: **10,000골드/목재 7**, 공통 요구: **행운의토큰**.
- 원본 JASS에서 같은 골드·목재 비용, 공통 `UNIT:h06G/1`, 결과 유닛을 지칭하는 `KING` 조건을 가진 `CWR` 등록식: **14개**. 따라서 비용 일치만으로 신비 조합이라고 단정할 수 없다.
- 기존 JASS 유닛 표기 `Bi8/Bi9`와 도감의 **등급·이름 상관관계**로 식별 가능한 재료를 대조하면, 13종 중 **8종**에 다른 후보보다 강한 일치 증거가 있다. 이 단계에서 확정된 결과 유닛 rawcode 매핑은 **0개**.

## 구조 대조에 사용한 추정 (확정 아님)

1. 모든 비용 일치 등록식에 공통인 `UNIT:h06G/1`이 공개 도감의 행운의토큰과 대응할 수 있다.
2. 일부 등록식의 `PICK:A800/1`은 도감의 '랜덤 등급 재료 1기' 슬롯과 대응할 수 있다.
3. 고죠의 추가 특수 요구인 **해적선**은 JASS에 따로 들어간 `UNIT` 한 항목일 수 있다.

위 세 가정에 따라 재료 슬롯 **수**가 맞는 등록식만 후보로 남긴다. 이름이 이미 상관된 JASS 재료가 공개 도감에 없는 경우에는 후보에서 제외한다. 그러나 이 방법으로 새로운 rawcode를 확정하지 않는다. 특히 `A0QG`는 같은 10,000/7 구조에 들어가지만 현재 도감 재료와 연결되지 않는 H-18 상관관계가 있어 13종의 구조 후보에는 남지 않는다. 이는 추가 1개의 실제 용도를 확정한 뜻은 아니다.

## 재현과 검증

```bash
python3 tools/reconcile_otherworld_mystic_jass_candidates.py
python3 -m unittest discover -s tests -q
```

입력: `data/original-jass-fusion-registry.json`, `data/original-unit-rawcode-label-links.json`, `data/otherworld-2323C-mystic-web-recipes.json`.

출력: `data/original-jass-mystic-candidate-reconciliation.json` (원본 조건 순서 보존, 13종 후보·근거·원본 SHA-256 포함).

Unity 편집기를 열면 `OrdrCharacterDataSync`가 이 JSON도 `Resources/OrdrData`에 복사한다. 게임 코드의 `OriginalMysticJassCandidateCatalog.FromJson`은 분석 후보를 **읽기 전용**으로 조회할 수 있게 하며, 검증된 객체 매핑·조합 실행 권한처럼 취급하는 입력은 거부한다.

## 실제 재료 소모를 열기 전에 필요한 일

1. 해당 원본 `.w3x`에서 추출한 유닛 객체 데이터와 `war3map.wts` 등으로 **모든 신비 결과 및 재료의 rawcode↔이름**을 확정한다.
2. `CWR`의 `PICK`, `UNIT`, `KING` 조건 실제 실행 의미와 토큰/해적선 요구 수량을 확인한다.
3. 확정된 하나의 조합으로 소유 재료·골드·목재·특수 소모품의 **원자적 검사→소모→결과 생성**을 Unity 게임 월드에 연결하고, 실패 시 완전 롤백을 검증한다.

검증이 끝날 때까지 기존 `OtherworldMysticFusionCatalog`의 `CanExecute == false` 정책과 `OtherworldMysticFusionAtomicCoordinator`의 실제 월드 어댑터 미연결 상태를 유지한다. 원본의 규칙·수치를 추정으로 바꿔 넣지 않는다.
