# 원본 피해·방어력·마법 저항 — 계산 근거

> **대상:** ORDR S2 2.323[C] 악몽·이세계모드. 이 문서는 원본 맵의 **확인된 상수·JASS 함수·능력 데이터**와 아직 증명되지 않은 최종 전투 결과를 구분합니다. 현재 게임 구현률은 [현재 상태](START_HERE.md), 다음 기술 작업은 [개발 작업](PLAYABLE_ROADMAP.md), 공통 호출 구조는 [전투 엔진](전투-공통엔진.md)을 우선합니다.

## 1. 피해는 어떤 정보로 결정되나요?

1. **공격 자체:** 원본 유닛의 공격 주사위 또는 JASS 스킬 피해량·난수·발동 시점.
2. **피해 종류:** 워크래프트 공격 타입과 피해 타입의 실제 조합, 대상의 방어 타입.
3. **대상 상태:** 현재 방어력, `A04Q` 마법 저항 레벨, 실제 적용된 방깎·오라·증폭·면역.
4. **최종 반영:** 원본 엔진의 실수 피해를 게임 HP에 반영하는 정수화·타격 순서.

**맵 상수만 확인됐다는 이유로 네 단계를 하나의 임의 공식으로 완성하면 안 됩니다.** 특히 도감의 ‘물리·마법’ 표기, JASS `ATTACK_TYPE_NORMAL`, 스킬 증폭, `A04Q` 적용 대상은 서로 다른 분류입니다. 같은 사건에서 기본 타격·도감 자동 효과·JASS·네이티브 주문을 중복 적용하지 않습니다.

## 2. 기본 공격·피해 계산에서 확인된 값

맵 `war3mapMisc.txt`의 `[Misc] DefenseArmor=0.02`입니다. **일반 Warcraft 기본값 0.06을 사용하지 않습니다.** 원본 `DamageBonus*` 열 순서는 `small, medium, large, fortified, normal, hero, divine, unarmored`입니다.

| 공격 타입 (`DamageBonus*`) | 8개 값 (위에 적힌 방어 타입 순서) |
|---|---|
| Chaos | `1, 1, 1, 1, 1, 1, 1, 0.50` |
| Hero | `1.05, 1.05, 1.05, 1.05, 1.05, 1.05, 1.05, 1.05` |
| Magic | `1, 1, 1, 1, 1, 0.80, 0.90, 0.40` |
| Melee (=Normal 행) | `1, 1, 1, 0.75, 1.25, 1, 0.90, 0.80` |
| Pierce | `1, 1, 1.25, 1, 0.75, 0.90, 1, 0.60` |
| Siege | `1, 1, 0.75, 1.25, 1, 0.80, 1, 0.60` |
| Spells | `1, 1, 0.85, 0.90, 1, 0.80, 0.90, 0.40` |

JASS의 **`ATTACK_TYPE_NORMAL`은 위 `Spells` 행**, `DamageBonusNormal`은 **`ATTACK_TYPE_MELEE`**와 대응합니다. 두 타입의 이름이 비슷하다고 배율 행을 바꾸지 않습니다.

| 원본 JASS | 확인된 역할 | 해석 주의 |
|---|---|---|
| `BFh` (3589~3595행) | 최초 `GetRandomInt(1,1000000)`, 이후 `(69069*x+1) % 2147483647` 난수 상태 | 원본 호출 횟수·순서까지 일치해야 난수 결과 비교 가능 |
| `BFj` (3601~3605행) | `min(a,b) + abs(b-a)*BFh()` | 스킬 원시 배율 계산이지 모든 타격의 최종 피해 공식은 아님 |
| `Bcb` (8226~8230행) | `UnitDamageTarget(..., BFj(low,high)*baseDamage, ..., attackType, damageType, ...)` | 공격/피해 타입 조합과 대상·면역을 별도 확인 |
| `Bcc` (8231~8235행) | 지점 광역 피해 `UnitDamagePointLoc` | 단일 대상 공격과 피격 사건을 혼동하지 않음 |
| `BdV` (8434~8457행) | 관측된 이벤트 피해를 방어·버프 효과로 **역산** | 실제 공격 피해의 보편적인 정방향 증폭 공식이 아님 |
| `BeC` (8572~8577행) | `A11S` 부여/레벨 증가 | 일부 HP 비례 타격에는 `0.79+0.01*현재 A11S 레벨` 보정이 명시됨. 전체 마방 공식 아님 |

`BdV`의 방어력 역산에서 양수 방어는 `1/(1+0.02*armor)`, 음수 방어는 `2-Pow(0.94,-armor)` 및 배율 상한 **1.71**을 사용합니다. 이는 JASS **역산기**에서 확인된 식이며 최종 Warcraft HP 감소가 전부 검증되었다는 뜻이 아닙니다.

`BdV`의 버프 우선순위도 **`if / elseif`**입니다. `B06J`면 `/1.1`, 아니면 `B04W`면 `/1.25`, 아니면 `B07S`면 `/1.2`, 그다음 방어 계수 `V2`를 처리합니다. 세 버프의 수치를 모두 곱해 일반 증폭 공식으로 쓰지 않습니다.

## 3. 악몽 몬스터 마법 저항: `A04Q`

원본 `JV=A04Q`, `Bd4`는 몬스터에 해당 능력을 추가하고 레벨을 정합니다. `war3map.w3a`의 `Def5`는 **마법 피해 수령 배율**입니다. 레벨 5~41은 0.79~1.15, 기본 `AbilityData.slk`의 레벨 1~4는 0.75~0.78로 확인되어 **1~41레벨**의 입력을 확보했습니다.

| 상태 | 마방 레벨 | 마법 피해 수령 배율 | 의미 |
|---|---:|---:|---|
| 악몽 시작 | 16 | 0.90 | 저항 10% |
| 신 난이도 비교 | 21 | 0.95 | 저항 5% (현재 고정 모드 아님) |
| 레벨 26 비교 | 26 | 1.00 | 저항 0% |
| 악몽 워큐리 발동 후 새로 생성된 대상 | 1 | 0.75 | 저항 25% |

**이 레벨은 몬스터를 생성하는 시점과 살아 있는 개체의 변경 시점이 다릅니다.** 원본 사건별 다음 소환 레벨은 [A04Q 사건 근거 JSON](../data/original-2323C-nightmare-a04q-event-evidence.json)에 있습니다.

| 사건 | 일반 몬스터 다음 소환 `LK[JG]` | 보스 다음 소환 `NJ` | 원본 함수 |
|---|---|---|---|
| 악몽 시작 | 16 | 16 | `CUM` |
| 워큐리 발동 | 플레이어 전체 −15 | −15 | `BeR` |
| 니카가 워큐리 해제 | 플레이어 전체 +15 | +15 | `BeQ` |
| 기록지침 아이템 `AI19` 사용 | 사용자만 +5 | 유지 | `BhL` |
| 브룩 특성 `TR12` | 사용자만 +3 | 유지 | `BzL` |
| 원피스 보물 완성 | 완료 플레이어만 +10 | 유지 | `CRW` |

`Original323NightmareA04QSpawnState`는 **다음 소환에 쓰는 값**을, `CombatEnemy.TryApplyObservedOriginalA04QLevel`은 실제 개체의 **관측된 변경**을 다룹니다. 살아 있는 몬스터의 `Bd5` 등 개별 수정은 별도 증빙(`IOriginal323LiveMonsterA04QWitness`) 없이는 자동·소급 적용하지 않습니다. 만료·중복·지원 범위 밖의 사건은 거부합니다. 워큐리의 설명용 +15%를 이미 `A04Q` 레벨 감소로 반영한 몬스터에 다시 더하면 **이중 적용**입니다.

## 4. 방어력 감소와 아머브레이크

| 원본 능력 | 확인된 사실 | 주의할 점 |
|---|---|---|
| `A04M` · `Bdq` | 대상 능력 레벨 누적; 실제 스택은 `레벨−1`로 참조. `Idef`의 레벨 5~76은 방어 −4~−75, 따라서 4~75스택의 −N 확인 | **1~3스택의 상속 필드 미확인**. 임의로 −N 확대하지 않음 |
| `A04N` | `Idef` 레벨 5~11에서 −12~−30 | 별도 원본 능력. `A04M`과 합산 규칙 미확인 |
| `A04O` | `Idef` 레벨 5~11에서 −85~−115 | 별도 능력 |
| `A04P` · `Bd2` | `Idef` 레벨 5~41에서 −4~−40 | **보니의 방깎**. `A04M` 아머브레이크와 혼동 금지 |

`Ordr323VerifiedPartialModifierRules`는 실제 `Bdq(A04M)` 호출/몬스터 스택 출처를 증명할 공급자가 있을 때만 확정 구간의 방어 변화를 적용합니다. 단순한 도감 `armorBreak` 태그나 미확인 오라를 실제 방깎으로 환산하지 않습니다.

개별 캐릭터의 JASS 근거는 [보니 `A04P` 조사](원본-2323C-보니A04P-오라조사.md) · [방깎·마방깎 기술 연결](원본-2323C-캐릭터방깎마방깎-연결.md)에 유지합니다. 오라의 공유 버프·다중 시전자와 UI 집계의 함정은 [전 유닛 오라 조사](전유닛-공통오라-규칙조사-20261025.md)에 있습니다. JASS `BH9/BIH/BIE`의 **정보창 방깎 합계는 실제 적 개체의 상태·중첩 법칙이 아닙니다.**

## 5. 원본 마법 피해 ‘중첩 공식’은 아직 확인되지 않았습니다

`Original323NativeMagicDamageReconciliation` 등 현재 코드에서 관측 피해를 맞추기 위한 경계를 다룹니다. 예전 코드 분석에서 다음 절차를 확인했지만, 이는 **모든 몬스터·스킬에서의 원작 계산 공식이 확정되었다는 뜻이 아닙니다.**

1. 몬스터의 생존·타격 대상과 타격 당시 **실제** 마방 레벨을 확인합니다.
2. 독립 증빙으로 확인된 1~41레벨 `Def5` 배율만 사용합니다.
3. 마방 감소·마법/전체/폭발 증폭·추가 레벨 변화가 있으면 각각 원본 호출·시점·중첩의 증빙이 필요합니다.
4. 원본에서 **마방 적용 전**이라고 확인된 피해에, 대상에게 실제 적용됐다면 해당 마방 배율을 **한 번만** 적용합니다. 다른 증폭 배율을 추측해 연쇄 곱하지 않습니다.
5. 원본 엔진의 HP 실수→게임 HP 변환과 관측된 실제 체력 감소가 맞지 않으면 원작 동등으로 승인하지 않습니다.

미확인: 원본 버프 간 최종 중첩 우선순위, 대상 마스크·시전/명중 사이의 만료, 스턴/면역, 각 공격의 `attackType/damageType`, 물리·마법·폭발 별 적용 경계, 최종 정수화/64비트 HP, 원작 난수 호출 순서. 특정 `Bcb` HP 비례 기술의 `A11S` 보정을 모든 마법 기술에 적용하지 않습니다.
