# S2 2.323[C] 원본 맵 기본 능력치 일괄 추출 (2026-10-21)

## 작업 기준

- 캐릭터 이름과 등급은 기존 271종 DB를 그대로 사용한다. 재수집하지 않는다.
- **기본 능력치**: 동일한 원본 W3X의 `UnitWeapons.slk`, `UnitBalance.slk`, `UnitAbilities.slk`에서 확인한다.
- **원작 캐릭터 ID**: 맵 이름·등급이 유일하게 일치하거나, 흔함 9종 직접 확인, 또는 동일한 W3X의 JASS 조합 결과(`CWR`)와 캐릭터 이름 표(`BjB`)가 교차 일치하는 경우에만 연결한다.
- 게임 중 업그레이드, 오라, 능력·JASS 트리거, 방어 보정, 실제 첫 공격 시각은 **추가 검증 필요**다. 이 작업만으로 캐릭터를 전투 완성 상태로 표시하지 않는다.
- 모바일에서 공격 사거리를 무제한으로 처리한다는 조작 정책은 유지한다. 원본 사거리 필드는 역사적 근거로만 저장한다.

### 흔함 9종: 맵 오브젝트 기본 평타

| 캐릭터 | rawcode | 오브젝트 기본 피해량 | 원본 공격 주기 |
|---|---|---:|---:|
| 루피 | `h003` | 29~31 | 1.02초 |
| 조로 | `h002` | 31~33 | 1.03초 |
| 나미 | `h001` | 26~30 | 0.98초 |
| 우솝 | `h007` | 25~27 | 0.84초 |
| 상디 | `h004` | 23~25 | 0.77초 |
| 쵸파 | `h008` | 22~24 | 0.57초 |
| 버기 | `h005` | 29~31 | 0.99초 |
| 해군 총병 | `h009` | 30~32 | 0.96초 |

`minimumBaseDamage = dmgplus1 + dice1`, `maximumBaseDamage = dmgplus1 + dice1 × sides1`.
이는 오브젝트에 저장된 기본 수치이며 **피격 대상에게 실제 적용되는 데미지나 실DPS가 아니다**. 도감의 공격력과 다르면 원본 오브젝트 수치를 별도의 우선 근거로 보존한다. 기존 구버전 도감 값은 삭제·덮어쓰기하지 않았다.

## JASS 조합 등록식으로 동일 이름 5종 구분 (2026-10-22)

`war3map.j`의 `CWR` → `BGH`에 등록된 **조합 결과 rawcode**를 `data/original-jass-fusion-registry.json`에서 확인했다. `BjB`의 이름 연결표가 있는 4종은 해당 rawcode와 교차 검증했다. 같은 이름이라고 공격력이 가장 강한 객체를 자동 선택하지 않는다.

| 캐릭터 | 조합 결과 ID (능력 ID) | 다른 같은 이름 객체 | 스킬 설명과 대조한 사실·한계 |
|---|---|---|---|
| 마르코 제한 | `h08O` (`A011`) | `h09Q` | 인간형·불사조형 기술과 별도 능력치가 있지만 **어느 ID가 어느 형태인지는 미확정** |
| 페로나 왜곡 | `h048` (`IF02`) | `h000` | 다른 객체는 평타가 없고 `Aloc`가 있음. 정확한 보조 객체 사용처는 미확정 |
| 우타 영원 | `h067` (`ET07`) | `h0AF` | 추출된 스탯·능력 목록 동일. 복제 목적은 미확정 |
| 센고쿠 불멸 | `h04E` (`IM06`) | `h0BM` | 공격력·능력 목록 다름. 강화형 여부는 미확정 |
| 카이도 불멸 | `h07M` (`IM11`) | `h0AD`, `h0BW` | 인간형·용형 스킬 설명 존재, 능력 목록도 다름. **형태별 rawcode 할당은 미확정** |

`tools/reconcile_ambiguous_original_map_objects.py`는 원본 조합 결과로 확인된 객체만 캐릭터와 연결하고 나머지는 `alternateRawcodes`에 유지한다. `sourceJassFusionAbilityRawcodes`가 연결 근거다. 이 매핑만으로 변신·스킬 효과·전투 동일성을 선언하지 않는다.

## 원본 이름과 캐릭터 이름이 다른 49종 추가 연결 (2026-10-22)

기존 104종 미연결 중 **49종**은 `BjB`의 `Bi8(유닛 rawcode, 조합 능력)`·`Bi9(캐릭터 이름)` 자료와 `CWR`의 정확한 조합 결과가 일치했다. 맵의 `UnitWeapons.slk`에도 그 rawcode가 존재한다.

- 히든 5종, 초월 30종, 영원 8종, 불멸 6종을 추가로 연결했다.
- 초월 캐릭터의 맵 오브젝트 이름은 `해적왕이 될 사나이`(초월 루피)처럼 이름·등급 형식이 아니어서 기존 검색에서 누락됐다.
- 예: 초월 루피 `TR-08` → `H099` (`TR09`), 초월 조로 `TR-20` → `H09F` (`TR06`), 영원 니카 `E-01` → `H0BK` (`ET02`).
- 연결 상태는 `verified-jass-label-and-fusion-result`; `sourceJassFusionAbilityRawcodes`가 출처인 조합 능력 ID다.
- JASS/라벨/객체의 rawcode와 출처 SHA, 등급 접미사가 충돌하면 연결을 거부한다. 초월처럼 원본 이름에 등급 접미사가 없다면 **명시적 JASS 조합+이름 교차 확인만** 허용한다.
- 이는 216종의 **오브젝트 기본 수치** 연결이지, 버프·변신·전투 동일성의 인증이 아니다.

```bash
python3 tools/reconcile_ambiguous_original_map_objects.py --verify
```

## 스킬 작업 대기열

기존 수집 자료 `character-skill-profiles.json`에 200종 캐릭터의 스킬 554개와 패시브 295개가 있다. 이번에는 554개 스킬의 **기재된 트리거 / 효과 종류 / 재사용 가능한 구현 그룹**을 자동 분류해 연구 큐를 만들었다.

- 생성 결과: `data/original-2323C-skill-research-queue.json`
- 스킬 분류 그룹: 271개 (숫자가 캐릭터 수와 우연히 같을 뿐 271종 구현을 뜻하지 않음)
- 트리거 분류는 도감 데이터에 기록된 이름 기준이다. **원본 JASS 스킬 ID나 실제 동작이 확인된 것은 아니다**.
- 다음 구현 순서: 공통 평타 → 공통 발동형 스킬 → 상태효과 → 특수·복합 스킬. 기본 능력치 미연결 또는 JASS 스킬 미검증 항목은 추측으로 활성화하지 않는다.

## 데이터 파일 및 실행

- 원본 맵 수치: `data/original-2323C-map-base-stats.json`
- 맵 일괄 추출기: `tools/build_original_map_base_stats.py`
- 스킬 분류기: `tools/classify_character_skills.py`
- Unity 읽기 전용 로더: `Assets/Scripts/Data/OriginalMapBaseStatCatalog.cs`
- Unity 편집기 실행 시 `OrdrCharacterDataSync`가 맵 수치 JSON을 Resources에 동기화하며 `OrdrCharacterCombatController.MapBaseStats`에서 조회 가능하다.

원본 맵은 별도 보관하고 리포지토리에 128MB W3X 원본을 추가하지 않는다. `mpyq` Python 패키지가 설치된 환경에서 다음 명령으로 재생성한다.

```bash
python3 tools/build_original_map_base_stats.py --w3x /path/to/ORDR_S2_2.323[C].w3x
python3 tools/classify_character_skills.py
python3 -m unittest discover -s tests -v
```

검증 옵션 `--verify`는 생성물의 내용이 원본에서 재현되는지 비교하며 파일을 수정하지 않는다. 기존 271종 스냅샷 검증 명령 `python3 tools/validate_character_master.py`도 그대로 통과해야 한다.

## 연결된 유닛 공격 표시 및 검증된 공격 경로 (후속 작업)

- `OriginalMapCommonAttackPreview`는 공격 수치와 시점이 유효한 연결 캐릭터에 **피해 없는 공격 미리보기 이벤트**를 발생시킨다. 현재 214종의 공격 필드가 있지만 `MY-08`은 공격 시점(0.75초)이 쿨다운(0.70초)보다 늦어 기본 미리보기로 자동 가정하지 않는다.
- `CharacterCombatRuntime`이 같은 전장에 실제 적이 있을 때만 타깃을 선택한다. 모바일 정책상 사거리 제한은 적용하지 않는다. 적 체력은 감소시키지 않으며 스킬 확률도 굴리지 않는다.
- 기존 모바일 유닛 표시에서는 `AttackPreview`를 파란 짧은 섬광, 피해 계산까지 검증된 `Attack`을 노란 섬광으로 구분한다. 이동/공격 모션은 추가하지 않았다.
- 추후 개별 유닛의 원작 공격 공식이 확정되어 `BindVerifiedBasicAttack`으로 등록되면 그 유닛의 미리보기 공격은 자동 해제되어 이중 공격을 피한다.
- `attackPointSeconds`를 소환 후 첫 공격 표시 지연으로 사용하는 것은 현재 **미리보기용 가정**이며, 원작 실제 첫 타격 시각 또는 피해 계산이 검증되었다는 의미가 아니다.
- `OriginalMapMappedNativeAttackEvidenceCatalog`는 214종의 원본 주사위·공속·공격 타입을 보존한다. `OriginalMapCommonNativeAttackBinding`은 **개별 유닛의 원본 네이티브 공격 경로를 외부 검증자가 승인한 경우에만** `CharacterCombatRuntime`의 실제 HP 피해에 연결한다. 승인되지 않은 유닛은 미리보기만 남는다.
- EditMode 테스트는 초월 루피 `H099`에 **테스트 전용으로** 승인 조건을 주면 최소 기본 피해 30,001과 0.38초 주기를 바탕으로 실제 HP가 감소하도록 검증한다. 이는 원작 버프/범위/방어/최종 정수화의 실전 검증이 아니다.
- 이전 Unity CI의 에넬 900/899 차이는 원본 `A04Q`의 `Def5`가 float32 근삿값이고 테스트 전용 버림 규칙을 적용했기 때문에 발생했다. 기대값을 899로 정정했지만 **실제 Warcraft HP 반올림/절사 정책은 아직 미확정**이다.
