## 1. 원본 데이터에서 확인한 값

### 원본 `war3mapMisc.txt`의 실제 전투 상수

`[Misc] DefenseArmor=0.02`. 워크래프트 기본 0.06이 **아님**.

`DamageBonus*`의 열 순서는 `small, medium, large, fortified, normal, hero, divine, unarmored`.

| Warcraft 공격 타입 | 8개 열 (원본 파일과 동일 순서) |
|---|---|
| Chaos | 1,1,1,1,1,1,1,0.50 |
| Hero | 1.05,1.05,1.05,1.05,1.05,1.05,1.05,1.05 |
| Magic | 1,1,1,1,1,0.80,0.90,0.40 |
| Melee (=DamageBonusNormal) | 1,1,1,0.75,1.25,1,0.90,0.80 |
| Pierce | 1,1,1.25,1,0.75,0.90,1,0.60 |
| Siege | 1,1,0.75,1.25,1,0.80,1,0.60 |
| Spells (=DamageBonusSpells) | 1,1,0.85,0.90,1,0.80,0.90,0.40 |

**중요:** JASS `ATTACK_TYPE_NORMAL`은 워크래프트 API 상의 *Spells*이고, 실제 `DamageBonusNormal`은 `ATTACK_TYPE_MELEE` 행으로 취급한다. 두 행을 바꾸면 수치가 달라진다.

### 원본 `war3map.j`에 확인된 산식

- `BFh`, 3589~3595행: 전용 난수 생성기 초기값 `GetRandomInt(1,1000000)`, 이후 선형합동 `(69069*x+1) % 2147483647` 방식.
- `BFj`, 3601~3605행: `min(a,b)+abs(b-a)*BFh()`.
- `Bcb`, 8226~8230행: `UnitDamageTarget(source, target, BFj(low,high)*baseDamage, true, false, attackType, damageType, ...)`.
- `Bcc`, 8231~8235행: `UnitDamagePointLoc(..., BFj(low,high)*baseDamage, attackType, damageType)`.
- `BdV`, 8434~8457행: 이벤트 피해를 역산할 때 양수 방어에 `1/(1+armor*0.02)`, 음수 방어는 `2-Pow(0.94,-armor)`와 배율 상한 `1.71`을 사용. **이것은 JASS 피해 역산기의 산식이지 엔진 결과의 실기 검증은 아님.**
- `BeC` 8572~8577행: 커스텀 능력 상수 `JD=$41313153`(ASCII `A11S`)을 부여하거나 레벨 상승.
- `Bcb` 다수 개별 HP비례 공격(15428, 17045, 17329행 등)에 `(.79 + .01*GetUnitAbilityLevel(target,JD))` 보정이 명시됨. `ScriptHealthProportionalCorrection(level)`로 옮겼지만 **일부 체력비례 스킬 전용이며 전체 마법저항 공식이 아님**.
- `BdV`에는 특정 버프 ID를 확인하여 `/1.1`, `/1.25`, `/1.2`로 복원하는 조건도 있으나, 버프 ID 별 최종 원작 중첩 효과 확인 전에는 임의의 일반 버프 규칙으로 확대하지 않는다.
- `Ordr323VerifiedDamageHit.School`(물리/마법/미확인)는 `UseMagicResistance`와 **별도 속성**이다. 마법 증폭 여부를 마법 저항 적용 여부로 판단하면 원작과 다른 피해가 발생할 수 있어 분리했다. 스킬 분류가 미확인인데 마법 증폭이 존재하면 계산을 보류한다.
- 원본 스킬 호출에는 `ATTACK_TYPE_NORMAL/DAMAGE_TYPE_UNIVERSAL`, `ATTACK_TYPE_CHAOS/DAMAGE_TYPE_NORMAL` 등 여러 쌍이 등장한다. **물리·마법·고정 이름만으로 일반 방어/마방 판정을 분류할 수 없음**.

## 2. 실제 코드에 반영한 공통 부분

- `Assets/Scripts/Combat/Ordr323MapDamageMath.cs`: 맵 고유 방어 계수, 음수 방어 함수, 7×8 타입 배율표, JASS `BFj` 기본 피해량 계산 공식 및 일부 HP비례 스킬 보정 함수를 저장. 입력 범위와 오버플로 검증.
- `Assets/Scripts/Combat/Ordr323OriginalDamageRules.cs`: 기존 `IOriginalCombatDamageRules`를 실제 계산에 연결. 원본 공격별 타입·방어 관여 여부·스킬 원시 피해를 제공받아 타입 배율 → 방어·저항 → 피해 증폭 → 정수 변환 정책을 처리한다.
- `Assets/Scripts/Combat/Ordr323DamageWorldBinding.cs`: 기존 `CharacterCombatRuntime`의 `CombatDamageRulesAdapter`에 원본 계산기를 연결하는 생성 헬퍼.
- `OrdrCharacterCombatController.ConfigureOriginal323DamageRuntime(...)`: 기존 Unity 컨트롤러에서도 원본 수치 계산기를 선택해 구성할 수 있도록 실제 연결 지점 추가.
- 사전 검증 `IOriginalSkillDamagePreflight`: 미확인 스킬 피해가 마나·체력을 먼저 소비하지 않도록 등록된 공식 여부를 검사. RNG 소모 없는 `IOrdr323VerifiedSkillLookup`가 필요. 실제 대상 조건·증폭 미확정인 경우 최종 처리 단계에서 재검사.
- `Assets/Tests/EditMode/Ordr323MapDamageMathTests.cs`: 상수·공식·타입 차이 및 난수 범위의 NUnit 사례 추가. **테스트 실행은 하지 않음**.

### 왜 아직 전체 전투를 켜지 않나?

현재 `CombatEnemy`는 `long` 체력이고 워크래프트3 `UnitDamageTarget`은 실수량 피해를 받는다. 원본과 같은 반올림/절사 적용 시점을 아직 확인하지 못했다. 또한 같은 '마법 데미지' 도감 스킬이라도 JASS 실제 `attackType/damageType`이 다르다. 잘못된 값으로 271종을 움직이게 하는 대신, 미확인 입력은 명확히 `NotSupportedException`으로 차단한다.

**실제 미등록 정책은 예외로 보류**: `IOrdr323VerifiedHitSource`, `IOrdr323VerifiedModifierRules`, `IOrdr323VerifiedDamageQuantization`가 원본 근거와 함께 구현되어야 캐릭터 실피해가 나온다.

이 단계는 **맵 자체에서 확인된 계산식의 공통 구현**이지 271종 전투 완성이나 게임 실행 확인이 아니다.
