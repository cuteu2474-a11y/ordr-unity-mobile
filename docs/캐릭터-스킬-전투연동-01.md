# 캐릭터 스킬 데이터 → 전투 런타임 1차 연결

> **기록 해석 기준:** 이 문서는 단계별 조사·구현 기록입니다. 본문의 미완료·미실행·다음 작업과 정책은 해당 작성 시점 기준이며, 현재 운영·전체 현황은 [최신 인수인계](새채팅-인수인계.md)의 ‘현재 작업 기준’을 우선합니다. 특히 과거 테스트 보류, 사거리 유지, 프로젝트/원본 수치 미확보 설명을 현재 상태로 적용하지 않습니다. 원본 규칙의 근거와 미검증 한계는 계속 구분합니다.

기준: ORDR S2 2.323[C] / 악몽 이세계모드 / 2026-10-21

## 구현 목적

도감 JSON에 등록된 전체 271종 캐릭터와 200종 상세 스킬(554개 스킬 항목)을 코드에서 읽고, 실제 게임 세션과 연결한다.

**전제:** 현재 모든 유닛의 원본 Warcraft III rawcode와 평타 공격력·공격 주기·사거리는 데이터에서 `null`이다. 도감 등록 숫자만으로 실제 공격을 자동 활성화하는 것은 원작 오동작을 일으키므로 하지 않는다.

## 호출 순서

1. Unity 프로젝트 루트에 `data/units.json`과 `data/character-skill-profiles.json` 파일을 유지한다. 메뉴 `ORDR > 캐릭터 데이터 271종 · 스킬 200종 동기화`로 `Assets/Resources/OrdrData`에 복사한다.
2. 씬 GameObject에 `OrdrCharacterCombatController`를 추가한다. `Awake`에서 두 파일을 적재한다.
3. **검증된 원작 기본 공격 피해 계산기(`IOriginalDamageResolver`)와 스킬 피해 계산기(`IVerifiedCharacterSkillDamageResolver`) 및 난수 생성기(`ICombatProcRandom`)를 구현·주입**해야 실제 전투 런타임을 시작할 수 있다. 아직 프로젝트에는 해당 원본 공식 구현체가 없다.
4. `ConfigureRuntime(basic, skill, random)` → `BeginSession()` → `Combat.BeginWave(1)`.
5. `Combat.SpawnCharacter("TR-16", x, y)`는 이름·등급과 스킬 데이터를 가진 인스턴스를 만들지만, 평타 수치가 없는 현재 데이터 상태에서는 **아직 공격하지 않는다**.
6. 실제 유닛 rawcode와 스탯이 확인되면 `Combat.BindVerifiedBasicAttack(id, new BasicAttackSpec(...), firstAttackDelay)`를 호출하여 자동 공격을 연결한다.
7. `Combat.SpawnEnemy(enemyId, health, kind, x, y, progress)`로 적을 생성한다.
8. Unity `Update`에서 `Combat.Step(deltaSeconds)`를 호출한다. 공격하면 타깃 선정 → 외부 원작 피해 계산 → 평타 적용 → 해당 스킬 확률 판정 → 효과 대상 판정 → 원작 피해·상태 적용 → 처치 기록 순으로 진행한다.
9. 유닛 위치는 `MoveCharacter`, 적 이동은 `TryMoveEnemy`(스턴 상태 이동 차단), 넉백·강제 이동은 `ForceMoveEnemy`를 사용한다. 모든 실행 결과는 `OnCombatEvent`로 HUD에 연결할 수 있다.

### 원작 피해 공식 미구현 상태에서 월드 구성

`OrdrCharacterCombatController.ConfigureCatalogOnlyWorld(seed)`로 **피해 계산을 무조건 보류하는 명시적 정책**을 연결하면, 평타 수치가 없는 캐릭터들도 소환·선택·배치·웨이브 월드 상태를 만들 수 있다. 이 모드의 `SeededNonOriginalProcRandom`은 원본 난수가 아니다. **전투 밸런스를 검증하는 플레이 모드는 아니며**, 피해 공식이 없는 유닛 공격은 `EffectDeferred`로 한 번 기록 후 해당 공격자를 보류한다. 원작 계산기를 주입한 뒤 `ResumeAfterVerifiedFormulaUpdate`로 다시 활성화할 수 있다.

향후 JSON에 `basicAttackVerificationStatus: "original-confirmed"`를 기록하고 평타 공격력·주기·사거리·계열을 채우면, `TryBindCatalogVerifiedAttack(instanceId, firstDelay)`를 통해 **검증된 캐릭터에 한해서만** 자동 공격 스펙을 등록할 수 있다. 플래그가 없거나 값이 `null`이면 공격은 비활성 상태를 유지한다.

## 확인된 연결 동작의 **코드 구현 범위**

- JSON 문자열 두 파일 로딩, 버전 검사, 중복 ID 검사, 등급·스킬 원문 보존
- 실제 게임 `UnitRoster` 선택·유닛 배치와 기본 전투 공격자 등록
- 현재 범위 내 가장 가까운 살아 있는 적 자동 선택(원본 우선순위는 미검증)
- 기본 타격 쿨타임과 유닛별 OnAttack / OnHit 스킬 확률 판정
- `chancePercent` 등 핵심 값이 불명확하거나 별도 조건이 있는 스킬은 **자동 발동 제외**, `DeferredReasons`에서 확인
- 확인된 대상 중심/시전자 중심 원형과 단일 대상의 유효 적 탐색
- 물리·마법·고정·폭발 타입별 원본 피해 공식 요청 후 실제 적 체력 차감 및 정확한 처치 카운터 갱신
- 스턴, 지속형 방깎·이감·마방깎·마법·폭발 증폭의 **개별 상태 데이터** 보관
- 아머브레이크 누적 수량 보관(전투 방어계산에는 원본 수식 주입 필요)
- 지원되지 않은 효과/도감에 없는 지속시간/다중 틱 피해를 **임의 계산하지 않고 EffectDeferred 이벤트로 기록**
- 스턴 상태 적의 일반 이동 차단(넉백은 별도)

## 2차: 사용형 스킬·유닛 스탯 출처 연결

- `CharacterActiveAbilities`는 확인된 `activeMana` / `activeHealth` / `manual` 스킬의 체력·마나 차감 및 개별 쿨타임을 관리한다. 초기 체력과 마나는 **검증 후 직접 주입**하며, 기본값·자연재생을 임의로 정하지 않는다.
- `Combat.ConfigureCharacterResources(id, new CharacterResources(maxHealth, health, maxMana, mana))`로 자원 상태를 바인딩한다.
- `Combat.TryCastActiveSkill(id, skillId, enemyId)`를 통해 UI에서 스킬을 요청하면, 자원·쿨타임·별도 선행 조건·지원 효과 유형 확인 후 `CharacterSkillEffectExecutor`에 전달한다. 미지원 조건과 지속 피해·소환수 등은 **자원 소비 없이 거부**하도록 설계했다. 다만 피해 공식 자체가 실행 시점에 `NotSupportedException`을 반환하는 경우에는 자원 소모 후 효과가 보류될 수 있으므로, 실제 플레이 활성화 전에 원본 공식 적용 여부를 확인해야 한다.
- 현재 액티브 사용은 `TryCastActiveSkill`을 호출하는 API만 추가됐고, **화면 스킬 버튼/자동 마나 사용 AI는 아직 연결되지 않았다.**
- `data/original-stat-evidence.json`에 패치노트로 확인된 공격 수치 일부를 **증거 데이터로만** 등록했다. 모리아(전설) 공격력 56,000(2.310 변경), 공격쿨타임 1.25초(2.300 변경), 사거리 850(2.322 변경), 베포/이나즈마(안흔함) 사거리 500(2.320 변경)을 담았다. 최종 원본 오브젝트 데이터와 피해 계열이 확인되지 않았으므로 해당 수치만으로 공격을 켜지는 않는다.
- `OriginalUnitStatEvidenceCatalog`는 이 출처 파일을 불러온다. Unity `ORDR/캐릭터 데이터 271종 · 스킬 200종 동기화` 메뉴가 세 번째 JSON 파일도 선택적으로 복사하고 `OrdrCharacterCombatController.StatEvidence`에서 읽는다.
- 출처: [2.320 패치](https://ordr.kr/patch-notes/2-320), [2.322 패치](https://ordr.kr/patch-notes/2-322), [2.323 패치](https://ordr.kr/patch-notes/2-323), [모리아 상세](https://ordr.kr/character/L12).
- **원본 출처 충돌:** 2.322 패치에는 신규 신비 유닛 유지로가 기록되지만 현재 도감의 신비함 13종 이름 목록에는 보이지 않는다. 따라서 데이터 등록률 **200/200은 ORDR 웹 도감의 상세 설명 기준**이며, 원본 2.323[C] 맵 전체 캐릭터·스킬의 완전성 검증은 아니다. 맵에서 확인할 때까지 별도 불일치로 관리한다.

### 추가 개발: 적 방어 프로필과 버전 충돌 방지

- `EnemyDefenseProfile`에 원작 적 분류(라인/보스/광폭화/스토리), 원시 방어력·마법저항·워크래프트 방어타입·근거를 보관한다. 방어력/저항의 미확인 값을 **0으로 취급하지 않는다**.
- `CombatEnemy.Defenses`와 `CombatEnemy.Status`를 외부 피해 계산기에 노출하고, 실제 스턴·방깎·이감이 붙은 적의 상태를 동일 객체에서 읽도록 통합했다. `Combat.SpawnEnemyWithDefenses(..., verifiedDefenses)` 호출로 소환 시 원작 스탯을 주입한다.
- `Combat.ProfileOf(instanceId)` / `Combat.EnemyOf(enemyId)`는 향후 모바일 HUD용 조회 API이다. 유닛 공격 활성화와는 무관하다.
- `original-stat-evidence.json`에는 패치 기록에서 모리아·베포·이나즈마·모건·초월 루치 **5종, 공격 수치 7개**를 근거와 함께 등록했다. 실제 공격은 아직 비활성.
- **2.323 도감과 2.320 패치 내용 불일치**: 고죠 사토루의 무량공처(범위/피해), 술식 반전 혁(확률), 술식 순전 창(틱 주기·이감) 3개 스킬은 웹 툴팁과 원작 패치 기재가 다르다. `data/character-skill-profiles.json`의 해당 스킬에 `requiresOriginalVerification:true`를 추가하고 발동 어댑터 및 사용형 시전에서 **원본 W3X 확인 전 차단**한다.
- 2.310 패치의 신규 특수 유닛 `가이몬`과 2.322 패치의 신비 신규 `유지로`가 웹 도감 271종 목록에서 보이지 않는다. 원작 W3X 기준 확인이 필요하다.
- `RejectUnverifiedDamageFormula`를 사용한 데이터 전용 월드에서는 피해 스킬의 액티브 시전 전에 원작 공식 미구현을 감지하여 체력·마나의 **헛소모를 차단**한다.
- 출처: [2.310 패치](https://ordr.kr/patch-notes/2-310), [2.320 패치](https://ordr.kr/patch-notes/2-320), [2.322 패치](https://ordr.kr/patch-notes/2-322), [사토루 도감](https://ordr.kr/character/MY1).

## 계속 미구현

- **원작 기본 공격력·공속·사거리·rawcode 전체 수집 및 실제 피해 계산기**
- 스킬 자동 발동 제외 유형: 마나·체력 소모/수동 스킬의 **자동 발동 AI 및 UI**, 주기 스킬, 변신/추가 조건형, 분신·소환수, 스택, 도트·다중 타격
- 상태효과가 적 방어력·실제 이동속도에 작용하는 원본 계산식, 중첩·저항, 보스/스토리 예외
- 오라 범위 전파, 아군 가속/버프 적용, 스킬 후속 연계
- 웨이브 적 생성 자동화, 승패, 도박·항법·스토리·조합/경제, 캐릭터 특성강화 연결
- 정식 Unity 프로젝트 설정/씬/적·유닛 그래픽·HUD 연동
- 실제 컴파일, NUnit 실행, 기기 테스트, APK는 **사용자 요청에 따라 아직 진행하지 않음**

## 결론

`200종 스킬 데이터 조회 → 유닛 소환 → 검증 스탯 바인딩 → 자동 타격·기초 확률형 스킬 → 피해 계산기 주입 및 상태효과` 연결 코드를 작성했다. **원작 공식이 없는 현 상태에서 모든 200종이 실제 전투를 수행한다거나 구현이 완성됐다고 표현하지 않는다.**
