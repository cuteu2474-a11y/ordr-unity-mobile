# 캐릭터 스킬 데이터 → 전투 런타임 1차 연결

기준: ORDR S2 2.323[C] / 악몽 이세계모드 / 2026-10-21

## 구현 목적
도감 JSON에 등록된 전체 271종 캐릭터와 200종 상세 스킬(554개 스킬 항목)을 코드에서 읽고, 실제 게임 세션과 연결한다.

**전제:** 현재 모든 유닛의 원본 Warcraft III rawcode와 평타 공격력·공격 주기·사거리는 데이터에서 `null`이다. 도감 등록 숫자만으로 실제 공격을 자동 활성화하는 것은 원작 오동작을 일으키므로 하지 않는다.

## 호출 순서

1. Unity 프로젝트 루트에 `data/units.json`과 `data/character-skill-profiles.json` 파일을 유지한다. 메뉴 `ORDR > 캐릭터 데이터 271종 · 스킬 200종 동기화`로 `Assets/Resources/OrdrData`에 복사한다.
2. 씬 GameObject에 `OrdrCharacterCombatController`를 추가한다. `Awake`에서 두 파일을 적재한다.
3. **검증된 원작 기본 공격 피해 계산기(`IOriginalDamageResolver`)와 스킬 피해 계산기(`IVerifiedCharacterSkillDamageResolver`) 및 난수 생성기(`ICombatProcRandom`)를 구현·주입**해야 실제 전투 런타임을 시작할 수 있다. 아직 프로젝트에는 해당 원본 공식 구현체가 없다.
4. `ConfigureRuntime(basic, skill, random)` → `BeginSession()` → `Combat.BeginWave(1)`.
5. `Combat.SpawnCharacter("TR-16", x, y)`는 이름·등급과 스킬 데이터를 가진 인스턴스를 만들지만, 평타 수치가 없는 현재 데이터 상태에서는 **아직 공격하지 않는다**.
6. 실제 유닛 rawcode와 스탯이 확인되면 `Combat.BindVerifiedBasicAttack(id, new BasicAttackSpec(...), firstAttackDelay)`를 호출하여 자동 공격을 연결한다.
7. `Combat.SpawnEnemy(enemyId, health, kind, x, y, progress)`로 적을 생성한다.
8. Unity `Update`에서 `Combat.Step(deltaSeconds)`를 호출한다. 공격하면 타깃 선정 → 외부 원작 피해 계산 → 평타 적용 → 해당 스킬 확률 판정 → 효과 대상 판정 → 원작 피해·상태 적용 → 처치 기록 순으로 진행한다.
9. 유닛 위치는 `MoveCharacter`, 적 이동은 `TryMoveEnemy`(스턴 상태 이동 차단), 넉백·강제 이동은 `ForceMoveEnemy`를 사용한다. 모든 실행 결과는 `OnCombatEvent`로 HUD에 연결할 수 있다.

### 원작 피해 공식 미구현 상태에서 월드 구성

`OrdrCharacterCombatController.ConfigureCatalogOnlyWorld(seed)`로 **피해 계산을 무조건 보류하는 명시적 정책**을 연결하면, 평타 수치가 없는 캐릭터들도 소환·선택·배치·웨이브 월드 상태를 만들 수 있다. 이 모드의 `SeededNonOriginalProcRandom`은 원본 난수가 아니다. **전투 밸런스를 검증하는 플레이 모드는 아니며**, 피해 공식이 없는 유닛 공격은 `EffectDeferred`로 한 번 기록 후 해당 공격자를 보류한다. 원작 계산기를 주입한 뒤 `ResumeAfterVerifiedFormulaUpdate`로 다시 활성화할 수 있다.

향후 JSON에 `basicAttackVerificationStatus: "original-confirmed"`를 기록하고 평타 공격력·주기·사거리·계열을 채우면, `TryBindCatalogVerifiedAttack(instanceId, firstDelay)`를 통해 **검증된 캐릭터에 한해서만** 자동 공격 스펙을 등록할 수 있다. 플래그가 없거나 값이 `null`이면 공격은 비활성 상태를 유지한다.

## 확인된 연결 동작의 **코드 구현 범위**

- JSON 문자열 두 파일 로딩, 버전 검사, 중복 ID 검사, 등급·스킬 원문 보존
- 실제 게임 `UnitRoster` 선택·유닛 배치와 기본 전투 공격자 등록
- 현재 범위 내 가장 가까운 살아 있는 적 자동 선택(원본 우선순위는 미검증)
- 기본 타격 쿨타임과 유닛별 OnAttack / OnHit 스킬 확률 판정
- `chancePercent` 등 핵심 값이 불명확하거나 별도 조건이 있는 스킬은 **자동 발동 제외**, `DeferredReasons`에서 확인
- 확인된 대상 중심/시전자 중심 원형과 단일 대상의 유효 적 탐색
- 물리·마법·고정·폭발 타입별 원본 피해 공식 요청 후 실제 적 체력 차감 및 정확한 처치 카운터 갱신
- 스턴, 지속형 방깎·이감·마방깎·마법·폭발 증폭의 **개별 상태 데이터** 보관
- 아머브레이크 누적 수량 보관(전투 방어계산에는 원본 수식 주입 필요)
- 지원되지 않은 효과/도감에 없는 지속시간/다중 틱 피해를 **임의 계산하지 않고 EffectDeferred 이벤트로 기록**
- 스턴 상태 적의 일반 이동 차단(넉백은 별도)

## 계속 미구현

- **원작 기본 공격력·공속·사거리·rawcode 전체 수집 및 실제 피해 계산기**
- 스킬 자동 발동 제외 유형: 마나·체력 소모, 수동 Q/W/R 스킬, 주기 스킬, 변신/추가 조건형, 분신·소환수, 스택, 도트·다중 타격
- 상태효과가 적 방어력·실제 이동속도에 작용하는 원본 계산식, 중첩·저항, 보스/스토리 예외
- 오라 범위 전파, 아군 가속/버프 적용, 스킬 후속 연계
- 웨이브 적 생성 자동화, 승패, 도박·항법·스토리·조합/경제, 캐릭터 특성강화 연결
- 정식 Unity 프로젝트 설정/씬/적·유닛 그래픽·HUD 연동
- 실제 컴파일, NUnit 실행, 기기 테스트, APK는 **사용자 요청에 따라 아직 진행하지 않음**

## 결론

`200종 스킬 데이터 조회 → 유닛 소환 → 검증 스탯 바인딩 → 자동 타격·기초 확률형 스킬 → 피해 계산기 주입 및 상태효과` 연결 코드를 작성했다. **원작 공식이 없는 현 상태에서 모든 200종이 실제 전투를 수행한다거나 구현이 완성됐다고 표현하지 않는다.**
