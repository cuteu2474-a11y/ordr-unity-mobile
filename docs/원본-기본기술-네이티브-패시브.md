# 원본 기본 기술·네이티브 패시브 조사

> ORDR S2 2.323[C] 원본 능력 증거를 **세 조사 범위(툴팁 누락 71종·순수 패시브 26개·안흔함 14종)**로 나눠 찾아볼 수 있게 통합했습니다. 원본 확인, 코드 연결, 최신 APK 실행, 워크래프트 실제 전투 동일성은 서로 다른 단계입니다.

| 찾아볼 내용 | 이 문서의 위치 | 해석 시 주의 |
|---|---|---|
| 도감 기술 설명 없는 71종의 능력 rawcode | 1절 | 181개 고유 rawcode는 기술 181개 완료를 뜻하지 않음 |
| 순수 기절 17개·크리티컬 9개의 수치·적용 기준 | 2절 | 네이티브 대상·면역·평타 승인 필요 |
| 안흔함 14종의 고유 기술과 실전 연결 경계 | 3절 | 람각·로빈 다중공격·Bash 등 판정 경로가 서로 다름 |

**현재 상태는** [게임 현재 상태](START_HERE.md), 남은 구현은 [작업 목록](PLAYABLE_ROADMAP.md), 캐릭터별 연결과 실제 보류 조건은 [스킬 누락·중복 검토표](스킬-누락-검토표.md)을 확인하세요. 원본 20명·별도 10명의 JASS/보조 주문 근거는 [캐릭터 기술 추출표](원본-캐릭터-기술-추출표.md)에 있습니다.

## 1. 툴팁 누락 71종의 원본 능력 ID

> 이 수량은 과거 도감·객체 대응 조사에서 집계된 **프로필 누락의 범위**이며, 현재 스킬 구현 미완료 건수로 사용하지 않습니다.

기존 도감 캐릭터 271종 중 스킬 설명 프로필이 있는 캐릭터는 200종, 없는 캐릭터는 71종이다. 이 71종에 대해 `data/original-2323C-map-base-stats.json`의 **원본 유닛 객체에 기록된 능력 rawcode와 순서**를 캐릭터 ID별로 연결했다.

| 등급 | 툴팁 상세 프로필 없는 수 | 원본 맵 유닛 및 능력 목록 연결 |
|---|---:|---:|
| 희귀함 | 24 | 24 |
| 특별함 | 25 | 25 |
| 안흔함 | 13 | 13 |
| 흔함 | 9 | 9 |
| 합계 | **71** | **71** |

해당 71종이 참조하는 능력 rawcode는 중복을 제외하면 **181종**이다. 예시:

| 캐릭터 | 원본 유닛 rawcode | 맵 객체에 저장된 능력 코드(순서대로) |
|---|---|---|
| 희귀 도플라밍고 (`R-04`) | `h01L` | `A0K2, A057, A07Y, A058, A0B9, A009, Avul` |
| 흔함 루피 (`C-01`) | `h003` | `A0JE, A09G, A00D, A012, Avul` |

위 코드가 실제로 **공격 발동 스킬인지, 패시브인지, 강화나 시스템 공통 능력인지** 아직 판정되지 않았다. 예컨대 여러 유닛에서 같은 rawcode가 보인다는 통계는 조사 우선순위의 힌트일 뿐, 그 기능을 입증하지 않는다.

원본 객체의 기본 능력치가 이미 연결된 `OriginalMapBaseStatCatalog`에 `OriginalAbilityRawcodes` 읽기 전용 접근자를 추가해 Unity 런타임에서도 원본 순서를 확인할 수 있다. **원본 능력 코드의 존재만 확인했으며 효과·최종 피해가 증명된 것은 아닙니다.**

### 데이터 파일·추출·검사 경로

- `data/original-2323C-missing-skill-profile-evidence.json`: 누락 71종, 원본 객체 이름·rawcode·원본 능력 코드 목록·공유 빈도·출처·미검증 상태.
- `tools/build_missing_character_skill_evidence.py`: 세 개의 원천 데이터에서 동일 결과 재생성.
- `tests/test_missing_character_skill_evidence.py`: 전체 71종, 버전·이름 일치, 순서 유지, 잘못된 출처 차단, 효과 미확정 검증.
- `Assets/Scripts/Data/OriginalMapBaseStatCatalog.cs`: 능력 코드 목록을 원본 순서로 노출하되, 길이 불일치/중복 코드 거부.

재추출 일치 검사 명령은 `python3 tools/build_missing_character_skill_evidence.py --verify`입니다. 본 문서 통합 작업에서 명령을 실행하거나 최신 통과 여부를 확인하지 않았습니다.

### 실행 방식

- 원본 소유 유닛·능력·레벨·확률·배율·영웅/일반 기절 시간과 대상 마스크를 읽는다.
  원본 능력 하나의 전체 효과가 순수 기절 또는 순수 크리티컬인 경우만 실행한다.
- 승인된 기본 공격의 주사위가 나온 뒤 기존 `ICombatProcRandom`으로 발동을 직접 판정한다.
  발동 결과나 미래의 최종 피해를 공급하는 관측기는 요구하지 않는다.
- 크리티컬은 원시 공격 피해에 배율을 적용한 후 기존 방어·증폭·HP 변환을 통과한다.
  최종 HP에 배율을 다시 적용하거나 추가 피해 패킷을 만들지 않는다.
- 실제 기본 타격 커밋이 성공하면 같은 공격의 활성화 정보로 기절·스킬 이벤트를 처리한다.
  피해 공식 보류·다른 전장·사망한 대상에 기절을 적용하지 않는다.
- 기절 시간은 명시된 Warcraft 영웅 여부를 사용한다. 보스/스토리 분류로 추정하지 않는다.
  대상 분류·면역 상태가 타격 중 변경되면 준비된 기절 적용을 보류한다.
- 기존 안흔함 브룩 처리기나 육식 크리티컬 처리기가 연결되어 있으면 해당 능력의 소유권을
  기존 처리기에 남겨 확률 추첨·기절·배율을 두 번 적용하지 않는다.
- 상세 패널에 한국어 능력명과 실제 확률·배율/시간을 표시하며, 원본 코드명을 노출하지 않는다.
  같은 A07I에 연결된 육식 크리티컬과 별도 람각의 구현 상태도 구분한다.

### 대상 상태와 기본 공격 승인

`Original323NativePassiveTargetProfile`은 실제 몬스터의 원본 객체 ID,
Warcraft 영웅 여부, 각 능력의 **원본 대상 마스크와 면역 판정을 통과한 능력 목록**을 보존한다.
이 목록에 없는 능력은 발동 난수도 소비하지 않는다. 누락 상태를 일반 적·면역 없음으로 취급하지 않는다.
대상 상태 변경은 예상 리비전이 일치해야 하며, 다른 객체 ID로 바꾸거나 죽은 적을 갱신하지 않는다.

검증 웨이브에는 아래 `nativePassiveTarget` 필드를 선택적으로 전달할 수 있고,
`CombatWaveDirector`가 실제 적 생성 시 같은 상태를 연결한다.
이 필드가 없으면 기존 승인된 기본 공격은 유지하며 새 패시브는 비활성이다.
프로필 작성자는 영웅 분류·네이티브 면역·대상 마스크를 확인해야 한다.

```json
"nativePassiveTarget": {
  "warcraftHero": false,
  "eligibleAbilityRawcodes": ["확인한 4자리 능력 ID"],
  "evidence": "해당 몬스터의 실제 분류·대상 마스크·면역 검증 출처"
}
```

코드 연결점:
- `Original323NativePassiveCatalog.FromJson`: 원본 수치·소유 관계 로딩.
- `Ordr323DamageWorldBinding.Create(..., nativePassives, externallyHandledAbilities)`:
  원시 기본 공격 공급자와 직접 실행 엔진 연결.
- `CombatEnemy.TrySetNativePassiveTargetProfile(expectedRevision, profile)`:
  명시적으로 확인한 현재 대상 상태 설정/갱신.
- `ConnectedNativePassiveOf(instanceId)`: 실제 연결 능력 확인.

기본 Unity 컨트롤러에서는 **원본 주사위만 반환하는** `OriginalMapCommonNativeAttackBinding`에
이 실행기를 자동 연결한다. 이미 크리티컬을 적용했을 수 있는 임의의 외부 피해 공급자는
자동으로 다시 감싸지 않는다. 원본 공격 경로·적 방어·HP 정수화 승인 조건을 낮추지 않았다.

### 보류한 효과

추가 물리 피해, 크리티컬+추가 피해+기절 등 복합 능력,
여러 AHbh 능력을 동시에 가진 유닛의 중첩/처리 순서, 여러 능력 레벨의 현재 선택은 보류했다.
에이스·타시기·하찌의 추가 피해, 전설 조로의 복수 능력, 초월 로우/상디 및 영원 비비의
다중 레벨을 단순한 고정 레벨이나 부분 효과로 대체하지 않았다.
람각의 원본 더미 주문·충돌/비행은 기존 별도 실행 범위이며 이번 크리티컬 추가로 완료 표시하지 않는다.

2. `OrdrCharacterCombatController`가 카탈로그를 월드에 자동 연결하며 유닛 탭에서 고유 스킬 증거를 표시한다.

7. 테스트의 가상 원본 타격·가상 추가효과는 실기 검증이 아니다. 런타임의 실제 2.323[C] 피해량과 원본 스킬 재현 완료를 뜻하지 않는다.

### 블루노·후쿠로 A07I: 육식과 람각의 서로 다른 타격 파이프라인

- 원본 유닛 rawcode는 블루노 `h00M`, 후쿠로 `h00A`이며 모두 `A07I`를 보유한다. 기존 추출 자료에 기록된 육식 크리티컬은 확률 **15%**, 원시 평타 **1.5배**다. 람각은 독립 확률 **10%**, 직선 마법 원본 표시값 **150**이다.

- 크리티컬 대상/계산 순서를 입증하는 `IOriginal323UncommonCriticalPrehitRules` 없이는 크리티컬 난수를 소모하지 않는다. `OrdrCharacterCombatController.ConfigureVerifiedOriginalUncommonCritical(verifiedRules)`를 **원본 피해 런타임 생성 전** 연결해야 한다. 별도의 `A07I:rankyaku` 주사위를 크리티컬 주사위로 대체해서는 안 된다.

- 다중 대상에 대해서는 전투 엔진 `TryCommitOriginalUncommonLine`이 대상 중복, 다른 전장, 사망, 근거 누락을 **일괄 사전 검증**하고, 성공할 때만 각 대상의 HP 감소와 처치/기여 이벤트를 동일 `CombatResolution`에 기록한다. 대상 하나라도 미검증이면 전부 적용 보류한다.
- 독립적인 다른 안흔함 효과를 함께 쓰려면 `Original323UncommonEffectRouter`로 명시적으로 묶을 수 있다. 타시기·하찌·에이스와 람각을 동시에 연결하는 `ConfigureVerifiedOriginalUncommonEffectBundle`도 추가되었다. 이 설정은 육식 크리티컬을 자동 승인하지 않는다.
- Unit-test의 가상 영웅/갑옷/경로/최종 HP 계산기와 항상 0을 반환하는 난수는 **실게임의 근거가 아니다**. 실제 몬스터 원본 경로·마법 저항·명중/최종 HP 반올림의 전수 검증 없이는 스킬 완성 판정은 보류한다.


### 로빈 A07M — 원본 꽃꽃 열매 다중 대상 평타 연결

- 원본 W3X의 로빈 `h00O`은 `A07M` 능력을 보유한다. 능력 목록에 붙은 3명 동시 타격 근거를 `Original323UncommonAbilityCatalog`에서 `U-01 / A07M:multi3 / NativeTargetCount=3 / 100%`로 고정한다.
