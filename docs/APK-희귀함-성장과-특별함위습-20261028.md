# 희귀함 성장과 특별함 위습

기준은 `ad2720c`의 특별함 성장·플레이 메뉴이며, `3134dc4`의 공유 위습 난수 복구·소환 거래 보호 수정도 보존했다. 원본 맵을 읽어 희귀함 재료 조합과 특별함 보상 지급을 확장했다.

## 추가한 플레이 기능

- **희귀함 조합 41종**을 더해 실제 제작 가능한 조합이 안흔함 13 + 특별함 31 + 희귀함 41 = **85종**이 됐다. 조합 메뉴에서 이름·등급을 검색하거나 플레이 메뉴의 현재 제작 가능한 조합에서 선택한다.
- 원본에 등록된 실제 유닛 재료를 소비하고 결과를 원본 능력을 가진 시전자 좌표에 만든다. 추가 골드·목재를 임의로 요구하지 않는다. 예: `A00F`는 특별함 루피 기어세컨드·봉쿠레·에넬을 소비해 희귀함 루피 기어써드를 만든다.
- 희귀함도 같은 10라운드 개발용 연습의 기본 공격 파이프라인을 사용한다. 조합 직후 공격자가 재등록되고, 실제 처치 골드·기존 희귀함 판매(랜덤위습 2개와 목재 1개)는 같은 보유 목록·지갑을 사용한다.
- **특별함 위습**은 원본 `CSB/CSC`의 33종 중 하나로 자동 지급된다. 원본 풀의 모든 항목은 동일 가중치이며, 싱글플레이 0번 시작 위치 `(-3776,4480)`에 실제 전투 유닛을 생성한다. 자동 배치가 원본 보상 좌표를 덮어쓰지 않도록 했다.
- 특별함 스모커·스쿼드의 직접 조합은 계속 잠겨 있지만, 특별함 위습으로 해당 유닛이 뽑히는 원본 획득 경로는 사용할 수 있다. 따라서 이들이 필요한 희귀함 재료도 실제 보유했을 때만 충족된다.
- 위습 생성·차감·확정이 실패하면 현재 실행 중에는 **같은 추첨 결과를 유지**한다. 재시도로 새 결과를 뽑지 않고, 유닛과 위습 차감도 함께 롤백한다. 성공 확정한 다음 보상부터 새로 추첨한다.

## 원본 대조와 남은 범위

[감사 자료](../data/original-2323C-rare-growth.json)와 [감사 도구](../tools/audit_original_rare_growth.py)는 고정 SHA의 원본 JASS·객체 자료·AbilityData.slk를 대조한다. 41종의 재료/결과·시전자 능력·타깃 없는 시전과 타이밍을 검사하고, `CH8`의 추가 생성 처리 대상이 아닌지 확인한다. 특별함 풀 순서·가중치를 실제 `CSB`의 등록 호출과 비교하고 `CSC`와 플레이어 시작 좌표도 확인한다. 원본 맵은 수정하지 않았다.

- 희귀함 브룩 음악가 `A1A0`는 AOsf 계열 네이티브 시전 추가 대조 전까지 직접 제작을 열지 않는다. 기존 특별함 AOsf 조합 2종도 계속 보류다.
- **희귀함/전설 위습**은 보유 재화로 유지한다. 희귀함 위습의 원본 99%/1% 분기·A0YE와 상위 등급 생성 처리를 생략해 지급하지 않는다.
- 공격력 주사위·주기·첫 공격 지연은 객체 자료를 사용하지만, 연습 모델의 기술·오라·공격속도 연구·네이티브 광역 평타·최종 원작 피해 동등성은 미완성이다. 정식 검증 공급자나 승인 플래그를 만들지 않는다.
- 위습 추첨 결과는 현재 실행의 메모리에 유지된다. 전체 게임 저장/복원과 65라운드는 아직 지원하지 않는다.

## 검사

- 고정 원본 JASS/SLK 대조: 희귀함 41종·특별함 풀 33종 확인.
- 로컬 Python 회귀 **148건 통과**, `git diff --check` 통과.
- Unity EditMode에 희귀함 41종 재료 소비·결과 생성, 특별함 위습 33종 지급과 원본 좌표 우선, 희귀함 조합 시전자 좌표, 지급/확정 실패 후 동일 결과 재시도, 희귀함 전투 중 조합→기본 공격→판매 통합 사례를 추가했다.
- Unity 실행 환경이 없어 로컬 Unity 검사·새 APK 설치는 하지 않았다. 기존 GitHub Actions의 테스트 실행 시작까지만 확인하며 결과는 별도 요청 전 조회하지 않는다.
