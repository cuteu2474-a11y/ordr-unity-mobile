# 새 채팅 개발 인수인계

- 대상: `cuteu2474-a11y/ordr-unity-mobile`의 `main`. ORDR S2 2.323[C], 악몽·이세계, Unity 독립 모바일. 시작 전에 최신 HEAD 확인.
- 원작 수치·능력·모드 규칙은 임의로 변경하지 않습니다. 구현/원본 수치 근거/Unity 검사/기기 실기는 서로 다른 완료 기준입니다.
- 스토리 건물 수동 파견·복귀, 가능한 개체만 표시·동일 상태 묶음, 스토리 파견 중 복귀 없는 조합·판매·분해를 공통 원자 거래에 연결했습니다(실기 미검증).
- 크립 사냥 UI: 스토리 메뉴 내 단계·HP·현재 승인 개체 선택·한 기 파견/이동/복귀. `CharacterCombatRuntime.CreepDispatch`가 메인·스토리·공유 목표와 공격·오라를 격리하고, 다음 원본 크립 출현 시 자격이 맞는 개체만 자동 타깃 변경합니다(미검증).
- 크립 원본 사건: `Original323CreepSourceProgression`에 CTs/LB 최초 사건 주입, 원본 최종 스탯 공급, 실제 사망 후 CTp/CTq 다음 단계 생성 및 CTr 종료 연결. 원본 사건 증빙이 없는 기본 앱에는 크립을 새로 생성하지 않습니다.
- 크립 보상: `Original323CreepRewardWalletPort`가 CTp 골드 1,000+목재1, CTq 공유 BFi 1회 결과 잠금(실물 h060+목재2 또는 목재7), CTr 골드 5,000+목재1+Bhd 보통 발굴 스택1을 동일 지갑·원자 영수증으로 처리합니다.
- CTq 해적선 원본 생성 좌표가 미확정이면 선택한 난수 결과를 보류하고 재추첨·가짜 지갑 해적선 지급을 하지 않습니다. 단순 OBJECT BASE 연습 크립 사망은 실전 도박 충전에서 제외합니다.
- 원본 크립 출현/보상·출전 목적지·난수 상태는 저장 v1에 없어 캡처를 거부합니다. 저장·이어하기 UI는 계속 비활성입니다.
- `Original323CreepSourceProgressionTests`, `Original323CreepRewardWalletPortTests` 등 회귀 **소스만** 작성, Unity·NUnit·Android 실제 실행 미검증. 기존 요청형 1~4R 시뮬 결과도 사용자 요청 전 조회하지 않습니다.
- 실제 크립 플레이의 남은 필수 입력: 원본 CTs 최초 이벤트 시점, 악몽 최종 HP·방어·면역, 유닛/폼별 사냥 자격·착지·변신, CTq h060 실제 생성 좌표, 원본 전투 중 저장 복원 스키마.
- 현재 상태는 [START_HERE](START_HERE.md), 작업 순서는 [PLAYABLE_ROADMAP](PLAYABLE_ROADMAP.md), 호출 경로는 [CODE_MAP](CODE_MAP.md), 규칙은 [토벌·크립 파견](토벌-크립-파견-시스템.md)에서 확인합니다.
- APK/워크플로·테스트 실행은 별도 명시 요청 규칙을 유지합니다. `main`만 사용하고 관련 코드·문서는 같은 커밋으로 반영합니다.
