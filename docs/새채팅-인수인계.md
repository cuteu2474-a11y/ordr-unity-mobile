## 목표와 고정 요구
- 원랜디 ORDR S2 2.323[C] **악몽 난이도, 이세계모드**를 Unity로 독립 제작. 기존 OpenRealm iPad 포팅이나 GrandLineDefense와 별개.
- 원작 사거리, 공속, 스킬 쿨타임/피해 공식, 타깃, 비용, 조합, 상점/도박/위습, 스토리 규칙을 **임의로 바꾸지 않음**. 게임 기능과 규칙이 그래픽/이펙트보다 우선.
- 모바일 정책: 일반 공격 자동; 확률 발동 스킬 자동; 유닛 배치 자동; 보스 타깃 자동; 수동 Q/W/R 자동; 스토리 파견 수동; 재료 조합 조작 보조; 상점·도박·위습 수동. 모바일 편의성과 원본 규칙을 분리.
- **모든 기능을 구현한 뒤 테스트**: 신규 NUnit 테스트·Unity 컴파일·기기 테스트·APK 빌드 보류. 기존 파일 유지. 한국어 커밋/업데이트.

- `Assets/Scripts/Mobile/MobileInteractionPolicy.cs`, `MobileManualInteraction.cs`, `Assets/Scripts/Unity/OrdrMobileTouchPanel.cs`: 지정한 모바일 조작 정책과 큰 터치 UI. **실제 원본 자동배치/보스선택/QWR 및 상점·도박·위습·스토리 실행 서비스는 아직 미완료**.
- `data/verified-mobile-fusion-recipes.json`: 도감 기준 7개 조합식. `AssistedFusionService.cs`: 자동 재료 선택·부족량·조합 확정 UI. 실제 조합 재료 소비·유닛 생성 미구현.
- 원본 W3X `war3map.j`의 `CWR`에서 **조합 등록 266건(TEST 1건 포함)** 추출; `data/original-jass-fusion-ordered.xz.b64`는 BGI 원본 호출 순서 보존본, `tools/unpack_ordered_jass_fusions.py`로 `data/original-jass-fusion-registry.json` 복원 가능. `tools/extract_jass_fusions.py`는 war3map.j 직접 추출 도구.
- `data/original-unit-rawcode-label-links.json`: 원본 JASS `BjB/Bi8/Bi9`로 이름·조합 능력 근거가 확보된 **81종** 대응표(초월 30, 히든 22, 불멸 12, 영원 11, 왜곡 6). **객체 rawcode/스탯 최종 검증 아님**.
- `Assets/Scripts/Mobile/OriginalJassFusionCatalog.cs`, `OriginalJassFusionPlanner.cs`, `OriginalJassKnownConditions.cs`, `OriginalJassFusionPort.cs`: 원본 UNIT/GOLD/WOOD와 UBAN/KING/RMAX 등 조건별 차단, 최종 재검사, 원자적 제작 **인터페이스**. 실제 제작은 비활성.
- `data/original-stat-evidence.json`: 패치노트 기반 기초 공격 스탯 일부(5종·7개 근거).

## 2026-10-21 후속 구현 — CWR 순서형 거래·원본 객체 ID 검수 연결

- **main에 코드 반영**: `OriginalJassFusionPlanner.cs`가 CWR 원본 `UNIT` rawcode마다 정확히 어떤 소유 인스턴스가 재료인지 `JassFusionMaterialBinding`으로 보존. `OriginalJassFusionCommitOrder`에는 원본 BGI 조건 **순서**, BGH 결과와 재료 rawcode↔인스턴스 연결이 함께 전달됨.
- `OriginalJassFusionAtomicCoordinator.cs`: 잠금 상태에서 다시 만든 주문을 재검증·실행에 공유. 주문이 아닌 원본 능력 ID만 받아 검증하던 인터페이스를 주문 전체를 받도록 변경.
- **실제 거래 순서 제어 코드 추가**: `OriginalJassFusionOrderedWorldAdapter.cs`가 원자적 세션 안에서 BGI마다 조건 재검증 → UNIT별 지정 인스턴스 소비 → GOLD/WOOD 원본 금액 차감 → 그 외 특수조건 실행 → BGH 및 원본 CHu/CHx 후속효과 → Commit 순으로 진행. 어떤 단계든 실패 시 Commit하지 않고 세션 Dispose로 롤백. 단, 현재 `IOriginalJassFusionOrderedSessionFactory` / 실제 원본 월드·특수조건 구현체는 **없음**. 이 코드가 실제 게임 제작 완료를 뜻하지 않음.
- Unity `OrdrCharacterCombatController.ConfigureOriginalJassCraftingOrderedWorld` 연결 진입점 추가. 반드시 검증된 월드 세션과 JASS 추가 조건/시전대상/객체 매핑이 모두 필요.
- `tools/extract_w3u_fusion_unit_names.py`: 원본 W3X에서 별도로 추출한 `war3map.w3u` + 선택적 `war3map.wts`를 읽어 CWR 재료 rawcode의 **객체 이름 근거 및 동일 이름 후보**를 출력하는 도구. W3U 객체파일은 현재 저장소에 없으므로 이 작업에서는 실행되지 않았고 새로 확정된 원본 재료 rawcode는 **0종**임.
- `OriginalVerifiedUnitObjectMap.cs`: 원본 객체 원시 ID·객체 이름·출처 SHA-256·사람의 개별 승인 정보가 있는 별도 JSON만 `IVerifiedUnitRawcodeMap`으로 로딩하도록 작성. 추출된 후보 또는 81종 JASS 이름표를 자동으로 승격하지 않음. 승인된 객체 매핑 JSON 자체는 **아직 없음**.
- **테스트, Unity 컴파일, 기기 구동, APK 빌드, 새 브랜치, GitHub Actions 모두 수행하지 않음.** 모든 런타임 동작은 미검증.

## 2026-10-21 추가: 하위 등급 매핑·실제 객체 검증 강화

- `OriginalJassFusionPlanner.cs`: 이전 81종 JASS 이름 등록 외에도 `IVerifiedUnitRawcodeMap`이 **개별 승인한** 하위 등급 결과·재료 rawcode를 `CharacterUnitCatalog`에 연동할 수 있게 확장했다. Unity 컨트롤러가 카탈로그를 주입한다. 원본/카탈로그 불일치, 승인 누락, 유닛 인스턴스 중복 사용은 차단한다.
- `OriginalJassFusionOrderedWorldAdapter.cs`: 잠금된 소유 재료 각각의 **실제 원본 유닛 rawcode**를 확인하는 `TryReadOriginalUnitRawcode` 계약 추가, 검증 불가/불일치 시 **재료나 재화를 소비하기 전에** 거래 차단. 아직 실제 게임 월드 세션 구현체는 없다.
- `OriginalJassFusionCatalog.cs` 및 `OriginalUnitRawcodeLabelCatalog.cs`: **원본 W3X의 고정 SHA-256 지문**과 CWR BGI 조건 순서 원본 보존 여부를 확인. 다른 맵이나 순서가 깨진 추출 자료로 게임을 제작하지 못하게 한다.
- `OriginalJassFusionPort.cs`: 조합 확정 시 원본 데이터 읽기나 거래 호출에서 예외가 발생하면 모바일 UI에 실패 응답을 돌려주고 성공을 주장하지 않도록 변경.
- `tools/reconcile_mobile_fusion_jass_candidates.py` 및 `data/original-jass-web-recipe-candidate-groups.json`: 웹 도감 7개 레시피를 원본 CWR과 교차 확인해 **2개 조합의 순서 없는 재료 후보군(원본 rawcode 7종)**을 분리 기록. **rawcode↔캐릭터 ID를 개별 확정한 값은 0종**, 후보 자동 소비 불가. [상세](원본-재료-rawcode-대조-후보군.md).
- **원본 재료 ID 미확인 163종** 숫자는 그대로이고 81종 JASS 이름 연결도 유지. 새로 확정된 원본 객체 매핑이나 실제 제작 가능한 조합은 아직 없다.
- 이번 작업에서 테스트·게임 실행·Unity 컴파일·APK 빌드·새 브랜치·워크플로를 실행 또는 생성하지 않았다. 모든 새로운 코드의 실제 실행은 미검증이다.
