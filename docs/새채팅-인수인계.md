# 개발 인수인계

처음에는 [작업 규칙](../AGENTS.md)·[현재 상태](START_HERE.md)·[개발 작업](PLAYABLE_ROADMAP.md)을 읽고 [코드 구조](CODE_MAP.md)는 작업 영역만 확인합니다.

## 이어받을 다섯 가지

1. **기준:** main의 `2661368f`에서 돈 도박을 확장했습니다. 기존 스토리 공성 표시와 유닛 관리 버튼 정리를 보존합니다. 새 작업은 실제 최신 HEAD부터 확인합니다.
2. **이번 결과:** 일반/고급 돈 도박을 동일 지갑·난수·거래 서비스로 연결. 실제 아론 보스 격파로 고급 해금, 고급 누적 반환 35000으로 졸업·R01M·목재 구매 기회 5회 원자 정산. 도박소에 재고·최근 결과·누적 손익을 표시합니다.
3. **검사:** 보유 원본 W3X/JASS SHA 대조·돈 도박 규칙 재추출·정적 연결/공백 검토. NUnit/Python 회귀 코드 추가만 했으며 실행 검사·APK·Actions 조회는 하지 않았습니다.
4. **남은 제약:** 초기 재고/재충전·난수열은 개발 모델. 졸업 상점 특성/희귀 유닛 구매와 유닛 도박은 미연결. 전체 저장은 별도이며 기존 APK에는 이번 변경이 없습니다.
5. **다음 행동:** 검사 요청이면 돈 도박 해금·두 추첨 경계·부족/정지·졸업/목재 권리/복원 회귀를 먼저 실행합니다. 기능 작업은 개발 작업 문서의 졸업 상점 또는 유닛 도박의 원본 결제/정산을 이어갑니다.

## 작업할 때

같은 카탈로그 불일치를 다시 조사하지 않으려면 `python3 tools/build_character_runtime_coverage.py --verify`를 사용합니다. C# 지원이 바뀌었으면 실제 지원 내보내기와 실행 범위 JSON을 먼저 갱신해야 합니다.

사용자가 요청한 범위에서 진행하고 Python/Unity/APK 실제 실행과 Actions 조회는 명시적 요청이 있을 때만 합니다. 문서 수정만으로 APK를 재제작하지 않습니다. main 반영 뒤 결과를 기다리지 않고 변경과 미검증 범위를 보고합니다.

날짜별 작업 보고를 이 파일에 추가하지 않습니다. 변경 이력은 Git 커밋, 원본 근거는 `data/`, 현재 상태와 다음 작업은 위 문서에서 찾을 수 있습니다.
