## 이어받을 다섯 가지

1. **기준:** main `30cccf6`에서 실패한 Unity EditMode 13건(2207건 중)의 연결 문제를 점검해 일괄 보완했습니다. 실제 최신 HEAD를 먼저 확인합니다.
2. **이번 결과:** 도박소 졸업 h0AL 특성 15000골드/1점·H0B0 희귀 5000골드/1회(스토리 R01N) 연결, 희귀 CJE 43/7 원본 추첨·롤백, 개인 미션 Q015 최상위 조합 신호와 기존 시라호시 4포인트 소비를 공유 지갑에 통합했습니다. 위습·보상 RNG 사전 자격 확인 및 13건 실패 관련 구형 테스트 기대치·확장 카탈로그 픽스처도 교정했습니다.
3. **검사:** 11a9c17 자동 Actions #386의 Python 342건 중 1건은 `CanCommitChoice` 추출 뒤 기존 정적 검사 위치 가정이 남아 실패했습니다. 실행 코드를 되돌리지 않고 공통 자격 검사→RNG→실물 생성 순서를 점검하는 테스트로 수정했습니다. Unity 단계는 실행되지 않았으며 재실행 결과는 대기 중입니다.
4. **남은 제약:** 네이티브 재고 초기값·실제 RNG 순서와 A0YE 실전 효과는 미인증, 상점 재고/타이머까지 포함한 전체 저장·CJM 유닛 도박·시라호시 A0L1/A0KZ 실제 기술·다른 영웅 특성 소비는 미연결입니다. 기존 APK에 이번 변경은 아직 없습니다.
5. **다음 행동:** 새 Actions 결과 요청 시 13건 회귀와 희귀 풀 생성·특성 구매 원자 차감·스토리 R01N/개인 미션 Q015 신호를 먼저 점검합니다. 기능 작업은 시라호시 후속 스킬(C01), CJM 유닛 도박(M03/M04) 또는 전체 저장(S01)으로 이어갑니다.

## 작업할 때

같은 카탈로그 불일치를 다시 조사하지 않으려면 `python3 tools/build_character_runtime_coverage.py --verify`를 사용합니다. C# 지원이 바뀌었으면 실제 지원 내보내기와 실행 범위 JSON을 먼저 갱신해야 합니다.

사용자가 요청한 범위에서 진행하고 Python/Unity/APK 실제 실행과 Actions 조회는 명시적 요청이 있을 때만 합니다. 문서 수정만으로 APK를 재제작하지 않습니다. main 반영 뒤 결과를 기다리지 않고 변경과 미검증 범위를 보고합니다.

날짜별 작업 보고를 이 파일에 추가하지 않습니다. 변경 이력은 Git 커밋, 원본 근거는 `data/`, 현재 상태와 다음 작업은 위 문서에서 찾을 수 있습니다.
