## 이어받을 다섯 가지

1. **기준:** `cuteu2474-a11y/ordr-unity-mobile` main의 `df393274`에서 시작해 `3a46135e`의 유닛 UI 정리를 보존하며 스토리 전장 표시를 개편했습니다. 실제 최신 HEAD는 시작 때 확인합니다.
2. **이번 결과:** 유닛 관리의 위치/조합 바로가기 제거를 보존했습니다. `OrdrStoryBattlefieldView`가 오른쪽 건물과 왼쪽 일렬 파견 유닛을 표시합니다. 공격 동작/궤적은 실제 이벤트, 건물 피격은 실제 HP 피해에 연결합니다. 전투 좌표·피해·확률·파견/보상 규칙은 불변입니다.
3. **검사:** 코드/호출/이벤트 수명·문서 링크·공백 정적 검토만 수행. 이번 Python/NUnit/Unity/APK 실행 및 Actions 조회 없음. 이전 340건 검사 결과를 이번 변경의 통과로 사용하지 않습니다.
4. **남은 제약:** 스토리 표시의 Unity/기기 가독성·터치·대량 유닛 검증 전입니다. 기존 APK에는 이번 화면이 없습니다. 원작 동등성과 전체 C# 지원 재내보내기도 별도 과제입니다.
5. **다음 행동:** 검사 요청 시 작은 가로 화면에서 파견→공격→건물 격파/교체, 페이지/개별 선택, 복귀·판매·조합 후 제거와 정지/재개를 확인합니다. 기능 작업은 개발 작업 문서의 남은 XP/특성/연구 연결을 따릅니다.

## 작업할 때

같은 카탈로그 불일치를 다시 조사하지 않으려면 `python3 tools/build_character_runtime_coverage.py --verify`를 사용합니다. C# 지원이 바뀌었으면 실제 지원 내보내기와 실행 범위 JSON을 먼저 갱신해야 합니다.

사용자가 요청한 범위에서 진행하고 Python/Unity/APK 실제 실행과 Actions 조회는 명시적 요청이 있을 때만 합니다. 문서 수정만으로 APK를 재제작하지 않습니다. main 반영 뒤 결과를 기다리지 않고 변경과 미검증 범위를 보고합니다.

날짜별 작업 보고를 이 파일에 추가하지 않습니다. 변경 이력은 Git 커밋, 원본 근거는 `data/`, 현재 상태와 다음 작업은 위 문서에서 찾을 수 있습니다.
