# 개발 인수인계

처음에는 [작업 규칙](../AGENTS.md)·[현재 상태](START_HERE.md)·[개발 작업](PLAYABLE_ROADMAP.md)을 읽고 [코드 구조](CODE_MAP.md)는 작업 영역만 확인합니다.

## 이어받을 다섯 가지

1. **기준:** main `30cccf61`의 실제 연결 상태를 대조하여 개발 목록을 구체화했습니다. 기능 코드는 바꾸지 않았습니다. 새 작업은 최신 HEAD부터 확인합니다.
2. **이번 결과:** [개발 작업](PLAYABLE_ROADMAP.md)에 구현·원본 조사 22건, 실행 검증 5건을 작업 ID·시작 코드·선행 조건·완료 기준으로 정리했습니다. 일반/고급 돈 도박과 졸업 목재 구매, 영웅 성장/XP바, 시라호시 4포인트 구매, 스토리 공성 표시는 이미 연결된 기능입니다.
3. **검사:** 이번에는 문서 경로·작업 ID·원본/현재 상태와의 중복을 정적으로 검토했습니다. Python/NUnit/Unity/APK 실행과 Actions 조회는 하지 않았습니다. 앞선 기능의 실제 실행 검증도 아직 별도입니다.
4. **남은 제약:** 누락 유닛 기술 전체는 현재 C# 지원 재내보내기 전 확정 총계가 없습니다. C03에서 기술별 빠진 효과를 특정하며, 도감 수를 완료율로 쓰지 않습니다. 원본 근거 없는 대상은 해당 입력만 보류합니다.
5. **다음 행동:** 기본은 C01 시라호시 16/24레벨 실제 기술 → C02 그린블러드 → C03/C04 누락 고유기입니다. 돈 도박을 마무리하면 M01/M02, 유닛 도박은 M03/M04, 전체 저장은 S01~S03 순서입니다. 검사를 요청받으면 Q01부터 해당 변경 범위를 확인합니다.

## 작업할 때

같은 카탈로그 불일치를 다시 조사하지 않으려면 `python3 tools/build_character_runtime_coverage.py --verify`를 사용합니다. C# 지원이 바뀌었으면 실제 지원 내보내기와 실행 범위 JSON을 먼저 갱신해야 합니다.

사용자가 요청한 범위에서 진행하고 Python/Unity/APK 실제 실행과 Actions 조회는 명시적 요청이 있을 때만 합니다. 문서 수정만으로 APK를 재제작하지 않습니다. main 반영 뒤 결과를 기다리지 않고 변경과 미검증 범위를 보고합니다.

날짜별 작업 보고를 이 파일에 추가하지 않습니다. 변경 이력은 Git 커밋, 원본 근거는 `data/`, 현재 상태와 다음 작업은 위 문서에서 찾을 수 있습니다.
