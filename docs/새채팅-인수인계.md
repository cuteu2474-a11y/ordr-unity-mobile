# 개발 인수인계

처음에는 [작업 규칙](../AGENTS.md)·[현재 상태](START_HERE.md)·[개발 작업](PLAYABLE_ROADMAP.md)을 읽고 [코드 구조](CODE_MAP.md)는 작업 영역만 확인합니다.

## 이어받을 다섯 가지

1. **기준:** main의 `daea7740` 돈 도박 작업을 보존한 뒤 선택 유닛 영웅 성장 UI·시라호시 특성을 연결했습니다. 새 작업은 실제 최신 HEAD부터 확인합니다.
2. **이번 결과:** 기존 일반/고급 돈 도박·아론 처치 해금·졸업·목재 구매를 보존. 선택한 원본 영웅에 Lv/XP바/성장 스탯, 시라호시 H08U/H0C1에 Bz6 4포인트 수동 강화·중복방지 지갑 영수증을 추가했습니다.
3. **검사:** 기존 돈 도박 원본 대조와 이번 영웅 성장/지갑 정적 검토. NUnit 회귀 시나리오를 추가했지만 Python/NUnit/Unity/APK 실행 검사는 하지 않았습니다. main push 뒤 Actions 시작만 확인하고 결과는 조회하지 않습니다.
4. **남은 제약:** 초기 재고/재충전·난수열은 개발 모델. 졸업 상점 특성/희귀 유닛 구매·유닛 도박, 시라호시 A0L1/A0KZ 실전 기술, 다른 영웅 XP 사건과 전체 저장은 미연결. 기존 APK에 이번 변경 없음.
5. **다음 행동:** 검사 요청이면 돈 도박 경계·졸업·복원과 선택 영웅 XP바/4포인트 차감/중복 구매/레벨 성장까지 묶어서 확인합니다. 기능 작업은 졸업 상점 원본 결제 또는 시라호시 후속 기술·XP 사건 연결을 이어갑니다.

## 작업할 때

같은 카탈로그 불일치를 다시 조사하지 않으려면 `python3 tools/build_character_runtime_coverage.py --verify`를 사용합니다. C# 지원이 바뀌었으면 실제 지원 내보내기와 실행 범위 JSON을 먼저 갱신해야 합니다.

사용자가 요청한 범위에서 진행하고 Python/Unity/APK 실제 실행과 Actions 조회는 명시적 요청이 있을 때만 합니다. 문서 수정만으로 APK를 재제작하지 않습니다. main 반영 뒤 결과를 기다리지 않고 변경과 미검증 범위를 보고합니다.

날짜별 작업 보고를 이 파일에 추가하지 않습니다. 변경 이력은 Git 커밋, 원본 근거는 `data/`, 현재 상태와 다음 작업은 위 문서에서 찾을 수 있습니다.
