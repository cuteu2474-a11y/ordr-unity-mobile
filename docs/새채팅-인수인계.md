# 개발 인수인계

> **목적:** 새 AI가 오래된 구현 일지를 다시 읽지 않고 **현재 `main`을 확인해 바로 다음 작업을 시작**하도록 돕습니다. 과거 커밋·날짜별 진행 기록은 Git 이력에 보관합니다.

## 시작할 때 읽는 순서

1. [AGENTS.md](../AGENTS.md): 프로젝트 범위·원작 규칙·수동 조작·검사/푸시 제한.
2. [현재 상태](START_HERE.md): **다운로드 가능한 APK와 최신 코드의 차이**, 코드 연결·실행 검증·원작 동등성을 구분.
3. [개발 작업](PLAYABLE_ROADMAP.md): 고정 작업 ID, 남은 구현·완료 조건·검증 대기 목록.
4. [코드 구조](CODE_MAP.md): 고치려는 영역의 실제 파일·공통 엔진. 그다음 해당 시스템 문서만 읽습니다.
5. [문서 목차](README.md): [조합](조합-시스템.md)·[위습](위습-시스템.md)·[경제·도박](경제-도박-시스템.md)·[화면·조작](화면-조작-시스템.md)·[스토리](스토리-시스템.md)·[개인미션](개인미션-시스템.md)·[도움소](도움소-시스템.md)·[악몽·이세계·항법](악몽-이세계-항법-시스템.md)·[전투 공통 엔진](전투-공통엔진.md) 등의 최신 규칙.

**맨 먼저 `main`의 실제 최신 커밋과 변경 파일을 확인하세요.** 이 문서의 과거 SHA·검사 통과 건수·예상 차수는 작업 기준으로 사용하지 않습니다.

## 현재 특히 주의할 경계

- **전투:** JASS 콜백 5경로와 자동 13+26개 기술의 발동 경로를 유지합니다. SLK 자원 4종·MY-06 MP 회복/MP 비례 피해 모델·L-18 재생·L-12 장군좀비·MY-08 상자/가족사진(Q)/아군 재생·공속·MY-13 강탈/공속·I-08 타격 대상 방어 감소를 공통 경로로 추가했습니다. MY-06 MP 계산, I-08 방어 지속, MY-13 공속 상한 및 MY-08 동반자 공격은 **TOOLTIP_MODEL_ONLY 또는 보류**이며 원본 동등성을 뜻하지 않습니다. L-03 HP30/비용33, MY-07 뼈 추가 시전, MY-05 지속시간, L-22 피해 계열, E-02 rawcode, 나머지 JASS 콜백은 **미완성**이고 Unity·APK 실행은 **미검증**입니다. [C03/C04 감사 자료](../data/original-2323C-c03-callback-audit.json) · [C 작업](PLAYABLE_ROADMAP.md).
- **조합·위습:** 조합 결과 생성과 `A0YE` 실제 능력 발동은 다른 작업입니다. `A0YE`의 실전 효과는 아직 보류입니다. 원본 확률·재료·실물/영수증을 변경하지 마세요.
- **경제:** 돈 도박·졸업 후 일부 구매는 코드 연결됐으나 **`CJM` 유닛 도박, 네이티브 재고/RNG 동등성, 전체 저장**은 남아 있습니다. 별도 도박을 완성으로 표시하지 마세요.
- **게임 전체:** 65R 완주, 실제 Android 터치/성능, Unity 최신 통합 검사는 [Q 작업](PLAYABLE_ROADMAP.md)의 별도 검증 대상입니다. 코드 연결과 기존 APK 성공 기록을 혼동하지 마세요.
- **이미지:** 공개 코드와 개인용 초상화 자산을 구분합니다. [이미지 목록](../art/README.md)과 [개인용 이미지 안내](PRIVATE_PORTRAIT_BUILD.md)를 참조하세요.

## 다음 개발 작업을 시작하는 법

- 작업 목록에서 **실제로 남은 ID**를 선택한 뒤, 원본 `data/`·현 코드·실제 호출 경로·검사를 먼저 대조합니다. 관련 효과는 공통 엔진에서 묶어 구현합니다.
- 이미 구현된 재료 거래·위습·스토리·돈 도박과 겹치는 코드를 새로 만들지 않습니다.
- 수정한 기능의 **유일한 기준 문서**와 [현재 상태](START_HERE.md)·[개발 작업](PLAYABLE_ROADMAP.md)을 필요한 만큼 동기화합니다. `CODE_MAP`에는 코드 위치 변경만 기록합니다.
- Python/NUnit/Unity/APK 실 실행은 성현 님이 요청했을 때만 합니다. **검사 미실행·실패·성공·실기 미검증을 분리해서 보고**합니다.
- `main`에만 반영하고 새 브랜치·워크플로·불필요한 Actions 재실행을 하지 않습니다. 작업 후 결과를 기다리지 않습니다.

**새 채팅에서는 먼저 구현할 기능의 완료 기준을 정하고, 이미 검증된 공통 구조를 재사용해 충분한 분량을 구현하는 데 집중합니다.**
