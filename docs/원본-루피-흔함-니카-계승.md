> **두 범위를 구분해 읽는 문서입니다.** (1) 흔함 루피 `C-01 / h003`의 원본 기본 공격·판매·조합 기능, (2) 초월 루피 `TR-08`과 스네이크맨 `TR-14`을 통한 영원 니카 제작을 정리합니다. **흔함 루피에서 니카까지의 전체 성장/조합 경로를 검증했다는 뜻은 아닙니다.**

원본 수치·원본 CWR 추출과 *작성 당시 구현 설명*을 구분합니다. 실제 최신 코드·완료 기준은 [현재 상태](START_HERE.md), [개발 작업](PLAYABLE_ROADMAP.md), [조합 시스템](조합-시스템.md), [위습 시스템](위습-시스템.md)을 따릅니다.

수동 흔함 유닛 판매의 원본 보상표는 `Assets/Scripts/Core/OriginalCommonSaleRules.cs`에서 외부 거래가 완료된 뒤 사용하는 **순수 보상 계산기**로 구현했습니다. 1/2회 판매에서는 RNG 없이 누적, 3/6/9회에 위습 1개와 독립 35% 목재 판정을 반환합니다. 실제 공유 지갑·위습·유닛 제거·세이브의 최신 트랜잭션 연결 상태는 현재 코드를 확인해야 합니다.

### 모바일 판매의 당시 연결 경계

- `OriginalLuffyCommonSaleCoordinator`를 추가했습니다. 루피 `C-01/h003`의 원본 객체를 잠금 하에서 재검증하고, 판매 카운터 `LY`, 원본 위습 `e0IX`, 조건부 목재 지급을 단일 트랜잭션에서만 실행합니다.
- `OrdrMobileTouchPanel`에는 보유 루피의 **판매 선택 → 판매 확인** 두 단계가 있고 `A0JE`·`Avul`을 조작 버튼으로 만들지 않았습니다.
- **작성 당시 실제 게임의 소유권/유닛 제거/위습 생성/재화/난수·저장 구현체가 연결되지 않아 버튼이 비활성화 상태**입니다. 임시 위습 아이템을 만들거나 경제와 다른 가짜 지갑에 지급하지 않습니다.
- 6개 NUnit 회귀 검사에서 중복 판매, 파견 유닛 판매 거부, 3회 누적 보상, 35% 경계, 지급 도중 실패 시 전체 롤백, 잘못된 난수·출처 카운터 거부를 검사합니다. 가상 거래 월드는 `TEST_ONLY`이며 완료 판정 근거가 아닙니다.

### 확정 모바일 조작

- **`A0JE` 유닛 모으기와 `Avul` 무적 능력의 별도 터치/수동 버튼은 만들지 않습니다.** 유닛 배치는 기존 자동 배치 경로에 맡기며, 필요한 보호/무적 판정은 전투 규칙에서 유지해야 합니다. 소스 등록값은 삭제하지 않습니다.
- 보유 루피 도감 화면의 '상세 미수집' 표기를 원본 JASS 능력 확인 결과로 바꿔, 가상의 액티브 전투 스킬이 존재하는 것처럼 안내하지 않습니다.
- 수동 판매 버튼의 포트 미연결 차단과 명시적 탭 동작을 신규 Unity 회귀 검사로 확인합니다. 판매 자동 실행은 금지합니다.

### 원본 위습의 실제 생성 위치

사용자 제공 원본 `war3map.j` L318의 `YR=$65304958`은 `e0IX`(원본 오브젝트명 '랜덤위습')입니다. `CJ=Rect(-3584,-9824,-3328,-9568)`의 중심 `(-3456,-9696)`에서 `Bcz→Bcy→CreateUnit`로 소환합니다. 거래 인터페이스에도 **원본 물리 유닛 rawcode와 이 생성 좌표를 강제 전달**하여, 위습을 재화 1개로만 대체하거나 전장 안 임의 위치에 두는 구현을 막았습니다. 문서 작성 당시 실제 월드 스폰 서비스는 미연결 상태였으며, 현재 지급 여부는 코드·실행 결과를 따로 확인해야 합니다.

### 판매 난수는 전체 게임 상태를 공유

원본 `CRO`는 새로운 독립 35% RNG를 생성하지 않고 `BFi(1,100)`를 호출합니다. `BFi`는 전역 `BFh`를 통하고 `H6` 상태·`H7=69069`·`H8=1`·`H9=2147483647`를 사용합니다(원본 JASS L93~96, 3589~3599). **게임의 다른 원본 확률 판정과 PRNG 호출 순서가 공유**될 수 있으므로, 독립 판매 RNG는 원작과 일치하지 않습니다. 판매 원자 거래 인터페이스가 이제 `TryRollOriginalSharedBFiOneToHundred`를 요구합니다. Warcraft 클라이언트의 부호 있는 정수 오버플로/ModuloInteger 결과·실제 분포는 아직 측정되지 않아 `35%`는 JASS 표면의 1~100 임계값 35라는 의미로만 유지합니다. 불확정 난수는 실제 보상 거래를 허용하지 않습니다.

## 2. 초월 루피 두 경로와 영원 니카(E-01/E-02)

### 확인 결과

**초월 루피와 스네이크맨은 서로 다른 유닛이다. 영원의 니카(루피)·니카(스네이크)는 같은 니카로 가는 두 재료 경로를 구분한 도감 항목이다.** 동일한 레벨과 스탯을 계승한 상태라면 출신 경로만으로 별도 스킬 세트를 적용할 근거는 없다. 조합 직전 재료의 성장 상태가 다르면 계승 결과의 실제 스펙은 달라질 수 있다.

| 비교 | 루피 초월 경로 | 스네이크맨 초월 경로 |
| --- | --- | --- |
| 초월 카탈로그 ID / 원본 객체 | TR-08 / H099 | TR-14 / H0B2 |
| 초월 객체 기본 공격 범위값 | 30,001~30,003 | 30,001~30,003 |
| 초월 객체 기본 공격 주기 | 0.38초 | 0.48초 |
| 초월 최대 마나 | 160 | 85 |
| 니카 도감 항목 | E-01 / 니카(루피) | E-02 / 니카(스네이크) |
| 추가 재료 | 전설 로우·희귀 캡틴 키드·안흔함 에이스·태양신의 흔적·목재5 | 동일 |
| 영원 스킬·오라 설명 | 아래 공통 효과 | 같은 효과 |
| 원본 CWR의 니카 결과 | ET02 → H0BK(태양의 신) | 별도 결과 등록이 아닌 같은 니카 조합 |
| 완성 시 성장값 | 사용한 초월 재료의 레벨·스탯 계승 | 사용한 초월 재료의 레벨·스탯 계승 |

초월 표의 공격력·주기는 [원본 기본 능력치](../data/original-2323C-map-base-stats.json)의 객체 기본 필드다. 업그레이드·능력치·버프·변신·공격 지연·실제 피해가 반영된 최종 DPS가 아니다.

### 공통 영원 효과 대조

[E1](https://ordr.kr/character/E1)과 [E2](https://ordr.kr/character/E2)는 조합에 쓰는 초월 유닛만 다르고 다음 효과의 수치가 일치한다.

- 주변 방어 감소35, 공격속도 버프25%, 자기 공격력 증가25%, 평타 스플래시 반경350.
- 체력115를 쓰는 4.25초 거대화와 변신 중 공격 효과.
- 마나150을 쓰는 범위750 혼합 피해 및 2.5초 기절.
- 공격 확률10% 혼합 광역 타격, 확률20%의 5배 치명타·단일2초 기절.
- 확률15% 이동속도 연계 물리 타격과 거대화 전용 확률20% 광역 타격.

기존 E-01/E-02 JSON은 같은 설명을 서로 다른 필드명으로 입력한 부분이 있다. 예를 들어 attackSpeedBuff/allyAttackSpeedBuff, basicAttackPercent/plusBasicAttackDamagePercent, self/area 위치가 다르다. 이는 별도 원본 성능의 근거가 아니며 공통 사양으로 정합화할 데이터 작업이다. 이번 문서 검토에서는 프로필·카탈로그 ID·원본 매핑 JSON을 병합하거나 전투를 활성화하지 않았다.

### 계승과 조합 조건

- [2.314 패치](https://ordr.kr/patch-notes/2-314): 니카 제작 시 재료 초월의 레벨과 스탯을 가져오도록 수정했다.
- [2.320 패치](https://ordr.kr/patch-notes/2-320): 재료 초월이 특성강화 후 상태여야 제작 가능하다. 루피 경로에서 스네이크맨 부재 메시지가 나오던 오류도 수정됐다.
- [2.321 패치](https://ordr.kr/patch-notes/2-321): 블랙맘바 상태의 스네이크맨을 사용했을 때 경험치 계승이 누락되는 오류를 수정했다.

따라서 ‘같은 니카’라는 이유로 재료 성장값을 버리거나, 두 초월 재료를 동시에 요구해서는 안 된다. 계승할 스탯의 구체 필드·복사 순서·블랙맘바 임시 보정 제거 및 숨은 기능은 별도 원본 처리 확인이 필요하다. 패치 문구만으로 모든 일시 버프까지 복사한다고 단정하지 않는다.

### CWR 등록과 웹 도감의 객체 대응 한계

[원본 CWR 등록 자료](../data/original-jass-fusion-registry.json)에서 H0BK를 생성하는 등록은 ET02 한 건이다. UNIT 조건은 H08T·h03C·h02D·h00K, 아이템 AI01과 목재5다. H08T는 기존 [조합 객체 교차대조](조합-거래-기술근거.md)에 ‘해적왕이 될 사나이 / 다섯번째 황제’로 기록된 공통 조합 입력이며, 구체적인 특성강화·변신 객체 처리까지 검증됐다는 뜻은 아니다.
