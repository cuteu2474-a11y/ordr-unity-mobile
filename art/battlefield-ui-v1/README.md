# 전장 바닥·수량 버튼 v1

사용자 확정 방향은 **오른쪽 상세 메뉴의 큰 장식 테두리 제거**, **남은 수량의 작은 버튼 표현**, **메인·스토리 전장 그래픽 개선**입니다. 추가 이미지 2장과 기존 스토리 요새를 재사용합니다. **승인된 원본을 게임 리소스와 표시 코드에 연결했습니다. Unity/Android 실행 검증과 기존 배포 APK 반영은 아직 아닙니다.**

## 파일

| 파일 | 용도 | 재사용 |
|---|---|---|
| [quantity-button-v1.png](quantity-button-v1.png) | 남은 수량 버튼의 빈 바탕 | ‘남은 수량’과 5개/0개 등은 별도로 표시. 같은 PNG를 금색·회색으로 틴트해 상태 구분 |
| [battlefield-ground-v1.png](battlefield-ground-v1.png) | 메인·스토리 공통 석재 바닥 | 메인은 차가운 톤으로 전체 표시, 스토리는 가로로 잘라 약간 따뜻한 톤으로 표시 |

스토리 건물은 [기존 요새](../story-building-v1/README.md)를 재사용합니다. 가로 행동 버튼도 [기존 공통 버튼](../ui/button-v1/README.md)을 유지합니다. 이전 [팝업 패널 이미지](../ui/skin-v1/README.md)를 오른쪽 시설 메뉴 전체의 테두리로 사용하는 시안은 채택하지 않습니다. 다른 팝업에 쓸 수 있는 원본은 보존합니다.

## 적용 원칙

- 수량 버튼 원본에는 글자·숫자를 굽지 않습니다. PNG의 투명 안전 여백과 실제 버튼 모양을 구분하고, 보이는 모서리를 유지하도록 9분할/배치를 수동 조정합니다.
- 5개·0개는 사용 예일 뿐 고정 수량이 아닙니다. 실제 잔여 수량과 실행 가능 여부를 기존 서비스에서 읽습니다. 버튼 모양을 추가했다고 새로운 결제·소환 동작을 임의로 연결하지 않습니다.
- 오른쪽 상세 메뉴는 어두운 평면 배경으로 유지하고 큰 은색 외곽선·중첩 장식 프레임을 사용하지 않습니다. 기능별 행 버튼·닫기·수량 표시는 따로 유지합니다.
- 바닥은 낮은 대비로 유닛 초상화·적·HP바보다 뒤에 표시합니다. 메인과 스토리는 텍스처만 공유하고, 실제 전장 좌표·카메라·클리핑·대상/파견 판정은 분리합니다.
- 이 바닥 그림은 통행로·장애물·원본 맵·크립 접근 권한의 근거가 아닙니다. 실제 이동선은 기존 RouteCorners를 따르며 그림의 돌 이음새를 경로/충돌로 해석하지 않습니다.
- 원본 바닥은 무한 반복 타일이 아닙니다. Clamp를 사용하고 메인 sprite bounds를 기존 전장 사각형에 맞추며, 스토리는 가로로 잘라 따뜻한 톤으로 그립니다. 실제 RouteCorners는 별도 표시를 유지합니다.
- 스토리 건물·HP바·이름은 분리하고, 원본 실제 HP와 격파 상태를 표시합니다. 공격 이펙트는 실제 공격/피격 사건이 있을 때만 보여줍니다. 파견 0기 화면에 공격 유닛을 임의로 추가하지 않습니다.

## 실제 게임 연결

| 보관 원본 | 게임에서 읽는 리소스 | 연결 |
|---|---|---|
| 공통 바닥 | [BattlefieldGround.png](../../Assets/Resources/OrdrArt/BattlefieldGround.png) | OrdrBattlefieldArt의 단일 Texture2D를 메인 BoardSprite와 스토리 바닥이 공유 |
| 수량 버튼 | [QuantityButton.png](../../Assets/Resources/OrdrArt/QuantityButton.png) | OrdrMobileUiTheme의 GPU 9분할. 안전 여백을 UV로 제외하고 실제 잔액과 부모 행 활성 상태로 금색/회색 표시 |
| 기존 요새 | [StoryFortress.png](../../Assets/Resources/OrdrArt/StoryFortress.png) | OrdrStoryBattlefieldView의 비율 유지·하단 정렬, 실제 HP/피격·기존 파괴 잔해 표시 |

보관 PNG와 게임 리소스의 Git blob은 동일합니다. 원본 파일은 가공하지 않으며, 런타임에는 개인용 초상화나 휴대폰 합성 화면을 넣지 않습니다. 수량 버튼은 1254×1254 원본의 (145,373,964,504), 요새는 1402×1122 원본의 (26,116,1348,792) 영역을 **좌하단 원점의 정규화 UV**로 사용합니다. 다운스케일해도 여백 제거가 유지됩니다.

Assets/Resources/OrdrArt PNG/메타는 실제 게임 자산이므로 추적합니다. Resources/OrdrData JSON과 개인용 CharacterPortraits는 기존 자동 생성/비공개 경계를 유지합니다. 각 자산은 한 번 로드하고 캐시하며 실패하면 기존 생성 그림으로 대체합니다. 텍스처 CPU 읽기는 끄고, Mip Maps 없음·Bilinear·Clamp·색 공간/알파와 최대 크기(바닥 2048, 버튼/요새 1024)를 메타로 고정했습니다. 공통 바닥이 비정사각형이어도 기존 전장 bounds를 덮는 배율을 사용합니다.

오른쪽 메뉴/대기판은 큰 테두리 없는 배경이며 닫기는 기존 동작의 × 버튼으로 표시합니다. 수량 면은 별도 입력 컨트롤을 만들지 않고 부모 행의 접기/펼치기·재시도만 한 번 처리합니다. 0개·차단 상태도 숫자를 읽을 수 있습니다. 스토리 필드는 전체 필드 공간의 24%로 늘렸고, 건물·HP바·한 줄 파견/페이지를 분리합니다.

## 확인 범위

[전체 프롬프트](prompts.json) · [크기·알파·해시·연결 상태](image-metadata.json). 내장 이미지 생성 도구의 선택 원본과 리소스 Git blob 동일성, PNG/UV, 호출부·문서·임포트 경계를 읽기 대조했습니다. 자산 포함/공유·비정사각 bounds·요새 비율·가로 레이아웃 회귀 코드를 추가했지만 **Python·NUnit·Unity·APK 실행은 하지 않았습니다**. 실제 기기 압축/선명도·0개/차단 터치·작은 화면/카메라·HP 대비는 실행 확인 대상입니다.
