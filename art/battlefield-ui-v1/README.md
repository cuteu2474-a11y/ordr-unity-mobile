# 전장 바닥·수량 버튼 v1

사용자 확정 방향은 **오른쪽 상세 메뉴의 큰 장식 테두리 제거**, **남은 수량의 작은 버튼 표현**, **메인·스토리 전장 그래픽 개선**입니다. 추가 이미지 2장과 기존 스토리 요새를 재사용합니다. **생성 원본을 보관한 상태이며 실제 게임 코드·APK 적용 결과는 아닙니다.**

## 파일

| 파일 | 용도 | 재사용 |
|---|---|---|
| [quantity-button-v1.png](quantity-button-v1.png) | 남은 수량 버튼의 빈 바탕 | ‘남은 수량’과 5개/0개 등은 별도로 표시. 같은 PNG를 금색·회색으로 틴트해 상태 구분 |
| [battlefield-ground-v1.png](battlefield-ground-v1.png) | 메인·스토리 공통 석재 바닥 | 메인은 차가운 톤으로 전체 표시, 스토리는 가로로 잘라 약간 따뜻한 톤으로 표시 |

스토리 건물은 [기존 요새](../story-building-v1/README.md)를 재사용합니다. 가로 행동 버튼도 [기존 공통 버튼](../ui/button-v1/README.md)을 유지합니다. 이전 [팝업 패널 이미지](../ui/skin-v1/README.md)를 오른쪽 시설 메뉴 전체의 테두리로 사용하는 시안은 채택하지 않습니다. 다른 팝업에 쓸 수 있는 원본은 보존합니다.

## 적용 원칙

- 수량 버튼 원본에는 글자·숫자를 굽지 않습니다. PNG의 투명 안전 여백과 실제 버튼 모양을 구분하고, 보이는 모서리를 유지하도록 9분할/배치를 수동 조정합니다.
- 5개·0개는 사용 예일 뿐 고정 수량이 아닙니다. 실제 잔여 수량과 실행 가능 여부를 기존 서비스에서 읽습니다. 버튼 모양을 추가했다고 새로운 결제·소환 동작을 임의로 연결하지 않습니다.
- 오른쪽 상세 메뉴는 어두운 평면 배경으로 유지하고 큰 은색 외곽선·중첩 장식 프레임을 사용하지 않습니다. 기능별 행 버튼·닫기·수량 표시는 따로 유지합니다.
- 바닥은 낮은 대비로 유닛 초상화·적·HP바보다 뒤에 표시합니다. 메인과 스토리는 텍스처만 공유하고, 실제 전장 좌표·카메라·클리핑·대상/파견 판정은 분리합니다.
- 이 바닥 그림은 통행로·장애물·원본 맵·크립 접근 권한의 근거가 아닙니다. 실제 이동선은 기존 RouteCorners를 따르며 그림의 돌 이음새를 경로/충돌로 해석하지 않습니다.
- 원본 바닥은 무한 반복의 이음새를 보장한 타일이 아닙니다. 먼저 Clamp와 비율 유지·잘라 쓰기로 배치합니다. 필요할 때 전용 반복 텍스처를 별도로 만듭니다.
- 스토리 건물·HP바·이름은 분리하고, 원본 실제 HP와 격파 상태를 표시합니다. 공격 이펙트는 실제 공격/피격 사건이 있을 때만 보여줍니다. 파견 0기 화면에 공격 유닛을 임의로 추가하지 않습니다.

## 연결 후보와 확인

수량·메뉴 바탕은 `OrdrMobileUiTheme.cs`와 `OrdrMobileTouchPanel.cs`, 메인 바닥은 기존 전장 표시/카메라, 스토리 바닥·요새는 `OrdrStoryBattlefieldView.cs`의 기존 표현을 확장하는 후보입니다. 임포트·코드·유닛/HP 대비·기기 터치 영역이 연결되기 전에는 구현 완료로 보지 않습니다.

[전체 프롬프트](prompts.json) · [크기·RGBA/알파·SHA-256](image-metadata.json). 내장 이미지 생성 도구로 만들었고 선택한 원본을 픽셀 가공 없이 보관합니다. 시각/PNG 정보/파일 해시/문서 연결만 확인했으며 Python·NUnit·Unity·APK 실행과 Actions 조회는 하지 않았습니다. 휴대폰 화면을 바탕으로 만든 합성 미리보기는 개인용 초상화가 포함될 수 있어 GitHub에 올리지 않습니다.
